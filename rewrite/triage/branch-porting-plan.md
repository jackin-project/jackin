**Repository:** [jackin-project/jackin](https://github.com/jackin-project/jackin)

## 1. Recommended outcome

Keep `main` as the integration target. Recover the small, compatible behaviors identified in P01–P21 through new, narrowly scoped changes based on current `main`. Close the old branch program after each selected behavior is either implemented and verified or explicitly rejected with current evidence. There is no justification for merging an old branch wholesale.

The most consequential findings concern credential-store resource limits, provider rollback ownership, sandbox file-write integrity, cancellation outcome reporting, and exact OpenRouter amounts. Several preserved branches contain useful fixes that disappeared during integration or later replacement. Conversely, most named feature/review/worktree branches already contributed their useful behavior to the rewrite or subsequent PRs. Restoring their old trees would remove newer multi-agent support, credential checks, native usage functionality, or CI generation.

Treat P01–P21 as **source-backed work items**, not as a claim that every proposed patch has already passed runtime verification. Some are directly observed current-code omissions; P17 also has a small isolated reproduction. Image-policy and guardrail work require the particular contract tests described below before accepting a port. If refreshed `main` already fixes a case, close that item with the exact evidence instead of implementing it again.

## 2. Evidence, method and limits

The audit used the paginated GitHub branch inventory, a full local fetch of all branch histories, branch parent/merge-base comparisons, unique changed paths, patch equivalence, exact tree/blob comparisons, integration history, and direct inspection of current production callers and relevant tests. Each branch has a pinned head in the manifest. Histories containing stash snapshots were checked for index/untracked side parents, rather than assuming the visible working-tree snapshot was all the content. The two histories with no Jackin merge base were treated as separate repositories.

The inventory contains 148 distinct head commits and 117 distinct trees. Main's rewrite was squash-merged: an old branch being “ahead” or not an ancestor of `main` is not evidence of unported behavior. Equally, a file matching an earlier integration tree is not evidence that its behavior remains in today's `main`. This distinction is why older `rewrite/triage` labels were checked rather than accepted. The reviewed final source for #1264 and squash commit `f683619b5f1607c56b23c400848e8f6a00e09037` have the same tree; later main commits still need to be considered.

Three parallel reviews covered preserved snapshots, recovery/checkpoint histories, and worktree/backup branches. A separate challenge review then looked for existing safeguards, donor regressions and overstated impact in the proposed ports. The recommendations below incorporate those objections: for example, retaining current `edit_checked`, recognizing that guarded purge rereads work state, and rejecting the donor's colliding checkout-prefix scheme.

**Verification performed:** static history/source/caller/test inspection, plus P17's isolated execution of the extracted current shell writer using disposable nonsecret files. **Not performed:** building the project, running its Nextest/CI suites, live OpenShell or provider tests, or validating the proposed final implementations. Existing test sources and historical green logs are evidence of intent/coverage, not fresh passing results. Future work must produce current-head red/green and integration evidence.

The snapshot is not a lock on the remote repository. Refresh every ref before implementation and again before deletion. A moved or newly created branch receives a new audit row; its old verdict does not transfer automatically.

## 3. Preserve these current design decisions

Read the current [AGENTS.md](https://github.com/jackin-project/jackin/blob/8d9b05927e266844b63c2a20893257061ab5a086/AGENTS.md), [rewrite/DESIGN.md](https://github.com/jackin-project/jackin/blob/8d9b05927e266844b63c2a20893257061ab5a086/rewrite/DESIGN.md), and relevant current implementation before each task. Apply the user's model restriction in section 4 instead of the old plan's default Opus orchestration and any unrestricted fallback routing.

- OpenShell remains the execution engine. Docker BuildKit is for image building; Docker capability is explicit opt-in. Preserve layer boundaries: only the appropriate image adapter invokes Docker, and only the OpenShell adapter imports its SDK.
- Termrock/`jackin-console` owns the UI. Keep the paired dependency revision consistent. Port backend behavior without introducing a second renderer, local screen wording, or an old bespoke console.
- Preserve D29's current agent/provider/auth tuple eligibility. Native subscription **usage accounting** does not establish execution support. Do not promote blocked T02/T05 or unavailable T04/T06/T07/T08 using old logs, a restored test, or a feature branch name.
- Keep #1296's current native usage account/vault/versioning behavior, account identity and renewal guards, current provider-specific source handling, and modern multi-agent launch/rollback semantics.
- Keep current cancellation, project-root verification, unexported-work refusal, secret redaction, and protected-file checks while extending gaps. Donor code can be weaker in neighboring paths.
- Keep `.velnor/rust-ci.toml` as the generator input and the current `velnor-gen` workflow generation. Do not port old generated actions/workflows, old runner pins, or old toolchain/release artifacts.
- Do not restore D16 removals: old Docker session management, daemon/FFI/macOS stacks, obsolete broker/protocol/telemetry layers, old Capsule daemon, repair workflows, or heuristic agent-status inference.
- Follow the repository's no-comment policy for product code, with its existing explicit exceptions. Do not import `.audit` trees, raw logs, screenshots, temporary databases, secret-bearing fixtures, huge historical triage packs, or duplicated evidence. New tests must prove a current behavior through a public boundary.

## 4. Model strategy: exact allowlist and effort levels

This is the model policy for the **future `/goal` execution**, including its orchestrator, implementers, reviewers, helpers, retries and fallback settings:

| Role | Allowed exact model | Normal effort | Escalation |
|---|---|---|---|
| Inventory, source extraction, matrix maintenance, simple fixture work | `claude-haiku-5-5` | `low` or `medium` | `high`, then `xhigh` only for bounded local ambiguity; `max` is available but rarely economical. |
| Orchestration, implementation and independent review | `claude-sonnet-5-5` | `high`; `medium` for small isolated changes | `xhigh` for concurrency, credentials, filesystem/policy and numeric boundaries; `max` for unresolved difficult integration. |
| Rare architectural/security adjudication | `claude-opus-5-5` | Choose the effort for the documented narrow question | Only after a concrete Sonnet escalation fails or independent reviews remain in substantive conflict. Return to Sonnet afterward. |

**Never use Fable. Never enable an unbounded “best model,” automatic alias, or fallback that can select a model outside this allowlist.** If the execution environment does not expose a requested model or effort, report the capability block and use another explicitly allowed model only when its role fits. Do not silently substitute another version or vendor. Repository specialist names specify expertise, not an exception to the allowlist.

Both Haiku 5.5 and Sonnet 5.5 support `low`, `medium`, `high`, `xhigh`, and `max`. This policy makes all five available without wasting a full five-level ladder on every task. Support and exact model identifiers were checked against Anthropic's [effort documentation](https://platform.claude.com/docs/en/build-with-claude/effort), [Haiku 5.5 overview](https://platform.claude.com/docs/en/models/haiku-5-5/overview), and [Sonnet 5.5 overview](https://platform.claude.com/docs/en/models/sonnet-5-5/overview) on the audit date. Availability in the actual executor must still be checked.

| Effort | Haiku assignment | Sonnet assignment |
|---|---|---|
| `low` | List refs, calculate hashes/counts, validate manifest/prompt formatting. | Straightforward edits to an already approved task brief or evidence summary. |
| `medium` | Extract scoped diffs and current symbols; classify straightforward duplicate/debris rows for review. | P10/P14/P18-sized changes with clear public acceptance cases. |
| `high` | Focused code tracing, test scaffolding at an approved boundary, small isolated implementation with Sonnet review. | Default orchestration, most ports, test-plan approval and independent code review. |
| `xhigh` | Resolve one difficult local equivalence question before handing off a concise finding. | P01/P03/P04/P15/P16/P17 and difficult races or end-to-end exact-number changes. |
| `max` | Optional last bounded analysis when a demonstrated Haiku bottleneck warrants it; otherwise hand to Sonnet. | One unresolved architecture/integration question after focused `xhigh` work, not a default for all branches. |

Before an Opus invocation, record the unresolved question, relevant SHAs/files, failed approaches, competing conclusions and required decision. One scoped independent answer is enough; do not run Opus across every branch or use it as the standing manager. An implementer must not be its own final reviewer. Separate contexts on Sonnet suffice; “independent” does not require invoking Opus.

Run at most two or three disjoint implementation tasks concurrently. Serialize edits to shared gateway contracts, filesystem traits, account transaction code and usage number representations. Give each worker only its donor commits, current target files, accepted invariant, exclusions and acceptance cases. Do not feed the whole historical log collection to every model.

## 5. Port specifications and acceptance criteria

### P01 — Bounded, consistent credential database capture

**Source:** [recovery head](https://github.com/jackin-project/jackin/commit/8508f6f8388d9988a940beb8fb0b812bf6bc1215), particularly old `jackin-omp-store` capture/directory/retry/query/WAL code and commits `606de485c` / `b90200cc5`. **Targets:** current [usage credential readers](https://github.com/jackin-project/jackin/blob/8d9b05927e266844b63c2a20893257061ab5a086/crates/usage/jackin-usage/src/credential.rs) and [session credential readers](https://github.com/jackin-project/jackin/blob/8d9b05927e266844b63c2a20893257061ab5a086/crates/jackin-session/src/credentials.rs).

Current OMP readers open a live path with SQLite. The usage reader compares device/inode observations but follows the opened pathname; its detached worker can remain blocked after the caller cancels. The session reader ignores its injected filesystem and synchronously opens the store. OpenCode already has in-memory snapshot replay, correct schema/committed-frame semantics and checksum/salt validation. It still lacks comprehensive input/query/expanded-image bounds: `apply_opencode_wal` can resize the image according to a very large page number in a small valid WAL.

1. Define a small bounded capture contract using existing safe filesystem primitives. Pin validated directories/files, refuse unsafe kinds, and fence the DB/WAL pair's identity and contents across capture; retry only within one deadline.
2. Cap input DB bytes, WAL bytes, expanded image/pages, SQLite result/secret length, SQL operations, attempts, concurrent workers and total runtime. Use checked arithmetic before allocations.
3. Query an in-memory/private snapshot with current OMP/OpenCode selection semantics. Ensure cancellation stops or bounds the worker itself. Preserve the current OMP shutdown improvement; replacing it with an unbounded `spawn_blocking` operation is a regression.
4. Apply the contract to both usage and session/CLI OMP consumers. Wipe owned secret buffers where supported; do not claim control of all SQLite allocator memory.

**Acceptance:** ordinary DB and committed WAL-only update; provider/row identity; symlink/FIFO/device/foreign-owned or hardlinked input according to the established boundary; replaced root/DB/WAL; malformed/checksum-invalid WAL; huge page number; oversized DB/WAL/row; timeout/cancel without permanent worker growth; no plaintext temporary artifact; errors without secrets. Keep current OpenCode tests. The existing FIFO test manually unblocks the FIFO after caller cancellation, so it does not prove worker termination.

**Exclude:** old adapter crate, old account-selector/role database schema, temporary plaintext materialization, delivery machinery, or wholesale restored tests. Share the necessary capture boundary without moving SQL/provider dependencies into a pure core layer merely for deduplication. **Owner:** Sonnet `xhigh`; independent security and test review. **Dependency:** coordinate with P04.

### P02 — Exact OpenRouter amounts through both live paths

**Source:** [exact-money recovery head](https://github.com/jackin-project/jackin/commit/6ebbe14490b2eddac73263b2df248252e1b10546), bounded decimal parsing/normalization/arithmetic from the former OpenRouter implementation. **Targets:** current [provider](https://github.com/jackin-project/jackin/blob/8d9b05927e266844b63c2a20893257061ab5a086/crates/usage/jackin-usage-provider-openrouter/src/lib.rs), provider-core HTTP/parse/model, and [connected OpenRouter](https://github.com/jackin-project/jackin/blob/8d9b05927e266844b63c2a20893257061ab5a086/crates/usage/jackin-usage/src/connected/openrouter.rs).

The provider path converts JSON through `f64` and stores money rounded to cents; `0.004` can become stored zero. The newer connected path uses floating point for balances, budget subtraction, per-key measures and activity aggregation. An integer `Money` after that conversion cannot restore lost decimals.

1. Preserve numeric lexemes at the HTTP decode boundary; parsing a decimal after default `serde_json::Value` has converted it through floating point is too late.
2. Choose a bounded exact representation compatible with the current output/storage contract. Explicitly decide precision, exponent, overflow and invalid-number behavior; current `Money` caps exponent at nine, while the old donor uses a different protocol.
3. Carry exact subtraction, addition, scale normalization and serialization through provider snapshots and connected-account persistence. Keep presentation rounding distinct. Approximate percentages need not force approximate money.
4. Preserve current management-key-only credit lookup, standard-key privacy, paging, BYOK/activity aggregation and account identity. Keep other providers stable unless their shared representation requires a justified change.

**Acceptance:** subcent values, exponent/string/null inputs supported by the contract, mixed scales, a tiny remainder between large operands, the current documented negative-value/clamping policy, overflow refusal, repeated sums, BYOK, standard versus management keys, and persistence/JSON/CLI round trips. **Exclude:** obsolete broker/FFI/protocol/UI stack and the donor's incompatible historical scale/protocol assumptions. The donor itself is bounded (scale 255/digits 288); those bounds are not automatically the right current contract. **Owner:** Sonnet `high`, `xhigh` for the representation decision; independent review of both paths.

### P03 — Cancellation with authoritative commit and recovery outcomes

**Source:** [session-boundaries snapshot](https://github.com/jackin-project/jackin/commit/16de1eedff91e0711a1c58e59f69d39d81c402bd), cancellation APIs and bounded recovery lookup. **Targets:** [ConfigStore](https://github.com/jackin-project/jackin/blob/8d9b05927e266844b63c2a20893257061ab5a086/crates/jackin-core/src/config/store.rs), gateway find/power/read/write boundaries, session lifecycle and [launch cancellation](https://github.com/jackin-project/jackin/blob/8d9b05927e266844b63c2a20893257061ab5a086/crates/jackin-session/src/launch/run.rs).

`ConfigStore` lock/edit APIs do not accept caller cancellation. Several gateway operations construct independent tokens. A cancelled launch then performs reconciliation without a short dedicated recovery budget; an uncertain lookup can be presented as “cancelled before a sandbox existed.” A cancelled remote RPC does not establish that its mutation never happened.

1. Thread caller tokens through waits and user work, retaining current API layering and `edit_checked` validation.
2. Define a config commit boundary: cancellation before it prevents mutation; once an atomic commit might have occurred, settle/report the actual outcome before deciding rollback. Never drop the write and guess.
3. Reconcile a cancelled launch with a fresh, bounded cleanup/recovery token. Distinguish observed existing, confirmed absent, and unconfirmed/ambiguous outcomes; retain the known sandbox and launch identity.
4. Update CLI/TUI wording, nested cancellation exit classification and recovery entries consistently. Give cleanup its own finite budget where it must outlive caller cancellation; do not replace every new token mechanically.

**Acceptance:** precancelled lock/RPC, cancellation while contended, before/after atomic commit, lost create/power/write response, lookup timeout or multiple matches, bounded cleanup, same-launch-ID retry, and no false absence or duplicate creation. Retain current account/current-config fences. A deterministic drain helper is justified only if needed to observe finite asynchronous completion in these tests. **Owner:** Sonnet `xhigh`; land contract changes before dependent observation work.

### P04 — Filesystem identity and app-owned private state

**Source:** session-boundaries and [w1 path hardening](https://github.com/jackin-project/jackin/commit/768b18cddc0b6346cc52fc7a64de4049f08e6ed7). **Targets:** [fs.rs](https://github.com/jackin-project/jackin/blob/8d9b05927e266844b63c2a20893257061ab5a086/crates/jackin-core/src/fs.rs) and `paths.rs`.

Current `lock_file` follows the final component; `create_private_all` only applies the requested mode to newly created directories; `sorted_entries` turns invalid UTF-8 into lossy strings. A useful donor adds safeguards, but its `symlink_metadata` followed by pathname `set_permissions` introduces a race and must not be copied literally.

1. Use anchored, non-following opens and validate the actual file/directory descriptor for app-owned locks/private state. Enforce the required ownership/kind/link policy at that boundary.
2. Tighten an existing app-owned private leaf via its validated descriptor. Do not chmod unrelated workspace/home ancestors or accept a swapped symlink.
3. Reject an unrepresentable path at the typed boundary, or use a truly lossless representation throughout. Never alias two filesystem names through lossy conversion. Keep sanitized display text separate from identity.

**Acceptance:** normal lock and contention, symlink/nonregular lock, ancestor/leaf replacement, existing permissive owned private directory, foreign-owned directory, valid Unicode, distinct invalid-byte names, and legitimate platform parent aliases. Preserve current project-root verification and existing safe regular-file reads. **Owner:** Sonnet `xhigh`; P01/P12 reuse the resulting primitives only where appropriate.

### P05 — Docker client certificate/key matching

**Source:** session-boundaries `EngineCert::check_pair` and launch cert binding. **Targets:** [docker.rs](https://github.com/jackin-project/jackin/blob/8d9b05927e266844b63c2a20893257061ab5a086/crates/jackin-core/src/docker.rs), [launch/certs.rs](https://github.com/jackin-project/jackin/blob/8d9b05927e266844b63c2a20893257061ab5a086/crates/jackin-session/src/launch/certs.rs).

Validate that the parsed certificate and private key actually match, both when binding the engine settings and on the exact bytes reread for transfer. Keep the existing CA/fingerprint/file-change checks. Return a typed mismatch error before side effects and wipe private-key buffers on every outcome. Choose the crypto implementation at the right layer; do not add an old dependency configuration merely because it appears in the snapshot.

**Acceptance:** matching supported keys, mismatch, malformed DER, multiple/encrypted keys as applicable to current policy, and a file changed between binding and use. This provides early actionable failure; normal mTLS already rejects a mismatch later. **Owner:** Sonnet `high`; security review.

### P06 — Complete, unambiguous change review

**Source:** session-boundaries changes loop and linked-worktree regression fixture. **Target:** [export/sandbox.rs](https://github.com/jackin-project/jackin/blob/8d9b05927e266844b63c2a20893257061ab5a086/crates/jackin-session/src/export/sandbox.rs), especially `changes`.

Iterate all present repository checkouts when collecting visible changes. Preserve the existing all-checkout dirty/export/purge safeguards and unborn-tree handling. Qualify both sides of renames using stable checkout/agent identity. The donor uses basename prefixes, but current agent paths all end in `project`, so copying that scheme would still collide. Apply total file/byte/time bounds across the whole result, not fresh independent limits for every checkout.

**Acceptance:** two agents edit the same relative path; rename old/new paths; tracked/untracked files; unborn/detached/missing checkout; aggregate caps and omitted/unreadable counts. Do not claim to fix lost export data without an actual reproducer. **Owner:** Sonnet `high`; coordinate token use with P03.

### P07 — Fresh and bounded fleet observation

**Source:** session-boundaries removal/rework of stale work caching and bounded gateway inspection. **Target:** [fleet.rs](https://github.com/jackin-project/jackin/blob/8d9b05927e266844b63c2a20893257061ab5a086/crates/jackin-tui/src/fleet.rs).

`WorkCache` is keyed by gateway/sandbox and phase/creation/supervisor facts, which do not change when Git or recovery refs change. Recompute work on refresh under a cap, or define explicit finite freshness/invalidation. Bound inspect, work and the newer task-file reads under one deliberate observation policy. Include queued permit waits in total cancellation/deadline behavior. Keep unreadable entries and partial results, and avoid holding a global lock across remote awaits.

**Acceptance:** external host recovery-ref change, sandbox edit after exited/cached state, large fleet cap, slow calls/permits, cancellation and partial gateway failure. Guarded purge independently rereads work state; this fixes the displayed state, not a demonstrated purge bypass. **Owner:** Sonnet `high`; depends on P03's token contract where shared.

### P08 — Local role manifests refresh after external edits

**Acceptance:** edited manifest at the same path; valid→invalid→valid; deletion/restoration; Git role remains cached appropriately. **Owner:** Sonnet `medium` or Haiku `high` implementation with Sonnet review.

### P11 — Merge host usage cache by observation freshness

**Source:** [7df6a3f52](https://github.com/jackin-project/jackin/commit/7df6a3f5287087351321f211b2261ae14e0b7738) in w1, overlapping session/Codex checkpoints. **Target:** [cache.rs::save](https://github.com/jackin-project/jackin/blob/8d9b05927e266844b63c2a20893257061ab5a086/crates/usage/jackin-usage/src/cache.rs) and current host report ordering.

The writer rereads under the lock and then blindly replaces edited entries. An earlier request completing after a later request can replace the later same-fingerprint good snapshot. Keep the newest observation while defining retry/cooldown/failure merging and tie ordering explicitly.
