## 0. Findings that change the plan

1. Workflows are generated by Velnor Actions 0.1.69 (jackin) from `.velnor/config.toml`. Siblings: sentinel and agent-smith at 0.1.12, the-architect at 0.1.0. The generator owns `.github/workflows/*`, `.github/actions/*`, `.github/scripts/*`, `.github/velnor/*`, `.github/jactionlint.yaml`. The only hand-owned file I found under jackin `.github/` is `dco.yml` (no generated header). Nothing below proposes hand-editing generated files.
2. The generated PR CI does not run `xtask ci`. It runs, per crate: build, fmt --check, clippy -D warnings, doc, nextest, doctest (read: `.github/velnor/task-execution-manifest-v1.json`, 257 task records; 43 crates x 6 tasks minus one missing doctest). Plus three `checks` (repository-policy, repository-links, dependency-usage), jactionlint, plan, required verdict. No cargo-deny, cargo-audit, REUSE, zizmor, docs build, powerset, snapshots or Docker anywhere in the required CI. `xtask ci` is a local merge-readiness gate only.
3. Only 43 of 152 workspace members get per-crate CI jobs. `[discovery].exclude` in `.velnor/config.toml` lists 120 entries, 110 of them crates (ran: python count). Most of the runtime-* and usage-* crates are never tested by generated CI.
4. #1231 (commit 4990e26a, HEAD~ chain) already removed tests and comments: 2878 files touched. About 47 files still contain `#[test]` or `#[cfg(test)]` (ran: grep). There is no `crates/tests/e2e`. The `e2e` Cargo feature in crates/apps/jackin/Cargo.toml:97 is empty, and no source in the repo gates on it (ran: grep). The `xtask ci --e2e` lane therefore runs a nextest profile over nothing.
5. `allow_empty_test_suite = true` plus `--no-tests warn` in the generated nextest argv means a repo with zero tests passes CI today. After the rewrite this must flip to false, or the gate lies.
6. The repo already contains an OpenShell plan: `docs/openshell-v2/` (SPEC, CONTRACTS, PLAN, 60+ task cards, validators). The project note also names `compatibility.lock.toml`; that file does not exist (ran: find). The pack SPEC line 5 keeps "Docker and Buildx as trusted image-building infrastructure". Your brief says all direct Docker execution goes away. These agree only if Docker stays as image build tooling, not as an execution engine. Upstream confirms why (section 2).
7. REUSE is not enforced anywhere. jackin has `REUSE.toml` but no `reuse` tool in `mise.toml`, `hk.pkl`, xtask or Velnor config (ran: grep, `mise exec -- reuse` fails). The siblings pin `pipx:reuse` in mise.toml but never invoke it (.pre-commit-config.yaml has only gitleaks and the marketplace audit). A REUSE gate is new work, not a keep.
8. zizmor is pinned in jackin mise.toml but not in any gate. I ran `zizmor --offline --no-progress .github/workflows`: 1185 findings, 174 informational, 0 low, 0 medium, 0 high. The generated release workflows already use `permissions: {}` at top level, SHA-pinned `uses:`, `id-token: write` and `attestations: write` only on the attest job, and `actions/attest-build-provenance@4d101475...` (read: binary-release.yml:2084, 2177; binary-preview.yml:491, 581). That meets your hardening list; it is Velnor's, not ours to change.
9. Local `rust-build-guard` (required by `scripts/hk-workspace-admission` and `scripts/hooks-install`) is not installed on this machine (ran: command -v, ls ~/.local/bin). All `hk` cargo steps and hook install fail here. It is an unpinned external binary, so it breaks the "hooks run the same pinned tasks as CI" rule.

### Smallest honest gate set for the rewrite

Principle: every gate is a mise task; CI (Velnor `checks`/stack) and hk call the same task. Keep one entry `xtask ci` only if it stays a thin loop over those tasks.

Required (PR and local):
1. fmt: `mise exec --locked -- mbx +1.99.1 fmt --check`
2. clippy: `mise exec --locked -- mbx +1.99.1 clippy --workspace --all-targets --all-features --locked -- -D warnings`
3. nextest: `mise exec --locked -- mbx +1.99.1 nextest run --workspace --all-features --locked --no-tests fail`
4. doctest: `mise exec --locked -- mbx +1.99.1 test --doc --workspace --locked`
5. deny: `mise exec --locked -- mbx +1.99.1 deny --locked --workspace check advisories bans licenses sources` (same invocation hk.pkl uses with `cargo deny`; the `mbx deny` passthrough is inferred from `mbx nextest`/`mbx fmt` working in the Velnor argv, not run)
6. unused deps: `mise exec --locked -- mbx +1.99.1 shear --deny-warnings` (already `check:dependency-usage`)
7. workflows: `mise exec --locked -- jactionlint --config-file .github/jactionlint.yaml --strict-exit --no-online --shellcheck=shellcheck --pyflakes=` plus `mise exec --locked -- zizmor --offline .github/workflows` (zizmor is new to the gate)
8. REUSE: `mise exec --locked -- reuse lint` (new: add `python` and `pipx:reuse` to mise.toml as the siblings do)
9. policy: `mise exec --locked -- mbx +1.99.1 xtask lint --strict`, trimmed to ratchet, agents, agent-links, suppressions
10. docs build: `cd docs && mise exec --locked -- bun install --frozen-lockfile && mise exec --locked -- bun run types:check && mise exec --locked -- bun run build`
11. repo links: `mise run check:repository-links`
12. secrets (hook only): `mise exec --locked -- hk check --all` after the hk file loses the `rust-build-guard` prefix

Optional or scheduled: `cargo audit` (network, advisory churn), `mbx xtask custom-lints` (pinned nightly-2026-10-18 dylint for TUI render purity), cargo-hack powerset (drop unless real feature flags exist), cargo-fuzz.

### What must change if role images become OpenShell sandbox images
Upstream facts (OpenShell main, checked 2026-11-01 with `gh api`; file paths in NVIDIA/OpenShell):
- `crates/openshell-cli/src/main.rs:1456-1464`: `sandbox create --from` takes "a rootfs tar archive ... or a container image reference. To use a local Dockerfile, build and tag it with the container engine used by your local gateway, then pass the resulting image reference here. A rootfs tar is staged for the VM compute driver."
- `docs/about/installation.mdx`: runtimes are Docker (Desktop or Engine 28.0+), Podman (Linux), MicroVM (Hypervisor.framework on macOS, KVM on Linux), Kubernetes. On macOS the installer uses Homebrew and runs the gateway as a brew service at https://localhost:17670.
- `docs/how-it-works/sandboxes/runtimes.mdx`: "When `compute_driver` is unset, the gateway auto-detects Kubernetes, then Podman, then Docker. The VM driver is never auto-detected." Gateway default image is minimal Ubuntu with no agent.
- `docs/how-it-works/sandboxes/templates.mdx`: templates take `--image`, env and resources; `--template` cannot combine with `--from`.
- Latest release v0.1.6 (2026-10-27), v0.1.5 (2026-10-20) (ran: `gh api repos/NVIDIA/OpenShell/releases`).
Consequence: OpenShell does not build role Dockerfiles. Some builder (Docker Buildx, Podman or a rootfs-tar pipeline for the VM driver) must still build and push role images. Docker as build infrastructure stays; Docker as agent runtime goes. That matches docs/openshell-v2/SPEC.md:5 and :123.

Changes needed:
1. Base image: remove docker-ce-cli, buildx, compose (agents get no Docker socket), iptables/ipset/sudo and libnss-extrausers (capsule firewall, sudo and host UID mapping; OpenShell enforces policy and identity). Keep git, gh, ripgrep, fd, fzf, jq, mise, starship, zsh/fish. Settle the user: construct uses `agent` UID 1000 with home dirs `.claude .codex .jackin`; pack SPEC.md:135 expects a `sandbox` account with nonzero UID. Drop `.claude` for the Codex+Grok scope. Needs verification against the OpenShell supervisor contract (not verified).
2. Publication: there is no image-publish workflow. Velnor stacks I saw are Rust, release, Homebrew (config schema 2). Whether Velnor can generate an image build/push/attest workflow is not verified. If not, the fix belongs in tailrocks/velnor-new (per .github/AGENTS.md), not in a hand-written workflow, and `.github/workflows/` is reserved for generated files.
3. Registry: the gateway must pull by immutable digest from a reachable registry (pack SPEC.md:123). Keep the bake `attest` provenance + SBOM, and add `gh attestation verify`/cosign verify to the consuming side.
4. Role contract: sibling `jackin.role.toml` fields `dockerfile`, `published_image`, `agents` (see section 6) are the interface; they change with the manifest crate.
5. Pins: siblings pin `projectjackin/construct:0.37-trixie@sha256:67fc093e...` while docker/construct/VERSION is 0.38-trixie (drift today). Renovate's regex versioning `^(\d+)\.(\d+)-trixie$` in each sibling tracks it.
