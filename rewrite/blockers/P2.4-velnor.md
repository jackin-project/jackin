## Need 1. A named check cannot provision `reuse`

### Need

A named check must run `xtask ci --only reuse`, which starts `reuse lint`. `reuse` is a PyPI package (`pipx:reuse` 6.3.0 with the `charset-normalizer` extra in `mise.toml`). Velnor admits qualified tools only through the `core`, `aqua`, and `cargo` backends, so no check can put `reuse` on its PATH.

Without `reuse`, a check that runs the `reuse` step fails.

### Command

Add a qualified tool with the backend the package needs, then plan:

```toml
[[qualified_tools]]
id = "reuse"
version = "6.3.0"
depends_on = []

[qualified_tools.backend]
kind = "pipx"
package = "reuse"

[qualified_tools.options]
kind = "default"
```

```sh
velnor-actions plan
```

### Output

```text
velnor-actions: .velnor/config.toml: document: TOML parse error at line 291, column 8 | 291 | kind = "pipx" | ^^^^^^ unknown variant `pipx`, expected one of `core`, `a
```

A check that lists the tool without a qualified record fails earlier:

```text
velnor-actions: .velnor/config.toml: checks[1].tools: unknown_qualified_tool:reuse
```

`docs/implemented/qualified-check-tools.md` in `velnor-new` states the closed set: `QualifiedToolBackend` supports `core` (rust, node, bun, zig, python), `aqua`, and `cargo`.

### Smallest failing case

One `[[checks]]` entry with `tools = ["reuse"]` and no way to write the matching `[[qualified_tools]]` record.

### Proposed upstream change

Add a closed `pypi` qualified-tool backend. Its record names the PyPI package and the exact version, depends on one qualified `core` Python tool, and lists every wheel with a URL and a SHA-256, sorted like the other artifact lists. Installation uses `pip install --no-index --no-deps --require-hashes` into an owned prefix, so no network resolution and no ambient index can fill a gap. The installed-tree digest and the executable probe bind the result, as for the other backends.

The input exists in this repository. `.mise/locks/pipx-reuse/6.3.0~068c1fb0/uv.lock` pins the full closure of `reuse` 6.3.0 with `charset-normalizer`. A generator command could turn that lock into the artifact list, the way `qualify-tools` turns archives into records.

When this ships, add a `[[checks]]` entry with `tools = ["reuse", "rust"]` and a mise task that runs `mbx +1.99.1 xtask ci --only reuse`, and regenerate.

## Need 2. A `cargo-deny` qualified record for `linux_x64`

### Need

A named check must run `xtask ci --only deny` (`cargo deny --locked check`). The check must list `cargo-deny` in `tools`. `.velnor/config.toml` has no `[[qualified_tools]]` record for it.

### Command

Add a check that lists the tool, then plan:

```toml
[[checks]]
id = "deny-probe"
task = "check:repository-steps"
directory = "."
inputs = ["Cargo.lock"]
tools = ["cargo-deny", "rust"]
timeout_minutes = 10
```

```sh
velnor-actions plan
```

### Output

```text
velnor-actions: .velnor/config.toml: checks[1].tools: unknown_qualified_tool:cargo-deny
```

### Smallest failing case

One `[[checks]]` entry with `tools = ["cargo-deny"]`.

### Proposed change

This is a procedure, not a missing Velnor feature. `velnor-actions qualify-tools` runs its version probes on the host platform, so an operator runs it on a Linux x64 host with the independently pinned `cargo-deny` 0.20.2 archive (`mise.toml`, `mise.lock`) and commits the record. Then add a check with `tools = ["cargo-deny", "rust"]` and a mise task for `xtask ci --only deny`, and regenerate.
