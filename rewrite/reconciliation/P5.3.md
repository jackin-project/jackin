## P5.3 flake: `shell_exit_code_cannot_hang_the_run`

Cause: the test paused the tokio clock while the gateway client held a real TLS connection to the in-process server. The SDK sets an HTTP/2 keepalive ping every 10 s with hyper's default 20 s pong timeout (`openshell-sdk` `transport.rs` `standard_endpoint`). A paused clock jumps to the next timer whenever the runtime goes idle, even when the socket already holds the server's pong. The ping timer (+10 s) and its timeout (+30 s) are both earlier than `PROGRAM_TIMEOUT` (60 s), so the client closed the connection after exactly 30 virtual seconds when the timeout won the race against the pong. The event loop then ended with `Ended(Failed("h2 protocol error: error reading a body from connection"))`, so the check reported "the shell exit code is not 3" instead of "the shell never ended". The same race in the cleanup RPCs gave the "did not end" panic at the outer 120 s timeout. The `PROGRAM_TIMEOUT` wrap in `shell_exit_code` is correct. The other two paused-clock tests (`exec.rs`, `status.rs`) stay safe only because their timeouts (5 s) are shorter than the first ping.

Fix: `tests/gateway/harness.rs` gains `drive_paused`, which pauses the clock and then advances it in 2 s steps. Before each step it waits 20 ms of real time in `spawn_blocking` (`recv_timeout`, since clippy bans `thread::sleep`), which tokio treats as a reason not to auto-advance, so real I/O (pongs) settles first. Time moves only by explicit steps. `tests/gateway/contract.rs` uses it in place of `pause` plus an outer `timeout`.

### Preconditions

- **P1 (locks).** The lock files are `account-<account>.lock` and `upload-<launch>.lock` under `cache_dir`, taken by one helper (`lock::hold`) that creates `cache_dir` with mode 0700, polls with `Clock::sleep(100 ms)` and honors cancel (`LockError::Cancelled`). The launch takes the account lock, re-checks `provider_state`, puts and releases (`Session::sync_if_absent`). It never calls the public `sync_account`, which takes the same lock; a second flock on the same file from the same process would wait on itself. `sync_account(account, cancel)` keeps "always put" and takes the lock itself.
- **P2 (upload timer).** The timer is `tokio::time::timeout` on real time (orchestrator decision O1). It starts after the upload lock is held and covers the marker read, the refusals, the facts, the bundle, the empty, the upload and the gate. It is not a `Clock::sleep` raced against the work. `FakeClock` fires a lone sleeper after 64 yields, so such a race would fire during any real git call.
- **P3 (fake gateway).** The fake `tracked_and_untracked` in `jackin-testkit/src/gateway/files.rs` (batch G3) runs `git ls-files -co` with the host config. Batch G3 gave it `-c core.fsmonitor=false -c core.hooksPath=/dev/null` (a6425e97), so row P53-G1-10(a) is green on the rebased branch with no hand patch.
- **P4 (one host git constructor).** `grep -rn "Program::Git" crates/jackin-session/src` lists `project/git.rs` (`HostGit::capture`) and `project/version.rs` (`git --version`, which reads no repository). `roles.rs` and `export/host.rs` build `HostGit`.
- **P5 (hardening).** `HostGit::capture` puts `-c core.fsmonitor=false -c core.hooksPath=/dev/null` before the subcommand. No directory is created. The overrides are arguments, so the `GIT_` scrub stays. The OpenShell CLI upload env belongs to batch G3 (transfer.rs); the session passes nothing.
- **P6 (gate list).** One NUL-separated list, `git ls-files -z -co --exclude-standard --deduplicate` minus `git ls-files -z -d`, is read in `stage`. The host gate adds it with `git --literal-pathspecs add -f --pathspec-from-file=<staging>/gate-paths --pathspec-file-nul`; the sandbox gets the same bytes in `gate-<launch>/paths` and runs the same `add`. A file deleted after the listing makes the host `add` fail with `ProjectFailed`; that is a typed failure, not a silent pass.
- **P7 (upload act order).** Lock, marker read, `stage` (refusals, facts, listing, staging directory, bundle), then `empty()`, `upload_tree`, bundle, repository, gate. `precheck` before any gateway call runs the same `stage` into a throwaway staging directory and removes it, so a partial clone is still refused before the image build.
- **P8 (run state reset).** `Done::forget_sandbox` keeps `Provider` in `steps` and resets `boot` and `started`; the rest of `steps` (Ready, Credentials, Hooks) belongs to the old sandbox. `Run::vanished_sandbox` calls it for an empty `find_sandboxes` after a sandbox was known, and for a probe that answers `NotFound` for the sandbox it just found.
