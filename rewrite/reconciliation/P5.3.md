### Preconditions

Each precondition is stated here before the rows that rely on it.

1. Scope and base: only the files named above change; the env helper lives in `transfer.rs`; `cli.rs` is untouched; `API.md` is not edited.
2. Cross-batch API: `files()` signature and `HostState.files` key type are unchanged. Link and empty-directory reporting is additive. A symlink appears only in the link map. The `Gateway` trait signatures do not change.
3. GIT_CONFIG semantics: the pairs go in `ProcessSpec.env` as `EnvValue::Plain`, built by one function (`git_config_env`) in `transfer.rs`, and attach to both upload calls. No other `GIT_CONFIG_*` name is set. `env_remove_prefixes` still lists `GIT_` and `OPENSHELL_`. That the real runner applies `spec.env` after prefix removal is covered by the jackin-session `process_runner/env.rs` tests.
4. Download rules: the temp file is in the target's directory, unique per call (process id plus a counter), and differs from the target. It is removed on every error path, including a runner `Timeout` and `Cancelled` (the runner kills and awaits the child first). It is renamed only after the digests match. The destination is never touched on failure. A hard kill can leave a temp file behind: recorded residual, not tested.
5. Size re-check: it runs right after the CLI returns `Ok`, on the temp file's `metadata().len()`, before any further gateway call, through the same `within_limit` helper as the `stat` check. See deviation 3.
6. Fake parity: a non-UTF-8 listed name is checked for the whole list before any copy. A non-file, non-directory, non-symlink entry anywhere (also inside a listed directory) is found by a pass over the whole list before any copy, so a refused upload leaves the sandbox untouched like the live CLI (`evidence/P5.3-live.md`: `/sandbox/fifo` was never created), and errors with `unsupported file type for upload: <path>` and `Exited(1)`. The fake refuses an upload with "sandbox not found" for an absent sandbox and "sandbox is not ready" for a sandbox that exists but is not exec-ready.
7. Fixture rules: the non-UTF-8 name goes in through the index (`git update-index --cacheinfo`), because APFS refuses to create it on disk. Specials use `/usr/bin/mkfifo` and `UnixListener::bind` with short temp paths. No `unsafe` and no `set_var`. Raw git commands set `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1`.
8. Consumers stay green: `nextest run -p jackin-session` (162 tests, all binaries including `export` and `project`) passes after the snapshot and fake changes.
9. Source-derived items: the non-UTF-8 error (`run.rs:5254`, `from_utf8(entry)?`), the special-file error (`ssh.rs:1128`), and the "not ready" text for phases other than Stopped are source-derived, not live. The live oracles are `evidence/P5.3-live.md` (Stopped upload: exit 1, "sandbox is not ready") and `evidence/P4.4-live.md` (absent: "sandbox not found").
10. Changed expectations: the removal rule in both download tests (a failed download now leaves the destination alone); the argv last-argument assertion (the CLI writes to a sibling temp, not to the destination); `TRANSFER_CHECKS` goes from 6 to 7; the `expect_git` call sites; `an_upload_to_a_stopped_sandbox_is_a_transfer_error_for_both_calls_and_changes_nothing` is replaced by the not-ready test; the fake upload text for a Stopped sandbox changes from "sandbox not found" to "sandbox is not ready".
11. Code hygiene: no code comments, SPDX headers kept.

### Deviations from the plan

1. `RoleFixture.dir` is renamed `_dir`. Removing the no-op `let _keep` bindings exposed a `dead_code` error on that field, which only holds the temp directory alive.
2. The snapshot row is five tests, one per change, so each shows its own red. On the HEAD `snapshot.rs`, "a link replaced by a regular file with identical content" is not red: the old code recorded the link's lstat mode (symlink mode differs from the file mode on macOS), so it already saw that change. The test stays as a guard for the new link representation and is red under the follow-links variant. The plan's claim that every positive case was red on HEAD holds for three of four.
3. The size re-check skips when `metadata()` of the temp fails and lets the digest steps report the problem. A strict error there broke the existing contract test `a_gateway_that_finds_a_missing_file_and_fails_later_fails_the_size_check`, which has a CLI that exits 0 without writing a file and expects the `Digest` failure. The oversize path is unaffected.
4. The adapter cancel scenario is a runner `Cancelled` reply after the CLI wrote partial bytes. The runner contract says the child is killed and awaited first, so the temp cleanup cannot race.
5. Clippy forbids `std::process::Command::output` (blocking). The test helpers use `spawn().wait_with_output()`.
6. The shared absent-sandbox check now asserts exit 1 and "found" without "ready" (plan). The adapter test also asserts that the absent check fails when the CLI says "sandbox is not ready".
7. The fake's own `tracked_and_untracked` passes `-c core.fsmonitor=false -c core.hooksPath=/dev/null` (G1 precondition P3). Row FAKE-LISTING-FLAGS pins the fsmonitor flag. The `core.hooksPath` flag has no behavior row: `ls-files` runs no hook, so no test can observe it.
8. `tests/gateway/support.rs` `git` (testkit) and the `project()` fixture in the adapter tests also use `/usr/bin/git` with the two config variables, to match decision 6.
9. `an_upload_to_a_stopped_sandbox_is_a_transfer_error_for_both_calls_and_changes_nothing` and `a_failed_download_leaves_no_local_file_and_a_good_one_writes_it` are replaced under new names; the old cancel test keeps its role under a new name.
