- B2. Gateway surface. `Gateway::upload_tree(&self, sandbox: &SandboxName, source: &ProjectRoot, dest: &SandboxPath, cancel: &CancellationToken) -> Result<(), GatewayError>` runs `openshell sandbox upload <sandbox> . <dest>` with the project root as `cwd`. `Gateway::upload_file(&self, sandbox: &SandboxName, source: &HostPath, dest: &SandboxPath, cancel: &CancellationToken) -> Result<(), GatewayError>` runs `openshell sandbox upload <sandbox> <file> <dest> --no-git-ignore` with no `cwd`, then compares the host `sha256` of the file with `sha256sum <dest>` in the sandbox. Both calls remove `OPENSHELL_` and `GIT_` from the environment, take a null stdin and the transfer timeout. `TransferOp` is `UploadFiltered` (tree call), `UploadFile` (file call), `Download`, `Digest`, `Size`. A mismatch is `Transfer { op: Digest, status: Exited(0), tail }`, and the tail holds both digests. `GatewayOp::UploadTree` and `GatewayOp::UploadFile` replace `GatewayOp::Upload`, so a `Trigger::Op` tells the two calls apart. `ProjectUpload` is deleted; the two calls take their arguments directly.
- B3. Fake fidelity. `FakeGateway::upload_tree` replicates the CLI source at `ac7f615` (`run.rs:5235`, `ssh.rs:1083-1120`) until L2, L7 and L8 are captured: it copies the set that `git ls-files -z -co --exclude-standard` lists, archives a listed directory in full (a nested repository keeps its `.git`), skips a listed path that is missing, never deletes, and does not list the `.git` entry of the project. It runs `ls-files` with `HOME` set to the shared temp home of the `World` (`FakeGateway::use_host_home`), so the user git configuration is the one the project module sees (`P51b-GATE-GLOBAL`). `upload_file` copies the file to the exact destination (parents created, an existing file replaced), then compares the SHA-256 of the source with that of the landed file. New faults: `Fault::CorruptUpload` flips one byte of the next landed file, so the digest check fails with `Transfer { op: Digest }`; `Fault::EditHostAfter { upload: UploadKind, edit: HostEdit }` edits the host after the next tree or file upload (`HostEdit::Write` or `HostEdit::Chmod`). The fake sandbox runs `/usr/bin/find`, `/usr/bin/mkdir` and `/usr/bin/rm` as the host `find`, `mkdir` and `rm`, and expands `/sandbox` inside environment values as it already does inside arguments (the gate sets `GIT_INDEX_FILE` and `GIT_OBJECT_DIRECTORY` under `/sandbox/.jackin`). `SandboxHandle::root()` returns the host directory that stands for `/sandbox`, so a test can run real git in the sandbox repository.

Tests never call `set_var`. `/etc/gitconfig` and the Apple system configuration are machine state; the runner and the fake set `GIT_CONFIG_NOSYSTEM=1`, and no assertion depends on them.
