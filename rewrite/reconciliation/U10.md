- B2. Gateway surface. `Gateway::upload_tree(&self, sandbox: &SandboxName, source: &ProjectRoot, dest: &SandboxPath, cancel: &CancellationToken) -> Result<(), GatewayError>` runs `openshell sandbox upload <sandbox> . <dest>` with the project root as `cwd`. `Gateway::upload_file(&self, sandbox: &SandboxName, source: &HostPath, dest: &SandboxPath, cancel: &CancellationToken) -> Result<(), GatewayError>` runs `openshell sandbox upload <sandbox> <file> <dest> --no-git-ignore` with no `cwd`, then compares the host `sha256` of the file with `sha256sum <dest>` in the sandbox. Both calls remove `OPENSHELL_` and `GIT_` from the environment, take a null stdin and the transfer timeout. `TransferOp` is `UploadFiltered` (tree call), `UploadFile` (file call), `Download`, `Digest`, `Size`. A mismatch is `Transfer { op: Digest, status: Exited(0), tail }`, and the tail holds both digests. `GatewayOp::UploadTree` and `GatewayOp::UploadFile` replace `GatewayOp::Upload`, so a `Trigger::Op` tells the two calls apart. `ProjectUpload` is deleted; the two calls take their arguments directly.
- B3. Fake fidelity. `FakeGateway::upload_tree` replicates the CLI source at `ac7f615` (`run.rs:5235`, `ssh.rs:1083-1120`) until L2, L7 and L8 are captured: it copies the set that `git ls-files -z -co --exclude-standard` lists, archives a listed directory in full (a nested repository keeps its `.git`), skips a listed path that is missing, never deletes, and does not list the `.git` entry of the project. It runs `ls-files` with `HOME` set to the shared temp home of the `World` (`FakeGateway::use_host_home`), so the user git configuration is the one the project module sees (`P51b-GATE-GLOBAL`). `upload_file` copies the file to the exact destination (parents created, an existing file replaced), then compares the SHA-256 of the source with that of the landed file. New faults: `Fault::CorruptUpload` flips one byte of the next landed file, so the digest check fails with `Transfer { op: Digest }`; `Fault::EditHostAfter { upload: UploadKind, edit: HostEdit }` edits the host after the next tree or file upload (`HostEdit::Write` or `HostEdit::Chmod`). The fake sandbox runs `/usr/bin/find`, `/usr/bin/mkdir` and `/usr/bin/rm` as the host `find`, `mkdir` and `rm`, and expands `/sandbox` inside environment values as it already does inside arguments (the gate sets `GIT_INDEX_FILE` and `GIT_OBJECT_DIRECTORY` under `/sandbox/.jackin`). `SandboxHandle::root()` returns the host directory that stands for `/sandbox`, so a test can run real git in the sandbox repository.
- B4. Host environment. The real runner applies `ProcessSpec.env` after `env_remove_prefixes` (`tests/process_runner/env.rs`). Every host git call of the project module sets `env_remove_prefixes` to `GIT_` and then sets `GIT_OPTIONAL_LOCKS=0`; the gate sets `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` explicitly; the bundle call sets `GIT_NO_LAZY_FETCH=1`. `TestRunner` gains a temp `HOME` (`TestRunner::with_home`, owned by `World::home()`), sets `GIT_CONFIG_NOSYSTEM=1` for every host git it starts, applies a list of ambient variables (`TestRunner::set_ambient`) before the `env_remove_prefixes` of the spec, so a test can put `GIT_DIR` into the runner as a process would, and runs a scripted reply for `git` when an expectation was added with `ScriptedProcessRunner::expect_git` (`git --version` for `P51b-GIT-VERSION`); every other git call runs the real `/usr/bin/git`. Tests never call `set_var`. `/etc/gitconfig` and the Apple system configuration are machine state; the runner and the fake set `GIT_CONFIG_NOSYSTEM=1`, and no assertion depends on them.

- B5. The checks and refusals run in `Run::execute`, before the first `find_sandboxes` call and so before the image, the provider and the create (O5). A failed or refused preflight returns `LaunchFailure { step: LaunchStep::Upload, sandbox: None }` and emits no step event; `LaunchStep` is unchanged, so the nine-step event contract of P5.1 holds. A cancel before or during the preflight ends as `Cancelled`. `check_git(runner, cancel) -> Result<GitVersion, HostGitError>` is public for `doctor()` (P5.2); the launch runs it first.

- B8. Identity is the effective configuration in the project root (`git config -z --get user.name` and `user.email`, global and `includeIf` included), passed to the sandbox as `git config --local -- <key> <value>` arguments of the exec call, never through a shell (O6). A key that is unset is not written. A value that is not UTF-8 is decoded lossily. Git itself trims leading and trailing crud characters (`'`, `"`, `.`, `,`, `;`, `<`, `>`, `\`) from the author name at commit time, so the hostile test name ends in a letter.
- B9. The host staging directory `cache_dir/upload-<launch>-<pid>-<n>` holds the bundle (`upload.bundle`), the temporary index (`gate-index`) and the temporary object directory (`gate-objects`). `prepare` creates it after the refusals and removes it when the bundle step fails; `Run::execute` removes it after the loop on every path (success, failure, cancel). A name that includes the process and a counter keeps two concurrent runs of one launch ID apart (the P5.1 test `two_concurrent_launches_with_one_id_end_with_one_sandbox_and_one_start` runs two in one process). `cache_dir/upload-<launch>.lock` is a file lock that serializes the upload act of one launch ID; it stays on disk like the image locks of F3-P9. Under the lock the act reads the upload marker once more and skips the upload when a peer finished it (`SkipReason::AlreadyUploaded`). Without the lock two `git init` runs in one directory fail with `File exists`.
- B10. A host HEAD on `refs/heads/jackin/*` arrives as a detached HEAD at its commit (O1). The fetch then names `HEAD` as an extra source, so the objects of a commit that no included ref reaches still arrive.
- B11. Host git floor 2.45.0 (`--no-lazy-fetch`). The sandbox never runs `--no-lazy-fetch`; its steps are `init`, `fetch`, `symbolic-ref`, `update-ref`, `reset`, `config`, `add`, `write-tree` and `ls-tree`. L4 reruns when the construct image git changes. The bundle command is `git --no-lazy-fetch bundle create --quiet <file> [HEAD] --exclude=jackin/* --branches --tags --remotes` with `GIT_NO_LAZY_FETCH=1`. Deviation from the D08 text: `--exclude` must come before `--branches` and take the pattern without the `refs/heads/` prefix; checked with git 2.54 on a repository that holds `refs/heads/jackin/old/main` at the same commit as `main`: the D08 order (`--branches --tags --remotes --exclude='refs/heads/jackin/*'`) and the prefixed pattern both list the jackin ref in the bundle, `--exclude=jackin/* --branches` does not. The sandbox fetch still carries `^refs/heads/jackin/*`, so each layer alone keeps the jackin refs out.
