### Decided behaviour change (M2)

`jackin workspace add` used to store a lexically normalised path and accepted a path that did not exist. It now stores the real path and fails for a path that is missing or is not a directory. The test `role_workspace::workspace_add_stores_the_docker_flag_and_an_absolute_path_and_ls_pins_the_shape` pinned the old behaviour: it added `proj/one` and `../two` without creating them. It now creates both directories first, and it expects the same stored paths (the test world is already canonical). `config_io` and the duplicate-name case of `role_workspace` create their directories for the same reason. AGENTS.md says jackin keeps no compatibility, so a config that holds a lexical path gets no migration: `workspace_for` still compares the stored path with the current directory, so such a workspace is not found from its real path until it is added again.

### Decisions the brief did not fix

- The CLI has no `workspace rename`. The guard covers `workspace rm` in the CLI, and delete and rename in the console.
- The guard needs every configured gateway. When the config holds a gateway and the workspace exists, `workspace rm` connects to all of them, as account removal does (D26). A gateway it cannot reach stops the command and names `jackin gateway rm <name> --offline`; an unreachable home gateway gives the connect error. A config with no gateway skips the check. The check and the config write are two steps, so a launch between them can still create a sandbox for the removed workspace. This is the same accepted shape as the guarded purge (D08).
- Restore is `Session::power(Start)` and a refresh, as the brief says. D09 makes `jackin-start` write `waiting` on every start, so Codex does not run until `jackin attach --restart`. The row therefore stays `restore available`, and the demo attach that follows the console Restore reports `not running`. Starting Codex again from the console needs the restart path of `Session::restart_agent` and a bounded wait for the `waiting` state; it is not built here (see the backlog items).
- Prewarm picks the gateway and the role as `jackin build` does without a role: the default gateway, the workspace default role, else the only allowed role. It never forces a rebuild.
- The console cannot give a revision for a Git role, so the role follows the default branch of the remote. `jackin role add --rev` still takes one.
- `jackin build` now goes through `jackin_session::build_observed`, so the CLI and the console share one progress loop.
- The docs pages `guides/workspaces.mdx`, `guides/sandboxes.mdx` and `guides/security-model.mdx` state the new behaviour.
- The `screen` check of `xtask` flagged a `"workspace"` literal in the prewarm code (C2). `Config::require_workspace` in `jackin-core` now builds the error, so the screen text comes from a domain crate.
- A CSI that the filter holds back is buffered up to 256 bytes. A longer one is dropped whole, which no real SGR, cursor or mode sequence reaches.
- The console launch of an unsaved directory now resolves the directory through `HostPath::canonical_dir` before it looks for a saved workspace.
