## What changed

- **Gate.** `ErrorsCheck` (`crates/xtask/src/checks/errors.rs`) is CI step `errors`, after `containers` and before `reuse`. It reads every `.rs` file that `Repo::files()` returns (`crates/usage/` stays skipped by `PENDING_PORT_PATHS` until P6.3; the gate adds no path filter of its own). It lexes `#[error(...)]` and checks every string literal inside the attribute and the argument tokens. One violation per literal, which names every offending placeholder: a Debug placeholder (a format spec that ends in `?`), or the argument `source` (`{source}`, `{source:#}`). The argument form `.source` is a violation of its own. `mise.toml` (task `check:repository-steps`, which the generated CI job runs) and `hk.pkl` list `errors`. `CiStep` implements `Display` with the clap names, so `xtask: errors` and `errors reported N violations` read as the `--only` values do.
- **The 137 placeholders in 98 attributes** are fixed. Identifiers print through `Display`. `jackin-core` gets `display.rs` with three helpers: `plain` (printable text as is, each control character as its Rust escape, found with `str::escape_debug` between the three quote characters, so `"`, `'` and `\` stay as typed), `plain_list` (items through `plain`, joined by `, `, an empty list is `none`), `plain_duration` (the old `30s`, `250ms`). A collection or a duration enters a message as a function argument, `#[error("... {}", plain_list(.0))]`, like the existing `found_text`.
- **New `Display` impls.** Core: `HostPath`, `SandboxPath`, `RepoPath` (all through `plain`, so a file name cannot carry a control character into a message), `ProjectRoot`, `TerminalText`, `Phase`, `Program`, `ProcessStatus`, `OutputStream`, `DockerSource`, `HookKind`, `CodexAuthMode`, `Platform`, `SupervisorReading`. OpenShell: `Missing`, `GatewayOp`, `TransferOp`, `ClosureViolation`. Session: `EnvFileProblem`, `LaunchStep`, `ProjectStep`, `EnvQuestion`, `UnknownReason`, `WorkState`.
- **Deleted (finished migration).** `report::phase_text`, `report::hook_name`, `report::work_state` (now `Phase`, `HookKind`, `WorkState` `Display`), `commands/progress.rs::step_name`, `engine.rs::describe`, and the `format!("{:?}")` of `LaunchStep` in `report.rs`.
- **Outside text.** `SupervisorStateError::{UnknownWord, BadExitCode, TrailingText}`, `IdError::InvalidChar.ch`, `DockerfileError::{FinalStageNotConstruct.found, UnreadableFrom.text}`, `DiscoveryError::{InsecureEndpoint.scheme, UnsupportedAuth.auth}`, `ExportError::BundleHeads.{extra, missing}` and the unusable branch names of `WorkState` go through `plain`.
- **`{source}` sites.** `RoleError::Manifest` prints only `invalid role manifest at <path>`; `report::chain` appends the cause once. `CiError::Spawn` prints `cannot start <program>`; `xtask`'s `fail_chain` appends the OS cause once.
- **`role check`.** `RoleCatalog::read_manifest` (shared by `load` and `findings`) stats the root first: `RoleError::RootMissing` (`<path> does not exist`), `RoleError::RootNotDirectory` (`<path> is not a directory`), and `RoleError::ManifestMissing` (`<root> has no jackin.role.toml`, an existing directory without the manifest). A symlink root still passes to the old walk.
- **`jackin ls`.** Human output with no listed sandbox prints `no sandboxes` on stderr after the per-sandbox warnings. Stdout stays empty and `--json` is untouched.

## Orchestrator decisions applied

1. Control characters: one helper (`plain`) in `jackin-core`, used at every site above. Exact strings in E3.
2. `ls` with only unreadable sandboxes prints the warnings and `no sandboxes`.
3. The role-check fix lives in `read_manifest`. Wording: `<path> does not exist`, `<path> is not a directory`, and, from the review example, `<root> has no jackin.role.toml`.
4. Gate scope is `Repo::files()`; both gates run as step `errors`.
5. Both `{source}` sites are fixed. `Spawn` keeps the OS cause once.
6. Collections go through a function passed as a format argument.

## Deviations from the plan

1. **X1 setup.** The plan sets `CARGO` to a missing path. `Repo::open` runs `cargo metadata` through the same `CARGO`, so the run then fails before any step, with `No such file or directory (os error 2)` and no program name. The test runs `ci --only docs` on a fixture with no `docs/` directory. `bun` cannot start there (`current_dir` fails), which gives `CiError::Spawn` with `ENOENT` and needs no change to `Spy`.
2. **X1 is green on the base code.** Before the fix the message already carried `{source}` once and `fail()` printed Display only. The test guards the fix, not the old state. Its two breaks are below.
3. **G1 gets one more case.** `pair {a:?} and {b:?}` pins the one-violation-per-literal rule. The plan's case 4 has a single Debug placeholder, so a per-placeholder mutant would pass it.
4. **Wording the plan left open.** `DockerSource` prints `the role`, `the workspace`, `both the role and the workspace` (the message reads `enabled by the role`). `Platform` prints its docker argument (`linux/arm64`). `CodexAuthMode` prints `api key` and `chatgpt login`. `Missing` prints `sandbox X`, `provider X`, `profile X`, `workspace X`. `BundleHeads` reads `extra a, b; missing none` (semicolon, so the two lists do not run together). `InsecureEndpoint` with no scheme reads `has no endpoint scheme`.
5. **`WorkState` and `UnknownReason` `Display` moved from `report.rs`** into `jackin-session` and print the words `report.rs` printed before. `PurgeError::WorkNotExported` now has a readable message of its own.
6. **Not changed, listed as suggestions.** `LaunchFailure` interpolates `{error}` on a field marked `#[source]`; the gate reads placeholder names, so it does not see it. `report.rs` formats a `LaunchFailure` itself and does not call `chain` on it, so no repeated cause reaches the user today. `PathError::{NotAbsolute, NotRelative, ParentSegment, EmptySegment}` and other plain `{message}` strings are `Display` already and are not wrapped in `plain`. A role root that is a symlink to a regular file still ends in the `FsError::Io` text.

## Suggestions

- Extend the `{source}` rule to a field marked `#[source]` or `#[from]` that the message prints by another name (`LaunchFailure.error` is the one case today). The gate would need the field attributes, not only the format literal.
- A role root that is a symlink to a file still ends in the OS text. A `stat` that follows links would close it.
- Wrap the remaining `{message}` strings of `PathError` in `plain` if user input can reach them with a control character.
