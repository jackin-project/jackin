### S1 `until_held`

- **Break a (plan):** `until_held` returns `false` at once.
  - Red: 2 tests run: 0 passed, 2 failed; `holds.rs` `the create never arrived` and `nothing had arrived yet`
  - Green after revert: 2 tests run: 2 passed
- **Break b:** the old poll comes back (2,000 polls of 1 ms, `tokio::time::sleep`).
  - Red: 1 failed, 1 passed; `the create never arrived`. The test starts paused and the create arrives after 5 s of virtual time. The poll gives up after 2 s of virtual time.
  - Green after revert: 2 passed
- The first test pins the wait to an event. The second pins the two cases where no arrival can come: no hold armed, and a release before the arrival. In both, `until_held` returns `false` at once. The old code waited 2 s of real time for them.

### S2 `sleepers`

- **Break:** `Waiter::drop` does not remove the id from `waiting`.
  - Red: 1 failed; `assertion 'left == right' failed: a dropped sleep still counts | left: 2 | right: 1`
  - Green after revert: 1 passed
- The test also drives a sleep to its end (`advance`, then poll) and expects 0 sleepers and one entry in `slept()`.

### S3 `FakeEngine::hold` and `waiters`

- **Break (plan):** `hold` returns `Ok(None)`, the trait default.
  - Red: 2 failed; `Error: "the fake engine granted no lock"` in both tests
  - Green after revert: 2 passed
- The assertions repeat the three that `crates/jackin-image/tests/image_io/lock.rs` makes for the real `BuildxEngine::hold`:
  - A second hold of one key waits until the first is dropped. Here that is `waiters` 1, then 0.
  - Different keys do not wait.
  - A waiter that is cancelled returns `Cancelled` and changes nothing for the holder: a later hold on the key still waits.
- The real engine has no `waiters`, so the fake test reads the wait from `waiters` and the real test reads it from the `contended` signal of `SignalFs`. The fake takes its exclusion from a `BTreeSet` of held tags and a `Notify`, not from a file lock. No other owned code is faked.

### S4 `BuildEffect::NewId`

- **Break (plan):** the effect is ignored.
  - Red: 1 failed; `assertion 'left == right' failed | left: ImageId(Sha256("f706da23…")) | right: ImageId(Sha256("abababab…"))`. The build returned the id derived from the tag, not the new id.
  - Green after revert: 1 passed
- The effect applies to the next finished build of its stage only. A build of another stage keeps its stable id and leaves the effect armed. The build after it returns to the stable id.

### S5 `SandboxHandle::image_id`

- **Break (plan):** the id is resolved when `image_id` is called, from the linked engine.
  - Red: 1 failed; `assertion 'left == right' failed: a retag moved a created sandbox | left: Some(ImageId(Sha256("bbbb…"))) | right: Some(ImageId(Sha256("aaaa…")))`
  - Green after revert: 1 passed
- `create_sandbox` reads the id once, from the linked `FakeEngine`, in the same step that decides whether the image resolves. A tag that only `add_image` knows has no id and `image_id` is `None`.
- The plan says "or a `sha256:` reference as is". `SandboxCreate::image()` is an `ImageTag`, and `ImageTag::parse` rejects `sha256:` text, so no create request can carry a reference today. The branch needs a product type that can. The unit that creates a sandbox from an image id adds it to `create_sandbox` and to this test.

### S6 provider pause

- **Break (plan):** `put_provider` and `delete_provider` do not pause.
  - Red: 1 failed; `Error: "the put finished without the hold: Ok(Ok(()))"`
  - Green after revert: 1 passed
- The pause runs after the scheduler yield and before the fault strike, like `create_sandbox`. `provider_state` does not pause.

### S7 `CancelsOn` and `PausesOn`

- **Break `CancelsOn`:** the wrapper hands the inner runner a fresh token instead of the one it was handed.
  - Red: 1 failed; the call of a cancelled token returns `Ok(ProcessOutput { status: Exited(0), .. })` where `Cancelled` is expected
  - Green after revert: 1 passed
  - The plan names the break "forgets to check the handed token". The testkit runners (`ScriptedProcessRunner`, `TestRunner`) already return `Cancelled` for a cancelled token, so an extra check in the wrapper would be dead code that no test can see. The wrapper hands the token on, and the break removes that.
- **Break `PausesOn`:** the pause does not wait for `release` or the token.
  - Red: 2 failed; `the call did not park` and, for the token case, `Ok(ProcessOutput { status: Exited(0), .. })` where `Cancelled` is expected
  - Green after revert: 2 passed
- `CancelsOn::new` is generic over the runner, so `&Arc<TestRunner>` and `&Arc<ScriptedProcessRunner>` both work. The session-local copy `crates/jackin-session/tests/common/cancels.rs` is deleted. `tests/project/cache.rs` and `tests/export/abort.rs` import the testkit type. These two edits to existing tests change no assertion.

### S8 `RoleCatalog::new` takes a clock

- Product change: `RoleCatalog::new(fs, runner, clock, cache_dir)` in `crates/jackin-session/src/roles.rs`. `App::catalog` passes `deps.host.clock`, which is `SystemClock` in production. `World` passes its `FakeClock`. Three session test files pass a fresh `FakeClock`.
- **Break:** a caller omits the clock.
  - Red: `error[E0061]: this function takes 4 arguments but 3 arguments were supplied | argument #3 of type 'Arc<(dyn Clock + 'static)>' is missing` at `crates/jackin/src/app.rs:70`
  - Green after revert: `cargo check` and the full session, testkit and CLI suites pass
- No test observes behavior. The catalog does not read the clock yet. The cache lock of U3 does, and U3.3 is the test that proves the wait. Until then the field carries `#[expect(dead_code)]`. The lock change makes that expectation fail to compile, which forces its removal.

## U1 restore fence (C1, C16)

Branch `wt/pr1264-U1`, base `69f94b7c8`. Rows U1.1 to U1.4 of the approved test plan, in `crates/jackin-session/tests/launch/fence.rs`. Commits: tests `c6a7fee90`, fix `c110db607`.

### Cause

`stale()` in `launch/decide.rs` compared the `image` and `docker` fields of the labels. A sandbox is created from more inputs: account, workspace, role, and the policy, which was never recorded. Every new creation input needed someone to add it to `stale()`. The Provider step also ran before the check, so a refused retry had already synced a provider.

### Fix

- `SandboxLabels::differences(&wanted)` compares the rendered label sets key by key. A new label is compared with no further edit.
- New label `jackin.dev/policy`: `PolicyLabel::of(rendered closed policy)`, the first 32 hex characters of its sha256. The plan computes it from the `ClosedPolicy` that goes into the create request, so it is the creation-time policy and an operator rule added later (D12) does not change it.
- `LaunchError::StaleSandbox { launch, sandbox, differences: Vec<LabelDifference> }`. The text names each differing label key with the value on the sandbox and the value in this launch.
- `decide` runs the stale check before the Provider step. The Provider step is the first step that changes anything after the image.
- A Docker flip or a moved engine port also changes the policy label, because the engine rule is part of the policy.
