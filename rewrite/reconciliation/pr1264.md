- **Break b:** the old poll comes back (2,000 polls of 1 ms, `tokio::time::sleep`).
  - Red: 1 failed, 1 passed; `the create never arrived`. The test starts paused and the create arrives after 5 s of virtual time. The poll gives up after 2 s of virtual time.

### S3 `FakeEngine::hold` and `waiters`

- **Break (plan):** `hold` returns `Ok(None)`, the trait default.

  - Green after revert: 2 passed
- The assertions repeat the three that `crates/jackin-image/tests/image_io/lock.rs` makes for the real `BuildxEngine::hold`:

- The real engine has no `waiters`, so the fake test reads the wait from `waiters` and the real test reads it from the `contended` signal of `SignalFs`. The fake takes its exclusion from a `BTreeSet` of held tags and a `Notify`, not from a file lock. No other owned code is faked.

### Fixes

- **C2.** `crates/jackin/src/commands/export.rs` destructures `ExportReport { sandbox, bundle: _, branches, detached, worktrees }`, so a new field breaks the build. One iterator over branches, detached HEAD and worktrees prints `host_ref<TAB>tip`. The note appears only when it printed nothing.
- **C14.** `Host::publish` takes `Vec<Update { target, tip, observed }>`. `observed` is the value of the ref in the `HostRefs` read at the start of `Session::export`. A missing ref uses `create <ref> <tip>`, any other uses `update <ref> <tip> <observed>`, both after `option no-deref`, in one `update-ref --stdin` transaction. When the transaction fails with a host git error, jackin reads every target again with `rev-parse -q --verify`:
  - a ref that holds the new tip counts as published and leaves the batch;
  - a ref that holds the observed value stays and is retried in the next transaction;
  - any other value returns the new `ExportError::RefMoved { host_ref, observed, found }`;
  - if no ref changed, the original git error is returned.
  The retry set shrinks each round, so the loop ends. `Observed { host, refs }` carries the start-of-export refs through `ship` and `import_exported`; a new parameter would have passed the clippy limit of seven arguments.
- **Why the design allowed C14.** `publish` was a blind write that took no value from the earlier observation (`refs()` ran at the start, the write came after a download and an import). The fix puts that observation into the write.
- **U4.3.** `Remote::uncommitted` also runs `git --no-optional-locks -C <checkout> ls-files -v -z` per checkout and counts each entry tagged `S` or a lowercase letter (`h`, `s`, ...). Git prints those tags for skip-worktree and assume-unchanged entries; I checked `h`, `S` and `s` (both flags) on git 2.54. It reads the index and writes nothing. A flagged file counts as one uncommitted entry whether or not its content changed: jackin cannot see the change, and D08 counts what it cannot inspect as not exported. A sandbox that never sets a flag is unaffected.

### Amended row (C-4)

U4.4 in the plan assumed a per-sandbox lock held from the start of `Session::export` through publish, and said a CAS design needs an amended row. The orchestrator chose CAS. The amended behavior: when the sandbox advances between the first export's bundle and its publish, the ref ends at the newest tip, and the older export never reports success for a tip the ref does not hold (it returns `RefMoved`). The test does not name the error variant in its assertions, so it fails on the assertion and not on the compile. Row U4.4b is new.
