### Amended row U9.1 (C-4)

The approved row refuses every `ONBUILD` in the final stage with a new `Onbuild` variant. The brief for this unit asks for the other design: validate the deferred payload as the instruction it defers. The row changes in three ways:

- `ONBUILD ENV <engine client name>` in all its forms is refused with the existing `EngineClientEnv` and `ExpandingEnvName` variants, with the line of the `ONBUILD`. There is no `Onbuild` variant.
- `ONBUILD USER root` and `ONBUILD RUN true` are accepted, as the top-level `USER` and `RUN` are. No rule applies to them.
- Two cause-level classes are added to the row. A heredoc body under `ONBUILD RUN`, `COPY` or `ADD` is data. A `syntax` directive may name only `docker/dockerfile`; the new variant is `DockerfileError::ForeignFrontend { line, frontend }`.

### Cause

- Every rule keyed on the first word of an instruction, so `ONBUILD` hid the instruction it defers.
- `skip_heredocs` made the same first-word test, so the body of `ONBUILD RUN <<EOF` was read as instructions. A `FROM construct` line in that body reset the final-stage ENV check, which hid a real `ENV DOCKER_HOST=x` above it. BuildKit treats `ONBUILD` as a compound command for heredocs (`canContainHeredoc` in `frontend/dockerfile/parser/parser.go`, v0.23.0).
- BuildKit selects the frontend from the first directive block in three forms: `# syntax=`, `// syntax=`, and a JSON object with a `syntax` key; a first line that starts with `#!` is skipped (`DetectSyntax` in `parser/directives.go`, v0.23.0). The role build reads the Dockerfile from stdin (`--file=-`), so the frontend named there decides what the file means. The old code looked only at `# escape=`. The JSON form never reaches a stage, so it already ended in `NoStages`; a row pins that.

### Fixes

- **C2.** `crates/jackin/src/commands/export.rs` destructures `ExportReport { sandbox, bundle: _, branches, detached, worktrees }`, so a new field breaks the build. One iterator over branches, detached HEAD and worktrees prints `host_ref<TAB>tip`. The note appears only when it printed nothing.
- **C14.** `Host::publish` takes `Vec<Update { target, tip, observed }>`. `observed` is the value of the ref in the `HostRefs` read at the start of `Session::export`. A missing ref uses `create <ref> <tip>`, any other uses `update <ref> <tip> <observed>`, both after `option no-deref`, in one `update-ref --stdin` transaction. When the transaction fails with a host git error, jackin reads every target again with `rev-parse -q --verify`:
  - a ref that holds the new tip counts as published and leaves the batch;
  - a ref that holds the observed value stays and is retried in the next transaction;
  - any other value returns the new `ExportError::RefMoved { host_ref, observed, found }`;
  - if no ref changed, the original git error is returned.
  The retry set shrinks each round, so the loop ends. `Observed { host, refs }` carries the start-of-export refs through `ship` and `import_exported`; a new parameter would have passed the clippy limit of seven arguments.
- **Why the design allowed C14.** `publish` was a blind write that took no value from the earlier observation (`refs()` ran at the start, the write came after a download and an import). The fix puts that observation into the write.

## U4b HEAD outside refs/heads (N3)

Branch `wt/pr1264-U4b`, base `ebc23f3fd` (U4 merged). Finding N3 of `/private/tmp/claude-501/plans/pr1264-new-triage.md`.

### Cause

`git worktree list --porcelain` prints `detached` for a detached checkout and `branch <ref>` for a symbolic HEAD. `checkouts()` in `crates/jackin-session/src/export/sandbox.rs` read only `detached`, and `repository()` skipped every checkout without it. A HEAD that is a symbolic ref outside `refs/heads/` (`refs/remotes/...`, `refs/tags/...`, `refs/notes/...`) was therefore in no list: its commits were in no branch, no detached head and no worktree entry, so `work_state` was `Exported` and a guarded purge deleted the sandbox. The enabling condition was a two-valued test ("detached or not") for a three-valued fact (detached, on a branch, on a ref that is not a branch).

### Fix

`Checkout.detached` became `off_heads`. It is set by `detached` and by `branch <ref>` when `<ref>` does not start with `refs/heads/`. Every such checkout takes the existing detached path: the root checkout fills `Repository.detached`, a linked one fills `Repository.linked`. No other file changed. The same list feeds the work-state check, the export and `Session::changes`.

### Decision: export it, do not refuse

The checkout is exported as a detached HEAD: `refs/heads/jackin/<sandbox>/HEAD` for the root, `refs/heads/jackin/<sandbox>/worktree/<id>` for a linked worktree. Reasons: the commits are the work and a detached HEAD holds the same thing (a commit with no branch name the host can reuse); a refusal would make `export` fail on a sandbox that only a forced purge can then clear, which loses the work; the host compares the commit with the host HEAD and the `jackin/` ref, which is the rule D08 already states for a detached HEAD. The sandbox ref name (`origin/x`) is not kept; the export report names the detached commit. `git bundle create HEAD` records the name `HEAD` for a symbolic HEAD, so the bundle header equals the requested set; the export test below passes through the bundle parser.

## U5 Supervisor environment (C6)

Branch `wt/pr1264-U5`, base `69f94b7c8`. Test commit `f7985c151`, fix commit `6e981d832`. Inputs: the approved plan row U5.1 and conditions C-2 to C-5, the comment C6.

### Cause and design

`jackin-start` evaluated the role env file (`eval "$env_text"` in a subshell) in the namespace that held its own state. The subshell inherits every shell variable, and the supervisor reads `project`, `run`, `attempt_id`, `main_ok`, `main_lines` and `codex_lines` after the `eval`. `RESERVED_NAMES` is a denylist of role names, so it needs one entry for each local of the script.

The three designs from the brief:

- A process boundary (`env -i` plus `exec`) cannot work here: the role environment must be added to the inherited one, and `eval` needs a shell.
- Validating role names against the supervisor's names is the denylist again, kept in a second place.
- A reserved prefix for every supervisor variable removes the class: a name a role cannot declare cannot collide, whatever the script grows.

Chosen: every shell variable of the script, including the `check_env` locals, starts with `JACKIN_`. The prefix is already unrepresentable for a role (`RESERVED_PREFIXES`, `ScopedEnvName`). The `check_env` locals are renamed too, so the rule has no exception and the test needs none. `check_env` now also refuses a `JACKIN_` name in the file (exit 65, "malformed at line N"), so the script holds the rule without trusting the host. Nothing is added to `RESERVED_NAMES`.

Not covered by the prefix, by design: shell-defined variables a role may set on purpose (`PATH`, `IFS`, `CDPATH`, `LC_ALL`, `TMPDIR`, `ENV`, `BASH_ENV`). After the `eval`, the script runs only `cd` with an absolute path, builtins, `/usr/bin/awk` and `/bin/mv` by absolute path, and `exec` of a path that contains `/`. The test attacks each of them. `PWD` and `OLDPWD` are not attacked: `cd` rewrites them by definition.

## U7 usage cache and atomic writes (C9)

Branch `wt/pr1264-U7`. Test commit `854096631`, fix commit `3f386d1f5`. Red ran from the test commit in a detached temporary worktree. Green ran on the fix commit. ## U6 accounts (C8, C20)

Branch `wt/pr1264-U6`, base `69f94b7c8`. Commits, in order: `b581c8528` (API refactor, behavior unchanged), `f1384e281` (tests), `808765657` (fix). Commands: `mise exec -- mbx +1.99.1 nextest run -p jackin-session --test accounts` and `... -p jackin --test cli -E 'test(/account/)'`.

### Cause

An account lives in three places: the config, the OpenShell provider of each gateway, and the host login files. Nothing owned the whole life of an account. `GatewayPlan::apply` took one `Session`, published the provider before the config write, and held the account lock only inside each gateway call. So `rm` reached one gateway of N, and the loser of a concurrent `add` could publish after the winner and leave its login on the gateway.

### Fix

- `AccountPlan::apply` and `GatewayPlan::apply` take `&Gateways` (the home session plus every other configured gateway). `Gateways::with_peers` connects the peers. A peer that is down is kept as a typed `UnreachableGateway`, and only a plan that needs it fails.
- `GatewayPlan` keeps only its edits. `apply` takes the account lock of every touched account in name order, reads the config under the lock, plans again, and only then touches a gateway. The loser of a write gets `ConfigError::DuplicateName` before any gateway call.
- Forget (account removed, or its login replaced by a key) runs on every gateway. A renewed login is published to the home gateway and to every peer that already holds the provider. A new account is published to the home gateway only. A plan that forgets or renews needs every gateway, or it fails with `AccountEditError::Unreachable(Vec<UnreachableGateway>)` before any change. A gateway call that fails is `AccountEditError::OnGateway { gateway, source }`.
- If the config write fails, the providers that this call created on the home gateway are removed. A provider that existed before is left alone. A failed removal is `AccountEditError::RollbackFailed`, which names the account and the gateway and keeps the first error.
- The CLI builds `Gateways` with `App::gateways`. `Session::forget_account` is removed.

## U6 security round (U6-1, U6-2, U6b)

Branch `wt/pr1264-U6`, base `4f6195756`. Commits, in order: `fa82576cc` (API, behavior unchanged), `6da05b19b` and `507330ecd` (tests), `07b5b9ff0` (fix), `da052816a` (one more test). ### Cause

A provider write is two gateway calls (`create_provider`, then `configure_provider_refresh`), and the provider exists after the first. Three paths published a provider and none handled a failure between the two calls or a config that changed after the plan:

- `publish()` pushed the account to `created` after `sync_locked` returned, so a failed second call left the login tokens on a gateway that no config entry names. `account rm` could not find them, because it plans from the config.
- A launch ran `sync_if_absent` from the account copy in its plan. The account lock ordered the launch against `account rm` but nothing checked the config after the lock was taken, so a launch planned before the rm re-created the provider after it. A failed write in that path left a provider that the next launch found `Present` and skipped.
- `gateway rm` edited the config and never touched the gateway.

### Fix

- `publish()` records an account that is not a renewal in `created` before it syncs. `forget_locked` deletes with `allow_missing`, so rolling back a write that never landed is harmless. A renewal is never recorded, because its provider belongs to an account that stays in the config.
- `sync_if_absent` takes the lock with `hold_current`: it reads the config under the lock and returns `AccountError::Removed`, `Changed` (the account differs from the plan) or `GatewayRemoved`. The launch fails at the Provider step with `ProviderUnavailable` and creates no provider. `SessionDeps` carries the `ConfigStore` for this.
- `sync_if_absent` also removes the provider again when its own write fails. The provider was absent when the launch took the lock, so any provider there is the launch's. A failed removal is `AccountError::RollbackFailed`, which keeps the first error as its source.
- `Session::remove_gateway` takes the lock of every login account in name order, reads the config under them, checks that the entry can be removed, removes the provider of each login account from that gateway, and only then edits the config. `jackin gateway rm` connects only the gateway it removes, and connects none when no account has a provider (`gateway_holds_providers`). An unreachable gateway is `AccountEditError::Unreachable`, which names it.
- `sync_account` is unchanged. It has no production caller; tests use it to put a provider on a gateway.

### Decision: forget first, not refuse

`gateway rm` forgets the providers first and fails closed, because `account rm` does, and the two must leave the same state.

- Refusing while providers exist would leave no way to clear the providers of one gateway. `account rm` is the only other command that removes a provider, and it also deletes the account and its bindings on every gateway. The operator would lose accounts to remove a gateway.
- A provider is derived state. The next launch creates it again from the host login. Forgetting it loses nothing.
- Both options fail when the gateway cannot be reached, because neither can tell whether a provider is there. Failing closed is the rule of `account rm` (U6), so `gateway rm` follows it.
- Cost: a gateway that is gone for good cannot be removed with the CLI while any account has a login. The operator restores it or deletes its entry from the config file. The D26 sentence of the U6 round that sends the operator to `gateway rm` for this is amended in the text below. U6 F1 below replaces the config-file route with `gateway rm <name> --offline`.

## U10 security round

Security review finding U10-1 (HIGH) and two LOW regressions, on `fef46b79f`.

### Cause

`ClipboardGuard` matched the literal bytes `ESC ] 5 2 ;`. A terminal parser reaches OSC 52 by many other byte paths: a C0 byte between `ESC` and `]` (`ESC DEL ]`, `ESC NUL ]`), a C0 byte inside the number (`ESC ] 5 NUL 2`), the 8-bit introducer `0x9d`, the UTF-8 introducer `c2 9d`, and the terminators `0x9c`, `c2 9c`, CAN, SUB and `ESC` plus any byte. The filter's own output was fed to the parsers of `alacritty_terminal` 0.26.0 and `termwiz` 0.23.3 (WezTerm), and both stored the clipboard for these inputs. Any filter that decides by matching bytes of a payload is open to the next byte path. The design permitted the bug because it listed what to drop. The fix lists what to pass.

### Fix

- `crates/jackin-session/src/clipboard.rs` is now a small terminal state machine: Ground, Escape, OSC body, and ESC inside an OSC body. A UTF-8 decoder in front of it separates a C1 control (raw `0x80..0x9f` outside a character, or `c2` followed by `0x80..0x9f`) from a continuation byte, so `0x9d` is an OSC introducer and `✝` (`e2 9c 9d`) is text.
- Introducers: `ESC ]` and C1 `0x9d` in any state. ESC in any state restarts the escape state. Inside Escape, C0 bytes act as in a terminal: they are executed and the escape stays open, so `ESC DEL ]` and `ESC NUL ]` are OSC. Terminators: BEL, `ESC \`, C1 ST (`0x9c`, `c2 9c`). CAN, SUB, ESC plus any other byte, or a new introducer end the OSC without a dispatch and drop it.
- Policy is deny by default. An OSC is forwarded only when its number is exactly on the allowlist below, its body is valid UTF-8 with no control or C1 character, and it is at most 4096 bytes. A forwarded OSC is written in its canonical form (`ESC ]`, number, `;`, body, then BEL or `ESC \`), so a hidden byte path cannot ride along. Leading zeros, C0 bytes in the number and a body with no `;` are all dropped.
- CSI, SGR, DCS, plain text and UTF-8 pass byte for byte. One normalisation: `ESC ESC` collapses to one ESC, and a C0 byte after an ESC is written before that ESC. A dangling ESC is never written ahead of a dropped OSC, because a later `]` would complete it.
- An OSC with no end hides the output that follows until a terminator or one of CAN, SUB, ESC arrives (the regression in the review is fixed: CAN and SUB end it). An oversized body is dropped without being stored.
- Operator input never holds a lone ESC or a bare `ESC ]` at the end of a read. Alt+] and the Esc key reach the sandbox at once.
- `vte` is not used. The workspace has no `vte` yet (`termpane` is not in this tree), and `vte` 0.15.0, the latest stable release, does not fit the job: it dispatches an OSC on CAN and on ESC before the next byte is known, it treats C1 controls only in Ground, and it gives no raw byte spans to forward or drop. ### Residual

- Operator input that a read splits directly after `ESC ]` is released at once (Alt+]); the rest of a split OSC reply then reaches the sandbox as text. A split directly after a lone ESC is closed: the ESC is sent and the rest of the OSC is dropped.

- A raw `0x80..0x9f` byte is read as a C1 control unless it follows a UTF-8 lead byte. A terminal in a legacy 8-bit mode that reads other bytes as C1 controls is outside the model.

## U11 security round

Security review finding U11-1 (MEDIUM), on `fef46b79f`.

### Cause

The watcher polled the destination path that jackin passed to the CLI. The pinned CLI (`openshell-cli/src/ssh.rs` `sandbox_sync_down_file` at `ac7f615`) does not write there. It makes `TempDir::new_in(parent(dest))`, streams the tar into that directory and renames the file onto `dest` at the end. The watcher saw no growth, and the test's fake CLI wrote straight to `dest`, a CLI that does not exist. The `stat` before the download also read only a size, so a directory or a special file got through to the CLI.

### Fix

- `download_file` makes a private staging directory beside the destination (mode `0700`, created with `create_dir`, so an existing path or a symlink fails) and passes `<staging>/file` as the CLI destination. The CLI then makes its own `.tmp*` directory inside the staging directory.
- `watch_growth` sums the apparent size of every file under the staging directory (no symlink is followed) every 10 ms. It cancels the CLI call and returns the size once the sum is over `DOWNLOAD_LIMIT`.
- `download_file` removes the staging directory with `remove_dir_all` on every path after the CLI call: success after the rename, failure, the size stop, timeout and user cancel. This removes the CLI's `.tmp*` leftovers after a kill.
- The `stat` call is `stat -c '%F %s' -- <path>`. Only `regular file` and `regular empty file` go on. Any other type returns `GatewayError::NotRegularFile { kind }` before the CLI runs. `kind` is the sandbox's text passed through `TerminalText::sanitize`.
- `RLIMIT_FSIZE` is not used: it needs `unsafe` (`pre_exec`), and the workspace forbids `unsafe_code`.
- The fake CLI of `download_bound.rs` now behaves like the real one: it makes a temp directory beside the destination, grows the file there, renames it onto the destination at the end, and on a cancel leaves the temp directory behind.
