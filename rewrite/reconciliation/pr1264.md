### S1 `until_held`

- **Break a (plan):** `until_held` returns `false` at once.
  - Red: 2 tests run: 0 passed, 2 failed; `holds.rs` `the create never arrived` and `nothing had arrived yet`
  - Green after revert: 2 tests run: 2 passed
- **Break b:** the old poll comes back (2,000 polls of 1 ms, `tokio::time::sleep`).
  - Red: 1 failed, 1 passed; `the create never arrived`. The test starts paused and the create arrives after 5 s of virtual time. The poll gives up after 2 s of virtual time.
  - Green after revert: 2 passed
- The first test pins the wait to an event. The second pins the two cases where no arrival can come: no hold armed, and a release before the arrival. In both, `until_held` returns `false` at once. The old code waited 2 s of real time for them.

### S3 `FakeEngine::hold` and `waiters`

- **Break (plan):** `hold` returns `Ok(None)`, the trait default.
  - Red: 2 failed; `Error: "the fake engine granted no lock"` in both tests
  - Green after revert: 2 passed
- The assertions repeat the three that `crates/jackin-image/tests/image_io/lock.rs` makes for the real `BuildxEngine::hold`:
  - A second hold of one key waits until the first is dropped. Here that is `waiters` 1, then 0.
  - Different keys do not wait.
  - A waiter that is cancelled returns `Cancelled` and changes nothing for the holder: a later hold on the key still waits.
- The real engine has no `waiters`, so the fake test reads the wait from `waiters` and the real test reads it from the `contended` signal of `SignalFs`. The fake takes its exclusion from a `BTreeSet` of held tags and a `Notify`, not from a file lock. No other owned code is faked.

## U9 Dockerfile validation (C22)

Test commit `41721f2f1`, fix commit `be7daeaaf`. Files: `crates/jackin-image/src/dockerfile.rs`, `crates/jackin-image/tests/dockerfile.rs`. Every command ran as `mise exec -- mbx +1.99.1 nextest run -p jackin-image -E 'binary(dockerfile)'`.

### Amended row U9.1 (C-4)

The approved row refuses every `ONBUILD` in the final stage with a new `Onbuild` variant. The brief for this unit asks for the other design: validate the deferred payload as the instruction it defers. The row changes in three ways:

- `ONBUILD ENV <engine client name>` in all its forms is refused with the existing `EngineClientEnv` and `ExpandingEnvName` variants, with the line of the `ONBUILD`. There is no `Onbuild` variant.
- `ONBUILD USER root` and `ONBUILD RUN true` are accepted, as the top-level `USER` and `RUN` are. No rule applies to them.
- Two cause-level classes are added to the row. A heredoc body under `ONBUILD RUN`, `COPY` or `ADD` is data. A `syntax` directive may name only `docker/dockerfile`; the new variant is `DockerfileError::ForeignFrontend { line, frontend }`.

### Cause

- Every rule keyed on the first word of an instruction, so `ONBUILD` hid the instruction it defers.
- `skip_heredocs` made the same first-word test, so the body of `ONBUILD RUN <<EOF` was read as instructions. A `FROM construct` line in that body reset the final-stage ENV check, which hid a real `ENV DOCKER_HOST=x` above it. BuildKit treats `ONBUILD` as a compound command for heredocs (`canContainHeredoc` in `frontend/dockerfile/parser/parser.go`, v0.23.0).
- BuildKit selects the frontend from the first directive block in three forms: `# syntax=`, `// syntax=`, and a JSON object with a `syntax` key; a first line that starts with `#!` is skipped (`DetectSyntax` in `parser/directives.go`, v0.23.0). The role build reads the Dockerfile from stdin (`--file=-`), so the frontend named there decides what the file means. The old code looked only at `# escape=`. The JSON form never reaches a stage, so it already ended in `NoStages`; a row pins that.
