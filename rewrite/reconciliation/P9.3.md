## Decisions the plan did not state, and where the plan does not fit the code

1. **Codex accounts without a ChatGPT login (plan 7.3, "add runs `Session::sync_account` first").** `sync_account` returns `AccountError::Unsupported` for a Codex account whose source is not a ChatGPT login, and `jackin account add codex --credential env:X` failed on it. The plan and D28 also need a usage-only Codex account with an `op://` source (the account form, T14, T30). One shared sequence cannot do both, so the plan syncs only accounts whose source is a ChatGPT login (the only ones that have an OpenShell provider). Every other account is stored without a provider. This changes the CLI: `jackin account add codex --credential env:X` now succeeds. The CLI test that expected the failure now expects the stored account and an untouched gateway (`a_codex_account_without_a_chatgpt_login_is_stored_for_usage_and_never_reaches_the_gateway`). `sync_account` and the launch path are unchanged, so a launch with such an account is still a typed `Unsupported`.
2. **"File counts in `Unexported`" (P-1).** The plan names no type. `uncommitted` counts the entries of `git status --porcelain --untracked-files=all` in every checkout plus the entries of `git stash list`. `unpushed()` counts branches, worktrees and a detached head that the host lacks. `Display` keeps the text `uncommitted changes`, so the CLI wording and its tests are unchanged. Commit counts would need the host history in the sandbox and are not provided.
3. **`GatewayConnector` and `ConnectError` moved to `jackin-session`.** TK-5 puts a scripted connector in the testkit, and the testkit cannot depend on `jackin`. The trait only uses core and openshell types. J1's `SessionConnector` can reuse it.
4. **Build is a free function.** The plan calls it "the build-for-workspace function". `jackin build` must not connect to a gateway (its test `build_prints_the_final_image_id_caches_it_and_needs_no_gateway`), so `build_for_workspace(engine, catalog, config, request, progress, cancel)` takes no `Session`. For the same reason `AccountPlan::apply` takes `Option<&Session>`: `jackin account add claude` still never connects.
5. **The fake nudge is a trigger, not tokio time.** The fake has no timer: `advance_repaint()` fires the nudge, as the plan says. The real transport already uses `tokio::time::Instant`; the new real test pauses tokio time and calls `advance`. Both read one table (`NUDGE_CASES`), so a change of the expected window list turns both red.
6. **Raw log and viewers.** `GrpcGateway` never sends the input of a `Viewer` attachment, so the fake does not log it. Bytes of a second `Owner` attachment that holds no lease are logged, because the real transport sends them and the supervisor drops them.
7. **Attachment cap.** OpenShell `MAX_CONNECTIONS_PER_SANDBOX` is 20 and is shared by SSH sessions and service forwards (`crates/openshell-server/src/grpc/sandbox.rs:2945` at v0.1.6). The fake counts main-process attachments only, and shell terminals (`ExecSandboxInteractive`) do not count.
8. **`Session::changes` returns files and hunks only.** The baseline `ChangeSet` also carries `unpushed`; the console takes that from `Unexported::unpushed()` through `work_state`, which needs the config.
9. **Output changes of existing commands.** `jackin ls --json` and `jackin inspect --json` print `created_at` in each summary when the gateway recorded it (additive). `jackin doctor` appends the fix text to `warn` and `fail` lines. `jackin usage` text is unchanged. The existing key-set tests for `ls` and `inspect` pin the new key.
10. **Repository rules met.** `rewrite/DESIGN.md` is not edited (only the orchestrator edits it); the D11 and D15 text of P-9 is for the orchestrator. `xtask containers` rejects a computed `Command::new`, so the TZ probe of the P-4 test runs through `/bin/sh -c 'exec "$0" ...'`. `cargo shear` reported `tests/common/*.rs` and `tests/support/trap.rs` as unlinked after I added four top-level `tests/*.rs` files to `jackin-session`; the same tests under one directory binary, `tests/seams/`, cleared it (the cause was not investigated).

## J0a: new tests, the named break of each, red and green

Method: each break was applied to the committed tree by a script (`red.py` in the task scratchpad), the narrowest `nextest` filter for the test was run, the file was restored, and the same filter ran again. "Red" is the first failing assertion; `actual` is the left side of `assert_eq!` and `expected` the right side. A long value is cut at the first difference. Rows count the tests of the filter, not of the crate. Run one by hand with, for example, `mise exec -- mbx +1.99.1 nextest run -p jackin-session --all-features -E 'binary(seams) and test(/origin::/)'`.

## J0b: decisions the plan did not state

1. **No new `ConfigError` variant.** A reserved name and a default role outside the allowed roles use `ConfigError::InvalidValue` with the keys `env.<NAME>` and `workspaces.<w>.default_role`. The exhaustive `label` matches in the core tests did not change. The text for a reserved name reads `invalid value for env.DOCKER_HOST: reserved by jackin`.
2. **`SetEnv.value` is `Option<PlainEnvValue>`.** Design 4.4 moves a variable with "unset at the old scope, set at the new", so an edit must be able to unset. An emptied `role_env.<r>` table is dropped, so a render has no empty table.
3. **Role references.** A role named in `roles` or `role_env` must be a configured role, as `default_role` already must. `RemoveRole` refuses a role that an allow-list or a `role_env` table still names (`ConfigReference::{WorkspaceRoles, WorkspaceRoleEnv}`), which is what T17 asks for the allow-list. The console editor's "a name in the list that is no longer a configured role" is a stale in-memory state, not a config state.
4. **`SetWorkspaceDefaultRole` and `SetWorkspaceRoles` keep the default inside the allowed roles.** Setting a default outside the set, or narrowing the set so it leaves out the default, is refused. The console clears the default first (its rule "unchecking the default clears it").
5. **`resolve_env` and the questions.** A scoped value for a declared name means the manifest entry is not asked, also with `Prompting::Interactive`. A declared name with no answer and no scoped value behaves as before (default with `Never`, a question otherwise). The Docker variables still override (`values.extend(docker.environment())`). `LaunchRequest::env` keeps its meaning (answers); `EnvUndeclared` is for answers only.
6. **`RoleNotAllowed` comes before the account is selected,** so a refused launch reads the same whatever the accounts are.
7. **`Workspace::new`.** `Workspace` has public fields, so every literal needed the three new fields. `Workspace::new(path, docker)` builds the empty case; the CLI `workspace add`, the ad hoc workspace of `lookup_workspace` and the core tests use it.
8. **DESIGN D11 and D15 text** (P-9 in plan section 14) is not edited: only the orchestrator edits `rewrite/DESIGN.md`. API.md section 1 and 4 carry the config and plan changes.
