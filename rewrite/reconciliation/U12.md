### U12 (P6.1, from rewrite/reconciliation/U12.md)

This file records the preconditions of the approved P6.1 test plan (U12-1 to U12-12), the orchestrator decisions OD-1 to OD-10, and the choices the plan left open. The tests of `crates/jackin/tests/cli` and `crates/jackin/tests/process` rest on them.

## Preconditions U12-1 to U12-12

- U12-1. `jackin::run(AppEnv, Deps) -> ExitClass` is the only entry that tests use. `ExitClass::code()` lives in the library. `main` builds the system dependencies, runs `run`, and returns `ExitCode::from(class.code())`. It has no other logic.
- U12-2. `AppEnv` is `{ args, stdout, stderr, terminal: Option<Box<dyn Terminal>>, cwd: HostPath, config_path, cache_dir, env: EnvSnapshot, cancel }`. `stdin_is_tty` is gone: a terminal means a TTY. `Terminal` is an owned trait: `size() -> TermSize`, `enter_raw() -> io::Result<RawMode>` (the guard restores the mode when dropped), `read_line() -> io::Result<Option<String>>` (`None` is end of input, used by prompts), and `next_input() -> TerminalInput` (`Bytes`, `Resized`, `Closed`, used by attach and shell). Output of attach and shell is written to `AppEnv.stdout`, so the trait has no output method. `Deps` gains `limits: LaunchLimits`, because the library holds no timing constants. The library never reads the process environment, the working directory, or the home directory.
- U12-3. Exit codes: Ok 0, Failure 1, Usage 2 (clap's own), Refused 3, Cancelled 130.
- U12-4. Stdout carries data only: JSON, help, version, the plain `build` image ID, the `ls` names, the export refs, and the sandbox name and launch ID that `load` prints without a TTY. The doctor report is the data of `doctor` (OD-8, amended): one line per check on stdout. Errors, warnings, prompts, progress, and the exit and detach lines go to stderr. Usage errors come from `Cli::try_parse_from` and are rendered into the `AppEnv` writers, so no clap code writes to the process streams or exits.
- U12-5. The JSON views are public serde types in `crates/jackin/src/views.rs`, each with `schema: 1` (`VIEW_SCHEMA`), and none derives `JsonSchema`. The key sets are final and the tests pin them. Every view prints as one compact line with a trailing newline.
  - `gateway ls --json`: `{schema, gateways: [{name, default, workspace, builder, platform, engine}]}`. `platform` is the Docker string (`linux/arm64`, `linux/amd64`). `engine` is `null` or `{port, certs}`.
  - `account ls --json`: `{schema, accounts: [{name, provider, credential, default}]}`. `provider` is the lowercase provider. `credential` is only the kind: `env`, `op`, `file`, or `codex-login`. No variable name, reference, path, or token appears. `default` is true for the default account of its provider.
  - `role ls --json`: `{schema, roles: [{name, source, bindings}]}`. `source` is `{kind: "path", path}` or `{kind: "git", url, rev}` with `rev` null when absent. `bindings` maps the agent name to the account name.
  - `workspace ls --json`: `{schema, workspaces: [{name, path, docker, default_role, bindings}]}`. `bindings` maps the provider name to the account name.
  - The lists are in name order. `ls`, `inspect`, and `build` print the typed views of `jackin-core` (`LsOutput`, `InspectView`, `BuildOutput`); their key sets are pinned in the same way.
- U12-6. `jackin::locations(&EnvSnapshot)` derives every host location from `AppEnv.env` and `main` calls it. Config: `$XDG_CONFIG_HOME/jackin/config.toml`, else `ConfigStore::default_path($HOME)`. Cache: `$XDG_CACHE_HOME/jackin`, else `$HOME/.cache/jackin`. OpenShell registry: `$XDG_CONFIG_HOME/openshell`, else `$HOME/.config/openshell`. Engine socket: the `unix://` path of `DOCKER_HOST`, else `/var/run/docker.sock`. A `DOCKER_HOST` with another scheme is ignored. `HOME` and `XDG_*` must be absolute, and a missing `HOME` is an error.
- U12-7. A handler validates, plans and prompts before it calls `connect`. `connect` is lazy and never runs for `role`, `workspace`, `gateway`, `build`, or `account add` of a provider other than Codex. `doctor` passes the connect error to `GatewayAccess::Failed`. `connect` takes the command's cancel token and returns `ConnectError` (a discovery failure or a `GatewayError`).
- U12-8. `error:` plus the cause chain is the stderr form of every failure. A launch failure prints the lowercase step name, the launch ID, the cause, and, when a sandbox remains, `sandbox <name> remains; retry with: jackin load --launch-id <id>`. A hook failure prints the lowercase hook name, the exit code, and the output as `TerminalText`, so control sequences are already removed. Names print with `Display`.
- U12-9. `account add` order: parse the credential, build the `Account`, check the add against a copy of the loaded config (a duplicate fails here), connect and `sync_account` for a Codex account, then edit the config. A failed step leaves the config bytes unchanged and, before the sync, the gateway untouched. `account rm` order: check the removal against a copy of the config (references fail here), delete the OpenShell provider of a Codex login account through `Session::forget_account` (which holds the account lock, ignores an account that is not a Codex login, and counts a `NotFound` as deleted), then edit the config. The gateway refuses to delete a provider that a sandbox uses, so the account stays.
- U12-10. `doctor` prints one line per check on stdout: the status (`pass`, `warn`, `fail`, `skip`), the id, and the detail. The ids come from an exhaustive function: `openshell-binary`, `ssh-binary`, `git-binary`, `gateway-registered`, `gateway-health`, `pinned-version`, `engine-socket`. The exit is Failure when a check fails and Ok for warnings and skips. When no gateway can be chosen (none configured, several without a default, or an unknown `--gateway`), the checks that need no gateway still run and print, and the run then fails with the config error (`no gateway is configured; run jackin gateway add`). A gateway that is chosen but does not connect goes to `GatewayAccess::Failed`. A cancelled token exits Cancelled and prints no report.
- U12-11. `load` prints the D24 warning to stderr once, after planning and before the launch, when the plan carries `LaunchWarning::DockerCapability`. The first line is `warning: the Docker capability is enabled for this sandbox`, and the fixed prefix that the test matches is `warning: the Docker capability is enabled`. One indented line follows for each `DockerRisk`. The `LaunchEvent::Warning` events are not printed, so the warning cannot repeat.
- U12-12. Test rules of U8-A9 and U11-18 carry over: no comments, each test under 150 lines, `TestResult`, a 10 s guard, no paused tokio time, no argv or call-order assertions. The only text assertion is `stderr.contains(identifier)` for an identifier that the fixture supplied.

## Orchestrator decisions

- OD-1. `AppEnv` gains `cwd`, the terminal port, and the prompt source (U12-2).
- OD-2. The exit codes are U12-3.
- OD-3. `load` without a TTY launches, prints the sandbox name and the launch ID on one stdout line separated by a tab, exits Ok, and leaves attaching to `jackin attach`.
- OD-4. `jackin` with no subcommand prints help on stdout, with or without a TTY, until the console lands (U14).
- OD-5. Every `Cancelled` error and EOF at a prompt exit Cancelled. A cancel during attach detaches and exits Cancelled.
- OD-6. `doctor` fails when no gateway is chosen and names `jackin gateway add`.
- OD-7. There is no `JsonSchema` and no `schemars`. The JSON views carry `schema: 1` and tests pin their key sets.
- OD-8. See U12-4. Amended by the orchestrator after the red/green review: the doctor report goes to stdout, and errors and warnings stay on stderr.
- OD-9. `ls` with a managed sandbox whose labels are unreadable exits Ok, names the sandbox on stderr, and leaves it out of the JSON.

## Records of the implementation

- Cancel classes: the session turns every failure that happens while the token is cancelled into `LaunchOutcome::Cancelled`, so `load` needs no class for a failed launch. `ExitClass::Cancelled` comes from `CommandError::Cancelled` (a cancelled launch, EOF at a prompt, a cancel during attach or shell), `ImageError::Cancelled` (`build`), `ExportError::Cancelled` (`export`), and `RestartError::Gateway(GatewayError::Cancelled)` (`attach --restart`). `account add` passes the token to `sync_account` and `account rm` to `forget_account`. A discovery or connection failure that is a cancel (`ConnectError::is_cancelled`) becomes `CommandError::Cancelled`, so one Ctrl-C during discovery exits 130. `doctor` exits Cancelled when the token is cancelled when its checks end.
- `main` cancels the token on the first Ctrl-C and returns code 130 at once on the second, because the Ctrl-C handler replaces the default signal action. During attach and shell the terminal is raw, so Ctrl-C is a byte for the remote process and not a signal.
- `Cli::command().debug_assert()` has a test (`help.rs::the_clap_definition_is_consistent`).

- `shell` needs a terminal first, then opens `Session::open_shell` and runs the same pump as `attach`. A shell that ends with the stream (`Exited`, then `Ended(StreamClosed)`) exits Ok; a non-zero shell exit code is noted on stderr. `stop` and `start` note the result on stderr and print nothing on stdout. `export` prints one `<host ref>\t<tip>` line per exported branch (and for a detached HEAD) on stdout, and notes on stderr when there is nothing to export. `purge` notes `deleted sandbox <name>` or `sandbox <name> is already gone` on stderr; it never touches the OpenShell provider.

- `load` order: read the config, resolve the path against the cwd, find the workspace of that path (`jackin workspace add` in the error), open the project, choose the gateway, load the role, plan (asking for missing env values on a terminal), print the Docker warning, then connect and launch. `jackin load [<role>] [<path>]` takes the role first, so a path alone needs the role before it.
- With a terminal, the prompt text is `<prompt or NAME> [<default>]: ` on stderr, read with `Terminal::read_line`. An empty answer takes the default and re-asks when there is none. EOF exits Cancelled with nothing created. Without a terminal, a missing value exits Refused.
- `load` with a terminal attaches after a `Ready` outcome. A `Cancelled` outcome exits Cancelled and names the sandbox and the launch ID. A launch failure exits Failure.
- `attach` needs a terminal first (`NoTerminal`, Failure) before any gateway call. `--restart` runs `Session::restart_agent` and attaches as the owner. Attach forwards every byte to `AttachedTerminal::input`; the detach keys (Ctrl-D, Ctrl-P Ctrl-Q) are handled by the terminal session, not by the pump. The pump ends on `Ended`, on terminal EOF (detach), or on cancel (detach and exit Cancelled). The terminal mode is restored by the `RawMode` guard on every path.
- The testkit gains `SandboxHandle::print_main`, which appends bytes to the retained main-process output and sends them to every attachment. The supervised fake main prints nothing, so the attach test needs it to prove that output reaches stdout.

- The plan row P61-GW-CHOICE says that a missing gateway names `jackin workspace add`. `ConfigError::NoGateway` names `jackin gateway add`, which is the right command, so the test asserts that. `load` in a directory with no workspace names `jackin workspace add` (P61-LOAD).

- `gateway add` takes `--engine-port` and `--engine-certs` as a pair (clap `requires`). A relative `--engine-certs`, workspace path, role path, `--chatgpt-from`, `file:` credential, and `role check` path are resolved against `AppEnv.cwd`.
- `role add <name> <source>`: a source that resolves to an existing directory is a `Path` source. Anything else must parse as a `RoleUrl` and is a `Git` source. `--rev` with a `Path` source is a usage error.
- `account bind <account> --role <r>` binds the agent of the provider of the account. A provider without an agent (for example `claude`) fails with `ConfigError::ProviderMismatch` (expected `codex`). `--workspace` binds the provider of the account.
- A non-`--json` `ls` prints one tab-separated line per entry (`default` is a last column). It is not a stable format.

- `SystemClock` implements `Clock` and `HostPorts::system(fs)` builds the host ports (`jackin-session/src/host.rs`). `main` uses it, and `HostClock` and the two `LiveClock` copies of the session examples are gone.
- `Session::forget_account(&Account, &CancellationToken)` is in `accounts.rs`. It takes the token because it holds the same account lock as `sync_account`.
- `GatewayConnector::connect(name, entry, cancel)` returns `ConnectError::{Discovery { gateway, source }, Gateway}`. `GrpcConnector` passes the token to `resolve_gateway` and reports a `DiscoveryError` as `Discovery`, so a missing `openshell` binary is not an unreachable gateway. `doctor` turns a `Discovery` error into the `GatewayError::Unreachable` that `GatewayAccess::Failed` needs, because the session type takes no other error; the `gateway-registered` line carries the discovery detail.
- `GatewayOp::Provider` never returns `NotFound` from the real or the fake `delete_provider` (both use allow-missing semantics), so the `NotFound` tolerance of `forget_account` is proven with an injected fault.
- Rebase onto the P5.3 fixes: `sync_account` takes a `CancellationToken`, `LaunchLimits` gains `bundle_bytes` (`launch_limits` uses `DEFAULT_BUNDLE_BYTES`), `Unexported` gains `worktrees` (the purge refusal names them), `Unexported.unusable` is `Vec<TerminalText>`, and the doctor test calls `expect_git_version`.
- The `Command::new` rule of the containers check flagged `Command::new(env!("CARGO_BIN_EXE_jackin"))` in `crates/jackin/tests/process`. `crates/jackin/tests/process/main.rs` joins `COMPUTED_COMMAND_DIRS` and the K6 test in `crates/xtask/tests/repo_gates.rs` is amended in the same commit, as P5.2 did for `host.rs`. Another file of `crates/jackin`, including another file of `crates/jackin/tests/process`, is still flagged.
- A paths argument may hold `..`. `HostPath::resolve` rejects a parent segment, so `jackin` resolves `..` and `.` lexically against `AppEnv.cwd` (`paths::absolutize`) before it builds a `HostPath`.
- `jackin-openshell` test `contract::shell_exit_code_cannot_hang_the_run` failed once in a full gate run under load (`left: Err("the shell exit code is not 3")`, `right: Err("the shell never ended")`) and passed on every rerun. It is not part of P6.1.
