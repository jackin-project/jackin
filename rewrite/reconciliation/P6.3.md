## Preconditions

1. Every fixture is `from parser` or `from upstream source`. No fixture is a recorded response (`rewrite/evidence/` holds none). A green suite proves "the port reads what the old parsers and the upstream clients read", not "the providers send this". Rows tagged port-fidelity below are the rows the live run must turn into recorded rows or cut.
2. Tests are not run against a live network. `XT-REQWEST` keeps one HTTP seam: only `jackin-usage-provider-core` imports `reqwest`.
3. Method for the red lines. For each test the named break (the "Red when" mutation of the plan, or a close variant of it) was applied to the final code of the commit, the suite was run with nextest, and the assertion diff was copied. The mutation was reverted after each run. The runs happened in a second worktree (`/private/tmp/claude-501/p63/wt-red`) checked out at the commit under test, so the main tree never held a mutation. Mutation specs and logs: `/private/tmp/claude-501/p63/specs/*.json` and `/private/tmp/claude-501/p63/red/*.log`. Where a break made several tests red, each test lists the break that turned the fewest tests red. In a red line, `left` is the actual value and `right` the expected one.
4. Green means: the test passes on the final code of its commit, and `mise exec -- mbx +1.99.1 xtask ci --fast` exits 0 on that commit.

## Decisions the brief did not specify, and deviations

1. Commit 16 and commit 17 are not in the design sequence. Commit 16 (`test(usage): make the provider rows fail on the right break`) exists because the red runs showed rows that passed for the wrong reason: the Z.AI rejection fixtures and the MiniMax `base_resp` fixture carried no windows, so ignoring the rejection still gave a provider error. The fixtures now carry a valid window, and new rows cover the MiniMax weekly window of other models, Gemini buckets without a model or fraction, an OpenCode entry that is not an API key, the Grok negative cent and zero cap. Commit 17 makes `kind_from_seconds` and `seconds_label` private and drops `Money::exponent`. Commit 18 adds this file. The orchestrator's commit 16 of the design (record P6.3 in `decisions.tsv`) is still to do, and `decisions.tsv`, `PLAN.md`, `DESIGN.md` are untouched.
2. `PENDING_PORT_PATHS` shrank per crate from commit 2 on instead of staying whole until commit 15. Each ported crate is scanned by the comments, containers and layers steps in its own commit, which is what made the `Secret::expose` and `reqwest` scans testable on the real repository (`xtask ci --only layers`). Commit 15 deletes the constant.
3. `ProviderError::Forbidden` exists (commit 5). OpenRouter tolerates a 403 on `/credits` but not a 401, and the HTTP layer would otherwise fold both into `Unauthorized`. The facade reports both as `expired_login`.
4. `rustls` 0.23.46 (aws-lc-rs, `std`, no default features) is a workspace dependency of `jackin-usage-provider-core` only. reqwest 0.12 with `rustls-tls-native-roots-no-provider` panics ("No provider set") when it builds a client unless a crypto provider is installed. `Http::new` installs the aws-lc-rs provider when none is set. The alternative feature `rustls-tls-native-roots` pulls ring and adds six lock entries (quinn, quinn-proto, quinn-udp, lru-slab, rand_pcg, web-time). The lock gains only the new workspace crates. reqwest has `default-features = false`, so no HTTP/2.
5. `UsageServer` is a hand-written HTTP/1.1 server on `tokio::net::TcpListener` (about 300 lines), not axum. It adds no lock entry. Every provider shares one origin: `endpoints()` maps a provider to `http://127.0.0.1:<port>/<provider>`, and `Http::with_base` replaces scheme, host and port and prefixes the base path. A route registered with `serve(provider, method, path, route)` lives under that prefix, so two providers with the same path do not collide. `Route` accepts several required headers (Codex needs two). `World.usage` is a `LazyUsageServer`: `world.usage.get().await?`.
6. The cache file is written after every successful report, even when no entry changed, and entries of accounts that are not in the request are kept. The plan removed the sentence "entries for accounts not in the request are dropped" unless a visible behavior was named, and the usage panel asks for a subset of accounts, so dropping would thrash the cache. `assert_only_state_written` then holds for a report that stores nothing, as the plan oracle says.
7. CLI-TEXT test 1 uses an OpenRouter account for the 401 line at commit 6 (Claude is not ported yet) and the Claude account the plan names from commit 7 on. The Gemini API-key line of CLI-TEXT test 3 arrives with commit 11.
8. UC-TIMEOUT test 1 uses a route that answers after 8 seconds for one account id, not a held route, because `hold` is keyed by path and would block both accounts. UC-CACHE-KEY test 3 uses an OpenRouter `Env` account (E9) and lands in commit 5.
9. `jackin usage --help` lists `--json` as its only own option. clap also prints the inherited global `--gateway` (declared `global = true` on `Cli`), which every subcommand shows; `usage` does not use it.
10. The Claude routines alias list (`seven_day_routines`, `seven_day_claude_routines`, `claude_routines`, `routines`, `seven_day_cowork`) is kept from the old serde aliases. No row covers the aliases other than `seven_day_routines`; `seven_day_cowork: null` appears in the live-mirror fixture.
11. Z.AI: `TIME_LIMIT` entries are not read (E5). The unit codes 5, 3, 1, 6 are the old author's mapping and unverified. MiniMax: the `data.model_remains` wrapper is cut (E4). Cursor and Grok drop a plan or config check that no row could tell apart from the empty-window error.
12. The `jackin-session` test `upload_timeout::an_upload_that_exceeds_its_limit_fails_with_a_typed_timeout_and_a_retry_converges` (real 1 second limit) failed twice in `nextest run --workspace` while mutation runs or the larger suite loaded the machine, and passed alone and on rerun. It is outside P6.3 and is not quarantined here. The suite grew from 650 to about 860 tests, which raises the parallel load of the gate.
13. Dependencies added: `chrono` 0.4.45 (`std` only, in the lock), `reqwest` 0.12.28 (the pin), `rustls` 0.23.46 (in the lock). `futures`, `sha2`, `serde`, `serde_json`, `thiserror`, `tokio` features and `tokio-util` are existing workspace dependencies. Latest stable on crates.io (checked 2026-11-03): chrono 0.4.45, rustls 0.23.46, futures 0.3.34, sha2 0.11.1, serde_json 1.0.154; reqwest is 0.13.5 and stays at 0.12.28 by decision.
14. Mutation specs that did not apply or did not compile on the first run were fixed and rerun; the ledger keeps only runs that executed. Mutations that no test noticed and that were equivalent (a check that the empty-window error already covers) led to deleting the redundant check, not to a test.
