## How the commands were run

Every `openshell` call took its stdin from `/dev/null`, ran under a hard `alarm` timeout (60 s to 180 s), and named the gateway, the OpenShell workspace and the sandbox explicitly. The only exceptions are the pty sessions of step 5 and 7, which a Python `pty` driver ran with its own timeouts and a final `SIGKILL`.

```text
t   = perl -e 'alarm shift; exec @ARGV' <seconds> /opt/homebrew/bin/openshell -g jackin-local --workspace default "$@" </dev/null
OS  = the same call with a 120 s limit (used inside step4-full.sh)
```

In the transcripts below, `./t 60 sandbox exec -n X ...` and `OS sandbox exec -n X ...` both mean `openshell -g jackin-local --workspace default sandbox exec -n X ...`.

### The second setup error: `mke2fs`

The VM driver builds ext4 root disks and needs `mke2fs`, `debugfs` and `e2fsck` from e2fsprogs (`docs/how-it-works/gateways/configuration.mdx:1541`). The previous agent installed them with `brew install e2fsprogs`. The first sandbox create then failed because the gateway inherited a `PATH` entry whose `mke2fs` could not be read (previous agent, raw log):

```text
Provisioning sandbox (structured output on stdout)...
Error:   × sandbox entered error phase while provisioning: ProvisioningFailed:
  │ inspect /usr/local/bin/mke2fs: Permission denied (os error 13). Install
  │ e2fsprogs 1.43 or newer, or repair the selected installation and the
  │ gateway service PATH; rerun config preflight with the service account and
  │ environment
```

On this Mac `ls -l /usr/local/bin/mke2fs` prints `Permission denied` (raw: `ls: /usr/local/bin/mke2fs: Permission denied`). The fix is to start the gateway with a short `PATH`: `/opt/homebrew/bin:/usr/bin:/bin:/usr/sbin:/sbin`. The keg-only e2fsprogs under `/opt/homebrew/opt/e2fsprogs` is found without a `PATH` entry (`configuration.mdx:1556`). `openshell-gateway config preflight` checks this.

### Reproducible start

`/private/tmp/claude-501/p0.2/start-gateway.sh` is the script. Its text is in `rewrite/drafts/gateway.md`. It is idempotent: it installs the driver only if the entitlement is missing, keeps existing PKI (`PKI files already exist, skipping`), writes the config only if absent, starts the gateway only if no matching process runs, and registers the gateway only if `gateway list` lacks it.

The core of it is:

```text
env -i HOME="$HOME" PATH=/opt/homebrew/bin:/usr/bin:/bin:/usr/sbin:/sbin \
  OPENSHELL_LOCAL_TLS_DIR="$STATE/tls" \
  OPENSHELL_DB_URL="sqlite:$STATE/gateway.db" \
  nohup /opt/homebrew/bin/openshell-gateway --config "$STATE/gateway-vm.toml" --port 17670 \
  >>~/Library/Logs/openshell-gateway-jackin-local.log 2>&1 </dev/null &
```

where `STATE=$HOME/.local/state/openshell/jackin-local`.

## Step 2. Docker driver fallback

Not run. The `vm` driver started, created sandboxes and ran commands in them. The task rule is to try Docker only when `vm` fails.

One lead for P0.3 (A2 image delivery). The `vm` driver can read a locally built image from a local container engine. It resolves the image reference with `bollard` before it tries a registry (`NVIDIA/OpenShell@v0.1.6:crates/openshell-driver-vm/src/driver.rs:3508`, `GuestImagePayloadSource::LocalDocker` at `driver.rs:290`). This is not tested here. How the driver finds the engine (`DOCKER_HOST` in the gateway environment, or the default socket) is also not tested.

### What the output proves

1. A default `sandbox upload` respects `.gitignore` (`ignored.txt` and `target/` are absent) and does **not** include `.git`. The CLI lists files with `git ls-files -co --exclude-standard -z` and uploads only that list (`NVIDIA/OpenShell@v0.1.6:crates/openshell-cli/src/run.rs:5235`, plan at `run.rs:5279` and `run.rs:5312`). `git ls-files` never lists `.git`.
2. `--no-git-ignore` selects the plain upload (`run.rs:5291`). It includes `.git`, `ignored.txt` and `target/`. It cannot give `.gitignore` filtering together with `.git`.
3. D08 needs both. The working method is two uploads: the filtered upload of `.`, then `sandbox upload <name> .git /sandbox/project --no-git-ignore`. After both, `git status --short` is clean, `git log --all` shows three commits, and the branches `feature/x` and `main` exist. Files are owned by `ubuntu:ubuntu`, and `git` raised no ownership warning.
4. A directory path is wrapped under its basename. `upload ... /abs/path/repo /sandbox/project` produced `/sandbox/project/repo/...` (`ssh.rs:1557`, `directory_upload_prefix`). A local path whose last component is `.` flattens the content into the destination (case B). The caller must therefore run with the repository as its working directory and pass `.`. The `.git` upload then uses the path `.git`.
5. The default upload needs `git` on the host (it runs `git ls-files`) and fails on a path that is not inside a work tree with `git rev-parse` status 128 (`g1` case). Outside a work tree the upload runs unfiltered with a warning (`nogit` case).
6. In filtered mode a single-file upload treats the destination as a directory: `/sandbox/single.txt` became a directory that holds `x.txt`. With `--no-git-ignore` the destination is the file name (`single2.txt`).
7. `sandbox download` accepts only paths under the sandbox workspace (`/sandbox`): `/etc/hostname` was refused (`ssh.rs:1392`). The bundle at `/sandbox/project.bundle` downloaded without change.
8. The bundle digest in the sandbox (`622e79d0...1e1`) equals the digest on the host (`622e79d0...1e1`). Fetching the bundle into a clone gave `refs/heads/jackin/p02-scm/main` at `9d1ad69...` and `.../feature/x` at `57fd95c...`, equal to the refs in the source repository.

## Gaps

### G1. The hang in `sandbox upload` was not reproduced

The previous agent hung for 80 minutes inside one `openshell sandbox upload` call. I could not reproduce it. I ran the cases below with stdin from `/dev/null` and a hard timeout. All finished in under 2 s.

The gateway log (`~/Library/Logs/openshell-gateway-jackin-local.log`) shows no `CreateSshSession`, `ForwardTcp` or `ExecSandbox` request after 17:56:17Z (the last `ExecSandbox` on `p02-scm`). The only later entries are the 60 s provider-refresh sweeps, one `ListSandboxes` at 18:19:14Z, and two sandbox-side `ReportProviderReadiness` logins at 18:54Z and 18:56Z. A hung upload that had reached the gateway would have logged a `CreateSshSession` (`ssh_tar_upload` calls `ssh_session_config` first, `ssh.rs:1258`). So the call stopped before it contacted the gateway, or the gateway did not log it. I cannot tell where. The steps before the first gateway call are the host `git rev-parse` and `git ls-files` (`run.rs:5124`, `run.rs:5235`) and the CLI start. I did not capture a stack, and I did not find the smallest hanging input.

A caller must run every upload and download under its own timeout and with stdin from `/dev/null`. The CLI does have an internal retry loop for transient errors (`SYNC_RETRY_ATTEMPTS`, `ssh.rs:1714`), and `ssh` uses `ServerAliveInterval=15` (`ssh.rs:226-236`), so a stuck call is not expected to wait forever.

Upstream change proposed: none until a hang is reproduced.

### G2. D08 needs two uploads, and the project root must be the working directory

There is no flag that gives "filtered by `.gitignore` and including `.git`". A single `sandbox upload` cannot meet D08 as written. Workaround that works in 0.1.6 and needs no shim: `sandbox upload <name> . /sandbox/project` with the repository as the working directory, then `sandbox upload <name> .git /sandbox/project --no-git-ignore`. Upstream change that would remove the two calls: a flag such as `--include-git-dir` for the filtered upload.

### G3. A `git` binary is needed on both sides

The host needs `git` (filtered upload). The sandbox image needs `git` (bundle). The default image has none. This is a construct image requirement (D06), not an OpenShell gap.

### G4. Homebrew bottle lacks the VM driver

The operator must fetch and sign `openshell-driver-vm` by hand (step 1). The release formula generated by upstream signs it in `post_install` (`crates/openshell-driver-vm/README.md:336`), but the `homebrew-core` bottle that was installed does not carry the driver. Jackin cannot repair this (D13), so `jackin doctor` should report a missing driver clearly.

## Appendix. The pty driver used in steps 5, 7 and 8

`pty_attach.py SANDBOX WATCH_SECONDS [detach] [-- <openshell args>]`. It forks the CLI in a pty, reads for `WATCH_SECONDS`, optionally types the text in the environment variable `SEND`, sends Ctrl-P and Ctrl-Q, waits up to 20 s for the client to exit and then kills it. Run it as `python3 -I pty_attach.py ...` under `perl -e 'alarm shift; exec @ARGV' 90`.

```text
#!/usr/bin/env python3
"""Drive `openshell sandbox connect` in a pty.

usage: pty_attach.py SANDBOX WATCH_SECONDS [detach] [send-before-detach]
Prints the raw bytes received (escaped), then reports exit status.
Hard limits: WATCH_SECONDS to observe, 20 s more to exit after detach, then SIGKILL.
"""
import os, pty, select, signal, sys, time, struct, fcntl, termios

sandbox, watch = sys.argv[1], float(sys.argv[2])
detach = len(sys.argv) > 3 and sys.argv[3] == "detach"
cmd = ["/opt/homebrew/bin/openshell", "-g", "jackin-local", "--workspace", "default",
       "sandbox", "connect", sandbox]
if "--" in sys.argv:
    cmd = ["/opt/homebrew/bin/openshell", "-g", "jackin-local", "--workspace", "default"] + sys.argv[sys.argv.index("--") + 1:]

pid, fd = pty.fork()
if pid == 0:
    os.execv(cmd[0], cmd)
fcntl.ioctl(fd, termios.TIOCSWINSZ, struct.pack("HHHH", 24, 100, 0, 0))

buf = b""
def pump(seconds):
    global buf
    end = time.time() + seconds
    while time.time() < end:
        r, _, _ = select.select([fd], [], [], 0.2)
        if r:
            try:
                d = os.read(fd, 65536)
            except OSError:
                return False
            if not d:
                return False
            buf += d
        done, _ = os.waitpid(pid, os.WNOHANG), None
        if done[0] != 0:
            return ("exited", done[1])
    return True

t0 = time.time()
res = pump(watch)
if os.environ.get("SEND") and res is True:
    os.write(fd, os.environ["SEND"].encode().decode("unicode_escape").encode())
    print(f"[driver] sent input {os.environ['SEND']!r} at +{time.time() - t0:.1f}s", file=sys.stderr)
    res = pump(2)
if detach and res is True:
    os.write(fd, b"\x10")
    time.sleep(0.2)
    os.write(fd, b"\x11")
    sent = time.time()
    res = pump(20)
    print(f"[driver] sent Ctrl-P Ctrl-Q at +{sent - t0:.1f}s", file=sys.stderr)
status = None
try:
    p, st = os.waitpid(pid, os.WNOHANG)
    if p == 0:
        os.kill(pid, signal.SIGKILL)
        p, st = os.waitpid(pid, 0)
        print("[driver] child still alive after limit; SIGKILLed", file=sys.stderr)
    status = st
except ChildProcessError:
    status = res[1] if isinstance(res, tuple) else None
text = buf.decode("utf-8", "replace").replace("\r\n", "\n")
sys.stdout.write(text)
print(f"\n[driver] bytes={len(buf)} wait_status={status} exit_code={os.waitstatus_to_exitcode(status) if status is not None else None}", file=sys.stderr)
```
