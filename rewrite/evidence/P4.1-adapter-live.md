## Review findings (most severe first)

Upstream facts are cited at `OS@v0.1.6`. Adapter lines are at `ee726799`.

### M1 (medium). Exec and shell calls report a vanished sandbox as `Protocol`, not `NotFound`

- `grpc/program.rs:198` and `:218` (`exec_collect`), `grpc/shell.rs:93` (`open_shell`) and `grpc/main_pty.rs:361` (`open_relay`) call `map_status(op, None, ...)`. `grpc/status.rs:32-35` turns `Code::NotFound` with no `Missing` into `Protocol { message }`.
- Live (e.1): `run_program` and `open_terminal(Shell)` on an absent sandbox return `Protocol { message: "sandbox not found" }`. `read_files` and `write_file` share `exec_collect` and behave the same. The API.md status table says `NotFound` maps to `NotFound`, and `detail`, `set_power` and the main terminal already do.
- Effect: `jackin-session` cannot tell a vanished sandbox from a protocol break on `exec`, `shell` and file reads.
- Fix: pass `Some(Missing::Sandbox(sandbox.clone()))` in these four places and add a test per entry point.

### M2 (medium). The Terminal contract group does not check the lease rules, and the suite leaves a profile behind

- `contract.rs:43` lists two Terminal checks. API.md section 3 (Contract suite) says the group covers detach and re-attach replay, the input lease rules, `Viewer` input ignored, and a shell exit code. `U5.md` ("The contract suite implements all three groups") does not record the missing checks. The live probes p.1 to p.5 show the adapter behaves correctly, but nothing asserts it, and `FakeGateway` will have no contract to follow for the lease.
- `contract.rs:492-520`: the first profile sync accepts `Imported`, `Updated` or `Unchanged`, so `Imported` is never asserted, and the suite leaves the `jackin-contract` profile in the workspace (the `Gateway` trait has no profile delete). I had to delete it with `DeleteProviderProfile`. A real `xtask e2e` run will leave one profile per OpenShell workspace.
- Fix: either add the lease, `Viewer` and Ctrl-C checks (the driver `live.rs` probes p.1 to p.4 are a template) or record the gap in `U5.md` and API.md; decide how e2e removes the profile.

### M3 (low to medium). The lease decision is a 250 ms heuristic and a late read-only notice never becomes `Lease(ReadOnly)`

- `grpc/main_pty.rs:314-325` collects early messages for `LEASE_WINDOW` (250 ms). `:97-114` decides from them. `translate` (`:126-133`) turns only the notice "input enabled" into a lease event. If the "attached read-only" notice arrives after the window (slow relay), the adapter has already emitted `Lease(Owner)` and the notice is passed on as `Notice` only.
- Live it was never late: the server sends the notice right after the subsystem success, before the output task starts (`OS@v0.1.6:crates/openshell-supervisor-process/src/ssh.rs:803-830`, notice text at `:826`), and p.1 got `ReadOnly` correctly.
- Fix: in `translate`, map the "attached read-only" notice to `Lease(ReadOnly)`. It is a two-line change and removes the timing dependence.

### L1 (low). A relay-open failure on the forward stream is swallowed

- `grpc/main_pty.rs:367-373`: `while let Ok(Some(frame)) = response.message().await` treats `Err(status)` as end of stream. The server reports `supervisor relay failed`, `relay open timed out` and `relay channel dropped` as an error item on the response stream (`OS@v0.1.6:crates/openshell-server/src/grpc/sandbox.rs:2716-2745` `await_relay_stream`, used by `handle_forward_tcp` at `:2747-2820`). The caller then sees an SSH error (`Protocol "ssh: ..."`) with the cause lost. Keep the last stream error and use it when the handshake fails.

### L2 (low). `Exited(Some(0))` is emitted when an attachment ends by detach key

- Live p.4 and p.5: a Ctrl-C by a viewer and a Ctrl-D by the owner give `Exited(Some(0))` then `Ended(StreamClosed)` while the main process keeps running (`Ready`). The server sends an SSH exit status of 0 when it closes an attachment. API.md already says the authoritative exit code is the `Phase`. `U5.md` records `Ended(StreamClosed)` but not this `Exited(Some(0))`. Record it, or drop `Exited` for a main-process terminal, so the console does not read it as a process exit.

### L3 (low). `write_file` uses a fixed temporary name and has no length check

- `grpc/program.rs:20`: the temporary file is `<target>.jackin-tmp`. Two concurrent writers to one target share it. A stale file from a killed run is overwritten by the next write (it converges), and a client drop mid-stream does not run the `mv` because the server fails the input stream instead of sending EOF (`OS@v0.1.6:crates/openshell-server/src/grpc/sandbox.rs:3859-3893`, `msg?` at `:3864` returns before `write_half.eof()`). If a writer can ever be concurrent, use a unique suffix; passing the expected byte count and checking it with `wc -c` before `mv` would also make the atomicity independent of the server's stream handling.

### L4 (low). The CLI transfer inherits the operator's `OPENSHELL_*` environment

- `transfer.rs:58-65` runs `openshell` with `env: Vec::new()` and relies on the `ProcessRunner`. I checked the CLI: `OPENSHELL_GATEWAY_ENDPOINT=https://127.0.0.1:9 openshell -g jackin-local --workspace jackin-test sandbox list` fails with `connect error: transport error`, so the environment endpoint overrides `-g` (`OS@v0.1.6:crates/openshell-cli/src/main.rs:79-97`, `resolve_gateway`). D03 asks for explicit identity. Either pass `--gateway-endpoint <registered endpoint>` as well, or require the P5.2 runner to remove `OPENSHELL_GATEWAY_ENDPOINT`, `OPENSHELL_GATEWAY_INSECURE`, `OPENSHELL_GATEWAY` and `OPENSHELL_WORKSPACE` and record that.

### L5 (low). `Unavailable` is always reported as an unreachable gateway

- `grpc/status.rs:54-57`. The server also returns `Unavailable` for `supervisor relay failed` (`OS@v0.1.6:crates/openshell-server/src/grpc/sandbox.rs:2661`, `:2796`, `:3237`), which is a sandbox condition. The retry class is right (`is_retryable`), the message names the gateway endpoint.

### L6 (low). Live policy endpoints with an unparsable host are skipped by the closure check

- `policy/yaml.rs:129-131`: `network_rules` continues past an endpoint whose host fails `HostPattern::parse`. For authored policies `check_endpoint` rejects it first (`yaml.rs:54-74`). For a live policy read by `sandbox_detail` the endpoint is dropped silently, so `closure_violations` cannot report it.

### L7 (low). `put_provider` races between the read and the create

- `grpc/provider.rs:251-263`: two concurrent calls both see `NotFound` and both create; the second gets `AlreadyExists { Provider }` and the adapter does not retry as an update. The same holds for `ensure_profile` import (`provider.rs:92-108`). A caller that serializes per account is safe.

### Informational

- I1. `grpc/shell.rs:26` starts `bash` by name. The shell works on the default image; an image without `bash` ends the shell with exit 127.
- I2. `grpc/sandbox.rs:240-257` ignores `GetSandboxConfigResponse.configuration_admitted` (`OS@v0.1.6:proto/sandbox.proto:473`). `PolicyReport.loaded` therefore says "the stored revision is loaded", not "the policy and provider composition is admitted". Not needed by API.md.
- I3. `CreateSandboxRequest.request_id` and `await_main_process_attachment` are unset (`grpc/sandbox.rs:108-130`). D07 handles retry by sandbox name, so this is consistent.
- I4. The exec user is the image user (here `ubuntu`), not a user named `sandbox`; API.md `run_program` says "as the user `sandbox`". It depends on the image.
- I5. `U5.md` line 19 (R12 live proof "is a hand-off") and line 28 (`Unchanged` "not verified") are now proven live by (a) and (b) above. Edit both lines.
