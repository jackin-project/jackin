## Defects

1. omp config publication does not reach omp 18.18.1: jackin writes `/sandbox/.omp/config.toml` with `providers.<id>.baseUrl`, `credentialEnv`, `modelRoles`, but omp reads provider overrides from `<agentDir>/models.yml` and settings from `<agentDir>/config.yml`; the config.toml is inert. T09 (zai) passed only because omp's built-in zai default coincides with the pinned baseUrl. T10 requires the `https://api.kimi.com/coding/v1` override (built-in moonshot default api.moonshot.ai is wrong for the Kimi coding plan) and a custom model entry `kimi-for-coding` (not in omp's bundled catalog); without it the tuple cannot run. Not fixed here (worktree diff restricted to the tuple flips).
2. `jackin account add` never updates an existing gateway provider: for a pre-existing `jackin-omp-kimi-omp` holding an unknown credential, the account's op-sourced key is silently not published and launch reports "provider: skipped, the provider exists". There is no `account update` (duplicate-name error) and no way to republish without deleting the provider (which would lose the stored credential). Worked around with a side provider + sandbox detach/attach.
3. Tooling: shared mbx cache served a stale jackin-core artifact for the worktree build (binary catalog out of sync with the worktree source until a forced rebuild). Worth a cache-bypass habit for proof worktrees.
4. Known from A4, unchanged: non-TTY `jackin load` returns the sandbox id without attaching, so the agent must be driven via `openshell sandbox exec`.
