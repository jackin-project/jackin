## Defects (main tree)

1. `render_claude_config` pins `ANTHROPIC_AUTH_TOKEN: "placeholder"` into settings.json (zai-lane defect 4, now reproduced on T15 and T16): Claude Code applies settings env over the process environment, so the published config clobbers the brokered token and every sanctioned-config call dies unauthenticated (`Not logged in · Please run /login`). The lanes work when settings.json carries only ANTHROPIC_BASE_URL and the brokered env token flows. Main fix needed (omit the auth entry, or document the gateway swap).
2. MiMo's responses endpoint rejects codex's default `web_search` tool advertisement (`responses_feature_not_supported`, tool type web_search), so a default T20 task fails on every request. Codex 0.166 only honors the TOP-LEVEL `web_search = "disabled"` (its `tools.web_search`/`features.web_search_request` knobs do not suppress the advertisement; the binary prints the hint itself). jackin's rendered codex config for T20 should pin that override (or MiMo must support the tool) — until then the sanctioned launch shape cannot complete a tool-bearing task on T20. T19 (MiniMax) accepted the default toolset.
3. Main-tree blockers this lane re-proved with the same worktree fix shape as the zai lane: `sync_login` cannot publish static-key accounts for the claude/codex lanes (gate `agent != Agent::Codex`, empty Claude `credential_env_names`); Claude Code install triples double the `linux-` prefix; t15/t16 profile assets broker under the provider key name instead of `ANTHROPIC_AUTH_TOKEN`. All three are one-line fixes proven here; they must land on main before the T13–T20 flips can be real.
4. Shared-config race between concurrent lanes: during this proof a concurrent lane restored `~/.config/jackin/config.toml` from its own snapshot, silently deleting this lane's role/workspace registrations (and the pre-existing `sentinel-kimi` role) while gateway state survived; the next launch failed with `no workspace for …`. Concurrent lanes need serialized config edits or per-lane config files; recovery was `jackin role add`/`jackin workspace add` again.
5. Launch-time static republish requires the raw key in the launching shell for claude (and omp) accounts even when the gateway provider already holds it (`holds_static_key` -> no Present-skip, launch/run.rs:343); codex launches skip when the provider is present. Combined with defect-4-style clobbering risk, an interrupted or wrong-value env at launch overwrites a good provider credential; the sha-guarded read in this proof prevented exactly that (a 65-char wrong op read for the MiMo reference was rejected before launch).
6. Credential access (process, not jackin): the 1Password CLI desktop-app authorization gate blocked this lane for ~12 h overnight (see incident above). Lanes that depend on op keys cannot run unattended; the account-add flow could offer a sha-pin so later republishes can be verified against the stored provider fingerprint (the gateway already holds the value).
