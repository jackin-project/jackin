Structure: Overview and providers stay in the native sidebar. Overview uses provider group rows with canonical account children. Selecting a provider opens one provider page with a native account picker and all quota windows.

Strengths: least structural churn; immediate all-provider scan; accounts visibly subordinate to providers; calm provider detail; strong parity with CLI and console grouping.

Risks: group rows must span hierarchy instead of placeholder dashes; table contraction must protect state and identity; two routes to provider detail must retain one selection.

Minimum width: hide sidebar on request; group labels span the table; secondary plan/reset text contracts before account and state.

B — Hierarchical Navigation Sidebar ELIGIBLE

┌────────────────────┬───────────────────────────────────────────────┐
│ Overview           │ OpenAI · team@example.test                    │
│ ▾ OpenAI           │ Plus                                          │
│   personal@example │ Limits                                        │
│   team@example     │ Weekly       0% left      Resets in 3d        │
│   organization@…   │ Status · Depleted                              │
│ ▸ Amp              │ Status · Updated now                          │
└────────────────────┴───────────────────────────────────────────────┘

Structure: provider and canonical account hierarchy moves entirely into the sidebar. Overview remains the first destination; selecting an account opens its quota detail directly.

Strengths: one navigation location; no account picker duplication; exact account context visible while inspecting details; direct keyboard drill-down.

Risks: dense sidebar with long account labels; provider-only state needs a stable destination; many accounts crowd navigation; may reduce overview scanability.

Minimum width: sidebar user-hideable; labels truncate with complete accessibility values; selection persists when hidden.

G — Attention Queue plus Complete Inventory ELIGIBLE

┌──────────────┬─────────────────────────────────────────────────────┐
│ Attention    │ Needs attention                                    │
│ Overview     │ Anthropic · personal@… · 12% left · resets in 1h   │
│ Providers    │ Kimi · cached · offline                            │
│   OpenAI     ├─────────────────────────────────────────────────────┤
│   …          │ Complete inventory                                 │
└──────────────┴─────────────────────────────────────────────────────┘

Structure: a stable Attention destination shows Rust-ranked depleted, stale, or failed accounts before the complete grouped Overview. Provider pages remain.

Strengths: fastest route to actionable risk; status-item worst-provider mode and window detail share one urgency model; no client-side ranking if Rust projects the queue.

Risks: another navigation concept; can duplicate Overview rows; "attention" must not imply launch blocking or client-owned policy; calm healthy states gain no benefit.

Minimum width: queue uses the same row contract as Overview; never cards or banners.

Structure: popover shows only identity, one Rust-ranked quota summary, explicit state, account picker, handoff actions. Retained Usage window uses A, B, or G for full detail.

Strengths: strongest popover scope adherence; fastest glance; complete data one action away with exact provider/account handoff.

Risks: hides multi-window quota detail from the glance; operators may expect the current complete popover form; selected window alternative must be recorded with it.
