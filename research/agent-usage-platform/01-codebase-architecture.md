### Discovery membership, identity precedence, and collisions
- Host membership discovery reads one read-only config snapshot, enumerates the default/global scope, each role, each workspace, and workspace-role combinations, and pre-deduplicates credential sources in a `BTreeMap` keyed by profile `(agent, root)`, environment `(surface, opaque handle)`, or forwarded capability `(surface, id)`. — `crates/jackin-usage/src/host/discovery.rs:439-453`, `crates/jackin-usage/src/host/discovery.rs:496-540`, `crates/jackin-usage/src/host/discovery.rs:568-605` (confidence: HIGH)
- Discovery excludes OpenCode in three distinct places: profile enumeration filters `Agent::Opencode`, governed environment enumeration filters the OpenCode owner and maps it to no surface, and Capsule forwarding admits only the seven-value desktop order. — `crates/jackin-usage/src/host/discovery.rs:542-565`, `crates/jackin-usage/src/host/discovery.rs:607-643`, `crates/jackin-usage/src/host/discovery.rs:646-718`, `crates/jackin-usage/src/host/discovery.rs:745-755` (confidence: HIGH)
- OpenCode also has no usable quota adapter: its snapshot is always `Unsupported`, with no source/confidence and an adapter-pending error. — `crates/jackin-usage/src/usage.rs:658-683` (confidence: HIGH)
- Authenticated identity precedence is provider-issued ID first, then authenticated account label; an empty result remains an anonymous binding and does not become an account row. Exact `CanonicalAccountIdentity { surface, subject }` is the deduplication key. — `crates/jackin-usage/src/host/discovery.rs:925-1008`, `crates/jackin-usage/src/host/discovery.rs:1027-1045`, `crates/jackin-usage/src/host/accounts.rs:19-35` (confidence: HIGH)
- Canonical account keys hash the surface-owned provider label and the exact subject bytes, without case or Unicode normalization. The subject enum tag is not included in the hash, so `ProviderId("x")` and `AuthenticatedLabel("x")` on the same surface produce the same account key even though they are distinct in the discovery `BTreeMap`. — `crates/jackin-usage/src/host/accounts.rs:51-57`, `crates/jackin-core/src/account_key.rs:11-17`, `crates/jackin-usage/src/host/discovery.rs:942-987` (confidence: HIGH)
- Conditional collision behavior follows directly from that representation: two sources with the same exact `(surface, subject variant, subject text)` merge; identical labels on different surfaces remain separate; same-surface labels differing only by case split; and a provider-ID identity and label identity with identical text remain separate during discovery but later share one hashed account key. — `crates/jackin-usage/src/host/discovery.rs:976-1000`, `crates/jackin-usage/src/host/accounts.rs:28-57`, `crates/jackin-usage/src/host/tests.rs:1018-1050` (confidence: HIGH)
- When two distinct discovery identities produce that same hashed capability, broker construction retains only the first binding through `entry(capability).or_insert(binding)`, while discovery account descriptors can still contain both records with the same `account_key`; downstream maps keyed by `(surface, account_key)` consequently have only one slot. — `crates/jackin-usage/src/host/discovery.rs:1027-1045`, `crates/jackin-usage/src/host/broker.rs:507-539`, `crates/jackin-usage/src/host/accounts.rs:151-156` (confidence: HIGH)
- Durable/live views are matched back to discovered membership by the first same-surface account whose visible label equals case-insensitively. Thus two current identities that expose the same label can alias a stored view to the first membership entry, independent of provider-ID strength. — `crates/jackin-usage/src/host/accounts.rs:372-386` (confidence: HIGH)
- Source precedence in materialization is membership-gated history, live provider state, discovered account views, then membership placeholders; within one account key, a better lifecycle rank replaces a worse one, and equal lifecycle uses the newest `fetched_at_epoch`. Provenance is unioned. — `crates/jackin-usage/src/host/accounts.rs:285-369`, `crates/jackin-usage/src/host/accounts.rs:426-469` (confidence: HIGH)
- When validated membership is present, durable history that has no current label match is filtered out; a matching stored entry is promoted to `Current`. When membership is absent, stored entries are `Historical`, so the same materializer has two membership semantics depending on caller state. — `crates/jackin-usage/src/host/accounts.rs:299-325`, `crates/jackin-usage/src/host/accounts.rs:329-343` (confidence: HIGH)
- Anonymous capability identity is not durable source identity. Catalog materialization assigns sequential `source-0001` ordinals from sorted source enumeration, and the broker hashes `bootstrap:{source_id}` for an anonymous binding; insertion or removal of an earlier sorted source can therefore change an anonymous capability and its persisted filename. — `crates/jackin-usage/src/host/discovery.rs:811-854`, `crates/jackin-usage/src/host/broker.rs:822-835`, `crates/jackin-usage/src/coordinator/state.rs:252-254` (confidence: HIGH)
- Environment credentials remain anonymous at discovery because the default cached resolver's identity method always returns `Anonymous`. It keeps secret material only in its process-local cache behind sequential opaque handles and deduplicates a handle by exact owner plus exact secret bytes. — `crates/jackin-usage/src/host/credential_resolver.rs:82-101`, `crates/jackin-usage/src/host/credential_resolver.rs:151-185`, `crates/jackin-usage/src/host/credential_resolver.rs:245-275` (confidence: HIGH)
- Provider-specific identity strength varies: the common validator prefers a provider ID over a label; Codex can return both; Amp extracts an authenticated label from a configured `apiKey@label` entry but leaves an unlabeled key anonymous; Grok treats the first recursive email, user ID, or team ID as an authenticated label rather than a provider ID. — `crates/jackin-usage/src/host/discovery.rs:949-965`, `crates/jackin-usage/src/host/discovery.rs:1260-1281`, `crates/jackin-usage/src/host/discovery.rs:1284-1320`, `crates/jackin-usage/src/host/discovery.rs:1323-1339` (confidence: HIGH)
- Selection is separately persisted by `(surface_id, account_key)`; stale or cross-surface keys are rejected/reconciled, and preferred current selection favors live-host provenance then the existing account sort. — `crates/jackin-usage/src/host.rs:838-868`, `crates/jackin-usage/src/host.rs:1485-1510`, `crates/jackin-usage/src/host/accounts.rs:158-188`, `crates/jackin-usage/src/host/tests.rs:1088-1137` (confidence: HIGH)

- The atomic desktop projection has one optional global error string plus a diagnostics vector. Only diagnostics with no `surface_id` enter the global error; surface-specific discovery failures remain in diagnostics, while provider empty states and account descriptors can independently carry `last_error`. — `crates/jackin-usage/src/host.rs:1207-1219`, `crates/jackin-usage/src/host.rs:1248-1303`, `crates/jackin-usage/src/host/accounts.rs:104-134` (confidence: HIGH)

### Broker ownership, freshness, locking, retry, cancellation, and recovery
- The coordinator is single-flight per exact capability. Under one global mutex, an active generation or a stale caller generation returns the existing winner even when `force=true`; `request_refresh_all` first deduplicates capabilities through a `BTreeMap`. — `crates/jackin-usage/src/coordinator.rs:179-191`, `crates/jackin-usage/src/coordinator.rs:281-380` (confidence: HIGH)
- Broker ownership is process-elected but not a standalone durable service: the first caller claims `leader.pid`, binds the Unix socket, constructs the file store/coordinator, and spawns a `usage-broker` thread in that caller's process. Other processes connect to the socket. — `crates/jackin-usage/src/host/broker.rs:542-577`, `crates/jackin-usage/src/host/broker.rs:774-815` (confidence: HIGH)
- The leader guard uses owner-only paths and PID liveness. A malformed/incomplete guard is treated as an election in progress; a live PID suppresses takeover; a dead PID causes guard deletion and recursive reclaim. — `crates/jackin-usage/src/host/broker.rs:765-805` (confidence: HIGH)
- Broker transport has four connection workers and a 128-connection bounded queue; the coordinator defaults to four provider workers, a 256-generation bounded queue, a five-minute success cooldown, and a 20-second classification threshold. — `crates/jackin-usage/src/host/broker.rs:126-133`, `crates/jackin-usage/src/coordinator.rs:60-80`, `crates/jackin-usage/src/coordinator.rs:222-260` (confidence: HIGH)
- Provider execution occurs outside the coordinator mutex, but queued/updating/terminal persistence occurs while account state is locked. The executor contract owns real network timeouts; the coordinator checks elapsed time only after `probe` returns, so its 20-second threshold does not preempt or cancel a blocked provider call. — `crates/jackin-usage/src/coordinator.rs:52-58`, `crates/jackin-usage/src/coordinator.rs:291-340`, `crates/jackin-usage/src/coordinator.rs:534-620`, `crates/jackin-usage/src/coordinator.rs:623-650` (confidence: HIGH)
- Freshness TTL is durable per account: success sets `success_deadline_epoch` from the configured cooldown. `force=true` bypasses only that success cooldown; it does not bypass an active winner, stale observed generation, provider rate-limit deadline, or general retry deadline. — `crates/jackin-usage/src/coordinator.rs:304-319`, `crates/jackin-usage/src/coordinator.rs:623-650` (confidence: HIGH)
- Rate-limited failures preserve last-good data and persist either provider `Retry-After` or exponential local backoff of 5, 10, 20, then at most 30 minutes. Non-rate-limit failures get no local backoff unless the provider supplies a retry deadline, so they are immediately eligible for another forced or ambient generation. — `crates/jackin-usage/src/coordinator.rs:24-26`, `crates/jackin-usage/src/coordinator.rs:653-704`, `crates/jackin-usage/src/coordinator.rs:735-748` (confidence: HIGH)
- There is no cancellation operation in the wire enum. Join timeout leaves ownership active; dropping the coordinator sends shutdown only to its workers and joins them, so an executing probe is waited out rather than cancelled. — `crates/jackin-protocol/src/usage_broker.rs:107-159`, `crates/jackin-usage/src/coordinator.rs:382-430`, `crates/jackin-usage/src/coordinator.rs:508-516` (confidence: HIGH)
- State is persisted per capability under `usage-broker/accounts` with schema, generation, phase, current result, last-good, error, all deadlines, and failure count. Writes sanitize display fields, create an owner-only temporary file, sync it, rename it, and sync the directory. — `crates/jackin-usage/src/coordinator/state.rs:21-56`, `crates/jackin-usage/src/coordinator/state.rs:105-142`, `crates/jackin-usage/src/coordinator/state.rs:179-227`, `crates/jackin-usage/src/coordinator/state.rs:286-329` (confidence: HIGH)
- Crash recovery is lazy on the next access to each capability. A persisted `Queued` or `Updating` phase becomes terminal `OwnerLost`, increments failures, clears retry/success deadlines, is persisted, and marks one recovery generation pending; concurrent callers then join that next generation. — `crates/jackin-usage/src/coordinator.rs:432-485`, `crates/jackin-usage/src/coordinator/tests.rs:480-516` (confidence: HIGH)
- Corrupt or unavailable persisted account state blocks that capability before provider dispatch. Validation enforces schema/capability equality, size, owner/mode, no-follow access, and bounded future timestamps. — `crates/jackin-usage/src/coordinator/state.rs:145-177`, `crates/jackin-usage/src/coordinator/state.rs:238-283`, `crates/jackin-usage/src/coordinator/tests.rs:320-336` (confidence: HIGH)
- The inspected discovery invalidation boundary is manual refresh reconciliation rather than broker scheduling. Forced FFI refresh calls runtime reconciliation, which evicts failed credential-cache entries, rereads config, compares the validated discovery generation, and prunes local discovered views when that generation changes; this path does not delete persisted broker account files. — `crates/jackin-usage-ffi/src/bridge.rs:140-148`, `crates/jackin-usage-ffi/src/bridge.rs:461-496`, `crates/jackin-usage/src/host/discovery.rs:1436-1475`, `crates/jackin-usage/src/host/credential_resolver.rs:223-231` (confidence: HIGH)
- Broker attachment does not reconcile a changed catalog into an already-live leader. `ensure_usage_broker_with_executor` returns immediately when its connection probe succeeds, discarding the newly supplied executor; the leader therefore retains the first process's scope, resolver, and binding map. FFI reconciliation updates its client-side capability list after calling this path, but cannot add, replace, or revoke bindings in that live broker. The leader rediscovery fallback runs only when a requested capability is absent and still uses the first owner's scope and resolver. — `crates/jackin-usage/src/host/broker.rs:408-421`, `crates/jackin-usage/src/host/broker.rs:488-503`, `crates/jackin-usage/src/host/broker.rs:544-558`, `crates/jackin-usage-ffi/src/bridge.rs:461-496` (confidence: HIGH)
- Runtime and native code retain separate scheduling state even though provider work is broker-gated: each `HostUsageRuntime` tracks process-local `last_refresh` and a refresh floor, and Swift polls every five seconds to ask that runtime whether refresh is due. — `crates/jackin-usage/src/host.rs:501-532`, `crates/jackin-usage/src/host.rs:763-775`, `native/Sources/JackinUsageBridge/PresentationStore.swift:826-860` (confidence: HIGH)
