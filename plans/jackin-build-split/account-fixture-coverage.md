## Current account path

AccountCredential is a profile directory plus optional explicit ProfileSelector/XdgRoots, an API-key reference, or an OAuth token reference (crates/jackin-config/src/accounts.rs:142-217). AccountConfig::supports_agent checks enabled state and provider/agent compatibility (accounts.rs:288-330). resolve_account applies role, workspace, then global bindings and fails closed for an unauthorized explicit binding; otherwise a workspace may select its sole compatible account, while ambiguity is an error (accounts.rs:817-876). resolve_launch precedence is one-launch selection, role/workspace/global launch defaults, account bindings, then sole eligible instance; explicit selections are validated atomically (accounts.rs:1090-1225).

Profile-store identity is intended to stay exact across discovery and launch: ProfileSelector records entry and optional profile (accounts.rs:142-175), and source validation accepts agent, provider, selector, source directory, and host home (crates/jackin-instance/src/auth.rs:171-194). The auth module validates and stages selected source material. Its source lock has a five-second bound and ten-millisecond poll (auth.rs:2057-2060,2924-3009). The sync_refreshes_changed_single_file_provider_credentials test (auth/tests.rs:2214) means changed source bytes are copied on another sync; it does not exercise OAuth refresh.

Discovery reads bounded files and distinguishes missing, unreadable, oversized, and malformed inputs (crates/jackin-config/src/accounts/discovery.rs:533-552). Kimi env candidates are ordered by file mtime after excluding directories (:504-531); Kimi credential recognition checks for a nonempty access token, with no expiry decision in that branch (:561-584). Gemini’s refresh-token recognition is documented as docs-derived and unverified (:584-590). In the account/discovery/auth paths reviewed, there is no provider refresh executor or expiry-aware refresh contract. Filesystem serialization and copy-on-change must not be presented as refresh single-flight.

## Proof and next bounded work

The named tests are **present in source only**. They were not run in this investigation, and no supplied CI evidence establishes execution of this account-fixture set. The permitted source work did not read host account state, credential values, keychain contents, provider databases, or make provider requests. Test names and code branches are evidence of intended assertions, not proof of a live provider session. In particular, OpenCode/Hermes/OMP store fixtures exercise parsers and synthetic filesystem/database content only.

After the OMP migration/ownership freeze, keep the next implementation bounded to two test seams: (1) jackin-config discovery and route-selection fixtures using temporary trees, explicit ProfileSelectors, and an injected clock; (2) jackin-instance staged-source fixtures for permission, mutation/revocation, and lock-contention behavior. Expiry and concurrent refresh need a refresh interface first, so assign its design/owner before adding tests that would otherwise encode nonexistent behavior. Keep provider/network access out of all fixtures.
