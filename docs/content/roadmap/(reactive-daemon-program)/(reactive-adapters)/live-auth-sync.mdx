---
title: "Live Bidirectional Auth Sync"
---

**Status**: Deferred

**Current state**: design proposal for live bidirectional credential reconciliation. The [host daemon foundation](/commands/daemon/) exists, but this feature's watchers, shared credential store, host writeback, and conflict protocol remain unimplemented. Plan 042 did not prototype live sync; credential-specific redaction, coredump, version-skew, and lifecycle validation remain prerequisites for its adapters.

## Shipped facts

Named profile accounts select authorized host credential directories at launch;
Capsule seeds durable agent homes from forwarded material without overwriting
credentials already refreshed in-container when a later tab opens. The old
per-agent `sync_source_dir` policy has been replaced by the
[account registry](/guides/authentication/agents/).

There is no live bidirectional credential reconciliation: host rotation is not
propagated into running agent homes, and an in-container rotation is not written
back to the host or sibling containers. Parallel containers sharing an OAuth
account can still invalidate each other's grant. The independent usage broker's
account refresh and Capsule's usage projection do not implement credential
writeback or conflict resolution.

This remains Phase 4 of the [auth reliability program](/roadmap/auth-reliability-program/).
`jackin daemon` already supplies a long-running per-user host process and control
socket; no auth adapter, shared credential store, or container-side watcher
proposed below has been built.

## Remaining work

1. **Credential adapter readiness** — use the shipped daemon lifecycle/control socket, then prove credential-specific redaction, coredump handling, restart, and version-skew behavior before enabling auth watchers. See [jackin❯ daemon](/roadmap/jackin-daemon/).
2. **Per-axis adapter** on the daemon's plug-in surface for `gh`, Claude, Codex, and future axes (Amp, etc.) — watches host token stores (inotify on Linux, polling on macOS) and reconciles a flock-protected shared store.
3. **Container-side watcher** — small static binary in the construct image, inotify on agent credential paths, pushes in-container refreshes to the shared store bind-mount.
4. **macOS Keychain bridge** — write refreshed tokens back to Keychain via `security add-generic-password -U` so the host user's normal `gh` / `claude` workflow stays consistent.
5. **Conflict resolution** — last-writer-wins by `(mtime, checksum)`, with in-container rotation winning over a stale host poll landing in the same window; surfaced via `jackin auth status` (tracked under [Auth health and operator visibility](/roadmap/auth-health-and-visibility/)).
6. **Account source contract** — expose live reconciliation as an explicit account capability with operator consent; preserve the distinction between launch-time profile forwarding and bidirectional host writes. Historical `sync` naming alternatives remain in the design rationale.

Full architecture sketch, naming options, and host-write rationale: [Live bidirectional auth sync — design rationale](/research/agents/authentication/live-auth-sync-design/).

## Out of scope

- SSH-key forwarding stays excluded. [Authentication](/guides/authentication/) documents why.
- Cross-host sync (different operator machines sharing one store). The daemon is per-operator-user, per-host.
- Distributed conflict resolution beyond last-writer-wins.
