title: "Alternative LLM Providers"

**Status**: Implemented through named accounts.

Provider selection is part of account management. Create a profile-folder, API-key, or supported OAuth-token account, then assign it to a workspace agent. First-start discovery imports available credentials from standard host locations. Additional folder accounts support isolated coding-agent profiles; API accounts carry provider identity, optional endpoint overrides, and model settings.

## Routing contract

Account compatibility is checked before launch. Claude uses selected-account Anthropic-compatible credentials and routing variables. Codex receives a private provider configuration with Responses API routing for supported account providers. OpenCode receives a provider configuration restricted to the selected account, with the endpoint, credential environment reference, and `provider/model` identifier resolved together. Folder accounts retain their copied configuration.

Credentials are transported separately from public capsule configuration and injected only into the assigned agent process. Ambient provider keys do not create additional account choices. The capsule has no provider picker or provider-override spawn frame.

Provider models belong to named accounts. An account model overrides the role's default agent model, and an explicit launch model overrides both. Role schema `v1alpha7` removes `[<agent>.providers]`; migration stops with remediation guidance when those tables remain.
