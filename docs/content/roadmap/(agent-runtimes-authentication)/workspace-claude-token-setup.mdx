**Status**: Open

**Current state**: named OAuth-token and profile accounts can register existing credentials and authorize workspaces. The former workspace `claude-token setup/rotate/revoke/doctor` orchestrator, console `G generate` action, and PTY minting flow were removed. Their account-based successor remains unimplemented; registration alone does not mint, validate, rotate, or revoke a token.

**Parent**: [Reliable Claude Authentication Strategy](/research/agents/authentication/claude-auth-strategy/)

## Current ownership

- [Claude OAuth-token accounts](/guides/authentication/agents/claude-code/#claude-oauth-token-account) — register an existing token or profile.
- [Workspace accounts](/commands/workspace/#workspace-account) — assign accounts and select agent bindings.
- [Account Credential Transport](/reference/capsule/token-orchestrator/) — selected account resolution and isolated credential delivery.

Named accounts replace the former `auth_forward = "oauth_token"` plus managed-env slot. Credentials are selected through the account registry and delivered only to the matching agent process. This replaces the storage/authorization model; it does not satisfy the removed orchestrator's minting and lifecycle outcomes.

## Remaining work

1. **Account-based token onboarding and lifecycle.** Implement OAuth minting, rotate/revoke/doctor, expiry visibility, and interactive storage selection for named Claude accounts. Preserve secret-free argv, explicit workspace authorization, validated storage writes, and failure atomicity before claiming parity with the historical orchestrator.
2. **1Password storage and validation.** Connect the existing secret-reference/picker primitives to this lifecycle, including existing-item writes and new-item creation; independently prove post-write validation and rollback behavior. Picker availability alone is insufficient.
3. **Pre-launch validity probe.** Surface invalid or expired selected credentials before Claude returns an API 401. [Auth health and operator visibility](/roadmap/auth-health-and-visibility/) owns the shared health contract; this item owns Claude integration.
4. **Apple Keychain backend.** Add a local OS-secret-store account source after the [Credential Source Pattern](/roadmap/credential-source-pattern/) contract is implemented.
5. **Bulk migration.** Define an explicit multi-workspace account assignment/onboarding workflow without silently converting old policy tables into credential grants.

## Completion gate

Prove the account-based lifecycle, storage validation, secret boundaries, failure atomicity, expiry presentation, and workspace/role authorization with focused acceptance evidence. Existing-account registration is not that proof.
