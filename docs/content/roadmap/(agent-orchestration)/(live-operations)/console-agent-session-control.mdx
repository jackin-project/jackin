**Status**: Partially implemented

**Current state**: instance discovery, console workspace tree-view (expandable instance rows, session pane, `N`/`X`/`T`/`P` instance-row actions with the `P` purge gated behind a confirmation modal), `hardline --shell`, in-container multiplexer primary session, secondary agent sessions via `hardline --new`, console `a`/`x` keybindings, and agent runtime status authority integration are shipped. The instance detail pane prefers live Capsule tab/pane snapshots with persisted-session fallback; Phase 4 still tracks durable session reconciliation and resource panel integration.

## Shipped facts

The workspace list is an expandable tree. Workspace rows with active containers show a running indicator; pressing `→` reveals instance child rows showing instance ID, role, agent, and status. Selecting an instance row opens a session pane using live Capsule tab/pane rows when a snapshot is available, with recorded multiplexer sessions as the fallback, with `Enter` (reconnect), `N` (new session with agent picker), `X` (shell), `T` (stop the running container, preserving local state), and `P` (eject + purge container resources AND local recovery state, gated by a confirmation modal) actions. `←` collapses the tree and returns to the workspace row. The workspace detail pane shows a compact running-instances badge when the tree is collapsed. These actions and the underlying `WorkspaceListAction` keymap live in <RepoFile path="crates/jackin-console/src/tui/keymap.rs" /> and <RepoFile path="crates/jackin-console/src/tui/screens/workspaces/update.rs" />.

CLI escape hatches are also in place: `jackin hardline <selector>` reconnects to the primary session, `--shell` opens a zsh shell without an agent slug, `--new` starts a secondary foreground agent session inside the same running instance, and `--inspect` prints manifest/Docker/mount state without attaching (`HardlineArgs` in <RepoFile path="crates/jackin/src/cli/role.rs" />).

The session substrate and CLI escape hatches are documented in [Container Supervisor and Session Model](/reference/getting-oriented/architecture/) (internals) and in the [`jackin hardline` command reference](/commands/hardline/). The console tree-view is documented in [`jackin console`](/commands/console/). The product-model rationale behind the tree-view/session-row shape is kept separately in [Console Agent Session Control: Product Model and Design Rationale](/research/product/operator-experience/console-agent-session-control-design/).

Per-session state indicators consume the [Agent Runtime Status](/roadmap/agent-runtime-status/) authority, which has shipped.

## Remaining work

1. **Durable session reconciliation.** Refresh loads both persisted manifest sessions and live Capsule snapshots through <RepoFile path="crates/jackin/src/console/services.rs" />. The instance detail renderer in <RepoFile path="crates/jackin-console/src/tui/screens/workspaces/view/list.rs" /> prefers live snapshot tabs and panes, including labels, account identity, agent, and status; it falls back to persisted session rows when no snapshot is available. This live presentation already exists. Reconciliation/writeback of live sessions into the manifest's `sessions` field remains unfinished; live snapshot rendering alone does not update that persisted record.
2. **Resource panel integration.** Per-instance CPU/RAM usage in the console requires the still-open [Console Resource Panel](/roadmap/console-resource-panel/) roadmap item.
