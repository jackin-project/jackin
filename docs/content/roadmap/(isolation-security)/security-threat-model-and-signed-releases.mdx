**Status**: Partially implemented

**Current state**: historical dev releases shipped signing artifacts, and the retired operator verifier passed against `jackin-dev-v0.1.13` on 2026-07-04. Jackin configures native Velnor preview and manual stable publication with signed receipts and exact-source capsule verification. Preview identity uses an immutable `preview-<full-source-sha>` tag bound to the signed receipt envelope; the version remains `<package-version>-preview.<main-commit-count>+<source-sha7>`. Stable behavior is unchanged. Live publication, Homebrew installation, and clean-cache download proof remain outstanding; see <RepoFile path="docs/integration/immutable-preview-publication.md">Preview publication and migration</RepoFile>.

## Problem

jackin❯ closed two credibility gaps with this work:

- **Undocumented security implementation.** Symlink rejection in <RepoFile path="crates/services/jackin-instance-agents/src/lib.rs">crates/services/jackin-instance-agents/src/lib.rs</RepoFile>, `shellfirm` and `tirith` in the construct image, and the YOLO-flag contract in <RepoFile path="docker/runtime/entrypoint.sh">docker/runtime/entrypoint.sh</RepoFile> were enforced in code but invisible to operators, role authors, and contributors who reason about the trust boundary.
- **Unsigned capsule binary.** `jackin-capsule` is downloaded into every container at runtime (<RepoFile path="crates/adapters/jackin-image/src/capsule_binary.rs">crates/adapters/jackin-image/src/capsule_binary.rs</RepoFile>) and was verified by SHA256 only — no signing, no SLSA provenance, no SBOM. A tampered artifact matching the expected SHA256 would go undetected.

## Shipped

The generated `binary-preview.yml` and `binary-release.yml` workflows separate unsigned payload builds, assembly, signing, and publication. Preview targets a per-source immutable prerelease after exact-commit main CI; stable starts through manual dispatch and creates immutable version releases. Workflow configuration is not proof that publication or installation has completed. The verification implementation and historical signed-release evidence remain available. Operator and contributor detail lives in canonical docs:

- **Security implementation** — threat model, the six `auth.rs` security functions, `shellfirm`/`tirith` rationale, and the YOLO-flag contract for all six launch branches → [/reference/security-implementation/](/reference/security-implementation/).
- **Release verification** — cosign keyless verification, SLSA provenance, SBOM inspection, and capsule-manifest auditing → [/getting-started/verifying-releases/](/getting-started/verifying-releases/).
- **Historical CI signing** — the former `release.yml` account in source snapshot `81a26f7e8511b2f19c9ba5a59a85b3ef0bbc804a` described cosign bundles, GitHub build attestations, CycloneDX SBOMs, and signed capsule manifests. Those records describe the historical workflow only.
- **Historical operator verification** — the retired `cargo xtask release-verify` gate checked the published `.sha256`, cosign bundle, GitHub attestation, and SBOM. It passed against `jackin-dev-v0.1.13` on 2026-07-04; that result does not validate current Velnor receipts.
- **Native capsule verification code** — <RepoFile path="crates/adapters/jackin-image/src/release_evidence.rs">release_evidence.rs</RepoFile> authenticates immutable-preview or immutable-stable receipts, the selected payload and companion, production Sigstore TUF trust, and exact-source provenance for the channel-specific workflow. Native channel and full-source build metadata authorize remote acquisition; ordinary local builds cannot acquire remote authority from version text. The preview tag and signed receipt envelope bind the same full source SHA. Publication identity is rechecked before execution and cache installation. Native caches cannot reuse local or other-source entries. A verifier implementation does not establish a successful live download; explicit local overrides, packaged capsules, and test fixtures do not prove the remote path.

## Remaining

- **Prove signed publication and promotion.** The current <RepoFile path=".velnor/config.toml">.velnor/config.toml</RepoFile> enables preview and stable release policies and preserves stable environment approval. Verify actual signed assets, attestations, SBOMs, and capsule manifests from the generated workflows. Complete the tap structural bootstrap, qualify repository credentials and exact-head review completion, then enable native PR promotion. Failed CI, invalid artifacts, and unaddressed feedback must block promotion. Do not hand-edit generated workflow YAML.

- **Clean-cache capsule download gate.** Historical evidence used `jackin-dev-v0.1.13` (2026-07-02). After a native release exists, run its prebuilt CLI from outside a Homebrew keg with a fresh private `JACKIN_HOME_DIR`, unset `JACKIN_CAPSULE_BIN`, and load a configured role with `jackin load agent-smith`. Retain the exact source/version, publication, verification, cache, and capsule-loading evidence. Running `cargo run` builds a local CLI without native release authority, and a Homebrew packaged capsule can bypass the download; neither proves remote verification. Do not remove an operator's existing cache to conduct this test.
- **Trust-root maintenance.** The verifier refreshes production Sigstore trust through TUF; monitor and test trust-root updates as part of the release verification maintenance.

This item retires once signed publication is enabled and proven, the capsule download path has been clean-cache verified end to end, and remaining verification residuals are either fixed or explicitly accepted.

## Non-goals

- No hostile multi-tenant safety claim from Docker hardening alone — that is [Docker runtime hardening contract](/roadmap/docker-runtime-hardening-contract/) scope.
- No microVM replacement — [smolvm backend research](/research/platform/isolation/smolvm-backend/) tracks that separately.
- No retroactive signing of historical releases — provenance starts from the first release produced by the native workflow.
