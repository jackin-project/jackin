The Roadmap answers **what jackin❯ intends to build next**. It contains only unfinished implementation intent: work already in progress, planned outcomes, and unscheduled ideas. Shipped behavior belongs in the normal guides, commands, and contributor references. Evidence and design rationale belong in [Research](/research/).

## Item contract

Every roadmap item starts with one exact status and a concise current-state boundary. Its body keeps implementation scope, remaining work, a completion gate, and links to related research or canonical docs. New items also state the intended outcome explicitly.

| Status | Meaning |
|---|---|
| `Partially implemented` | A usable baseline exists; named work remains |
| `Open` | Desired implementation outcome; no sufficient baseline yet |
| `Deferred` | Desired but intentionally blocked or postponed |
| `Exploring` | Brainstorm only; not designed or scheduled |

<Aside type="note">
When the last unfinished outcome ships, retire the roadmap item. Do not keep a completed archive here; canonical docs and Git history own shipped behavior and historical rationale.
</Aside>
