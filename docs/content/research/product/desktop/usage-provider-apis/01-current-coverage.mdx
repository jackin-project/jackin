## Summary

At the 2026-07-24 verification cutoff, probes covered seven providers through
one normalized limits pipeline, with provider-specific credential and quota
gaps documented below.

## Question and scope

For each provider probe in `crates/services/jackin-usage-provider-codex`, `crates/services/jackin-usage-provider-claude`, `crates/services/jackin-usage-provider-amp`, `crates/services/jackin-usage-provider-grok`, and `crates/services/jackin-usage-provider-zai`: (1) which HTTP endpoints/URLs it calls for usage/quota; (2) which credential source it uses (location/type only); (3) which fields and UI labels it produces; (4) confirm/refute two suspected gaps — (a) no run-out/projection phrases in jackin-usage, (b) no Amp workspace credit balance; (5) how data flows to display surfaces (HostUsageRuntime, usage_snapshot_store, jackin-usage-ffi DTOs).

This chapter informs jackin-desktop.

## Method

**Method:** codebase read
**Verification cutoff:** 2026-07-24

## Findings

### Q1 — Endpoints/URLs per probe

- **Codex (crates/services/jackin-usage-provider-codex/src/lib.rs)** — dual source, RPC preferred over OAuth HTTP (`codex_snapshot`, crates/services/jackin-usage-provider-codex/src/lib.rs):
  - CLI RPC: spawns `codex -s read-only -a untrusted app-server` (crates/services/jackin-usage-provider-codex/src/lib.rs); JSON-RPC methods `account/rateLimits/read` (crates/services/jackin-usage-provider-codex/src/lib.rs) and `account/read` (crates/services/jackin-usage-provider-codex/src/lib.rs). (confidence: HIGH)
  - OAuth HTTP: base URL from `$CODEX_HOME/config.toml` `chatgpt_base_url`, default `https://chatgpt.com/backend-api` (crates/services/jackin-usage-provider-codex/src/lib.rs); usage path `/wham/usage` (or `/api/codex/usage` for non-backend-api bases) via `resolve_codex_usage_url` (crates/services/jackin-usage-provider-codex/src/lib.rs); reset-credits at `{base}/wham/rate-limit-reset-credits` via `resolve_codex_reset_credits_url` (crates/services/jackin-usage-provider-codex/src/lib.rs). (confidence: HIGH)
  - Token refresh (401/403 retry only, never persisted back): POST `https://auth.openai.com/oauth/token` with public client id — `CODEX_OAUTH_TOKEN_URL` / `CODEX_OAUTH_CLIENT_ID` (crates/services/jackin-usage/src/usage.rs:1294-1295; refresh flow crates/services/jackin-usage-provider-codex/src/lib.rs). (confidence: HIGH)
- **Claude (crates/services/jackin-usage-provider-claude/src/lib.rs)** — Historical finding at the 2026-07-24 cutoff: GET `https://api.anthropic.com/api/oauth/usage` with `anthropic-beta: oauth-2025-04-20` and a `claude-code/<version>` User-Agent; that snapshot also described a `claude -p /usage` fallback. Current main-port candidate source, as of 2026-10-10, instead sends `User-Agent: jackin/<version>` (`crates/services/jackin-usage-provider-claude/src/spend.rs`) and has no CLI usage fallback. The route remains private and undocumented; this source change does not establish Anthropic support or live readiness.
- **Amp (crates/services/jackin-usage-provider-amp/src/lib.rs)** — POST `https://ampcode.com/api/internal?userDisplayBalanceInfo` with JSON body `{"method":"userDisplayBalanceInfo","params":{}}` (crates/services/jackin-usage-provider-amp/src/lib.rs). Fallback: CLI `amp --no-color usage` (crates/services/jackin-usage-provider-amp/src/lib.rs). (confidence: HIGH)
- **Grok (crates/services/jackin-usage-provider-grok/src/lib.rs)** — dual source (crates/services/jackin-usage-provider-grok/src/lib.rs):
  - CLI ACP RPC preferred: spawns `~/.grok/bin/grok agent stdio` (or `grok` on PATH) (crates/services/jackin-usage-provider-grok/src/lib.rs); JSON-RPC method `x.ai/billing` (crates/services/jackin-usage-provider-grok/src/lib.rs). (confidence: HIGH)
  - Web fallback: POST `https://grok.com/grok_api_v2.GrokBuildBilling/GetGrokCreditsConfig` as gRPC-web+proto with bearer token; response parsed by a hand-rolled protobuf scanner (crates/services/jackin-usage-provider-grok/src/lib.rs). (confidence: HIGH)
- **Z.AI (crates/services/jackin-usage-provider-zai/src/lib.rs)** — GET `{host}/api/monitor/usage/quota/limit`, default host `https://api.z.ai`; overridable via `ZAI_QUOTA_URL`/`Z_AI_QUOTA_URL` (full URL) or `ZAI_API_HOST`/`Z_AI_API_HOST` (crates/services/jackin-usage-provider-zai/src/lib.rs). (confidence: HIGH)
- **MiniMax (usage/minimax.rs)** — GET with four-URL fallback: `https://api.minimax.io/v1/token_plan/remains`, `https://api.minimax.io/v1/api/openplatform/coding_plan/remains`, then same two paths on `https://api.minimaxi.com` (usage/minimax.rs:391-394); overrides `MINIMAX_REMAINS_URL` / `MINIMAX_API_HOST` / `MINIMAX_HOST` (usage/minimax.rs:371-374). Sends header `MM-API-Source: jackin-capsule` (usage/minimax.rs:349). (confidence: HIGH)
- **Kimi (usage/kimi.rs)** — GET `https://api.kimi.com/coding/v1/usages` (usage/kimi.rs:258-267). (confidence: HIGH)

All bearer GETs route through the shared `get_json_bearer` helper (crates/services/jackin-usage/src/usage.rs:1451-1479). (confidence: HIGH)

Env `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN` are presence/origin only — never used for the fetch (crates/services/jackin-usage-provider-claude/src/lib.rs, comment 73-75). No keychain reader in the capsule (comment crates/services/jackin-usage-provider-claude/src/lib.rs). (confidence: HIGH)
- **Amp**: env `AMP_API_KEY` wins; else API key from `~/.local/share/amp/secrets.json` (`apiKey@*` keys), then handoff `/jackin/amp/secrets.json` (`container_paths::AMP_SECRETS`, crates/core/jackin-core/src/container_paths.rs:79) (crates/services/jackin-usage-provider-amp/src/lib.rs). (confidence: HIGH)
- **Grok**: OAuth bearer from `~/.grok/auth.json`, else handoff `/jackin/grok/auth.json` (`container_paths::GROK_AUTH`, crates/core/jackin-core/src/container_paths.rs:83) (crates/services/jackin-usage-provider-grok/src/lib.rs); token entries keyed by `https://auth.x.ai::` (OIDC) or legacy sign-in scopes, with expiry check (crates/services/jackin-usage-provider-grok/src/lib.rs). Env `XAI_API_KEY` / `GROK_DEPLOYMENT_KEY` are presence/origin only (crates/services/jackin-usage-provider-grok/src/lib.rs). (confidence: HIGH)

- **MiniMax**: env `MINIMAX_CODING_API_KEY`, else injected `provider_keys`, else env `MINIMAX_API_KEY` (crates/services/jackin-usage/src/usage.rs:918-926). No file source. (confidence: HIGH)
- **Kimi**: env `KIMI_AUTH_TOKEN`/`kimi_auth_token`, else local OAuth token file `~/.kimi-code/credentials/kimi-code.json` or `~/.kimi/credentials/kimi-code.json` (expiry-checked `access_token`), else same file under handoff home `/jackin/kimi-code` (`container_paths::KIMI_CODE_DIR`, crates/core/jackin-core/src/container_paths.rs:38), else injected `provider_keys`, else env `KIMI_CODE_API_KEY` (crates/services/jackin-usage/src/usage.rs:909-916; usage/kimi.rs:269-297). (confidence: HIGH)
- The host credential matrix (docs/debug, no secret reads) mirrors this at crates/services/jackin-usage/src/host.rs:1035-1087. (confidence: HIGH)

### Q3 — Extracted fields and UI labels

- **Codex**: primary/secondary rate-limit windows (`used_percent`, `resets_at`, window duration) → buckets "Session" (StatusSlot::Session) and "Weekly" (StatusSlot::Weekly) (crates/services/jackin-usage-provider-codex/src/lib.rs); per-limit-id extra limits (everything except limit id `codex`) → "`<label>` 5-hour" / "`<label>` Weekly" detail rows — the Codex-Spark entry yields "Codex Spark 5-hour"/"Codex Spark Weekly" (crates/services/jackin-usage-provider-codex/src/lib.rs; fallback placeholders 163-204); "Limit Reset Credits" bucket with "N manual resets available · Next expires …" detail (crates/services/jackin-usage-provider-codex/src/lib.rs); "Credits" bucket with balance/unlimited (crates/services/jackin-usage-provider-codex/src/lib.rs); plan label mapped following CodexBar — `pro` → "Pro 20x", pro-lite variants → "Pro 5x" (crates/services/jackin-usage-provider-codex/src/lib.rs); account label from RPC email or JWT email (crates/services/jackin-usage-provider-codex/src/lib.rs). (confidence: HIGH)
- **Claude**: the 2026-07-24 matrix recorded `limits[]` and legacy named-window parsing, placeholder buckets, spend bounds, and plan labels. Current main-port source retains the API parsing path but removes the CLI `claude -p /usage` parser/fallback described by that earlier snapshot. Treat the older CLI behavior as historical, not current coverage.
- **Amp**: `free_remaining`/`free_limit`/`hourly_replenishment`/`individual_credits` (+account email) (crates/services/jackin-usage-provider-amp/src/lib.rs) → buckets "Amp Free" (currency used/limit, remaining %, replenishment-derived "Resets in …" label) and "Individual credits" (crates/services/jackin-usage-provider-amp/src/lib.rs); plan label fixed "Amp Free" when data present (crates/services/jackin-usage-provider-amp/src/lib.rs); CLI fallback parses "Signed in as", "Amp Free:", "Individual credits:" lines (crates/services/jackin-usage-provider-amp/src/lib.rs). (confidence: HIGH)
- **Grok**: RPC billing — `monthlyLimit`, `onDemandCap`, `on_demand_enabled`, usage `includedUsed`/`onDemandUsed`/`totalUsed` (cents), billing cycle start/end (crates/services/jackin-usage-provider-grok/src/lib.rs) → headline bucket labeled "Weekly"/"Monthly"/"Credits" by cycle length (Weekly slot; Grok has no session window), plus "Included usage" and "On-demand usage" detail rows (crates/services/jackin-usage-provider-grok/src/lib.rs); web fallback extracts only `used_percent` + reset epoch from protobuf (crates/services/jackin-usage-provider-grok/src/lib.rs); plan label `auth_mode` oidc → "SuperGrok" (crates/services/jackin-usage-provider-grok/src/lib.rs); account from email/user_id/team_id keys (crates/services/jackin-usage-provider-grok/src/lib.rs). (confidence: HIGH)
- **Z.AI**: `limits[]` with `type` TOKENS_LIMIT/TIME_LIMIT, unit/number windows, usage/currentValue/remaining/percentage, `nextResetTime` (ms) (crates/services/jackin-usage-provider-zai/src/lib.rs) → buckets "5-hour" (Session slot, shortest token window), "Tokens" (Weekly slot, longest), "MCP" (time limit, count detail line) (crates/services/jackin-usage-provider-zai/src/lib.rs); plan label from `planName`/aliases (crates/services/jackin-usage-provider-zai/src/lib.rs). (confidence: HIGH)
- **MiniMax**: per-model `model_remains[]` interval + weekly counts/percents/status/end-times (usage/minimax.rs:116-144) → buckets "General · 5h" (Session slot) and "General · Weekly" (Weekly slot) for the `general` model; other models render as `"<Model>"` / `"<Model> · Weekly"` detail rows (usage/minimax.rs:166-199, 283-316); "Usage: X / Y" count detail (usage/minimax.rs:318-333); plan label from subscribe/plan/combo titles (usage/minimax.rs:201-217). (confidence: HIGH)
- **Kimi**: `usage`/`usages[]` (scope FEATURE_CODING preferred) detail limit/used/remaining/resetTime + `limits[]` rate windows (usage/kimi.rs:88-125) → buckets "Rate Limit" (Session slot, window-paced) and "Weekly" (Weekly slot) (usage/kimi.rs:127-160); fallback placeholders "Weekly" and "5-hour rate limit" (usage/kimi.rs:29-52); no plan label (usage/kimi.rs:60). (confidence: HIGH)
- Pace vocabulary (where emitted): "On pace" / "N% in reserve" / "N% in deficit" (`quota_pace_label`, crates/services/jackin-usage-provider-core/src/format/labels.rs) — reserve/deficit against elapsed window, not a run-out projection. Grok buckets pass `None` for pace on both web and RPC branches (crates/services/jackin-usage-provider-grok/src/lib.rs — verified 2026-07-24), even though the RPC path has period bounds. (confidence: HIGH)

### Q4 — Confirmed gaps

- **(a) No run-out/projection phrases — CONFIRMED.** Method: `grep -rniE "runs out|projected empty|lasts until|run-out|projection"` over `crates/services/jackin-usage` and `crates/adapters/jackin-usage-ffi` returned zero matches. The only forward-time strings produced are reset countdowns ("Resets in …", crates/services/jackin-usage-provider-amp/src/lib.rs; `compact_duration_label` crates/services/jackin-usage-provider-core/src/format/labels.rs), expiry labels (crates/services/jackin-usage-provider-core/src/format/labels.rs), and the pace reserve/deficit tokens (crates/services/jackin-usage-provider-core/src/format/labels.rs). (confidence: HIGH)
  - Adjacent signal outside the crate: the Swift Desktop shell *can split* a pace label of the form "On pace · Runs out in 4d 21h" (native/Sources/JackinDesktop/UsageWindow/ProviderCardView.swift:209 comment cites CodexBar's dual-column pace; tests native/Tests/JackinUsageBridgeTests/ArchitectureTests.swift:368-369 and native/Tools/StatusItemChipHarness/main.swift:396-397 use that exact fixture), but no Rust producer emits such a phrase — the display splitter is fed only the vocabulary above. (confidence: HIGH)
- **(b) No Amp workspace credit balance — CONFIRMED.** `AmpApiUsage.individual_credits` (crates/services/jackin-usage-provider-amp/src/lib.rs) is the only credit-balance field; the JSON parse looks for `individualCredits`/`individualBalance` only (crates/services/jackin-usage-provider-amp/src/lib.rs), the CLI parse only for the "Individual credits:" line (crates/services/jackin-usage-provider-amp/src/lib.rs). Method: `grep -n "workspace"` in crates/services/jackin-usage-provider-amp/src/lib.rs → zero matches; no team/workspace key is requested or parsed, and the request asks only `userDisplayBalanceInfo` (crates/services/jackin-usage-provider-amp/src/lib.rs). (confidence: HIGH)

### Q5 — Data flow to display surfaces

- **Probe dispatch**: `build_snapshot` selects the per-surface probe and resolves keys (crates/services/jackin-usage/src/usage.rs:887-931); each probe returns a `FocusedUsageView` via the shared `usage_view` builder.
- **Cache + persistence (capsule and host share one path)**: `UsageCache::refresh_active_account_snapshots` (crates/services/jackin-usage/src/usage.rs:434) runs due probes, then persists all refreshed views with `usage_snapshot_store::store_usage_snapshots` (crates/services/jackin-usage/src/usage.rs:536-538) and materializes accounts JSON (crates/services/jackin-usage/src/usage.rs:543-545, 630-634). Readers call `UsageCache::focused_snapshot` (crates/services/jackin-usage/src/usage.rs:394).
- **Durable store**: `store_usage_snapshots` flattens each view into per-bucket `StoredAccountUsageSnapshot` rows (crates/services/jackin-usage-snapshot-store/src/write.rs). Capsule store lives under `/jackin/state/` (module header, crates/services/jackin-usage-snapshot-store/src/lib.rs); host store at `<data_dir>/usage-menu-bar/snapshots.db` (crates/services/jackin-usage/src/host.rs:31, 233-235).
- **HostUsageRuntime** (crates/services/jackin-usage/src/host.rs:274-290): `open` wires the store/accounts paths into the cache (host.rs:312-320); `refresh` drives `cache.refresh_active_account_snapshots` under a ≥60s floor (host.rs:425-465); `snapshot` returns the live focused view or a selected durable account view (host.rs:493-515); `overview_rows` builds Desktop popover/Usage-window rows (percent headline, reset countdown + exact clock, status word, worst severity) (host.rs:783-831); compact menu-bar labels pick the min-remaining bucket (host.rs:682-761, 988-1003). Provider keys for Z.AI/MiniMax/Kimi are injected credential-free via `set_provider_key` (host.rs:393-399).
- **FFI layer** (crates/adapters/jackin-usage-ffi): `bridge.rs` wraps `HostUsageRuntime` with a coarse sync API — `snapshot` maps through `view_dto` (crates/adapters/jackin-usage-ffi/src/bridge.rs:95-100), `overview_rows` through `overview_row_dto` (bridge.rs:190-194). DTOs mirror the protocol views 1:1: `UsageViewDto` (crates/adapters/jackin-usage-ffi/src/dto.rs:62-80), `QuotaBucketDto` incl. `used_money`/`limit_money` Money mirrors and `status_slot` session/weekly/spend strings (dto.rs:44-58, 234-261), `OverviewRowDto` (dto.rs:93-101), `AccountDescriptorDto` (dto.rs:105-113). (all confidence: HIGH)
- **Settled-ground note (location only, not evaluated)**: monetary data in the pipeline is exclusively provider-supplied caps/balances (Claude "Extra usage" + dollar-budget windows, Grok billing cents, Amp dollars, Codex credits). A static USD-per-1M-token pricing table and per-session cost estimation exist in `crates/services/jackin-usage-token-monitor/src/pricing.rs` and `crates/services/jackin-usage-token-monitor/src/discover.rs` (token-monitor internals, not part of the seven probes above). (confidence: HIGH)

### Current provider gaps and confirmations

- **Grok current config fields dropped**: official `x.ai/billing` carries
  `config.prepaidBalance`, `onDemandCap`, and `onDemandUsed`; jackin❯
  obsolete top-level decoder misses them. Extra Usage Credits and on-demand
  cap/used are quota bounds; `history`/`productUsage` remain excluded.
  (confidence: HIGH)
- **MiniMax documented host absent**: jackin❯ URL fan-out covers only `api.minimax.io` / `api.minimaxi.com` (usage/minimax.rs:391-394); the officially documented host `www.minimax.io` (chapter 06) is not probed. (confidence: HIGH)
- **Codex OAuth client-id parity OK**: jackin❯ `CODEX_OAUTH_CLIENT_ID = app_EMoamEEZ73f0CkXaXp7hrann` (crates/services/jackin-usage/src/usage.rs:1295) matches the official CLI's client id (chapter 02). No stale-constant risk. (confidence: HIGH)

### Dead ends and contradictions

- The Capsule-side Claude provider probe has no macOS Keychain reader; its source comments describe file-based credentials (crates/services/jackin-usage-provider-claude/src/lib.rs). The separate main-port monitor bootstrap is host-only and attended; it does not change the Capsule probe's credential path.
- Claude env keys (`ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN`) are not used to fetch usage; presence/origin only (crates/services/jackin-usage-provider-claude/src/lib.rs). Same for Codex `OPENAI_API_KEY` env and Grok `XAI_API_KEY`/`GROK_DEPLOYMENT_KEY` env (crates/services/jackin-usage-provider-codex/src/lib.rs; crates/services/jackin-usage-provider-grok/src/lib.rs).
- Telemetry route-template vs actual URL mismatch for Codex reset credits: the telemetry label says `/backend-api/wham/usage/reset_credits` (crates/services/jackin-usage-provider-codex/src/lib.rs) while the real request path is `{base}/wham/rate-limit-reset-credits` (crates/services/jackin-usage-provider-codex/src/lib.rs). Label-only discrepancy; the HTTP call uses the latter.
- Credential-origin label vs actual source for MiniMax/Z.AI: MiniMax always reports "API token · env MINIMAX_API_KEY" (usage/minimax.rs:49-56) and Z.AI "API token · env ZAI_API_KEY" (crates/services/jackin-usage-provider-zai/src/lib.rs) even when the key came from `MINIMAX_CODING_API_KEY`, `Z_AI_API_KEY`, or the injected `provider_keys` map (crates/services/jackin-usage/src/usage.rs:901-926). Cosmetic origin inaccuracy, not a data-flow issue.
- Codex RPC reset credits carry only `availableCount` (crates/services/jackin-usage-provider-codex/src/lib.rs); expiry detail ("Next expires …") is available only on the OAuth HTTP path (crates/services/jackin-usage-provider-codex/src/lib.rs) — the two sources are not equivalent for that bucket.
- No embedded instructions were encountered in any file read; comments referencing CodexBar/OpenUsage are provenance notes, not directives.


## Implications for jackin❯

Keep one normalized limits pipeline, but correct provider-specific credential, freshness, reset-credit, and account-balance gaps before Desktop treats every probe as equivalent.

## Limitations and unknowns

- Whether the Amp `userDisplayBalanceInfo` endpoint *could* return a workspace/team balance field that the parser silently drops (the parser whitelists keys, so any such field would be ignored) — determining this requires observing a live response from a workspace-attached Amp account, not the codebase. (LOW lead)
- Whether `seven_day_oauth_apps` (explicitly ignored, crates/services/jackin-usage-provider-claude/src/lib.rs) carries limit data that would matter for Desktop; code states it is not a CodexBar quota window, but its live payload shape was not verified here. (LOW lead)
- The Grok web-billing protobuf field mapping (path `[.., 1]` fixed32 = used percent, epoch varints = reset) is heuristic by construction (crates/services/jackin-usage-provider-grok/src/lib.rs); which proto schema it actually corresponds to is unverified against any xAI IDL. (MED — code read is primary, wire schema is not)
- OpenCode has a probe surface (`opencode_snapshot`, crates/services/jackin-usage/src/usage.rs:928) outside this chapter's seven-file scope; its endpoint/credential story is not covered here.
