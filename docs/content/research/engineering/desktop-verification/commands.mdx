## Findings

### Crates tests
- Current generated Rust CI invokes each package separately:
  `mbx nextest run --profile ci --locked --offline --manifest-path crates/services/jackin-usage/Cargo.toml --package jackin-usage --no-tests fail`
  and the corresponding `jackin-usage-ffi` invocation —
  <RepoFile path=".github/workflows/ci.yml" /> (confidence: HIGH).
- Local desktop testing runs
  `mise exec -- mbx +1.97.1 nextest run -p jackin-usage -p jackin-usage-ffi --lib` through
  <RepoFile path="crates/tools/jackin-xtask/src/desktop.rs" />. The July 24 catalog's
  combined `--locked` command came from retired PR CI; it is not today's
  generated invocation (confidence: HIGH).
- General runner and filters: `mise exec -- mbx +1.97.1 nextest run`, `-E 'test(name)'`,
  `--all-features` — <RepoFile path="TESTING.md" /> (confidence: HIGH).

### Bindings drift gate
- `mise exec -- mbx +1.97.1 xtask desktop bindings-check`
  — local `mise -C native run ci` cadence in <RepoFile path="native/mise.toml" />;
  the former desktop-merge workflow was retired. <RepoFile path="mise.toml" /> pins `cargo:boltffi_cli` at `0.30.1`
  to provide `boltffi`; no current hosted bindings gate executes it
  (confidence: HIGH)

### App build / verify / run
- `mise exec -- mbx +1.97.1 xtask desktop build --version "$JACKIN_APP_VERSION" --build "$JACKIN_APP_BUILD"`
  → `native/dist/JackinDesktop.app`; `mise exec -- mbx +1.97.1 xtask desktop verify

- The local `merge` cadence also exercises the built app via UI tests
  (`native/Scripts/run-ui-tests.sh`, after `mise -C native run ci`)
  (confidence: HIGH)

### Swift tests
- `mise exec -- mbx +1.97.1 xtask desktop test` (direct command)
  requires macOS, runs the two Rust library suites, then five pure Swift
  harnesses. Counted SwiftPM tests use `mise exec -- mbx +1.97.1 xtask desktop test-swift` —
  <RepoFile path="crates/tools/jackin-xtask/src/desktop.rs" /> (confidence: HIGH).
- **Snapshot runner stability:** The July 24 catalog recorded macOS 26 GA
  under explicit `macos-26` labels and a June 2026 transition schedule for
  the moving `macos-latest` alias. That is historical runner evidence; confirm
  runner availability before adding a hosted native lane.
  Native system-font/SF-Symbol golden tests must use explicit `macos-26`,
  freeze Dynamic Type/accessibility/animation inputs, and keep tolerant
  pixel comparison; otherwise the runner major can change without a source
  diff. —
  https://github.com/actions/runner-images#available-images
  (confidence: HIGH)

### Workspace lint/fmt gates

  `mbx clippy --locked --offline --manifest-path <manifest> --package <package> --all-targets -- -D warnings`
  — <RepoFile path=".github/workflows/ci.yml" /> (confidence: HIGH).
- Local formatting is `mise exec -- mbx +1.97.1 fmt --check`; local lint and
  merge-readiness entry points are documented in
  <RepoFile path="CONTRIBUTING.md" />. These local commands do not establish
  hosted desktop coverage (confidence: HIGH).

### Release verification
- `mise exec -- mbx +1.97.1 xtask desktop sign-notarize` (`mise -C native run sign-notarize`),
  `--release` verification requires Developer ID + notarization/staple/Gatekeeper —
  <RepoFile path="native/README.md" /> and <RepoFile path="mise.toml" />.
  The historical release catalog attributed publication and archive naming to the former
  release workflow. That workflow is absent; current Rust CI does not publish
  or sign desktop releases (confidence: HIGH for local source contracts).
