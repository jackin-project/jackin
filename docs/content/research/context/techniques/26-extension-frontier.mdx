Source cutoff: **2026-10-24T01:15:00Z**. This refresh preserves **V1–V8**, reconciles current native/provider behavior, and withdraws unsupported savings, portability and quota-weight forecasts.

## Summary

The remaining frontier includes useful integration projects, but “buildable” does not mean quality neutral, authorized to activate, or proven economical. Quota observation can be noisy, image substitution can lose information, warming costs money, and an asynchronous judge can detect a failure only after it happens.

Keep the selected model and effort fixed in the primary experiment. Scheduling, media representation and native cache policy can be tested under that constraint; cross-model vision/routing and changed effort belong in explicitly separate arms. Compare against existing native features before claiming a new benefit.

## Question and method

Each proposal identifies the gap, eligible surface, economic denominator, failure modes and smallest decisive experiment. Current official contracts are in [provider features](/research/context/techniques/12-provider-features/), [quota economics](/research/context/techniques/19-subscription-and-quota-economics/) and the [host matrix](/research/context/techniques/23-cross-agent-portability/). No account probing, paid inference, warm request, OCR pipeline or deployed policy compiler ran here.

## V1. Quota-window scheduler

**Mechanism:** defer already authorized discretionary work until the applicable account window or resource limit permits it. Use current plan, connection mode, reset information and fresh observations. [Claude plan guidance](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan) and [Codex pricing](https://learn.chatgpt.com/docs/pricing) describe different structures; Codex Pro currently has no five-hour limit. A model-specific allowance does not imply that routing away from it preserves every shared limit.

**Economics:** measure accepted tasks completed before a deadline, utilization, time spent waiting and paid spill. Delaying work does not create more allowance and can make source state stale. Flat subscription price does not erase opportunity cost or purchased-credit expense.

**Decisive test:** matched authorized tasks/windows with other account activity recorded, scheduling latency and deadline failures included. Preserve model/effort, auth and spend limits. Do not switch accounts, enable overage or use linked monthly API credits merely because the queue hits a cap; those are distinct user choices and billing routes. No fixed quota-weight formula is assumed.

## V2. Per-account quota observation and calibration

**Mechanism:** compare supported native usage snapshots or authorized exports with scoped task usage. A local statistical model may help predict an account's next observed utilization change. The older proposal to transparently proxy subscription traffic and infer a universal denominator from undocumented headers is not a supported default.

**Identifiability matters:** rolling-window expirations, background sessions, dashboard quantization, delayed updates, varying task/model weights and correlated token classes can produce several equally plausible fits. A stale usage bar is not a request receipt. A good fit to one window does not identify a stable provider formula.

**Decisive test:** before fitting, establish fresh observations and which other activity shares the balance. Use multiple windows and held-out tasks, report uncertainty and detect policy drift. If classes cannot be separated, report observed utilization per accepted task rather than invented coefficients. Do not synthesize paid probing traffic without authorization. Native usage visibility is useful even when the denominator remains unknown; V1 need not wait for an unidentifiable model. [Quota measurement](/research/context/techniques/19-subscription-and-quota-economics/).

## V3. Vision representation and optional vision-model routing

**Mechanism:** first compare native image handling with supported resolution/detail choices on the **same selected model**. Cropping, multiple crops, downsampling or a derived text description each changes the evidence. A separate vision model adds a second model, summarization and recovery; it must be declared as a routing arm.

The [current media contracts](/research/context/techniques/20-multimodal-token-economics/) depend on model, dimensions, detail settings, resizing and endpoint. Old family-wide caps do not establish that every screenshot costs the cap. A 67% cap difference is not a measured 67% task saving or quota change. Small labels, selection state, alignment, overlays and coordinates may carry the answer.

**Decisive test:** fixed screenshots with exact text, spatial questions and UI action targets, followed by complete tasks. Record native image tokens, any text summary/output, schema/instruction overhead, rereads and missed details. Retain the original and correctly map crop coordinates. An active pre-tool hook must not duplicate screenshot capture or silently replace a tool result on a host without that contract.

## V4. Screenshot/PDF-to-text extraction at ingestion

**Mechanism:** use a trusted available text layer or accessibility representation when it contains the needed evidence; use OCR as a fallible extraction process. Born-digital PDF text can still lose columns, reading order, equations, font meaning or embedded figures. Screenshots can reveal state absent from an accessibility tree. Text extracted from source code is not proof of the rendered UI.

[Claude PDF support](https://platform.claude.com/docs/en/build-with-claude/pdf-support) and [vision guidance](https://platform.claude.com/docs/en/build-with-claude/vision) describe distinct input paths. Text can be cheaper in some documents and larger in others after extraction/markup. The earlier 50–85% and 25-page ratios were not reproduced and are not a new forecast.

**Decisive test:** exact text/identifier checks, table and layout questions, provenance back to page/region and requested visual evidence. Retain accessible originals and expose an explicit fallback. Count OCR runtime, dependencies, models, error handling and additional model calls. Do not remove the image/PDF from an exact-layout task merely because the extracted string is shorter.

## V5. Time-value speed policy

**Mechanism:** a user-selected profile may buy lower latency on a supported unchanged model/effort when reduced waiting is worth the premium. Record the actual billing route: API pricing, purchased credits and included-limit multipliers differ. Fast mode on an unsupported model can switch models, so that path is ineligible for the fixed-model arm.

Use <code>value_of_avoided_critical_path_wait &gt; additional_total_cost</code>. Whole-task time includes tools, queues, verification and retries. Response-generation speed is only one component. Autonomous jobs can have deadlines or expensive infrastructure occupancy; an attached human is not proof that every saved second is productive time.

Current [Claude Code caching](https://code.claude.com/docs/en/prompt-caching) documents a persistent header after first fast enablement: the first relevant request misses, while later toggles/fallback retain that header. The old “every toggle rebills the prefix” rule is withdrawn.

**Decisive test:** randomized same-model speed arms with the user's explicit latency/cost preference, whole-task p50/p95 and paid/included usage. Keep the standard path available and do not automatically enable paid overage. No speed change was made here. [Latency economics](/research/context/techniques/21-latency-and-time-economics/).

## V6. Cached repository core and staggered starts

**Mechanism:** a bounded, relevant and revisioned repository core may be loaded once and reused as an eligible common prefix. [CAG v2](https://arxiv.org/abs/2412.15605v2) studies preloading manageable knowledge collections and reusing state. It does not establish that preloading a changing codebase beats precise native retrieval.

[Provider cache scope](/research/context/techniques/22-fleet-and-multitenant-cache/) remains binding. Separate Claude API workspaces do not share entries. Do not merge tenants, credentials or histories to manufacture reuse. Model identity, tool/schema order, current instructions and permitted content must match. Moving dynamic system data to a user message changes authority. Stable context must be true, not merely byte-identical.

Read prices and minimums are model-specific. Waiting for one useful pioneer or issuing a paid prewarm can reduce repeated writes under particular conditions; current Claude Workflow already staggers same-prefix fan-outs. The idealized one-write-plus-reads arithmetic is a prefix-only scenario, not a tenfold task or cold-start result.

**Decisive test:** native retrieval versus curated core, with and without explicit warming, at cold/warm and realistic idle/concurrent conditions. Include irrelevant core carry, indexing/retrieval, schema and output, stale revisions, unused warms and actual cache receipts. Invalidate on relevant source/policy changes and preserve exact current-read fallback. Versioned cache state must never make an old revision appear current.

## V7. Online monitoring with bounded rollback

**Mechanism:** monitor a previously qualified compression lane for omitted constraints, diagnostics, wrong references and recovery failure, then stop or revert the affected treatment. Deterministic checks can reject some outputs before exposure; sampled asynchronous review mainly detects later drift.

An LLM judge can miss errors, share model biases and fail to observe an omitted fact without the original. Sampling never guarantees every dangerous output was checked, and later rollback cannot undo an earlier edit or external action. The old claim that a 1–10% sampled guard removes standing caveat risk is withdrawn.

**Decisive test:** calibrated seeded failures, false-positive/negative rates, detection delay, rollback scope and known-critical-failure handling. Use raw/provenance-bound evidence within the right permissions; account for judge and adjudication costs, retries and exposure before detection. Preserve selected model/effort unless a separate judge treatment is explicitly configured. Do not promote an unqualified aggressive lane because it has a monitoring dashboard. [Governance and online quality](/research/context/techniques/25-meta-cost-governance-and-online-quality/).

## V8. Cross-host portable policy compiler

**Mechanism:** resolve a declarative policy against exact native host/version capabilities, emit a reviewable configuration, and show effective settings and unsupported requests. Separate intent such as “retain exact recovery” from mechanisms such as one host's output hook or a provider beta.

The current [twelve-host matrix](/research/context/techniques/23-cross-agent-portability/) documents different replacement, promise/error and provider boundaries. Model/effort names, output caps, tool discovery, TTLs and instruction authority do not translate automatically. Jackin's registry is not identical to launch dispatch. A generated config file alone is not activation evidence.

**Decisive test:** resolve defaults, validate schema and permission behavior, inspect actual model-visible output, exercise failure/timeout/cancel/resume and verify disabling restores native behavior. Unsupported optional transforms should leave the native path intact with a visible reason; missing required security/authorization controls should block activation. Never fall back to another model, billing route or broad proxy silently.

No per-lever saving is added for configuration translation. Its value is measured avoided integration work, reduced drift and qualified behavior. Ongoing adapter maintenance belongs in the economics; “60–80% portable” and “neutral configuration change” are retired.

## Composition and next decisions

| Phase | Eligible next step | Evidence before widening |
|---|---|---|
| Observe | Native usage/context/capability inventory and explicit unknowns | Fresh account observations only when authorized; no inferred quota prices |
| Small local experiment | Exact templates, bounded extraction, versioned source pointers | Fidelity, permission and recovery fixtures |
| Native-policy experiment | Supported cache, scheduling or same-model speed profile | Real cold/warm receipts and accepted-task/latency outcomes |
| Runtime experiment | One retrieval/reducer implementation at an owned seam | Canonical critical-failure, quality, cost and latency gates |
| Separate policy research | Model routing, training, semantic vision summaries | Explicit treatment identity and full escalation/recovery cost |
