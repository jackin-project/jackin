**Research state:** Current

## Summary

The market now spans deterministic filters, request proxies, symbol retrieval, persistent memory, formats, cache management and complete agent workflows. The earlier description of a market confined to visible prose and memory is withdrawn. The useful decision is which **component and execution boundary** can improve accepted work while preserving the selected model, effort and permissions.

For jackin❯, the narrow reuse shortlist is `mq-markdown` for document parsing, selected `sem-core` APIs for semantic context, and `fff-search` for resident search when indexing pays for itself. Published archives and their source identities were inspected; these are **candidates for qualification**, not integrated or proven savings. Whole plugins, gateways and licensed applications require separate decisions.

## Question, cutoff and method

This chapter covers the six core products, all twelve historical adjacent candidates, and the earlier Cavemem, Cavekit, Claude-mem, Aider, LLMLingua, LiteLLM, TOON and ccusage leads. Boost is an additional current competitor. The snapshot cutoff is **2026-10-24 01:15 UTC**. Release/tag identities are frozen to that cutoff; retrieval times, default-branch heads, package checksums and later rechecks are separate fields in the [source register](#evidence-register).

The coordinator inspected pinned manifests, licenses and selected runtime files for the twelve adjacent repositories. This workstream reopened the relevant contracts, resolved the additional release tags, inspected their source, and downloaded four small published Rust archives into memory to verify checksums and delivered manifest/API files. It did not install these applications, execute their model benchmarks, or establish host interception. An upstream test file or README guarantee is source evidence until its execution is recorded.

The comparison unit is **all-attempt cost per accepted task**, with quality, retries, recovery, latency and resource use reported alongside it. A tokenizer proxy, compressed-file size, vendor lookup benchmark, inferred API-equivalent cost and actual provider receipt remain different measurements. The [validation protocol](/research/context/techniques/16-validation-harness/) defines the acceptance gates.

## Mechanism map and native baseline

| Layer | Current prior art | What the experiment must isolate |
|---|---|---|
| Generated answers | Native concise styles; Caveman and Ponytail instructions; structured output | Completeness, hidden reasoning, formatting failures and repair; a shorter final answer is only one part of the bill. |
| Tool-result representation | RTK, Caveman engine, LeanCTX, Headroom, Lemon, Boost, Context Mode | Actual model-visible replacement, stderr/status preservation, exact recovery and future re-reads. |
| Repository navigation | fff, sem, mq, jCodeMunch, Serena, CodeDB, Aider, Claude Context, Repomix | Search quality, indexing cost, stale state, tool-schema overhead and extra calls. |
| Memory and long sessions | Cavemem, Claude-mem, Entroly; native compaction and memory controls | Storage is not model exposure; charge capture, selection, summaries, injection and invalidation. |
| Request proxies | Paritok, pxpipe, Headroom, Caveman; LiteLLM infrastructure | Authentication, cache envelopes, signed/history blocks, streaming, model routing and upstream usage. |
| Observability and serving | ccusage; provider ledgers; self-hosted KV systems | Measurement itself does not save tokens; hosted billing and accelerator memory are different resources. |

The six core products have dedicated, independently reviewed dossiers: [Caveman](/research/context/tools/01-caveman-design/), [RTK](/research/context/tools/03-rtk-design/), [Headroom](/research/context/tools/02-headroom-design/), [LeanCTX](/research/context/tools/04-leanctx-design/), [Ponytail](/research/context/tools/09-ponytail-design/) and [Lemon](/research/context/tools/10-lemoncrow-design/). A product name does not identify its treatment: a style skill, deterministic filter, shell wrapper, MCP server and provider proxy can have different defaults and licenses inside one distribution.

Before adding a component, compare it with the **current native capability for the same host and model**:

| Native control | Earlier record retained | Current decision |
|---|---|---|
| Prompt caching and TTL | 05 | Preserve stable eligible prefixes; account separately for uncached input, writes by lifetime and reads. There is no universal 0.1× read or write multiplier. See [cache economics](/research/context/techniques/07-caching-exploitation/) and [provider contracts](/research/context/techniques/12-provider-features/). |
| Clear, compaction and context editing | 06, 12 | Use the actual host/API contract and retain task state. Resets, summaries and edits can change both quality and cache reuse; a historical compaction threshold is not a portable constant. See [context architecture](/research/context/techniques/06-context-architecture/). |
| Instructions, scoped rules and skills | 07, 21 | Remove measured duplication only after rule-sensitive checks. Count loading/discovery and repeated cache rent; do not remove a requirement merely to shorten a file. |
| Tool discovery and programmatic execution | 10, 11 | Compare with native deferred schemas and selective tool results already enabled. A proxy cannot claim savings against a fully expanded tool fleet if that fleet is absent from the real baseline. |
| Model and effort controls | 08, 09 | Hold both fixed in the main treatment. Routing and effort changes are separate experiments with escalation, retries and cache resets charged. |
| Batch and multi-agent execution | 13 | Batch has a different latency contract; teams have duplicated context and coordination costs. Neither a blanket team multiplier nor a cheaper-model substitution proves a compression gain. |
| Native output styles, structured output and multimodal controls | 01, 14, 20 | Compare with [native brevity](/research/context/techniques/04-style-and-language-compression/), [typed formats](/research/context/techniques/05-tokenizer-arbitrage/) and [image/PDF accounting](/research/context/techniques/20-multimodal-token-economics/) before adding learned or image-based compression. |

Current Claude and Codex hook contracts support different kinds of result replacement. MCP availability alone does not establish replacement, and an observer running asynchronously cannot retroactively remove a result. Jackin has twelve registry/adapters but only six entrypoint dispatch cases at the pinned baseline. Use the [host matrix](/research/context/techniques/23-cross-agent-portability/) before claiming automatic operation.

## Implications for jackin❯

Build toward **automatic, useful operation once a treatment qualifies**. Instrument the existing execution boundary first, retain complete bounded-recoverable originals, and select transformations by content and cost. Routine recognized output can then shrink automatically. For an already-authorized captured result, unsupported formats/hosts, failed storage or failed fidelity checks preserve the original result. Authorization or path-integrity failures stop retrieval/processing; they must never broaden access or recover unrelated raw bytes. This is a qualification path, not a dashboard-only endpoint.

Prioritize components where Jackin can own the contract: typed document extraction, semantic/navigation hints, deduplicated observations and versioned recovery. Measure indexing and cache churn before adding resident services. Require exact source identity before edits; a summary, graph node or old memory is evidence to inspect, not authority to rewrite a file.

Use the same accepted-work and latency gates for every candidate. A 12–30-task pilot can discover failures but cannot certify a one-percentage-point noninferiority margin. Learned compressors, pixel representations, new model policies and complete workflows need their own experimental arms, all retries and secondary calls charged, and the user's selected model/effort preserved in the principal comparison.
