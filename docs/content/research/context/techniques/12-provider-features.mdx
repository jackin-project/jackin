Three changes invalidate the earlier baseline: OpenAI GPT-5.6+ has paid cache writes; Claude has new model-specific read discounts and signed-thinking continuation rules; Gemini Interactions/Argon has different cache and usage semantics from legacy `generateContent`. ### Disjoint usage fields

| API | Input classes | Generation classes |
| --- | --- | --- |
| OpenAI Responses | Total input includes ordinary, cache reads and writes; subtract read/write subsets to obtain ordinary input | `output_tokens` includes reasoning; do not add reasoning details again |
| Claude Messages | Ordinary `input_tokens`, cache creation and cache read are disjoint; creation lifetime buckets subdivide creation | `output_tokens` includes thinking; visible thinking summary length is not the billed count |
| Gemini Interactions | Cached input is a subset of total input | `total_output_tokens` and `total_thought_tokens` are disjoint; add them for generation pricing |

Claude compaction may report an `iterations` array while top-level input/output omit compaction work. Price the documented iteration records once instead of adding them to top-level usage. The machine-readable register and the [measurement tools](/research/context/techniques/tools/) contain fixtures for these differences.

## Prompt caching: what actually ships

[OpenAI GPT-5.6+ caching](https://developers.openai.com/api/docs/guides/prompt-caching) combines implicit reuse with explicit breakpoints, a 1,024-visible-token minimum and 30-minute/12-hour write classes. `prewarm: true` creates paid cache state without generation. TTL eligibility does not guarantee physical KV residency or a latency benefit. Earlier model policies and Codex credit billing differ.

[Claude automatic caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) is now documented across platforms except older Bedrock model paths. Model/platform minimums vary; the newest listed families commonly start at 512 tokens. Automatic and explicit breakpoints share the same lookup and isolation rules. Claude API, Claude Platform on AWS and Foundry isolate caches by workspace; Bedrock and Google-managed paths document organization-level isolation.

[Gemini caching](https://ai.google.dev/gemini-api/docs/caching) is implicit-only through Interactions. Explicit objects are unsupported from Argon onward. Argon's minimum cacheable input is 4,096 tokens. Separately, its 2,050-token aggregate-increment rule can make a shorter next increment reprocess a recent suffix. The [cache chapter](/research/context/techniques/07-caching-exploitation) quantifies a synthetic example without claiming an observed bill.

## Compaction and observation editing

| Feature | Contract | Material limitation |
| --- | --- | --- |
| Claude on-demand compaction | Beta `compact-2026-09-04`, separate request with top-level summarize operation, signed readable compaction block | Use required beta and compatible continuation; cannot combine with threshold context management in the same call |
| Claude threshold compaction | Beta `compact-2026-01-12`, `compact_20260112` edit at threshold; current default 150K and minimum 50K | Summary requests cost tokens; dropped evidence needs recovery and fidelity testing |
| Claude context editing | `clear_tool_uses_20250919` and `clear_thinking_20251015` on supported models | Placeholder is not original evidence; editing changes cache state |
| OpenAI Responses compaction | Server threshold or standalone `/responses/compact` | Standalone returns a canonical next window, not just one opaque item |
| Native host compaction | Host-managed prompt, continuation, file/rule reload and diagnostics | API availability does not prove host exposure or identical settings |

Sources: [Claude overview](https://platform.claude.com/docs/en/build-with-claude/compaction), [on-demand](https://platform.claude.com/docs/en/build-with-claude/compaction-on-demand), [threshold](https://platform.claude.com/docs/en/build-with-claude/compaction-threshold), [context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing), [OpenAI compaction](https://developers.openai.com/api/docs/guides/compaction).

On-demand Claude compaction can read tool definitions but does not execute tools. Incomplete tool-use/result pairs can be rejected. Its output budget includes thinking. Background preparation and keeping recent turns have signed-boundary rules; substituting an arbitrary summary is not equivalent. Current [compaction/thinking guidance](https://platform.claude.com/docs/en/build-with-claude/compaction-thinking-blocks) explains when tail thinking must be dropped.

New independent and author-led compaction work exists; the earlier “no studies” claim is withdrawn. [CompactionBench/APEC](https://www.microsoft.com/en-us/research/publication/benchmarking-long-horizon-agent-context-compaction-with-compactionbench/) motivates task-level repeated-compaction evaluation, not unqualified adoption of a smaller context.

## Thinking, effort and append-only history

[Preserved thinking](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking) now includes model-specific prefix and account binding. Fable 5.1, Opus 5.5, Sonnet 5.5 and Haiku 5.5 have prefix-validation rules; Mythos 5.1 differs, so “all current models validate identically” would also be wrong. Accounts created from August 31, 2026 default to enforcement under the documented controls; older accounts can expose diagnostics or explicit behavior.

Changing earlier tool results, system instructions or tool definitions can invalidate later signed blocks. A current-result transformation before first model exposure is different from revising past history. Server-managed context editing can preserve a continuation that an external history rewrite would break. Retention is also model-specific: the old blanket claim that all Haiku models strip prior thinking is stale.

[Effort](https://platform.claude.com/docs/en/build-with-claude/effort) controls reasoning allocation, not a fixed token quota. Opus 5.5 and Haiku 5.5 default to medium; Opus 5.5 thinking cannot be disabled. Mid-conversation effort/system/tool controls can preserve an existing prefix on supported models when their append rules are followed. They are not permission to change the selected effort in Jackin's primary experiment.

[Task budgets](https://platform.claude.com/docs/en/build-with-claude/task-budgets), beta `task-budgets-2026-03-13`, are advisory across an agent loop and have a 20K minimum. They include thinking, tool activity and output. With full history, repeatedly subtracting past consumption from the supplied remaining budget can double-count progress and cause premature stopping. `max_tokens` remains a hard per-request generation cap; SDK spend limits are a separate host feature.

## Tool search, programmatic calls and structured outputs

[Tool search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool) defers model loading of schemas while preserving their definitions in the API request. It adds search calls and requires discoverable descriptions. Bedrock's documented server-side tool search uses InvokeModel rather than Converse; Claude Platform on AWS uses the Anthropic Messages API and has a different contract.

[Programmatic tool calling](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling) requires a supported model and code-execution tool version `code_execution_20260120` or later. Code can aggregate/filter tool results before sending a compact result to the model. Include script generation, execution charges, data movement and errors. It does not automatically expose every native host tool, and current strict-tool and parallel-call compatibility restrictions matter.

The PTC page reports an average 11% performance gain with 24% fewer input tokens on its cited research/search benchmarks. This is a first-party benchmark statement, not a Jackin reproduction or a coding-agent guarantee. Likewise, tool-search schema-reduction examples measure specific catalogs rather than completed tasks.

[Structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs) constrain syntax and schema. They can reduce parse retries but do not guarantee truthful values, complete requirements or correct code. Include schema size, grammar initialization/caching and refusal/incomplete-response paths. Measure formats with the exact provider tokenizer; old fixed tool-overhead and tokenizer-divergence numbers are not current constants.

## Batch, token counting and rate limits

[Claude Batch](https://platform.claude.com/docs/en/build-with-claude/batch-processing) discounts eligible input/output rates and can stack with supported cache pricing. It changes latency, ordering and failure handling; it is unsuitable for an interactive dependency that needs an immediate result. Cache TTL reuse is uncertain under asynchronous scheduling.

[Token counting](https://platform.claude.com/docs/en/build-with-claude/token-counting) is free estimation infrastructure with its own rate limits. Current Start/Build/Scale limits are 5,000/10,000/20,000 RPM, replacing earlier values. Counting a request is not a receipt for actual cache hits, compaction iterations, generation or subscription utilization.

[Claude rate limits](https://platform.claude.com/docs/en/api/rate-limits) count ordinary input plus cache creation against ITPM; cache reads are excluded for current models, with the documented legacy Haiku 3.5 exception. RPM and output limits still apply. Limits are maximum allowed usage, not guaranteed throughput.

## Stateful APIs and native availability

[Gemini Interactions](https://ai.google.dev/gemini-api/docs/interactions-overview) can preserve history using `previous_interaction_id`, but tools, system instructions and generation configuration must be redeclared per request. Storage is not free prompt processing. Retention and `store: false` affect linking/background behavior and must be considered separately from cache TTL.

The [host matrix](/research/context/techniques/23-cross-agent-portability) distinguishes a documented provider feature from a usable adapter. Keep the off/native path and existing permissions intact; do not install a gateway, warmer, beta or changed reasoning policy merely because the API supports it.

## Decision and unresolved evidence

Use current rates and endpoint-specific usage normalization first. Evaluate caching, native tool discovery and context handling before adding a second optimizer. Treat compaction, task budgets, PTC and custom formatting as explicit interventions with failure/recovery tests.

This workstream establishes current documented contracts and synthetic arithmetic. It does not establish task-quality equivalence, provider-billed savings, quota conversion, host interception or enterprise-account pricing. Earlier fixed usage shares, obsolete prices, universal long-context rules and no-native-control claims are withdrawn in the [coverage ledger](/research/context/techniques/tools/#october-24-provider-evidence).
