## JSON, rows, delimiters and nested data

### Minification

Removing whitespace inside a model-visible JSON string reduces the recorded fixture. Minifying the outer HTTP transport envelope does not by itself shorten the text or objects that the provider places in the model context. Identify which layer actually crosses the model boundary.

Two- and four-space indentation happen to tie on this fixture; tabs do not. Whitespace is not universally free. Parsing and reserializing can also change key order, numeric formatting, escaping and signed content. Reject duplicate keys and nonfinite numbers where the contract requires strict JSON. Do not rewrite JSON signatures, exact byte snapshots or error evidence merely because the parsed values appear equivalent.

### Fields plus rows

A schema-once representation removes repeated field names while remaining ordinary JSON. The local codec explicitly requires identical key sets, preserves nested values and rejects missing fields rather than filling them with null. It also validates field uniqueness and row width. This addresses a narrower and more reproducible problem than claiming every object array can become a table without loss.

Sparse records, heterogeneous unions, repeated object keys, absent versus null values, numeric precision and ordering requirements require their own contracts. Keep native structured tool output intact if a consumer expects its original schema. A separate model-facing view needs its own recovery and validation path; changing bytes in a post-tool hook is not permission to break that host's typed result.

### CSV, TSV, pipes, Markdown, YAML and XML

Delimiter choice depends on actual quoting, escapes, vocabulary and the selected tokenizer. The table shows no universal winner: plain CSV is shortest here, while TSV is shortest among the typed-cell encodings. Numeric columns, embedded tabs, newlines and multilingual strings can change the ordering.

Markdown tables add alignment and presentation syntax; they can be useful to humans without being a preferred machine representation. YAML carries scalar-typing and parser-version concerns; XML carries tags and attributes but can express contracts that flat rows cannot. This probe did not execute YAML/XML or measure their model fidelity. Do not transplant earlier token counts into a new dataset or discard hierarchy merely to make a table shorter.

## TOON, TRON and independent format evidence

[Notation Matters v2](https://arxiv.org/html/2605.29676v2) provides more relevant counterevidence than a format repository's token-only headline. It tests five open model configurations across four tool-use benchmarks. Its reported maximum TRON reduction is 27% with accuracy drops up to 14 percentage points; TOON's headline reduction is 18% with drops up to nine points. These are study-specific maxima, not a guaranteed paired result for every task.

Its input treatment combines tool schemas and responses, while its full treatment also changes emitted tool calls. Multiturn parsing failures and parallel-call behavior therefore cannot be attributed solely to a tool-result codec. Frontier models and Jackin's twelve host adapters were not qualified by that study. The inspected [repository revision](https://github.com/lkutschka/notation-matters/tree/b31385bb66ffdfd0b9da7eeaef03870a74aeafb1) makes the treatment identity explicit.

The [Onto paper](https://arxiv.org/html/2604.17512v1) reports columnar-format gains on synthetic operational datasets and Qwen2.5-7B. That narrower task/model evidence is compatible with format gains in some settings and failures in others. Its local tokenizer setup is not proof of current Claude billing behavior.

The [Caveman dossier](/research/context/tools/01-caveman-design/) covers its pinned TOON implementation, guards and component tests. A tested codec round trip, an author benchmark and an accepted agent task are separate evidence classes. Earlier TOON marketing averages and truncation claims are withdrawn as present-day universal quality claims; this refresh did not rerun their original model benchmark.

## Identifiers, numbers and decoration

The following counts are small reproducible examples, not data-model migration recommendations:

| Recorded surface | cl100k / o200k | Interpretation |
| --- | ---: | --- |
| Hyphenated UUID string | 25 / 25 | Exact existing identifiers must remain usable |
| Same UUID bytes rendered without hyphens | 20 / 20 | Requires an explicit reversible representation contract |
| Same 16 bytes in base64 | 16 / 15 | This example does not imply base64 generally saves tokens |
| ISO timestamp | 13 / 13 | Date, timezone and units are explicit |
| Corresponding Unix seconds | 4 / 4 | Units, epoch and interpretation must be supplied |
| Camel-case / snake-case sample | 4 / 4 each | One tie does not establish a casing law |
| ASCII operator expression | 11 / 11 | Familiar syntax can already be compact |
| Unicode operator expression | 11 / 13 | Fewer characters can require more tokens |

Base64's byte expansion ratio is not its token expansion ratio. Random hashes, repeated patterns, separators and vocabulary merges differ. Do not strip hash characters or shorten identifiers without collision analysis and exact restoration. If an alias is used only in the model-facing view, include the dictionary, its loading cost and its lifetime across children and compaction; see [style compression](/research/context/techniques/04-style-and-language-compression/).

Numeric formatting is semantic. Dropping trailing decimal places may change significant precision, converting to a float may lose an integer, removing grouping may confuse locale, and scientific notation may shorten one number while adding tokens to another. Preserve the authoritative value and units. “Digits always group in threes” or “scientific notation is always worse” is not a general provider contract.

Decorative box drawing, emoji and repeated separators can be removed from a derived view when they carry no task information. Do not delete Unicode from identifiers, source code, mathematical operators or user language wholesale. The [multilingual tokenizer study](https://arxiv.org/abs/2305.15425v2) documents disparities; it does not validate translating a task into another language to reduce billing.

## Counting against the actual provider

[Claude's current token-counting endpoint](https://platform.claude.com/docs/en/build-with-claude/token-counting) is free and model-aware, but returns an estimate that can differ from actual usage. Its current named Start/Build/Scale limits are **5,000 / 10,000 / 20,000 requests per minute**, not the prior 2,000/4,000/8,000 table. Counting does not create cache entries or demonstrate a cache hit, and account access and input handling still matter. No authenticated counting request ran here.

Use exact model identifiers and the complete relevant message/tool envelope. Preserve separate counts for text, images, tools and endpoint-added overhead where exposed. Provider usage receipts settle billed token classes; local counts describe the exact local encoder. The [accounting register](/research/context/techniques/12-provider-features/) separately covers cache writes, cache reads, reasoning and model-dependent thresholds.

Changing tokenizer families by routing to a cheaper model or lowering effort is outside this chapter's main treatment. The earlier content-specific “tax” measurements and assertions that all current Claude models share exactly two tokenizers are not maintained without fresh full-fixture counting across the actual models.

## Cache effects, qualification and Jackin decision

A shorter view can invalidate a stable prefix, introduce a grammar legend, cause recovery reads or increase model output. Gemini's current cached-continuation block processing can even make a smaller delta cost more under some boundaries; [cache arithmetic](/research/context/techniques/07-caching-exploitation/) records a synthetic example. A token reduction cannot be multiplied by one universal input price.

For a proposed view, record the source bytes, transformation version, schema, exact retained fields, tokenizer identity and immutable recovery artifact. Validate deterministic round trips and rejection paths first. Then compare accepted tasks on the same host/model/effort with native alternatives and all attempts included, using the [validation harness](/research/context/techniques/16-validation-harness/).

This refresh qualifies the recorded local codecs and arithmetic only. It does not qualify automatic TOON/CSV conversion across hosts, multilingual rewriting, identifier changes, output-format reliability or subscription quota conversion.
