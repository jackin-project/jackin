## Current provider contracts

### Claude

[Claude vision](https://platform.claude.com/docs/en/build-with-claude/vision) and its [coordinate guide](https://platform.claude.com/docs/en/build-with-claude/vision-coordinates) document one visual token per 28×28 patch after resizing and padding:

| Native tier | Current models | Long-edge limit | Visual-token limit |
| --- | --- | ---: | ---: |
| High resolution | Claude 4.7 and later | 2,576 pixels | 4,784 |
| Standard | Other models | 1,568 pixels | 1,568 |

Both constraints apply. The process preserves aspect ratio, rounds resized dimensions as documented, then pads the bottom/right to patch boundaries. Scaling only to the long-edge limit can produce the wrong size and wrong coordinates. Current Haiku/Sonnet models are not automatically in the old standard-resolution tier simply because of their family names.

For ordinary image blocks, images above native bounds are normally downscaled. **Computer-use and browser-use tool-result images above those bounds are rejected instead**; the application must satisfy those tool contracts. An image-block transformation option can also request rejection for oversized ordinary inputs. Do not infer the same acceptance behavior from all places an image can appear.

The API accepts at most 100 images for models with a 200K-token context window and 600 for other models, subject to request size and platform limits. Above 20 images in one request, stricter per-image dimensions apply; resent historical images and nested tool results count. The documentation gives at most 2,000 pixels on each side as the cross-platform safe dimension in that many-image case. Standard first-party endpoints have a 32 MB request ceiling. Files API references reduce transport size but do not eliminate visual inference costs or all many-image failures.

### OpenAI

The [current image guide](https://developers.openai.com/api/docs/guides/images-vision) separates patch-based models from legacy tile pricing. For **GPT-6 Astra**, `high` uses a 2,500-patch budget and maximum dimension 65,535 pixels; `original` preserves dimensions unless that pixel limit requires resizing. `auto` uses `original` behavior. The resulting 32×32 patches are multiplied by 1.2 and rounded up for billed image input.

A separate **30,000-patch rejection limit** applies after model/detail processing. An oversized `original` image is not automatically downsampled to satisfy that final limit. GPT-5.6 Sol/Terra/Luna have their own high-detail pixel bounds, while their `auto` also uses original sizing. The table does not establish the image rules for every GPT-6 Sol/Luna sibling; do not infer them from a shared text price or name.

Detail names are not universal cost rankings. For example, the current GPT-5.4 table gives `low` a 6,144-patch budget and `high` a 2,500-patch budget. Legacy “low detail equals a fixed 85 tokens” guidance cannot be copied onto all current models. Record the exact model and effective detail, including defaults.

### Gemini

The [Gemini 4/3 media-resolution contract](https://ai.google.dev/gemini-api/docs/media-resolution) gives approximate image budgets:

| Image resolution | Approximate tokens | Arithmetic at $2/M uncached input |
| --- | ---: | ---: |
| Low | 280 | $0.00056 |
| Medium | 560 | $0.00112 |
| High / default image setting | 1,120 | $0.00224 |
| Ultra high, per-content setting | 2,240 | $0.00448 |

The rate is Gemini 4 Argon's snapshot introductory input rate from [current pricing](https://ai.google.dev/gemini-api/docs/pricing), used only to illustrate arithmetic. Endpoint overhead, extracted text, cache classes and generated output are additional. Generic image documentation still contains older 258-token/tile examples; those cannot override the newer model-specific media-resolution table.

The same source specifies video at approximately 70 tokens per frame for default/low/medium and 280 for high, audio at 25 tokens per second, and PDF resolution entries that add native text to visual budgets. Media resolution controls tokens per selected frame; media-processing/frame selection controls which content is loaded. They are separate quality treatments.

## Executed formula examples

The <RepoFile path="docs/content/research/context/techniques/tools/refresh-2026-10-24/representation/README.md">offline bundle</RepoFile> contains a small independent integer search over Claude's documented bounds and arithmetic for documented OpenAI examples. No image was generated or resized. These are formula reproductions, not billed usage receipts or OCR results.

| Original dimensions | Claude standard: resized / tokens | Claude high: resized / tokens |
| --- | --- | --- |
| 1,000×1,000 | unchanged / 1,296 | unchanged / 1,296 |
| 1,920×1,080 | 1,456×819 / 1,560 | unchanged / 2,691 |
| 3,840×2,160 | 1,456×819 / 1,560 | 2,576×1,449 / 4,784 |
| 1,075×1,520 | 924×1,307 / 1,551 | unchanged / 2,145 |

The A4 example's sides are below 1,568, yet its patch count still forces resizing on the standard tier. This is why a long-edge-only implementation is insufficient. The recorded 1,000-pixel square costs 1,296 visual tokens, regardless of whether its compressed file contains more or fewer bytes at the same dimensions.

For GPT-6 Astra, the documented 1,024-pixel square at high detail yields 1,229 billed image tokens. A 2,048-pixel square at high detail becomes 1,600×1,600 and yields 3,000; preserving that 2,048-pixel square with original detail yields 4,916 by the same formula. Actual endpoint rounding and complete usage should be checked before treating estimates as invoices.

## PDF accounting and extraction

[Claude's current PDF guide](https://platform.claude.com/docs/en/build-with-claude/pdf-support) says each page is represented by its image and extracted text. Its **1,500–3,000 tokens per page estimate concerns the text component**, with visual tokens added; it is not a fixed total per page. Density, layout, model tier and extraction affect the result.

The current document limit is 600 pages, reduced to 100 when the request's context window is under one million tokens, with a 32 MB request size limit. Dense material may fill context or fail earlier. Native document references and file uploads avoid repeated transport but do not make inference free.

Platform behavior also differs: on Amazon Bedrock Converse, citations must be enabled for visual PDF understanding; otherwise the documented path falls back to text extraction. InvokeModel has separate controls. For Gemini, the media-resolution table explicitly combines visual budgets and native text for low/medium/high PDF processing. Record the endpoint and actual response usage, not only the file extension.

A text-only extraction can be sufficient for some questions, but it can omit charts, column relationships, footnotes, annotations, formulas, handwriting and page structure. Preserve page identifiers and the original document for recovery. Page selection and extraction completeness must be tested against the user's actual question; the old blanket “Markdown avoids a twofold tax” claim does not survive these distinctions.

## Six treatments and their qualification

| Treatment retained from the earlier chapter | Fixed-model implementation | Decision boundary |
| --- | --- | --- |
| M1: vision-tier routing | No routing in the main comparison | Changing model or effort is a separately authorized experimental arm, even if its image price is lower |
| M2: resize before sending | Set an explicit supported size/detail for the selected model | Validate small text, icons, diagrams and coordinates; native downscaling may already have removed the same pixels |
| M3: text instead of screenshot | Use reliable native text/DOM/structured output when it contains the needed evidence | Preserve visual evidence when layout, rendering, state or pixels are the task |
| M4: text/Markdown instead of PDF | Extract the required content with page provenance and original recovery | Compare extraction failures and missing visual content; no universal PDF multiplier |
| M5: crop the relevant region | Retain crop origin, scale, source hash and enough surrounding context | A smaller frame may omit an error, label, adjacent control or contradictory evidence |
| M6: obtain vision when needed | Use current tool-supported text paths and capture images when visual state matters | Count every delivered frame and replayed history; a stale text tree cannot verify a visual change |

Compression of JPEG/PNG bytes can improve upload size and time without changing visual-token count. Lossy compression can also damage small text. These are different measures; do not report byte savings as token savings.

### Coordinate and recovery contract

Claude coordinates refer to the resized image, before interpreting padding as content. Use resized dimensions rather than padded dimensions when mapping back. Clamp returned points to the resized bounds and apply separate x/y scale factors, since integer rounding can make the two factors differ slightly. A crop also adds its original x/y offset. When screenshot pixels differ from logical screen coordinates on a HiDPI display, convert through the display scale before acting. Keep those transforms with the exact image artifact; a coordinate from an older frame is not a valid target in a changed interface.

Server-rendered PDF page dimensions are not under the caller's control, so the Claude guide cautions that their coordinates cannot reliably be mapped to the source page. A caller-managed raster is a separate pipeline when exact coordinate recovery is required. Native browser/DOM identifiers may avoid pixel mapping for some actions, but do not prove rendered appearance.

Store originals outside the model context when permitted, with immutable identity, lifetime and a retrieval path the agent can use. A truncated preview with no surviving artifact is not recovery. Charge the original retrieval and any follow-up frame to the same task.

## Text rendered as images: a distinct experimental family

Dense text rendered into pixels can cost fewer image tokens than the original text tokens on some model/profile combinations. It converts exact text reading into visual recognition and can change cache, OCR, coordinates, accessibility and recovery behavior. The output image must be counted with the provider's actual preprocessing and all surrounding instructions.

The inspected [pxpipe v0.15.0 applicability source](https://github.com/teamchong/pxpipe/blob/0f16bdb3783ea01b3a9f773f49b42fe36a27f2e6/src/core/applicability.ts) defaults to Fable 5, Opus 5.5 and the Gemini family. Its comments report model-specific fixture failures, including weak dense-hex recall on opt-in GPT-5.6 Sol and a removed Opus 5 default. Those are vendor source claims, not trials executed by this refresh. A good gist score does not establish exact identifier, configuration, hash or safety-condition fidelity.

Keep raw text for exact-match workloads until the complete treatment is qualified. Model-family prefix eligibility, a font profile and an attractive token estimate are insufficient. The [market scan](/research/context/techniques/03-prior-art-and-market-scan/) and [Caveman dossier](/research/context/tools/01-caveman-design/) distinguish adjacent implementations, runtime scope and evidence.

## Whole-session economics and Jackin decision

For each image/document event, record model, endpoint, source dimensions, processed dimensions or effective detail, media type, source hash, extraction/crop version, token classes, generated output and recovery. Cache hits, writes, storage and retention may change the marginal cost; [provider accounting](/research/context/techniques/12-provider-features/) handles those classes. A screenshot repeatedly replayed in history can matter more than a one-time upload.

Do not delete images or signed reasoning/history blocks outside the provider's supported continuation contract merely to reduce context. Native compaction and context-editing behavior is covered in [context architecture](/research/context/techniques/06-context-architecture/). A first successful call does not prove that the next tool continuation remains valid.

The old personal-session counts, text/screenshot break-even claims and fixed quality-neutral resize assertions are withdrawn because their complete artifacts and accepted-task comparisons were not reproduced. Current remaining questions include exact-character OCR, missing visual evidence, coordinate accuracy, repeated-history billing, native host image limits and subscription quota effects. Apply the [validation harness](/research/context/techniques/16-validation-harness/) before enabling a treatment; this refresh establishes current contracts and reproducible arithmetic only.
