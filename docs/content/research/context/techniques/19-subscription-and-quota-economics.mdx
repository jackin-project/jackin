## Summary

**Research state:** Current

**Snapshot:** 2026-10-24 01:15 UTC. API dollars, purchased credits, included-plan utilization and elapsed time are distinct metrics. A token reduction does not establish the same percentage improvement in each. No account credentials, paid sessions or live quota counters were used in this workstream.

Current official sources invalidate two major old claims: eligible Claude Max/Team plans can provide a **separate monthly API-credit balance** for eligible API/SDK work, and Codex token-based credits have **no separate cache-write charge** even though newer OpenAI API-key calls do. Headless work cannot be classified by its command name alone.

## Billing routes at the snapshot

| Route | What is charged or limited | What an optimizer may legitimately report |
| --- | --- | --- |
| Direct API key | Provider usage classes and applicable rates | Estimated/observed API cost with complete receipts |
| Native host signed into a plan | Included usage windows and model/feature limits | Observed utilization change with uncertainty; no invented dollar equivalence |
| Native host purchased usage credits | Published credit/rate card and account agreement | Actual credits and their applicable purchase cost |
| Eligible Claude monthly API credits | Linked Console organization's eligible API usage | Credit consumed, remaining credit and any purchased-credit spill |
| Enterprise negotiated route | Contract-specific rates, permissions and limits | Account-authorized contract values or explicitly unknown fields |

Capture authentication route before launching a task. An environment API key can take precedence over subscription login, and a gateway can change billing ownership. Changing that route, enabling overage or linking an account is a user decision, not an optimization default.

## Claude included plans and usage credits

[Claude's current Pro/Max guidance](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan) describes five-hour and weekly limits, shared usage across Claude applications, and additional model-specific limits such as Fable weekly usage. Long tasks, context, model and tool activity affect consumption. The public guidance does not publish a complete universal token-to-plan-percentage formula.

Current wrap-up allowance behavior can let an already-running operation finish after a window limit while still counting against weekly usage. This is not unlimited extra capacity. Availability and rollout details should be read from the current account surface; no account-specific entitlement was established here.

[Usage credits](https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans) are an opt-in way to continue eligible Claude application usage after included limits. Spend caps, balances and auto-reload determine whether work continues. They are separate from the monthly API-credit benefit below. Do not enable extra usage, auto-reload or an alternative API key in response to a limit without authorization.

The native [`/usage` documentation](https://code.claude.com/docs/en/costs) now distinguishes included usage and usage-credit rows. It can display a recent cached snapshot when the usage endpoint is rate-limited. An error fetching limits is not proof that inference is limited, and a displayed stale bar is not a fresh measurement.

## Claude monthly API credits: a new distinct benefit

The [current monthly-credit policy](https://support.claude.com/en/articles/17154008-monthly-api-credits-for-max-and-team-plans) documents the following eligible balances:

| Plan | Monthly API credit | Scope |
| --- | ---: | --- |
| Max 5× | $100 | Linked Console organization |
| Max 20× | $200 | Linked Console organization |
| Team standard seat | $20 per seat | Team pool, subject to the documented $500 pool cap |
| Team premium seat | $100 per seat | Same pool/cap |
| Free, Pro, Enterprise | Not eligible for this benefit | Their other entitlements remain separate |

The plan must have been active for at least seven days, and a user must opt in and link an eligible Console organization under the one-plan/one-organization rules. Credits expire monthly, do not roll over and are consumed before purchased credits. All eligible API keys in that linked organization share the balance; this is not a private per-process budget.

Covered usage includes eligible API, Batch, Playground, Managed Agents and Agent SDK traffic. It excludes interactive Claude Code/Cowork/application extra usage and third-party cloud routes. The [SDK-with-plan guidance](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan) distinguishes a self-run SDK or `claude -p` using the linked organization's API key from OAuth headless usage that still counts against plan limits. GitHub Action/IDE/Desktop-initiated usage can remain classified as Claude Code even with a headless flag.

Exhausting monthly credits can consume purchased credit or auto-reload when configured; otherwise eligible API usage stops. The benefit does not increase included application limits. Therefore “headless always stays inside the interactive cap” and “a subscription never subsidizes API usage” are both stale generalizations.

## Codex / ChatGPT Work limits and credits

The current [Codex pricing page](https://learn.chatgpt.com/docs/pricing) says ChatGPT Work and Codex share usage. Plus and Standard Business provide task-dependent five-hour message estimates; **Pro plans currently have no five-hour limit**, while weekly and other limits may apply. Estimates are not fixed message entitlements.

Token-based credits are a separate published metric. Current Standard rates per million tokens include:

| Model | Input credits | Cached-input credits | Output credits |
| --- | ---: | ---: | ---: |
| GPT-6 Astra | 250 | 25 | 1,250 |
| GPT-6.1 Sol | 50 | 2.5 | 250 |
| GPT-6 Sol | 50 | 5 | 250 |
| GPT-6 Luna | 2.5 | 0.25 | 12.5 |
| GPT-5.6 Sol | 100 | 10 | 500 |

**Codex credit billing has no separate cache-write charge.** API-key usage follows API pricing, including GPT-5.6+ write classes. Do not apply the API calculator to a Codex credit receipt or use the credit rate card to infer opaque included-plan utilization.

Speed settings use different multipliers for different billing surfaces. Current Fast consumes included limits at 2.5× Standard but purchased/enterprise pay-as-you-go credits at 2×. Current GPT-6 Astra and GPT-6.1 Sol Ultrafast use 8× included limits and 6× paid credits. Speed is a separate latency/cost treatment; changing it is not context compression.

Some Enterprise agreements remain on legacy cards or negotiated USD billing, and credit purchase discounts depend on the agreement. The model rate table alone cannot establish dollars per task. Current documentation also distinguishes model access through sign-in from API availability; retirement on one surface does not imply retirement on the other.

## How optimization priorities change

| Intervention | API/credit hypothesis | Included-plan hypothesis | Required evidence |
| --- | --- | --- | --- |
| Stable cache prefix | Lower read price and fewer costly writes where applicable | May reduce weighted usage | Native receipts or account observations; no universal percentage mapping |
| Smaller useful tool results | Less repeated input and possibly fewer context limits | May improve task capacity | Quality/recovery and utilization measurements |
| Earlier compaction | Less replay, more summary/reread expense | May avoid oversized turns but consume extra work | Long-task comparison at fixed model/effort |
| More subagents | Parallel speed with duplicated setup/work | Can use shared limits faster | Whole-tree usage and accepted throughput |
| Longer TTL / keepalive | Different write/read economics | Host may control or ignore TTL; weighting is not public | Supported configuration and observed billing route |
| Lower model/effort | Different unit prices and capability | Different consumption and possibly entitlement | Separate optional treatment with non-inferiority tests |

The old “prefix stability is the number-one quota lever because each miss costs exactly 1.25–2× cap weight” is not justified by public plan accounting. Those are API write multipliers. The old forced 400K compaction window, assumed free one-hour TTL inside every plan and fixed request-count overhead are withdrawn as general recommendations.

## Measure quota without inventing conversion

For an authorized account experiment, record plan, model, effort, host version, connection mode, window reset times, concurrent background usage and fresh utilization snapshots around matched tasks. Record other Claude/ChatGPT surfaces sharing the balance. Use multiple tasks/windows because dashboard quantization, delayed updates and overlapping work can overwhelm a small difference.

Report percentage points consumed per accepted task, tasks completed before the relevant limit, wall time including waiting, and any paid spill. Keep raw token/cost measurements alongside them. A token ratio alone cannot prove ten times as many included tasks; nor does opaque weighting prove that such a gain is impossible.

When a limit is reached, distinguish waiting for reset, using already authorized paid credits and switching accounts/models. Only the first is a time trade without new billing authorization. Do not treat an undocumented header or reverse-engineered community weight as an official entitlement or stable API.

## Decision and unknowns

Default to the user's existing route and selected model/effort. Show observed API cost or credit consumption accurately; show included utilization only when actually observed. Display unknown quota conversion as unknown, rather than manufacturing precision from API rates.

This refresh measured no personal account, reset window, subscription capacity or paid overage. Earlier account totals, undocumented multipliers, daily-cap anecdotes and universal headless/TTL claims are explicitly withdrawn as current evidence. The [source and coverage registers](/research/context/techniques/tools/#october-24-provider-evidence) preserve their dispositions and the current official replacements.
