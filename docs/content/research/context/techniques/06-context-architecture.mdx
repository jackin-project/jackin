## Summary

**Research state:** Current

**Snapshot:** 2026-10-24 01:15 UTC. Official documents were retrieved on October 24; access times and hashes are in the [source register](/research/context/techniques/tools/#october-24-provider-evidence). Current research does not mean that an optimization has passed Jackin's task-quality gates.

The most promising first intervention is to avoid loading irrelevant material while retaining an explicit route to complete evidence. This changes selection, retrieval and sometimes instruction authority. It is not automatically lossless or quality-improving. A shorter context can omit the requirement, exception or source line needed to finish correctly.

Keep the selected model and effort fixed. Compare retrieval, filtering and compaction treatments against the host's existing tool search, truncation and compaction. Replacing native behavior without measuring it risks counting an existing saving twice.

## Prevent unnecessary loading

| Technique | Actual boundary | Benefit to test | Failure or recovery requirement |
| --- | --- | --- | --- |
| Tool search / deferred MCP schemas | Tool discovery before a model request | Fewer unused definitions in context | Discovery can miss tools or incur extra calls; preserve exact callable schemas and permissions |
| Instruction audit | Startup and per-path instruction loading | Remove duplication, obsolete guidance and irrelevant examples | Preserve operative requirements; size alone does not identify redundant policy |
| Skills | Description initially, full instructions when invoked | Load specialized guidance when relevant | Descriptions still cost context; invocation can load large references or scripts |
| Path-scoped rules | File access activates applicable rules | Keep unrelated guidance out | Rules needed before file access can arrive too late; verify glob, directory and worktree behavior |
| Repository map / outline | Search and navigation response | Locate symbols before reading bodies | Maps can be stale or hide exceptions; retain revisioned file/symbol pointers |
| LSP or symbol graph | Typed navigation | Narrow reads to definitions, references and implementations | Generated code, macros, dynamic imports and incomplete language servers need ordinary reads |

Claude's current [tool-search API](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool) retains definitions in the request but defers their inclusion in model context; at least one tool stays non-deferred. This differs from deleting schema fields or changing names. Its first-party schema-reduction examples are not measured Jackin task results. Measure native [MCP search](https://code.claude.com/docs/en/mcp) and [skills](https://code.claude.com/docs/en/skills) before adding another discovery layer.

Current [Claude Code context documentation](https://code.claude.com/docs/en/context-window) describes startup project instructions, rules, memory, skill descriptions and MCP names, followed by on-demand nested rules and files. Audit what the pinned host actually loads, including global and managed instructions. Counting the repository's <RepoFile path="AGENTS.md" /> does not measure the complete startup request.

Moving dynamic system sections into a user message can improve prefix reuse but changes their authority. The Agent SDK's [`excludeDynamicSections`](https://code.claude.com/docs/en/agent-sdk/modifying-system-prompts) is an explicit application design choice. Stable paths, deterministic serialization and a stable authorized tool set can improve reuse without discarding instructions; cross-session identity must remain truthful.

## Transform observations before they enter history

A tool-output transformation should run **after one execution and before the original enters the model conversation**. The host must provide a genuine replacement channel. Appending a compact explanation while retaining the original increases input; a pre-tool hook that runs the command itself can duplicate a side effect. The [twelve-host matrix](/research/context/techniques/23-cross-agent-portability) distinguishes typed replacement, feedback substitution, observation and request rewriting.

Preserve command identity, exit status, errors, warnings, meaningful paths, locations and values. Store a scoped original before discarding material. Recovery must reopen the exact captured result, not rerun a command against a changed tree. Redaction and authorization rules apply to the original too. A host may truncate output before the hook receives it; recovery cannot manufacture missing bytes.

For read-before-edit workflows, an outline is insufficient evidence of the current file. Keep original offsets or line mappings, content hashes and an explicit native read path. Revalidate file identity before patching. A deterministic transformer can still make a lossy semantic choice when it drops lines.

## Retire old observations and compact deliberately

### Observation masking and context editing

Replacing an old result with a placeholder reduces repeated input, but the placeholder is not the evidence. Claude's [context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing) supports tool-result and thinking-block clearing with model-specific controls; changing retained history also changes cache reuse. Server-managed editing and a proxy rewriting old messages are different interventions.

The new [preserved-thinking contract](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking) is a decisive constraint: supported models bind thinking signatures to their preceding system, tools and messages. Editing earlier tool results or retaining signed thinking after an incompatible custom summary can invalidate it. Default enforcement also depends on account age and explicit controls. Historical compression requires a tested provider-specific continuation strategy.

### Compaction and reset

`/clear`, native automatic compaction and a custom summary have different semantics. Clear abandons conversational state; use it only for an independent task whose required instructions/evidence are reloaded. An arbitrary earlier compaction threshold may save replay input while increasing summary expense, rereads and lost requirements.

Current [Claude compaction](https://platform.claude.com/docs/en/build-with-claude/compaction) has separate on-demand and threshold beta paths. On-demand `compact-2026-09-04` produces a signed summary and supports background preparation/retained recent turns under its rules; threshold `compact-2026-01-12` summarizes at a configured boundary. Both require complete continuation contracts and accounting for compaction iterations. A cheap custom summarizer changes the model treatment and must be declared separately.

[OpenAI Responses compaction](https://developers.openai.com/api/docs/guides/compaction) supports server-managed thresholds and a standalone compact endpoint. The standalone response is the complete canonical next context window: using only its encrypted compaction item drops retained context. With `previous_response_id`, supply new input rather than manually pruning server-managed history.

Native Claude Code compaction reloads material. The [current host documentation](https://code.claude.com/docs/en/context-window) describes retained instructions, refreshed repository metadata when enabled, recent files and invoked skills subject to budgets. Since version 2.1.198, compaction inherits session thinking. A comparison against a hypothetical empty post-compaction context is invalid.

### New long-horizon evidence

[CompactionBench/APEC](https://www.microsoft.com/en-us/research/publication/benchmarking-long-horizon-agent-context-compaction-with-compactionbench/) separates an observational analysis of 13.5 million Copilot coding sessions from controlled experiments on persistent software-evolution tasks. The authors report up to 25.4% lower total cost and 9.6% less execution time for asynchronous progressive compaction. These are author-reported results on their harness, not this refresh's reproduction or a portable guarantee. They support testing prefix-preserving background compaction and retire the earlier blanket claim that no relevant controlled evidence exists.

## Isolate exploration and externalize durable state

[Claude subagents](https://code.claude.com/docs/en/sub-agents) normally start with their own context and return a final result; a fork inherits the parent's conversation. Exploration isolation can reduce parent replay while increasing total system input and coordination. Measure both. Current Explore normally uses the parent model, with Fable-specific connection-mode exceptions described in [routing](/research/context/techniques/10-model-routing-and-delegation); it is no longer sound to price every Explore call as Haiku.

Memory files, notes and artifact references are retrieval systems with a lifecycle. Record provenance, revision, author, task scope and expiry; distinguish a conclusion from underlying evidence. Revalidate mutable facts before acting. Cross-task memory can preserve a past mistake or an adversarial instruction, so stored content remains subordinate to the current user's instruction and current authorization.

Learned pruning such as SWE-Pruner and latent-state approaches remain separate quality-changing research treatments; see the [literature review](/research/context/techniques/24-fresh-literature-and-market-delta). A headline token reduction does not establish exact recovery, read-before-edit safety, current host compatibility or non-inferiority on Jackin's tasks.

## Decision and remaining experiments

Start with an inventory of native startup context, tool availability and file access. Test narrower discovery and current-result transformations with exact recovery. Evaluate masking and compaction on long tasks crossing multiple boundaries. Include rare facts, repeated reads after edits, cancellation, resume, forks, failed summaries and stale memory.

Withdraw the old fixed repository-token totals, assumed system/tool/history shares, universal quality gains from shorter context, and claims that pre-tool shell filtering safely replaces a result. No paid task, native host continuation or long-horizon fidelity trial was executed here. [Coverage dispositions and offline evidence](/research/context/techniques/tools/#october-24-provider-evidence) preserve the previous scope and explain numerical withdrawals.
