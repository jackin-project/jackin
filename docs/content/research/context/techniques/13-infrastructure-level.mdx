## Two operating regimes

| Regime | Controls available | Costs and limits |
| --- | --- | --- |
| Hosted API with native agent | Native tool/instruction surfaces, provider features exposed by host, account controls | Opaque serving placement and subscription weighting; provider API availability is not host support |
| Hosted API through an authorized gateway | Transport, request identity, accounting, retries, supported cache controls and explicit routing | Added failure point, latency, schema/version compatibility and data handling; no private KV access |
| Owned inference | Engine prefix cache, memory/storage tiers, scheduler, affinity and model-serving configuration | GPUs, CPU/RAM, transfer/storage, cold starts, observability and operations |
| Research transformations of model state | KV quantization, eviction, cross-model/latent interchange, non-prefix blending | Different numerical/semantic treatment, often model-specific; requires independent quality qualification |

Preserve the selected model and effort. A gateway that routes to a cheaper model or an inference engine with different weights is a separate treatment.

## Hosted gateway hygiene

[Claude Code gateway guidance](https://code.claude.com/docs/en/llm-gateway) requires compatible request/response handling and authentication. Preserve model identifiers, message order, beta headers, cache controls, signatures, streaming event order, usage details, stop reasons, errors and cancellation. Retrying after an ambiguous completion can duplicate tool actions or billable generation.

Current cache-read prices are model-specific, so “preserve the 0.1× cache” is obsolete as a universal rule. Preserve actual cache classes and lifetimes. Do not collapse OpenAI inclusive input accounting into Claude's disjoint fields, or Gemini Interactions output/thoughts into a single already-inclusive total.

Append-only thinking and compaction state matter as much as JSON schema. An external rewrite of past tool results can invalidate [Claude thinking signatures](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking), while an OpenAI compact response or Gemini interaction identifier has its own continuation rules. A syntactically accepted proxy request can still alter the task.

### Wire minification is not model-context compression

Removing whitespace from HTTP JSON or applying gzip reduces transport bytes. Providers parse the envelope before constructing model context, so a smaller serialized body is not evidence of fewer billed tokens. When JSON is itself text inside a tool result, changing its representation can change token count; that is a separate content transformation with syntax/fidelity implications.

Do not remove tool descriptions, schema constraints or fields on the assumption that they are irrelevant. They can determine argument correctness and permissions. Measure the exact request through provider usage or a supported count endpoint, and test semantic behavior. Previous serialized-schema and gzip ratios are withdrawn as current provider-billing evidence.

## Response caches and deduplication

A response cache skips inference by returning an earlier result; a prefix cache reuses computation while still running the current request. They have different correctness requirements.

[LiteLLM exact caching](https://docs.litellm.ai/docs/proxy/caching) keys request content and supported parameters. A growing agent history normally changes the key. Even an exact request can become stale when external files, time, permissions or tool state change. Cache only a declared immutable/read-only operation with explicit identity, expiry and invalidation. Never replay a side-effecting tool action as if it just executed.

Current [LiteLLM semantic-cache documentation](https://docs.litellm.ai/docs/proxy/caching_semantic) specifically warns about agent loops: adjacent turns can be highly similar, and assistant tool-call structure is not fully represented in the embedding text. A stale response can repeat an obsolete tool call; raising the similarity threshold does not reliably solve this. Embedding lookup also adds cost and latency.

Tenant and end-user partitions are part of correctness. LiteLLM's optional end-user scope falls back to a broader key-level scope if the expected user identifier is absent. A missing identity must not silently widen an application's reuse permission. Cache hit-rate alone cannot validate this boundary.

Deduplicating concurrent identical requests needs cancellation and ownership rules: one caller's cancellation must not corrupt another's result, and credentials, permissions and mutable state must match. The mechanism does not authorize sharing across users.

### Compression and routing proxies

Learned prompt compression changes evidence and needs fidelity testing plus compressor compute/latency accounting. Earlier universal LLMLingua compression ceilings and a fixed 5.5× break-even threshold are withdrawn. A gateway plugin's existence does not prove current model compatibility or accepted-task savings.

LiteLLM now has an [AutoRouter add-on](https://docs.litellm.ai/docs/auto_router/), beyond load balancing. Classifier inference, model switching, escalation and session pinning belong in a separate [routing experiment](/research/context/techniques/10-model-routing-and-delegation). Do not bundle them into a claimed compression win.

## Owned inference: prefix reuse and storage

### vLLM automatic prefix caching

[vLLM APC](https://docs.vllm.ai/en/stable/features/automatic_prefix_caching/) reuses matching prefix KV blocks to skip prefill. It does not shorten output decoding, so long-generation workloads can see little benefit. Performance depends on shared prefixes, eviction, concurrency and engine/model configuration.

The [current cache design](https://docs.vllm.ai/en/stable/design/prefix_caching/) incorporates parent hashes, exact block tokens and extra identity such as LoRA/media hashes and cache salts. It documents SHA-256 defaults from v0.11 and serialization differences between pickle and canonical CBOR choices. Per-request salts constrain reuse to an authorized group. They are identity controls, not a reason to pool unrelated tenants.

Prefix reuse is intended to preserve the same model computation. Do not promise byte-identical completions across different hardware, engine builds, scheduling or numerical modes merely because temperature is zero. Evaluate correctness and required numerical equivalence for the actual deployment.

### SGLang RadixAttention and HiCache

[SGLang HiCache design](https://docs.sglang.io/docs/advanced_features/hicache_design) extends radix-prefix reuse from GPU memory to host memory and a storage backend. **L1 GPU and L2 host memory are private to each inference instance.** Cross-instance reuse requires L3 configured to a shared namespace; increasing the host-cache size does not pool other machines' RAM.

The default file backend is node-local unless its path is a shared mount. Distributed backends also require matching namespace/configuration. Prefetch policies trade waiting for hits against recomputation: best effort, wait-complete and timeout do not have the same latency behavior. See [HiCache practices](https://docs.sglang.io/docs/advanced_features/hicache_best_practices).

Measure GPU prefill avoided against CPU memory, device/host transfers, storage lookups and writes, locking, eviction and cold recovery. Historical SGLang/HiCache speedups belong to their reported workload/hardware; they are not current Jackin latency measurements.

### LMCache and cross-process sharing

Current [LMCache multiprocess documentation](https://docs.lmcache.ai/mp/index.html) describes a separate cache service reached by vLLM over ZMQ or gRPC, with node-level sharing and configurable L1/L2 storage. Its prerequisites explicitly call for the latest development branch and compatible vLLM. This review did not qualify a stable released pair or execute the service.

Process separation can isolate resource contention, but introduces transport and lifecycle requirements. Match model weights, tokenizer, positions, adapters, KV representation, runtime compatibility and authorization before reuse. Non-prefix CacheBlend-style methods and lossy KV quantization are different treatments from exact prefix caching; evaluate them separately.

### Cache-aware replica routing

[SGLang Model Gateway](https://docs.sglang.io/docs/advanced_features/sgl_model_gateway) balances cache locality with worker load. Current documentation also states that multiple gateway replicas do not synchronize their cache-aware radix trees. Session affinity at one layer therefore does not guarantee a global hit.

A cache-heavy hot worker can have worse queue latency than a cold idle worker. Compare scheduling policies using end-to-end p50/p95 latency, accepted throughput and resource cost, including misses and failover. Do not infer a fleet-wide latency saving from a prefix-hit counter or an advertised example.

## Decision and missing evidence

For hosted Jackin, prioritize truthful accounting and native-compatible boundaries before a gateway rewrite. Any optional gateway must preserve the off/native path, permission contract, recovery and signed state. Self-hosted KV controls require an owned-serving proposal with actual hardware and workload evidence; they are not portable hosted optimizations.

Withdraw blanket negative-cost/identical-output labels, serialized-JSON token claims, fixed historical speedups and stale “load balancing only” descriptions. No GPU throughput, resident memory, transport overhead, tenant-isolation execution or production gateway compatibility was measured here. [Coverage dispositions](/research/context/techniques/tools/#october-24-provider-evidence) retain each former infrastructure category.
