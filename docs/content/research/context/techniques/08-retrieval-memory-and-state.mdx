**Research state:** Current

## Summary

Snapshot **2026-10-24T01:15:00Z**; mutable primary documents were reopened on October 24 and their access times recorded. Retrieval can avoid unnecessary loading and repeated exploration, but a smaller answer, an unchanged-file marker and a remembered conclusion have different correctness requirements. Preserve native reads and edits while qualifying one additional retrieval path at a time.

Three distinctions govern the design: a source index is not evidence that the current model saw a file; a path or URL is not an immutable original; and a memory note is not an instruction with authority over the current user. The target is useful automatic retrieval and recovery under Jackin's lifecycle, with an explicit native/off path. No external retrieval backend has completed that qualification in this research.

## Question and scope

When do scoped instructions, repository maps, search, handoffs and durable memory improve accepted work relative to the host's native context management? Which content can be omitted safely, who can recover it, and what survives restart, compaction, a fork or a worktree change?

## Native instruction and memory loading

### Keep mandatory policy visible and detail discoverable

Current [Claude Code memory documentation](https://code.claude.com/docs/en/memory) distinguishes startup instructions from on-demand nested/path rules. Imports load with the importing file; splitting text into `@` imports does not itself defer it. Current AGENTS instruction discovery has version and resolution rules. Audit the selected host's effective files instead of assuming one repository filename represents the whole prompt.

Keep the authoritative task constraints and security rules available before the actions they govern. An index may point to specialist detail, but must make its trigger and required reading clear. Moving mandatory rules behind optional retrieval can change behavior even if no source text is deleted. Instruction files guide the model; enforced settings and OS permissions carry the security boundary. Native tool discovery and scoped rules belong in the [baseline](/research/context/techniques/06-context-architecture/).

### Auto memory is bounded, shared state

The same [native documentation](https://code.claude.com/docs/en/memory#auto-memory) specifies:

| Surface | Current loading or ownership rule |
|---|---|
| Startup `MEMORY.md` | First 200 lines or 25 KB, whichever is smaller; topic files load on demand |
| Startup `CLAUDE.md` | Loads wholly only up to 4 MiB; larger files are skipped; nested/path rules have separate limits |
| Repository memory | Machine-local and shared across the repository's worktrees/subdirectories |
| Child contexts | Ordinary subagents do not load the parent's auto memory; forks inherit its context; a child's own memory is separate |
| Enablement | Local default differs from self-hosted/background/nested-session behavior; inspect effective settings |

This replaces the old unlimited-CLAUDE.md and universal-default-on assumptions. A line/byte cap is not a fixed token tax. Jackin should preserve an existing native memory choice, identify its actual directory, and avoid injecting the same note through several mechanisms. Sharing a project note does not make a branch-specific fact current: retain source revision, author, scope and review/expiry information. Credentials and private task details need the same access controls as the underlying source.

### What compaction reloads

[Current Claude Code context documentation](https://code.claude.com/docs/en/context-window#what-survives-compaction) retains system/style instructions, reloads root rules and auto memory, and reloads nested/path rules on demand. Skill descriptions are rebuilt from version 2.1.304; the old claim that the listing always disappears is stale. Invoked bodies still have 5,000-token-per-skill and 25,000-total budgets. Up to five previously read or edited files are reread, choosing the most recently modified; a file above 5,000 tokens can return as a reference. Compact-source hooks run again, while their earlier added context is summarized.

These are documented host rules, not a proof that every decisive fact survives. A recovery reference may remain useful after its exposure epoch ends. Invalidate permission to emit “already seen” stubs on unknown/reset epochs without deleting referenced originals. Background work can continue through compaction; a reset must not accidentally start the same operation twice.

## Handoffs and recoverable observations

### File-based progress and continuation

[Anthropic's long-running harness](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents) uses an initializer, explicit feature requirements, progress artifacts and verification to bridge sessions. Its [March 2026 follow-up](https://www.anthropic.com/research/harness-design-long-running-apps) describes a different model/harness combination that removed explicit context resets and used continuous SDK compaction. Neither establishes that always clearing, always resuming, or always handing off is cheapest at a fixed model and task.

A useful handoff contains the goal and non-negotiable constraints, source/worktree identity, decisions with reasons, changed files, completed verification, failures, unfinished work and exact artifact references. Preserve a critical requirement verbatim when paraphrase can change its scope. The receiver revalidates mutable facts and can retrieve evidence behind a conclusion. Do not mark work complete solely because the previous agent's summary said so.

Generate checkpoints through the task owner after meaningful progress, with one writer or an explicit merge protocol. An exit-only hook can be skipped by a crash and should not be the sole persistence guarantee. A shared coordination file helps discover ownership; it does not authorize overwriting another agent's work or substitute for session identity. Compare handoff-plus-new-context, native resume and native compaction on the same multi-session tasks, charging checkpoint generation and recovery.

### A locator is not an exact-original guarantee

[Manus's context-engineering report](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus) motivates removing bulky context while retaining routes back to evidence. A mutable URL, renamed path or rerun command can return different information. Jackin's stronger requirement is a scoped, acknowledged artifact containing the exact authorized bytes, producer status, timestamp, content identity and completeness. Recovery opens that observation; it does not re-execute the producer.

Archive before a lossy replacement. If optional transformation or storage fails, return the already captured authorized observation. Authorization, mandatory redaction and integrity failures must not bypass policy. Refuse new loss before evicting active originals under quota pressure. Off stops new reductions while preserving references already emitted. These are proposed [broker contracts](/research/context/engine/07-memory-and-state/), not shipping Jackin features.

Executed product faults explain the requirement: Headroom's reviewed Rust CCR write API does not acknowledge its tested database failure; LemonCrow Lite can emit a repeat-shell marker after a failed spill. Caveman's tested closed-store path instead returned the original with an error, and its native capacity test preserved old records while refusing a new one. These specific paths do not prove universal product safety or failure. [Headroom](/research/context/tools/02-headroom-design/), [LemonCrow](/research/context/tools/10-lemoncrow-design/), [Caveman](/research/context/tools/01-caveman-design/).

## Client memory tools and provider history management

### Client-side memory operations

The current [Claude memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool) uses `memory_20250818` without requiring a beta header. The application supplies storage and executes view/create/edit/delete/rename operations. SDK helper names still contain `beta`; that does not make the storage a provider-hosted database. Keeping the same tool declaration and application store enables later conversations to reuse it.

Treat the handler as a security boundary: admit the consumer and storage root, validate every path and operation, handle symlinks and concurrent writes, and distinguish missing/denied records. Memory content stays subordinate to current instructions. The cost includes extraction/writes, injected protocol, retrieval and stale-note repair; a memory directory's existence does not establish a net benefit. This is a separate SDK integration from Claude Code auto memory.

### Context editing and its cache tradeoff

[Claude context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing) can clear selected tool results or thinking under model-specific rules. A placeholder preserves conversation structure but is not the original. Protect critical tool results and retain a usable recovery path. Provider-managed edits differ from a gateway rewriting past messages: current [preserved-thinking rules](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking) can reject incompatible earlier-history changes.

The original [context-management announcement](https://claude.com/blog/context-management) reports 84% fewer tokens on a 100-turn web-search evaluation, with performance improvements of 29% for editing and 39% for editing plus memory on its internal search evaluation. Those are first-party, combined/historical workload results. They do not isolate memory savings or predict current coding work.

The old fixed `11.5 × suffix/cleared` break-even used old price assumptions. In a simplified prefix-only scenario, clearing `C` tokens while rewriting `S` retained tokens pays back only when future savings `N × C × read_rate` exceed the rewrite premium `S × (write_rate − read_rate)`. This excludes summaries, new uncached input, changed cache eligibility, rereads and failures. Use current [cache classes](/research/context/techniques/07-caching-exploitation/) and actual receipts rather than treating that inequality as a task result.

### Compaction is a separate, billed continuation

[Current Claude compaction](https://platform.claude.com/docs/en/build-with-claude/compaction) has on-demand and threshold paths, signed boundaries and model-specific continuation rules. Bill the documented iteration records once; top-level usage alone can omit summary work. [OpenAI compaction](https://developers.openai.com/api/docs/guides/compaction) returns a canonical continuation window on the standalone path. Gemini stored history requires its recurring tool/system/configuration contract. The [provider chapter](/research/context/techniques/12-provider-features/) owns these details.

Do not treat the old $1.98 example as a universal compaction bill or the old missing-cache-rate observation as a current API fact. Native compaction is already part of the control arm. The CompactionBench/APEC abstract reports controlled long-horizon software-evolution experiments alongside observational coding-session analysis. Relevant coding context-management research is therefore not categorically absent, but abstract-level access does not verify the full harness or raw data, and its reported outcomes are not a Jackin reproduction. [Primary research](https://www.microsoft.com/en-us/research/publication/benchmarking-long-horizon-agent-context-compaction-with-compactionbench/).

## Repository retrieval and external memory evidence

### Search, maps, symbols and semantic indexes

Compare the host's native grep/read/navigation against an additional backend. [Cursor's November 2025 study](https://cursor.com/blog/semsearch) reports improved codebase-question accuracy and retention from semantic search alongside grep; it does not supply a complete accepted-task cost comparison for Jackin. [Cline's historical design argument](https://cline.bot/blog/why-cline-doesnt-index-your-codebase-and-why-thats-a-good-thing) identifies fragmentation, freshness and duplicate-storage risks; it is not a controlled demonstration that indexing never helps. [Aider's map](https://aider.chat/docs/repomap.html) ranks repository relationships within a configurable token budget that can expand, rather than guaranteeing a fixed 1,000-token ceiling.

Use outlines/maps to locate evidence, then request the current exact region when the task depends on implementation details. Index identity includes repository/worktree, admitted files, dirty content, parser/configuration and source generation. Model-exposure identity additionally includes consumer and context epoch. LeanCTX's branch/restart/custom-consumer probes demonstrate why those are separate; a current source cache can still emit a stub inappropriate for a fresh model context. [LeanCTX](/research/context/tools/04-leanctx-design/).

Restricted MCP retrieval adds tools and schema/discovery cost; it does not replace native reads automatically or mint native read-before-edit receipts. Keep execution and editing in the host. Compare native retrieval, a restricted LeanCTX process, LemonCrow Runtime Lite and narrow structural primitives independently. Heavy process-global libraries, optional model downloads and license boundaries are part of the [reuse decision](/research/context/engine/09-reuse-decision-matrix/). An embedding index may improve recall and still cost more after construction, repair, lookup and extra turns.

### Dedicated memory systems: benchmark definitions matter

| Historical primary evidence reopened | Supported interpretation | Limit for this decision |
|---|---|---|
| [Mem0 v1](https://arxiv.org/abs/2504.19413v1) | Dialogue extraction/retrieval; 26% relative judge gain over its OpenAI comparator and over 90% token-cost reduction versus full context are different comparisons | Model, grader, history ingestion and full-context accuracy must remain visible; no current Jackin release-matched trial |
| [Letta filesystem study](https://www.letta.com/blog/benchmarking-ai-agent-memory/) | Reported 74.0% on LoCoMo with GPT-4o mini and constrained tool rules | Files are automatically embedded, and semantic `search_files` is required first. This is **not a grep-only/no-index baseline**; comparison to Mem0's reported 68.5% is not one common rerun |
| [ConvoMem v1](https://arxiv.org/abs/2511.10523v1) | Conversational benchmark with 75,336 questions; evaluated full-context methods exceed tested Mem0 variants on shorter histories | The reported 30/150-conversation transition is workload-specific, not a universal threshold for repository tasks |
| [MemGPT v2](https://arxiv.org/abs/2310.08560v2) | Explicit movement between in-context and external memory, evaluated on document analysis and multi-session chat | A useful architecture does not establish today's coding quality or economics |
| [Zep's critique](https://www.getzep.com/blog/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/) | Challenges competitor ingestion, timestamp handling and benchmark design | Zep and Letta are interested vendors; their critiques are not neutral replications or a universal memory-service verdict |

Retain full-context, file-backed iterative search and selected memory-service baselines where feasible. Charge memory extraction, retrieval, embedding/judge calls and all failed attempts. Test temporal corrections, contradictory notes, abstention, source provenance and cross-user/worktree isolation. The former claim that all memory products necessarily lose quality, and the universal claim that no relevant coding research exists, are too broad.

### Semantic response caching is a different treatment

[GPTCache](https://aclanthology.org/2023.nlposs-1.24/) reports conditional cache-hit speedups. [GPT Semantic Cache v3](https://arxiv.org/abs/2411.05276v3) reports 61.6–68.8% hits and over 97% positive-hit accuracy in its repetitive-query setting. These are different projects and denominators. They do not establish a safe coding-task hit rate, and the earlier prediction of approximately zero hits was also unmeasured.

Similarity of a prompt is insufficient to reuse an answer about a changed repository, different permissions or a side-effecting task. A candidate cache needs complete input/source/configuration identity, authorization, expiry and task-specific correctness checks. Consider read-only deterministic subproblems separately; never treat a remembered execution result as proof that the requested action ran now. This remains outside the initial automatic profile.

## Implications for jackin❯

Build small Rust-owned admission, source identity, exposure epoch and exact-recovery interfaces around one selected worker. Preserve native context features and the user's model/effort. Start retrieval in an explicit experimental profile with independent worktree/consumer state and no unqualified unchanged-content omission. Package and configure it automatically only after actual host and outcome qualification; do not make operators maintain parallel global plugins by hand.

The first useful automatic profile can deliver reviewed instruction assets and a qualified diagnostic reducer before adding a retrieval backend. Retrieval joins that profile when it demonstrates better accepted work under the [canonical gates](/research/context/tools/07-evidence-and-claims/), with actual startup/index/storage/query costs and a working off/native path. [Implementation sequence](/research/context/engine/10-rollout-and-validation/).

## Limitations and next experiments

The highest-value comparisons are native search versus one restricted retrieval backend; native continuation versus explicit handoffs on the same long task; and existing native memory versus one scoped note policy. Include rare decisive facts, missing originals, edits after reads, compaction/resume/fork, stale indexes, denied paths, concurrent roots, crash and quota pressure. Pilot task counts discover defects; they do not prove non-inferiority.

No personal account, provider bill, end-to-end retrieval task, real host compaction or memory-service outcome was executed here. Older numerical claims and each previous topic remain individually mapped in the <RepoFile path="docs/content/research/context/techniques/tools/refresh-2026-10-24/jackin-architecture/integration-coverage-dispositions.json">integration coverage ledger</RepoFile>. No savings is claimed from merely replacing a transcript with a shorter file.
