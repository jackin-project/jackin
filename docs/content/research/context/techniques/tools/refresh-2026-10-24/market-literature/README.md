## Main findings

Narrow Rust components are plausible reuse leads, with different default features and native dependencies. sem-core's optional disk-cache feature is off by default; the architecture bundle's extracted two-dependency SQLite constraint probe is not a successful sem-core consumer build. fff-search defaults to ripgrep and does not need Zig in that profile, but still has native libgit2/LMDB dependencies. mq-markdown is a narrower parser surface than the mq-lang interpreter and its optional I/O capabilities.

Licenses prevent treating every attractive product as permissive reusable code. Serena's current application is GPL3+ while its separately identified SolidLSP component is MIT; jCodeMunch's DualUse1.2 license restricts commercial use and modified redistribution; ContextMode is ELv2; Boost's application is All Rights Reserved preview software while its skills are MIT. This is a source/component classification, not a legal opinion.

Published numbers use materially different denominators. TOON's pretty-JSON baseline differs from compact JSON; Paritok's toy content run differs from a projected schema-heavy full stack; jCodeMunch compares symbols with files; CodeDB's twelve-task result has concentrated feature-task savings. Boost's introduction and current benchmark page have different cohorts/costs, and the newer cost table provides no success cell. The reports are preserved separately.

The literature has useful independent evidence and important counterevidence, but no cross-product winner. AgentDiet includes auxiliary-model expense and mixed pass-rate changes. TurnCost challenges flat-price accounting under a simulated high-hit cache; it does not show that removing turns preserves task success. CompactionBench/APEC was available only as a public abstract. CAVEWOMAN paper and expanded-repository versions differ. Notation Matters shows that format-token savings can accompany accuracy loss. The two incorrect routing citations are withdrawn.
