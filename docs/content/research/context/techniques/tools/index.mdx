A samples file is a JSON array of objects with <code>label</code> and <code>text</code> strings. File reads preserve CRLF and final-newline bytes before UTF-8 decoding. Offline request output contains the supplied content: retain it only where that content is authorized.

## Explicit network execution

Only <code>count_tokens.py</code> and <code>image_tokens.py</code> accept <code>--execute</code>. That opt-in sends the prepared content to Anthropic using <code>ANTHROPIC_API_KEY</code>, or a named <code>--api-key-env</code> variable. It does not reuse Claude Code credentials. This refresh did **not** execute provider calls.

The [official counting documentation](https://platform.claude.com/docs/en/build-with-claude/token-counting) governs support, rate limits and estimate semantics. There is no default model or assumed tokenizer-family equality. An input-counting endpoint cannot calibrate hidden reasoning by subtraction or reveal a real cache hit.

## Claude transcript accounting

The parser deduplicates response IDs within a session; absent a session ID, the explicit file scopes the response. Equal receipts repeat. Monotone cumulative streaming receipts replace earlier ones. Model conflicts, decreasing counts, missing response IDs, incomplete input/output and inconsistent TTL breakdowns fail visibly.

Cache writes are partitioned into five-minute, one-hour and **unknown TTL** classes. The aggregate is not added again. If final <code>usage.iterations</code> exists, its entries replace the top-level counters so compaction is counted once.

A <code>--prices</code> file contains USD/MTok for <code>input</code>, <code>cache_read</code>, <code>cache_write_5m</code>, <code>cache_write_1h</code> and <code>output</code>, keyed by exact model. This aggregate pricing mode is suitable only when all receipts for each model share that price profile. Separate mixed context tiers, authentication routes, service modes and dates, or price each request with the final-usage instrument first. The script does not infer those conditions from a model name.

Unknown model/TTL means unknown estimate, not zero; a true zero remains zero. Output includes reported thinking, prose and tool arguments. Include failed attempts, children, compaction and repair sessions explicitly. Current SDK main-loop <code>result.usage</code> and whole-tree <code>modelUsage</code> are different summaries; this JSONL parser does not automatically reconcile both. [Agent-loop contract](https://code.claude.com/docs/en/agent-sdk/agent-loop).

## Explicit final-usage contracts

| Contract | Normalization | Required distinction |
|---|---|---|
| OpenAI Responses, paid writes | Ordinary input = input total minus cached reads minus writes; write lifetime buckets must sum | <code>--cache-writes paid</code> for the documented API profile; missing write data fails |
| OpenAI Responses, earlier ordinary-input policy | Ordinary input = input total minus cached reads | Explicit <code>--cache-writes ordinary-input</code>; not a Codex-credit receipt adapter |
| Claude Messages | Disjoint ordinary/read/write input; iterations counted once | Thinking is a subset of output where reported; unknown TTL is not guessed |
| Gemini Interactions | Ordinary input = total input minus cached; generation = output plus thought | Thought and output are disjoint; missing thought or inconsistent totals fail |

Optional <code>--rates</code> is a flat class-to-USD/MTok JSON object for **this one request's** exact model, context tier, date and API route. It does not fetch prices or apply subscription quotas. Non-token fees, contractual discounts, storage and tax remain outside the estimate. Missing prices return unknown. [Current economics](/research/context/techniques/01-economics-and-measurement/) explains the source contracts.
