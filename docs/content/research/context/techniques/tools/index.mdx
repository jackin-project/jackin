## Instruments and scope

| Instrument | Input and result | Limit |
|---|---|---|
| <RepoFile path="docs/content/research/context/techniques/tools/count_tokens.py">count_tokens.py</RepoFile> | Explicit model plus UTF-8 text, file, or labeled JSON samples; emits an offline request by default | A provider input-count estimate includes framing; it is not an output-token receipt or an invoice |
| <RepoFile path="docs/content/research/context/techniques/tools/image_tokens.py">image_tokens.py</RepoFile> | Explicit model and synthetic PNG dimensions; prepares image-count requests | Measures neither OCR accuracy nor exact-text preservation; no inherited universal pixel formula |

| <RepoFile path="docs/content/research/context/techniques/tools/test_measurement_tools.py">Accounting regressions</RepoFile> | Synthetic receipts, duplicate/streaming records, cache TTLs, zero costs, CRLF text, PNG headers | Offline unit evidence for the instruments, not provider or agent qualification |

Run from this directory:

```sh
python3 count_tokens.py --model EXACT_MODEL text 'public fixture'
python3 count_tokens.py --model EXACT_MODEL file fixture.txt
python3 image_tokens.py --model EXACT_MODEL 280x280 1000x1000
python3 session_cost.py explicit-session.jsonl explicit-worker.jsonl
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v test_measurement_tools.py
```

A samples file is a JSON array of objects with <code>label</code> and <code>text</code> strings. File reads preserve CRLF and final-newline bytes before UTF-8 decoding. Offline request output contains the supplied content: retain it only where that content is authorized.

## Explicit network execution

Only <code>count_tokens.py</code> and <code>image_tokens.py</code> accept <code>--execute</code>. That opt-in sends the prepared content to Anthropic using <code>ANTHROPIC_API_KEY</code>, or a named <code>--api-key-env</code> variable. It does not reuse Claude Code credentials. This refresh did **not** execute provider calls.

The [official token-counting documentation](https://platform.claude.com/docs/en/build-with-claude/token-counting) is the authority for endpoint support, rate limits, and estimate semantics. Recheck the exact model before execution; the scripts deliberately have no default model or assumed tokenizer-family equality. An input-counting endpoint cannot calibrate hidden reasoning by subtraction.

## Usage accounting

The parser deduplicates response IDs within a session; when the session ID is absent it scopes the ID to the explicit file. Equal receipts repeat. Monotone cumulative streaming receipts replace earlier ones. Model conflicts, decreasing counts, missing response IDs, incomplete input/output receipts, and inconsistent TTL breakdowns fail visibly.

Cache writes are partitioned into five-minute, one-hour, and **unknown TTL** classes. The aggregate is not added a second time. A supplied rate file must contain USD per million tokens for <code>input</code>, <code>cache_read</code>, <code>cache_write_5m</code>, <code>cache_write_1h</code>, and <code>output</code>, keyed by the exact model string. Unknown TTL or unknown model means an unknown estimate, not zero. A real zero remains zero.

Output usage includes reasoning, prose, and tool arguments as reported by the source. The script does not label a replay-count residual as measured thinking. Include all failed attempts, subagents, compaction, and repair sessions in the explicit file list; missing files remain missing evidence. Provider invoices, API list-price estimates, and subscription quotas are separate measurements.
