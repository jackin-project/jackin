## Evidence and native baseline

The [current Claude Code style contract](https://code.claude.com/docs/en/output-styles) supplies a stronger baseline than the old generic “be concise” instruction:

| Native behavior | Current contract | Qualification |
| --- | --- | --- |
| Built-in `Concise` | Available from 2.1.237; result first, reduced preamble, narration and recap | Detailed answers requested by the user, errors, tests, warnings and destructive-action confirmations remain complete |
| Style switching | New style applies on the next message from 2.1.251 | Current [cache documentation](https://code.claude.com/docs/en/prompt-caching#changing-output-style) describes an appended conversation message that preserves the existing prefix |
| `/output-style` | Available from 2.1.269, including documented noninteractive/SDK use | Settings names are case-sensitive; the slash command ignores case |
| Custom style files | Read at startup | Creating or editing a file requires restarting to load the edit; this differs from selecting an already loaded style |
| Coding instructions | `keep-coding-instructions: true` retains the engineering section in the full system prompt | The shorter prompt lacks that section, so the field has no effect there; changing prompt mode is another intervention |
| Children | Main conversation and forks inherit the style | Ordinary subagents have their own prompts and do not automatically inherit it |

These are documented host behaviors, not a native session execution in this refresh. Record the host version, prompt mode, style source and child behavior. Do not quietly change the prompt mode, model, review policy or tool permissions to make a style treatment work. The [Caveman dossier](/research/context/tools/01-caveman-design/) separates its style skill from the broader plugin's other policy changes.

## Output registers and the independent evidence

A useful treatment ladder is native concise behavior, plain explicit brevity, telegraphic prose, and aggressively abbreviated output. Preserve obligations at every level: exact identifiers, negation, conditions, uncertainty, references, tests and the information needed to act. A shorter explanation that omits a failed test is an acceptance failure even if the code patch happens to pass another check.

[CAVEWOMAN v1](https://arxiv.org/html/2606.24083v1) is independent evidence about compression channels, not a benchmark of the current Caveman release. Its eight-model, five-dataset study uses 11,465 short-answer items per model. Input compression applies deterministic part-of-speech filtering; output compression changes the system style instruction. Decoder budgets also change across levels, so the treatment is not a pure style-only comparison at constant output allowance. At the first reduction level, the paper reports cheaper output compression in **17 of 20 API model/dataset cells**, while input deletion can increase cost through longer responses. Its NLI measure compares surface text with the model's own baseline, not ground-truth acceptance.

Keep that paper separate from the [expanded October repository](https://github.com/danielle34/cavewoman/tree/28875b39a6c957a0ae96950538cdacfcd0eff0b3): the later version adds a ninth model and extensions and reports 18 of 20 cells after judge corrections. Neither denominator validates a fixed current model on long coding tasks. Hidden reasoning, extraction failures, changed budgets, task selection and the availability of only partial generation artifacts limit transfer.

## Reasoning prompts: historical results, different controls

| Technique | Primary evidence and mechanism | Current disposition |
| --- | --- | --- |
| Chain of Draft | [2502.18600v2](https://arxiv.org/html/2502.18600v2): terse intermediate steps on reasoning benchmarks | Candidate prompt treatment; its best-case token fraction is not an agent-task savings forecast |
| Concise CoT | [2401.05618](https://arxiv.org/abs/2401.05618v3): shorter GPT-3.5/4 reasoning on multiple-choice tasks, with task-dependent accuracy changes | Evidence against assuming brevity is free; the abstract's math degradation is not silently converted from percent to percentage points |
| TALE | [2412.18547v5](https://arxiv.org/html/2412.18547v5): task-aware token-budget prompts | Advisory budgets can be counterproductive when too tight; include any budget-estimation call in cost |
| Sketch-of-Thought | [2503.05179](https://arxiv.org/abs/2503.05179v4): conceptual, symbolic and expert-language paradigms selected for tasks | Historical multi-dataset evidence; selector, model, prompt and task must be reproduced separately |
| System-2-to-System-1 distillation | [2407.06023v2](https://arxiv.org/html/2407.06023v2): train a model on filtered outputs from more expensive reasoning | Training/model change, outside fixed-model runtime compression; the paper also reports tasks that resist distillation |

These papers concern particular visible reasoning protocols or training procedures. They do not authorize reconstructing hidden reasoning, reducing the user's selected effort, or assuming that an instruction controls every billed reasoning token.

The [current effort guide](https://platform.claude.com/docs/en/build-with-claude/effort) treats effort as a behavioral signal rather than a hard budget, and distinguishes models whose visible response length does not reliably follow effort. Prompt guidance can influence when or how a model reasons; “style cannot affect thinking at all” was too strong. Conversely, an instruction to be brief is not a guaranteed reasoning cap. Measure provider usage directly and retain the same effort in the main comparison; any effort sweep belongs in a separately labeled experiment.

## Symbols, aliases and unfamiliar language

### Symbolic notation

[MetaGlyph](https://arxiv.org/html/2601.07354v1) tests eight models and finds that parsing notation and following its operators can diverge. The author reports 100% parse success but 26% membership-operator fidelity for Haiku 4.5. That task-specific result does not describe every Claude model or every symbolic operator. The local token fixtures above also defeat a universal “one glyph equals one token” assumption.

Use established domain notation when it is part of the user's task and understood by its consumer. A newly invented glyph language adds an interpretation problem. Record syntax, model version and task-specific execution checks; a deterministic parser round trip proves only the codec.

### Repeated identifiers and codebooks

An alias is plausible when a long name repeats and an explicit, collision-free mapping remains available. In the recorded fixture, the full path costs 18/19 tokens, `RCF` costs 2, and its legend costs 20/21. The purely token-count break-even occurs at the second mention. This calculation excludes the legend's cache class, repeated loading after compaction, retries and errors resolving the alias.

Keep the full identifier in authoritative tool arguments, persisted patches and final references where needed. The model-visible shorthand must not silently rename a file or change an API identifier. Cross-agent mappings require an explicit version and recovery location; ordinary child prompts may not contain the parent's legend.

[MTOB](https://arxiv.org/abs/2309.16575v2) studies learning a low-resource language from extensive reference material. [NEO-BENCH](https://aclanthology.org/2024.acl-long.749/) studies robustness to new words. They provide reasons to test unfamiliar representations; neither measures the reliability or economic break-even of Jackin session aliases.

### Natural language and instruction compression

Character density is not token density, and tokenizer behavior changes across languages and versions. The [NeurIPS 2023 multilingual tokenizer study](https://arxiv.org/abs/2305.15425v2) documents unequal encoding costs across languages, not a generally safe translation strategy. Preserve the language appropriate for the user and task; translation can alter scope, modality or technical terms even when the token count falls.

Instruction-side compression can reduce repeated input, but its value depends on the actual cache path. At the snapshot rates, Fable 5.1 output is $50/M and cache reads $0.25/M: a **200:1 price ratio**, not the old universal 50:1. Writes and uncached reads have different rates, and other models differ. See [provider features](/research/context/techniques/12-provider-features/) and [cache economics](/research/context/techniques/07-caching-exploitation/). Editing an instruction can also invalidate a prefix or weaken a rule; it is not costless because the resulting text is shorter.

[Prompt-compression evaluation](https://arxiv.org/html/2505.00019v1) reports task- and context-dependent outcomes. [CompressionAttack](https://arxiv.org/html/2510.22963v2) specifically studies adversarial semantic drift through compressors. Preserve the authority and provenance of instructions, and do not turn untrusted tool text into governing instructions during shortening.

## Jackin decision and remaining uncertainty

Qualify a style-only treatment against native concise behavior first. Freeze the selected model, effort, host version, prompt mode and test policy. Include child outputs, retries, recovery reads, failed attempts and the user's required explanation in the result. Keep the original instructions recoverable and compare accepted tasks using the [validation harness](/research/context/techniques/16-validation-harness/).

No current Jackin acceptance or subscription-quota benefit was measured here. The open questions are sustained-task correctness, hidden-reasoning response, user readability, native child inheritance and net cost after cache effects. Aggressive registers, invented languages and model distillation remain separate experiments, not default settings.
