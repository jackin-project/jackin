## Baseline, measurement and acceptance

Use the selected model and effort with native host features before adding a custom persona. [Claude Code's built-in Concise style](https://code.claude.com/docs/en/output-styles) is available from 2.1.237 and reduces preamble, narration and recap while retaining requested detail and complete errors, tests, warnings and destructive-action confirmations. Merely asking for a terse answer is not evidence that the engineering work was completed.

The [accounting model](/research/context/techniques/01-economics-and-measurement/) includes generated tool arguments and provider-billed reasoning as well as visible prose. Do not subtract a local visible-text token estimate from a provider total and label the residual exact hidden thinking. Use explicit usage fields where available and preserve their provider-specific overlap rules.

Measure all attempts and the accepted result: retries after malformed output, repeated edits, recovery reads, child work, failed tests and the required final explanation. The [validation harness](/research/context/techniques/16-validation-harness/) defines the common gates. A smaller serialized response is intermediate evidence; an accepted task with lower total cost is the decision target.

## Edit the changed region

When the selected host supports a precise edit operation, a small uniquely anchored change can avoid generating an entire unchanged file. It must still be the native operation the host and repository accept.

The <RepoFile path="docs/content/research/context/techniques/tools/refresh-2026-10-24/representation/README.md">offline fixture</RepoFile> contains a deterministic 200-line file and a one-line value change. Complete JSON payloads count as follows:

| Synthetic payload | Bytes | cl100k | o200k |
| --- | ---: | ---: | ---: |
| File path plus exact old/new strings | 95 | 30 | 30 |
| File path plus complete new content | 5,524 | 1,809 | 1,809 |

The local application produces the expected final bytes and rejects an anchor that occurs twice. This proves the fixture transformation and its proxy counts. It does not measure whether a model can select a correct anchor, whether a particular host accepts the payload, or whether retry cost erases the saving. The 200-line synthetic file is deliberately favorable to a local edit.

[Aider's unified-diff work](https://aider.chat/docs/unified-diffs.html) provides author evidence that edit format can change model behavior, including omission and laziness failures. Its historical models and harness do not qualify every modern model or Jackin adapter. Test exact-match edits, unified diffs and whole-file writes where each is appropriate; do not force a format solely for its smallest successful example.

Preserve file revision, encoding, line endings and atomic application behavior. If the anchor no longer matches, obtain the current bounded region and regenerate rather than applying a fuzzy replacement silently. A rejected edit is a paid attempt when model generation preceded it. Recovery is part of the treatment cost.

## Remove redundant narration, preserve useful reporting

A candidate output instruction can request the result first, affected paths, verification and material limitations without restating an already applied patch. It should still explain a complex decision or failure when that information changes what the user should do.

Do not hide test failures, truncation, incomplete work or uncertainty to satisfy a length target. Do not replace the requested deliverable with a status sentence. Full code belongs in the file when the task is an edit; full explanatory prose belongs in the answer when the user requested an explanation. A fixed “never show code” or “always answer in one line” rule changes task acceptance.

Measure visible brevity independently from tool-use completeness. The [style chapter](/research/context/techniques/04-style-and-language-compression/) records native inheritance rules, current CAVEWOMAN evidence and complete short-text fixtures. Its manual wording candidates have no validated semantic-equivalence or model-compliance result.

## Reasoning and effort are separate controls

The [current Claude effort documentation](https://platform.claude.com/docs/en/build-with-claude/effort) describes a behavioral signal affecting reasoning and tool behavior, not a strict output allowance. It also notes model-specific differences in the relationship between effort and visible response length. Lower effort is an explicitly separate quality/cost treatment; it must not be smuggled into the fixed-model, fixed-effort compression arm.

Chain of Draft, Concise CoT and TALE target particular reasoning/output protocols. [Chain of Draft](https://arxiv.org/html/2502.18600v2), [Concise CoT](https://arxiv.org/abs/2401.05618v3), and [TALE](https://arxiv.org/html/2412.18547v5) do not establish a safe universal short reasoning budget for current coding agents. An instruction can influence reasoning behavior without offering hard control over billed hidden tokens. Include any estimator or judge calls in the all-attempt comparison.

## Structured output: useful constraints with explicit exceptions

Use structured output when a downstream consumer needs it, not to assume that JSON is always shorter than prose. Native API constrained decoding, a host's JSON event envelope and a request to “return JSON” are different mechanisms.

| Surface | Current primary contract | Qualification |
| --- | --- | --- |
| Claude API | [`output_config.format` JSON schema and strict tool use](https://platform.claude.com/docs/en/build-with-claude/structured-outputs) | Supported schema subset; SDKs may transform unsupported constraints |
| Claude Code noninteractive | [`--output-format json --json-schema`](https://code.claude.com/docs/en/headless) | `structured_output` may be absent on refusal; `format` is annotation rather than enforcement in this host path |
| OpenAI API | [Structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs) distinguish schema enforcement from JSON mode | Refusals and incomplete responses need handling; supported schemas differ from Claude |
| Ordinary agent prose | Natural-language formatting instruction | No parser guarantee; retry and validation belong to the application |

Claude's API does not support recursive schemas or numeric minimum/maximum constraints in the wire grammar; current OpenAI structured outputs document recursive schemas. Do not use one provider's subset as a universal schema specification. Claude SDK helpers can remove unsupported constraints, add their meaning to descriptions and validate afterward; sending a description is not the same as enforcing that constraint during decoding.

Claude currently documents three particularly relevant failure cases: refusals may return HTTP 200 and billed text outside the requested schema; `max_tokens` may yield incomplete output; and **string enum/const capitalization is not guaranteed**, even with a normal stop reason. The capitalization caveat also applies to strict tool use. A case-insensitive domain can map permitted values explicitly; a case-sensitive identifier or permission must be validated exactly rather than normalized blindly. JSON syntax validity is not semantic correctness.

There is overhead as well. Claude compiles a grammar, caches it for 24 hours since last use, adds format instructions to the prompt, and documents prompt-cache invalidation when the output format changes. Its current combined limits include 20 strict tools, 24 optional parameters and 16 union-typed parameters across strict schemas. Narrow a schema only when the consumer contract allows it; changing required fields to save tokens can remove necessary information. These are [documented limits](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), not executed account probes.

Validate the complete structured result before side effects. Record schema hash, host/API version, refusal/incomplete status, parser errors and application-level checks. A normal finish reason alone is insufficient.

## Prefill, stop sequences and generation limits

### Prefill

The old assistant-prefill recommendation is stale for current Claude models. [Current migration guidance](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#migrating-away-from-prefilled-responses) says last-turn assistant prefills are unsupported starting with Claude 4.6 and Mythos Preview and return HTTP 400. This is broader than “unsupported only while thinking is enabled.” Earlier-model support and ordinary earlier assistant messages are distinct. Use supported prompting or structured output for the actual endpoint.

### Hard generation caps

A model's `max_tokens` or equivalent caps generation for that request, not completed-task cost. On current Claude reasoning models it includes thinking plus response text; a cap can stop before the required answer or tool operation finishes. [Stop-reason documentation](https://platform.claude.com/docs/en/api/handling-stop-reasons) distinguishes exhausted output allowance from successful completion and other stops.

A cap can be a useful explicit spend guard. Evaluate whether the result is usable and budget recovery; it is not automatically an optimizer and an exhausted cap is not automatically a valid task. Soft task budgets, SDK session limits and workspace spend caps have different enforcement scope, documented in [governance](/research/context/techniques/25-meta-cost-governance-and-online-quality/) and [provider features](/research/context/techniques/12-provider-features/). In-flight work and retries can exceed a per-response accounting assumption.

### Stop sequences

Where the selected model/endpoint supports them, stop sequences can delimit a controlled single-shot output. The delimiter must not occur in legitimate strings, code, identifiers or structured content. Verify whether it is emitted, stripped or reflected in the stop metadata before parsing. Do not reuse a delimiter from one task as a universal hidden-reasoning limiter. No stop-sequence token saving was measured in this refresh.

## Style lifecycle and the terseness floor

A selected native style now applies on the next message; a newly edited style file still needs a restart. Custom coding-instruction retention depends on the host's prompt mode. Forks inherit the parent's style; ordinary subagents do not. [Native style documentation](https://code.claude.com/docs/en/output-styles) supplies these contracts, while the [Caveman dossier](/research/context/tools/01-caveman-design/) shows why a full plugin must not be treated as only a persona.

The [token-complexity study](https://arxiv.org/html/2503.01141v1) reports task/model-specific relationships between available output and correctness. It is not a theorem that a chosen compression ratio is safe above a universal threshold. The [compression trade-off study](https://arxiv.org/html/2505.00019v1) similarly motivates checking omitted conditions and hallucinations across tasks.

A practical correctness check asks whether scope, negation, exception conditions, identifiers, evidence and next actions survived. Counting the word “not” cannot establish that a condition retained its meaning. Use adversarial cases with similar identifiers, conflicting constraints, failed tests, mandatory caveats and tasks requiring substantial explanation.

## Jackin decision and unresolved evidence

Candidate defaults are the host's native concise mode where supported, exact native edits when the change is local, and a complete final report proportionate to the task. Structured output belongs where there is a real machine consumer and an explicit validation contract. Strong persona changes, hard caps and effort reductions remain independently labeled treatments.
