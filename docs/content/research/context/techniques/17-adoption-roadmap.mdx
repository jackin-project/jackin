**Research state:** Current

## Summary

Snapshot **2026-10-24T01:15:00Z**. The goal is a useful optimization layer that Jackin packages and configures automatically after qualification. An operator should not need to remember a compression command, maintain duplicate hook files, or manually classify every tool result. Native execution, editing, permissions, the selected main model and its reasoning effort remain the control.

The old day/week/month sequence is retained as three dependency stages, not a promise about elapsed implementation time. First establish the actual native baseline and one owned configuration surface. Then implement exact recovery and prove one real host/result treatment. Finally activate the combinations that pass task, security, cost and latency gates, with experimental alternatives and a working off path. No external optimizer has completed that full qualification in this research.

## Question and scope

What can be preserved or simplified today, what needs implementation, and what evidence permits automatic activation? This research PR changes documentation and reproducible evidence; it does not install an optimizer, modify user settings, lower model effort or make paid requests.

## Findings and implementation sequence

### Day 1 stage: native truth and owned configuration

| Work | Automation vehicle | Completion evidence |
|---|---|---|
| Record effective host/version, main model, effort, auth, permission mode, tools, rules and native context management | Launch/configuration audit | The actual process and delivered configuration match the recorded control; registry membership alone is insufficient |
| Detect duplicate owned policy and hook delivery | Asset manifest and discovery audit | One intended copy, correct precedence, preserved unrelated user content, clean update/off behavior |
| Preserve current native caching, tool discovery and compaction | Host-specific configuration contract | Supported effective settings and real discovery behavior; no redundant external owner |
| Consolidate a restrained optimization asset | One versioned instruction/configuration owner | Required constraints and literal content preserved; scope and precedence tested; no stronger upstream style policy silently substituted |
| Establish all-attempt local accounting | Existing usage collection plus bounded receipts | Provider classes, task/attempt identity and missing-data flags; privacy and export choices remain explicit |

Audit before removal: two apparent registrations can have different scopes or matchers. The old reductions of 966 tokens per startup and 118 per prompt came from a particular earlier setup, not a verified current installation. An automatic migration should remove only the obsolete bytes it owns, detect user modifications and leave unrelated settings intact. A hook-path string is not a content-integrity or trust check. [Baseline](/research/context/techniques/02-baseline-audit/), [ownership contract](/research/context/engine/05-output-and-prompt-layer/).

Native Concise/output-style choices and a restrained task policy are candidates for low-impact qualification. Preserve exact identifiers, caveats, diagnostics, required explanations and schema fields. Caveman's full plugin and Ponytail's shortest-diff policy are separate experimental arms; their delivered rules do more than shorten prose. The Caveman plugin's explicit child-model selections must not enter a fixed-model/effort comparison unnoticed. Do not promise a universal 20% output reduction or zero quality risk. [Style](/research/context/techniques/04-style-and-language-compression/), [output](/research/context/techniques/09-output-discipline/), [Caveman](/research/context/tools/01-caveman-design/), [Ponytail](/research/context/tools/09-ponytail-design/).

Keep the user's current main model and effort fixed throughout qualification. Moving exploration to a cheaper model, lowering effort, advisor routing or changing models mid-session is a separate treatment requiring explicit evaluation. The earlier fan-out divisor and per-switch dollar estimate are not current default settings. Choose session/task boundaries deliberately; automatic clearing is not a cost-free substitute for native resume or compaction. [Routing](/research/context/techniques/10-model-routing-and-delegation/), [retrieval/state](/research/context/techniques/08-retrieval-memory-and-state/).

Native tool discovery remains the first baseline. Remove an unused server only after checking its ownership and actual workflow use. Deferred schema loading, discovered-tool retention and per-host exceptions must be observed; the old 95.8% example is not a guaranteed saving. Telemetry can help, but a dashboard alone does not supply accepted-task grades or complete child/retry bills. Do not silently enable remote export. [Context architecture](/research/context/techniques/06-context-architecture/), [measurement](/research/context/techniques/01-economics-and-measurement/).

### Week 1 stage: scope, recovery and one host treatment

Build the contracts needed to reduce a result safely before optimizing many families:

1. **Admit one consumer and operation.** Bind the logical session, capsule, repository/worktree, authorized root and context epoch. OS UID/GID does not identify what the current model has seen.
2. **Capture once and acknowledge durable recovery.** Preserve the authorized observation, producer status, completeness and exact byte identity before a lossy replacement. A transform/storage failure returns that existing observation; authorization or integrity failure never bypasses policy, and the producer is not rerun.
3. **Qualify one replacement boundary.** Prove the real host consumes the transformed result, preserves native read/edit receipts, honors cancellation and does not merely append feedback. Claude typed replacement and Codex feedback substitution are distinct conformance arms.
4. **Try one bounded diagnostic reducer.** A pinned RTK OSS `pipe --filter <named-family>` subprocess for one qualified test/diagnostic format is an initial candidate, not a whole-product winner. Jackin passes through unknown or unqualified families. This is not a generic clippy/cargo-check/lint filter or an Apache public Rust library kernel. Known diff/newline/truncation regressions exclude affected families until resolved.
5. **Run paired tasks with raw independent grading.** Keep model, effort, starting state and relevant cache policy fixed; collect setup, failed attempts, child work, recovery and extra turns. Pilot tasks discover faults and estimate variance; they do not establish promotion by count alone.

The proposed Rust broker, worker and selector are not currently shipping. Current `jackin-exec` is an execution MCP surface, not the general optimizer. Restricted retrieval is another arm and must not replace native shell/edit authority or invent native read-before-edit receipts. [Architecture](/research/context/engine/02-architecture/), [observation pipeline](/research/context/engine/03-observation-pipeline/), [RTK](/research/context/tools/03-rtk-design/).

Inject storage refusal, timeout, crash, malformed output, missing/corrupt artifacts, restart, compaction, fork, worktree changes and concurrent consumers before task-level promotion. A smaller payload with an unusable recovery marker is a failed treatment. Protect exact paths, counts, failure statuses, diagnostics and truncation indicators. Fixture behavior establishes a component property; a passing native edit/replacement session establishes a different property. [Security and recovery](/research/context/engine/07-memory-and-state/).

Use the [canonical qualification protocol](/research/context/tools/07-evidence-and-claims/) and [validation harness](/research/context/techniques/16-validation-harness/): zero new critical correctness/security/permission/isolation/recovery regressions; acceptance lower one-sided 95% bound above −1 percentage point; for a new complex optimizer, upper one-sided 95% all-attempt cost-per-accepted-task ratio at most 0.80; p95 task latency no more than 10% worse unless a distinct tradeoff profile is declared. The quality margin bounds uncertainty and never permits a known correctness loss. Insufficient cost precision keeps a complex treatment provisional/experimental instead of waiving default-promotion evidence. Twelve to thirty tasks are pilot work; confirmation size follows paired/task-cluster variability.

For subscriptions, evaluate accepted work per real usage window and observed cap events. Do not convert API cache prices into unpublished quota weights. Existing native optimizations and low-impact owned-delivery fixes need proportionate verification, not an artificial requirement to save 20%. Absolute cold/warm time, RSS, artifact and index limits are explicit proposed budgets in the [engine rollout](/research/context/engine/10-rollout-and-validation/).

### Month 1 stage: package and activate qualified combinations

| Profile | Proposed user-visible behavior | What must be ready |
|---|---|---|
| Automatic | Jackin preserves native controls, delivers one owned restrained asset and selects a qualified reducer for the supported host/version/content family | Checksummed package, notices, host proof, recovery, task gates, resource limits, effective configuration and clean upgrade/off |
| Experimental | The operator explicitly selects one upstream backend, retrieval path or exact policy | Candidate/version/features visible; broader authority is not granted by selection; isolated evidence and limits are retained |
| Off / raw | Native authorized observations and normal host behavior, with new reductions and steering disabled | Previously emitted recovery references continue working; disable does not delete history or waive security |

Automatic selection happens after launch admission and checks capability/version/family qualifications. Users should not have to prepend commands or remember which result needs compression. Unsupported content follows the authorized native path. An inactive candidate reports the missing qualification without claiming that observation alone optimizes the task. The implementation should package one useful supported slice before widening to every host, tool family or backend.

Use the actual <RepoFile path="crates/core/jackin-core/src/manifest.rs">role schema</RepoFile>, <RepoFile path="crates/adapters/jackin-image/src/derived_image.rs">derived-image packaging</RepoFile>, <RepoFile path="crates/apps/jackin-capsule/src/runtime_setup.rs">runtime setup</RepoFile>, <RepoFile path="crates/apps/jackin-capsule/src/session/agent_cmd.rs">session admission</RepoFile> and <RepoFile path="crates/services/jackin-usage-token-monitor/src/session.rs">usage collection</RepoFile>. A future profile requires an explicit validated schema extension: the existing role manifest rejects unknown fields. The old `[token_policy]` and launch-line sketch did not establish an implemented feature. Keep heavy engines outside the control loop and avoid creating a parallel launcher.

Current main advanced after the external cutoff. The <RepoFile path="docs/content/research/context/techniques/tools/refresh-2026-10-24/jackin-architecture/main-overlay-review.md">separate integration-base review</RepoFile> records new installation/account-marker guards. Future packaging must preserve those checks and their failure semantics. A receipt's internal hash consistency does not alone authenticate the build or authorize execution.

Retrieval follows its own qualification: native search/read baseline, restricted process, explicit consumer epochs, restart/branch tests, schema cost and task-level benefit. Evaluate Headroom Rust versus Python, LemonCrow Lite versus historical fuller runtime, LeanCTX process versus embedding facade, and Caveman engine versus policy as different artifacts. One successful package build must not approve another version or mode. [Reuse matrix](/research/context/engine/09-reuse-decision-matrix/).

SDK context editing, compaction and structured-output sidecars remain separate integration lanes. Native interactive compaction is already the control; do not add a competing history owner. Verify current model/tool eligibility, returned usage iterations and continuation rules. Stable schemas can help scripted extraction but incur protocol/cache cost and must preserve contractual field names and enum values. Batch is appropriate only for eligible asynchronous tasks, using current provider/model rates and completion semantics. The old universal 0.05× cache-read multiplier is retired. [Provider features](/research/context/techniques/12-provider-features/), [output contracts](/research/context/techniques/09-output-discipline/).

Advisor/routing experiments remain optional and separately reported because changing model or effort changes this research's primary control. The earlier 5–6.6× composed forecasts are not rollout evidence. Combined profiles are evaluated after their individual components; overlapping payload, cache and output savings cannot be multiplied mechanically. [Composed stacks](/research/context/techniques/15-composed-stacks/).

### Automatic ownership and recurring verification

| Repeated operator burden | Proposed product responsibility | Guard |
|---|---|---|
| Remember a policy or wrapper | Install one versioned owned asset and select qualified result families | Preserve user changes and host precedence; expose off |
| Reapply settings per capsule | Admit effective configuration once and carry its identity into receipts | Do not alter model/effort/auth choices silently |
| Decide whether a cached file was seen | Track source generation separately from consumer exposure epoch | Unknown epoch returns content; shared index does not authorize a stub |
| Rerun canaries after an upgrade | Invalidate affected qualifications and run the exact host/version contract | Keep native behavior available; do not label an old green run current |
| Watch prefix/schema growth | Budget the actually delivered payload in CI and runtime samples | Count all automatic assets; network token counting requires explicit credentials/authorization |

A release, host hook schema, package feature, source license, provider accounting rule or owned asset change can invalidate a qualification. Recheck the affected contract after change and retain periodic drift review; a monthly calendar alone is not sufficient. Use local deterministic token/byte counters for routine budgets when appropriate, and state tokenizer limitations. The old claim that a provider count endpoint is universally free does not authorize credentials or network calls in CI. [Verification contract](/research/context/techniques/28-drift-delta/).

## Limitations and next decision

No new elapsed-time promise, accepted-task result, quota multiplier or production activation is established here. The immediate implementation decision is a small owned-delivery and recovery foundation, followed by one real diagnostic/result treatment and an automatic package after it passes. This is a path to effective defaults; a dashboard-only end state does not satisfy the objective.

Keep a native holdout and hard rollback triggers. A critical security, correctness or recovery regression stops the affected treatment regardless of average savings. Off must preserve exact recovery already promised, and installation/authority failures must not be converted into raw bypass. Broaden only after the original supported slice is demonstrably useful and maintainable.
