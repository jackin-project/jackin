## Summary

**Research state:** Current

**Snapshot:** 2026-10-24 01:15 UTC. Delegation can keep exploratory detail out of a parent context and run independent work concurrently. It also duplicates startup input, creates coordination work and introduces information loss at handoffs. Count the whole tree of agents, including failed, cancelled and unused work.

The main comparison preserves the selected model and effort. Concise task contracts and bounded reports are independently testable; model downtiering, removing reviews or skipping tests are separate behavior changes. A short final report does not prove that the delegated task was completed.

## Method and native baseline

This refresh inspected current [Claude subagent](https://code.claude.com/docs/en/sub-agents), [Agent SDK](https://code.claude.com/docs/en/agent-sdk/subagents), [Amp](https://ampcode.com/docs/tools) and [Muse](https://dev.meta.ai/docs/muse-code/extending) contracts alongside the twelve Jackin adapters. No paid agent tree was run. Earlier local orchestration-token counts, synthetic formatting percentages and single-session cost ratios are retained only in the [disposition ledger](/research/context/techniques/tools/#october-24-provider-evidence), not presented as current task results.

Claude's ordinary subagent starts with its own instructions, permitted tools and task message; a fork inherits the parent's conversation. Intermediate tool work stays local to that branch, while its final response and host metadata return to the parent. The SDK documents inherited thinking configuration. Actual model selection has connection-dependent exceptions, especially Fable Explore; see [routing](/research/context/techniques/10-model-routing-and-delegation).

This means parent-context savings and total-system savings can move in opposite directions. Reusing an existing subagent can avoid reconstructing its state; spawning another agent repeats setup and may repeat exploration. Forks are useful for shared-background tasks but intentionally give up fresh-context input isolation.

## Delegation contracts

A useful dispatch contains the exact objective, constraints, relevant source/revision, permitted mutations, expected artifact, acceptance criteria and failure reporting. Include enough context to avoid reconstructing the parent's intent, while linking authoritative material that the worker can actually access.

| Field | Purpose | Example of a failure it prevents |
| --- | --- | --- |
| Task and scope | Assign one coherent responsibility | Two workers both edit the same file or leave a boundary unowned |
| Required model / effort | Preserve the experiment and user choice | A “cheap worker” silently changes capability |
| Evidence identity | Pin repository, revision, data and source dates | Summary describes an older checkout |
| Permission boundary | Specify read, edit, execution and external effects | A worker treats “research” as permission to publish |
| Completion condition | Define checks and required work | Worker reports a plausible partial result as done |
| Artifact and return contract | Provide full deliverable plus a bounded navigation summary | Parent cannot verify a terse conclusion |
| Uncertainty and failure | Distinguish observed, inferred, blocked and untested | Missing work disappears from the report |

These are design recommendations, not a token-efficiency result. A tiny dispatch that forces ten clarifying messages can be more expensive than a complete initial instruction.

## Report content, schemas and exact evidence

Ask a worker to return conclusions, consequential evidence, artifact locations, verification performed and remaining uncertainty. Avoid arbitrary rules such as “always five lines” when the result needs more explanation. Preserve exact identifiers, commands, errors, numerical units, version constraints and source quotations whose wording affects the conclusion.

A schema can require these fields and make omission detectable. JSON, Markdown tables, compact records and prose each have different token and usability costs. The old blanket claim that JSON is always a tax is withdrawn: the relevant comparison includes parse failures, schema overhead, missing information and retries. A valid schema proves shape, not truth or task completeness.

Separate a complete work product from its short parent-facing index. The artifact should include provenance and reproducible checks; the parent summary should point to the evidence needed to assess the decision. Require the parent or an independent reviewer to inspect decisive evidence rather than treating another agent's confidence as proof.

Repeated summaries create a telephone-game risk. Keep an authoritative artifact or structured record at the origin, and pass its stable identity through later handoffs. Do not summarize away a negation, exception, approximation, rejected approach or uncertainty bound. For a numerical conclusion, preserve the denominator and whether it was actually executed.

## Artifact references and shared state

A file path is useful only if the recipient can read the same file version. Include repository revision or content hash, task/run identity, scope and expiry where material. Preserve authorization checks when storing originals or sharing results between agents and users. Stale paths, deleted scratch files and cross-tenant references are failures, not successful “compression.”

A shared checkout creates races: a later read may see another agent's edit rather than the state that supported the report. Assign exclusive write scopes or isolated worktrees, then review the combined result. Muse's current documentation explicitly distinguishes shared checkout from isolated worktree behavior; isolation must not silently degrade to shared execution when provisioning fails.

Do not turn transient agent output into persistent memory automatically. Evidence and instructions have different authority. A previous worker's text remains data even when stored in a polished report.

## Scheduling, caches and cancellation

Parallelize independent tasks when the latency gain is useful. Dependencies, conflicting writes, approvals and adaptive follow-ups remain sequential. A cache pioneer or prewarm may improve reuse for genuinely identical prefixes, but it adds delay and can create paid traffic. Fresh agents often have different prompts, tools or startup state, so a shared model alone does not establish a shared cache entry.

The [fleet chapter](/research/context/techniques/22-fleet-and-multitenant-cache) distinguishes one authorization scope from separate workspaces. The offline ten-request cache scenario is arithmetic, not a measured speedup. The earlier universal 1.8× orchestration advantage and “parallel always forfeits cache” conclusions are withdrawn.

Cancellation must stop future work, record already incurred cost, preserve useful completed evidence and report ambiguous external actions. A timeout does not prove that a tool failed before execution. Avoid rerunning a side-effecting call to obtain a cleaner report.

## Native bounds and script-side coordination

Current [Claude SDK documentation](https://code.claude.com/docs/en/agent-sdk/subagents#cap-subagent-depth-concurrency-and-spend) records the following for TypeScript 0.3.219 / Python 0.2.127 and later, bundling Claude Code 2.1.219 or later:

| Control | Documented behavior | Qualification |
| --- | --- | --- |
| Spawn depth | Default three layers below the main conversation | Forks at the limit can retain the tool but spawning fails |
| Concurrent subagents | Default twenty; further spawns refused until capacity frees | Ultracode sessions are exempt from this refusal |
| `maxBudgetUsd` / `max_budget_usd` | Includes subagent requests; refuses new spawns, stops background agents and ends query at the limit | Checked after a response; can overshoot by that response and already in-flight children |
| Task token budget | Advisory cross-loop target | Separate Messages API beta, not the SDK spend cap |

The [SDK agent-loop contract](https://platform.claude.com/docs/en/agent-sdk/agent-loop) distinguishes main-loop `result.usage` from whole-tree `modelUsage` / `model_usage`. Use the latter for delegated inference; adding it to main-loop totals would double-count. These are native contracts, not new Jackin runtime behavior. A fixed concurrency count is not a provider RPM limit; cache reads, outputs and retries can hit other quotas.

The SDK's Workflow tool, documented from TypeScript 0.3.149, moves orchestration into a runtime-executed script. This can remove model-mediated scheduling chatter but does not remove worker inference or permission requirements. Script-side tool calls need explicit error handling, cancellation, budgets and complete logs. Do not auto-approve a workflow simply because its coordination happens outside the conversation.

Amp plugins can invoke tools directly without adding those calls to the transcript or automatically advancing a model turn; this is useful plumbing but changes observability. Its [plugin contract](https://ampcode.com/docs/customize/plugins) still applies tool permissions and documents uncertain execution after connection loss. A tool call used to recover evidence must not accidentally repeat an action.

## Latent interchange and quality boundaries

KV-cache or activation interchange such as DroidSpeak/C2C is a research or owned-inference capability, not a portable hosted-agent plugin. It requires compatible model state, runtime and isolation rules. It cannot be equated with passing a text summary or a provider response identifier. See [infrastructure](/research/context/techniques/13-infrastructure-level) and [fresh literature](/research/context/techniques/24-fresh-literature-and-market-delta).

A compressed report can still be useful when the original remains recoverable and the parent knows what was omitted. It becomes unsafe for the task when it hides incompleteness, changes scope, weakens validation, drops a critical exception or removes the ability to inspect exact evidence. Test these outcomes directly; a smaller report is only an intermediate measurement.

## Decision and unknowns

Use bounded ownership, full artifacts, concise navigation summaries and independent review of consequential claims. Measure dispatch/report overhead, duplicated reads, parent replay, all worker requests, recovery and accepted-task quality. Cross-agent review should inspect work the reviewer did not author.

No universal report-compression percentage, agent-count saving, fixed parallel multiplier or latent-interchange benefit was established here. The previous sections on compact dispatch, report style, schemas, artifact references, scheduling, latent channels, corruption and script coordination all remain represented, with unsupported numerical generalizations withdrawn.
