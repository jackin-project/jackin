## Summary

**Research state:** Current

**Snapshot:** 2026-10-24 01:15 UTC. Jackin's pinned registry contains **twelve agent adapters**; its runtime entrypoint has **six dispatch cases**. Registry membership, a configuration directory and a documented upstream hook are not proof that a host launches or that an optimizer intercepts its results.

The previous seven-host matrix included Aider, Copilot and Cline while omitting actual Jackin adapters. It is replaced below. Capability percentages such as “80% portable” or “60% survives a provider switch” had no defined denominator and are withdrawn.

The evidence is source inspection and current upstream documentation, with the architecture workstream's isolated launch-dispatch probe. No installed native host performed an optimized model task. [Host contracts, hashes and source pins](/research/context/techniques/tools/#october-24-provider-evidence) make this distinction explicit.

## Actual Jackin baseline

At commit [`6e266406b49da2ab3c55355f3b7d33d1643ee6cd`](https://github.com/jackin-project/jackin/tree/6e266406b49da2ab3c55355f3b7d33d1643ee6cd), [the agent registry](https://github.com/jackin-project/jackin/blob/6e266406b49da2ab3c55355f3b7d33d1643ee6cd/crates/core/jackin-core/src/agent.rs) and adapter modules enumerate all twelve hosts. The [runtime entrypoint](https://github.com/jackin-project/jackin/blob/6e266406b49da2ab3c55355f3b7d33d1643ee6cd/docker/runtime/entrypoint.sh) dispatches only Claude, Codex, Amp, Kimi, OpenCode and Grok. Other names reach the unknown-agent failure. The derived-image path embeds that script; registration does not add a launch branch.

The existing dispatch flags can bypass native agent approval prompts. Jackin's current isolation boundary must be described and preserved as it actually exists; this review does not claim that native prompts are enabled. Introducing a transformer must not broaden existing execution or data permissions.

## Current model-visible tool-result boundaries

| Host | Documented or source-inspected post-tool capability | Limits that matter |
| --- | --- | --- |
| Claude | `updatedToolOutput` can replace built-in and MCP output | Built-ins require exact valid result shape; MCP lacks equivalent shape validation; originals may already reach telemetry |
| Codex | PostToolUse block/exit 2 replaces feedback; `continue:false` substitutes model-visible feedback | Block rejects nested code-mode promise; continue:false does not. Parsed `updatedMCPToolOutput` / `suppressOutput` are unsupported, not typed replacement parity |
| Amp | `tool.result` returns replacement status/output | In-process plugin; lifecycle/thread identity and permissions remain host-specific |
| Kimi | PostToolUse / failure events observe | Only selected pre-tool, stop and prompt events affect control; event existence does not imply replacement |
| OpenCode | Current pinned source `execute.after` mutates result/error and core consumes changed result | Public docs also show older `tool.execute.after` API; actual installed package must match |
| Grok | `updatedToolOutput` replaces validated built-ins; MCP alias also supported | Settings command/HTTP hooks support replacement; SDK callback hooks do not; size and original-shape limits apply |
| Antigravity | PostToolUse receives call metadata and returns no replacement | Documented payload lacks full result; invocation injection appends/executes different work |
| Gemini CLI | AfterTool deny/reason or exit 2 substitutes feedback; additional context appends | Tail-tool request runs another tool and replaces the result; this is not pure postprocessing |
| Cursor | `updated_mcp_tool_output` replaces MCP output in supported local contexts | Ordinary shell output remains observational; cloud HTTP MCP post-hook is redacted and cannot replace |
| Muse | Stable docs advertise hooks; preview SDK reference has post-tool feedback controls | No verified universal typed-output replacement; unsupported fields can fail validation |
| Omp | `tool_result` patches content/details/isError; ordered handlers see prior changes | In-process extension; crash containment and persisted `toolResult` format differ from event names |
| Hermes | `transform_tool_result` returns replacement string; first string wins | Empty string is a replacement; ordinary post-tool observers ignore returns; terminal-only path is narrower |

The current [Gemini CLI hook documentation](https://geminicli.com/docs/hooks/reference/) says unpaid-tier and Google One users have moved to Antigravity. That is a distribution/access caveat; it does not add a Jackin launch branch or establish equivalent hooks between those two hosts.

Primary contracts: [Claude hooks](https://code.claude.com/docs/en/hooks), [Codex hooks](https://learn.chatgpt.com/docs/hooks), [Amp plugins](https://ampcode.com/docs/customize/plugins), [Kimi hooks](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/hooks.html), [Antigravity hooks](https://www.antigravity.google/docs/hooks), [Gemini CLI hooks](https://geminicli.com/docs/hooks/reference/), [Cursor hooks](https://cursor.com/docs/hooks), [Muse extension guide](https://dev.meta.ai/docs/muse-code/extending).

### Source pins and runtime distinction

OpenCode was inspected at cutoff-eligible commit [`c272a63cb4dd86a3e8771cf9a03be051fae28e95`](https://github.com/anomalyco/opencode/blob/c272a63cb4dd86a3e8771cf9a03be051fae28e95/packages/core/src/tool.ts). Its current core invokes `execute.after` and then normalizes/returns the mutated result. That establishes source behavior, not compatibility with whatever package Jackin installs. Official plugin loading uses `opencode.json` with `plugin` or supported plugin directories; the existing Jackin status-hook installer uses a different `plugins.json`/`plugins` shape and needs a conformance check.

Grok's inspected hook contract is pinned to [`2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8`](https://github.com/xai-org/grok-build/blob/2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8/crates/codegen/xai-grok-pager/docs/user-guide/10-hooks.md). It retains originals in transcript/telemetry, limits replacement size and distinguishes ordinary tool failures from dispatch failures. A plain string cannot replace a built-in whose contract requires a tagged object.

Omp is pinned to the adapter's [v18.2.4 source `1c0303b1f2ec515cbf4b44a9a49d68a029531aac`](https://github.com/can1357/oh-my-pi/blob/1c0303b1f2ec515cbf4b44a9a49d68a029531aac/docs/extensions.md). Its tool-result event can change content, but asynchronous callbacks outside managed wrappers can still crash the host. Source inspection does not qualify arbitrary extension code.

Hermes was inspected at [`5894e750c3dba980d43b25aa29e3958149ba2c61`](https://github.com/NousResearch/hermes-agent/blob/5894e750c3dba980d43b25aa29e3958149ba2c61/website/docs/user-guide/features/hooks.md). Its [middleware contract](https://hermes-agent.nousresearch.com/docs/developer-guide/middleware) explicitly preserves a completed downstream tool result if later middleware processing fails, avoiding automatic re-execution. Terminal transformation can receive already bounded capture, so it does not guarantee a complete original.

Muse's [hook reference](https://meta-models.github.io/muse-code-sdk/next/guides/plugins/reference/hook-events/) is a `next` documentation surface. It is useful evidence of a proposed/current preview contract, not a stable standalone runtime version. That limitation remains visible rather than being converted into a supported row.

## Permission, trust and ordering

A synchronous post-tool callback is required for direct substitution. Async reporters, dashboards and status hooks can observe but cannot reliably replace a result already sent to the model. For Claude, original output may enter telemetry before replacement. For Grok it remains in transcript/telemetry by design. A transformer therefore cannot promise that rejected/private text never reached any host subsystem.

Jackin’s Codex installer currently writes flat event entries containing `command`; the current official documentation shows nested matcher entries with `hooks: [{type, command}]`. No documented flat shortcut was found. Schema acceptance and discovery therefore remain unqualified until tested with the selected host parser; this source comparison does not establish a runtime rejection.

Codex nonmanaged hooks require trust of their exact current definition; installing a plugin is not equivalent to granting that trust. A changed definition can need review again. Other hosts have project trust, plugin loading and approval rules of their own. Do not bypass those rules to make an integration appear portable.

Input rewriting, post-result replacement, denial feedback, additional context, whole-request rewriting and executing a follow-up tool are separate capabilities. In particular, a Gemini tail-tool or a pre-tool command replay can execute a second action. An observation-only adapter must not simulate replacement through an unqualified alternate path.

## What ports and what needs an adapter

| Candidate | Portable idea | Host/provider-specific part |
| --- | --- | --- |
| Concise instructions | Request only necessary prose and preserve requirements | Instruction precedence, loading lifecycle and model behavior |
| Deterministic external tool wrapper | Transform the wrapper's own captured output | Native tool interception, exit status, cancellation and permissions |
| Exact-original store | Retain scoped evidence and content identity | Recovery discovery, authorization, host truncation and lifecycle |
| Smaller tool surface | Avoid irrelevant definitions | Native deferred loading, MCP discovery and schema validation |
| Context compaction | Bound repeated history with retained evidence | Signed state, opaque items, native reload and beta availability |
| Cache stabilization | Preserve a truthful eligible prefix | Pricing, TTL, scope, minimums and native defaults |
| Model routing / effort | Explicit optional policy | User selection, native overrides, provider compatibility and quota |

Aider-style keepalive, architect/editor/weak-model division, Cline-style stale-read deduplication, cache-preserving truncation, per-tool budgets and conditional rules remain useful design categories. They are not proof of implementation in the twelve Jackin adapters. Keepalive spends money; tiered routing changes the model; read deduplication needs file revision checks; budgets can hide important output. The previous “borrow” sections are retained as qualification questions, not unreviewed copy/install recommendations.

## Cross-provider boundaries

The same host can connect through subscription login, direct API, gateway or cloud-provider endpoint. A supported hook does not establish the downstream cache, thinking or billing contract. [Provider features](/research/context/techniques/12-provider-features) and [subscription economics](/research/context/techniques/19-subscription-and-quota-economics) separate those dimensions.

Claude signed thinking can reject history edits. OpenAI feedback substitution can change nested tool promise behavior. Gemini Interactions requires recurring configuration even with stored history. A portable adapter must preserve these semantics or declare the transformation ineligible.

## Qualification and decision

Before enabling a host adapter, execute version-pinned fixtures proving: exactly one original tool execution; model-visible substitution; intact status/error shape; exact recovery; no read-before-edit mismatch; preserved permission/isolation behavior; cancellation and timeout handling; large output; restart/resume/compact/fork lifecycle; and a verified off/native path.

Current source inspection supports several feasible adapters, but it does not qualify them. Missing launch dispatch, unresolved plugin discovery and preview-only contracts remain explicit blockers to a runnable claim. Preserve unknown behavior as native passthrough or an explicit unsupported result; never silently change model, approvals or result meaning.

The [architecture dossier](/research/context/tools/11-jackin-integration) owns implementation boundaries and the dispatch evidence. This matrix owns current upstream capability distinctions and the twelve-host coverage; neither claims a production optimizer was implemented by this research.
