**Research state:** Current

**Cutoff: 2026-09-23 UTC.** This dossier compares the six stable releases in the [release register](/research/context/tools/08-current-release-register/). It distinguishes source-verified capabilities from executed conformance tests and independent accepted-task outcomes. No paid six-way benchmark or complete upstream build was run for this refresh.

## Research question

What should Jackin automatically install, embed, adapt, or implement to reduce token usage without sacrificing correct outcomes, native-agent behavior, or capsule isolation?

## Headline findings

**Use a Jackin-owned integration and measurement layer with replaceable upstream components. Do not make any complete optimizer runtime mandatory or install all six together.** Prefer reuse over rewriting when a supported boundary works; own the contracts that third-party products cannot know about Jackin's sessions and worktrees.

| Product | Reviewed release | Best candidate contribution | Initial integration decision |
|---|---|---|---|
| Caveman | 2.7.0 | Optional concise narration | Reviewed instruction asset; full engine separately license-gated |
| RTK | 0.49.0 | Command-specific filters and recall | Pinned executable or upstream kernel extraction; no blanket rewrite |
| LeanCTX | 3.10.2 | Progressive repository retrieval | Restricted per-worktree MCP; evaluate lean-ctx-embed separately |
| Ponytail | 4.10.0 | Reuse-first implementation policy | Adapt selectively; preserve Jackin's engineering and testing obligations |
| Headroom | 0.38.0 | Rust typed compression transforms | First library-reuse spike: selected headroom-core transforms in a worker |
| LemonCrow | 0.7.4 | Integrated ranked retrieval/runtime | Read-only comparator, then separately evaluate full replacement |

These are architecture recommendations, not a measured performance ranking. Sources and limits appear in each design page.

## Method and evidence

Release objects and tagged source were checked directly. Current RTK includes recall and diff-parser corrections. LemonCrow includes its engine source and a bounded advisory lock. LeanCTX exposes an unpublished preview crate named `lean-ctx-embed`. Headroom exposes public Rust transforms. Those facts change the reuse options; they do not establish whole-task savings.

JetBrains' three articles do not test LemonCrow or today's six releases. The [evidence ledger](/research/context/tools/07-evidence-and-claims/) records admissibility rather than recycling old percentages into a current leaderboard. No independent, release-matched accepted-task result for all six was established.

## Limitations and open questions

Default enablement still needs a current Jackin experiment. Source availability is not successful build reproduction; a health endpoint is not proof of active compression; token estimates are not subscription-quota receipts. The unchanged agent/model/reasoning configuration must remain the control.
