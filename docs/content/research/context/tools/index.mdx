## Decision

**Make Jackin responsible for configuration, host compatibility, recovery, state identity and outcome evidence. Reuse narrow upstream components behind those contracts. Start with native context efficiency and precise retrieval; qualify additional interventions before automatic activation.** No complete optimizer is established as the overall winner.

The first implementation stage should automatically deliver a short role-aware instruction asset for bounded reads, targeted searches, edit-over-rewrite, useful brevity and complete acceptance checks; preserve the selected host's native caching, tool discovery and context management; and configure compatible, pinned optional components without extra operator installers. Novel result reduction and persistent exposure suppression remain experimental until their specific gates pass. This PR supplies research and reproducible probes; it activates no production behavior. [Implementation stages](/research/context/tools/11-jackin-integration/).

## Concrete profiles

These are proposed product semantics, not existing Jackin CLI flags.

| Profile | Automatically configured behavior | Qualification rule |
|---|---|---|
| **Default** | Native execution/editing/authentication and configured security boundary; native cache/discovery/compaction; short clarity-first and precise-read guidance; exact captured-result fallback for optional transforms of authorized observations. | Preserve model and effort. New instruction delivery needs host activation and regression checks. Existing native features are not subject to an arbitrary new-optimizer benefit threshold. |
| **Experimental** | One pinned observation or retrieval component per arm, capsule-local state, server-side allowlist, preserved originals, explicit host/model/version contract. | Compare Apache RTK OSS filtering, Caveman Go transforms, Headroom no-ML transforms, LeanCTX exact retrieval and LemonCrow Lite retrieval separately. Promote by accepted-task evidence. |
| **Off/raw** | Remove Jackin-added optimizer instructions, schemas, hooks, routing and workers; use the configured native agent. | Disable auxiliary optimizer traffic while retaining evidence needed by resumable sessions. Native host truncation and compaction remain native behavior. |

Ship useful default behavior when its low-complexity conformance checks pass. Do not wait for every market candidate or activate an unverified reducer to meet an adoption target. The [reuse matrix](/research/context/engine/09-reuse-decision-matrix/) specifies upstream, contribution and narrowly owned implementation choices.

## Evidence and confidence

Confidence is high in inspected component/license boundaries and narrowly reproduced failures; moderate in architectural deductions from current host and Jackin source; and low in comparative complete-task savings. No paid or subscription agent benchmark was authorized or run. Native Claude Code/Codex model sessions were not executed, and the private advanced LemonCrow engine was inaccessible.

Historical JetBrains, Quesma and other studies remain useful for failure hypotheses. New release-matched RTK evidence is small and host-dependent. A recent package containing an older benchmark does not make that benchmark current. The [evidence ledger](/research/context/tools/07-evidence-and-claims/) records authorship, treatments, denominators, exclusions and uncertainty.

Keep agent, model and reasoning effort fixed in the main comparison. Routing, effort changes, full-product personas, provider proxies and restricted retrieval are separate treatments. Count every attempt, retry and recovery. For a new complex optimizer, combine zero known critical regressions, a predeclared quality confidence bound, substantial all-attempt economic benefit and a latency budget; [the protocol](/research/context/techniques/16-validation-harness/) defines their interpretation.
