**Research state:** Current

## Summary

Cutoff **2026-10-24T01:15:00Z**; inspected October 24. Compose independently qualified capabilities with one owner at each boundary. The default architecture preserves the native agent and its configured security boundary, then adds selected instructions, exact retrieval or observation transforms through host-specific contracts. A combined treatment needs its own outcome test.

## Question and method

How can Jackin automatically configure useful components without duplicate reduction, competing installers, stale exposure state or unowned auxiliary requests? Map each component's actual reach using the [six-product comparison](/research/context/tools/05-head-to-head/), current [host contracts](/research/context/techniques/23-cross-agent-portability/) and [Jackin source audit](/research/context/tools/11-jackin-integration/). Distinguish display changes, appended feedback and replacement of bytes consumed by the model.

## Ownership map

| Object | Authoritative owner | Required contract |
|---|---|---|
| Native process/edit/approval result | Existing host and Jackin configured process boundary | Execute once; preserve exit/signal/cancellation, native read receipts and actual authorization policy |
| Transformed observation | One selected host adapter plus one reducer | Exact producer identity, capture completeness, original digest, transform/config version and eligibility decision |
| Recoverable original | Jackin-scoped artifact broker or explicitly admitted upstream store | Acknowledged persistence before loss, authorized exact retrieval, explicit retention and missing/corrupt errors |
| Source index | One backend per qualified arm | Worktree/root/revision/generation identity, dirty-file freshness, traversal policy and native fallback |
| Model exposure | Host consumer and context epoch | Never infer exposure from file hash, process uptime or another agent's read |
| Instructions and MCP registration | Jackin configuration owner | Preserve unrelated entries, no duplicate schema/policy, reversible owned writes and effective configuration |
| Memory item | Named session/repository memory policy | Provenance, trust, validity, supersession and retention distinct from observed source bytes |
| Provider request and credentials | Existing route or one explicitly selected proxy | Streaming, auth, signed thinking, usage events, retries, cache writes and auxiliary traffic owned end to end |

Current `SessionIdentity` holds UID/GID, not this full context identity. Existing Claude and Codex hooks report status and do not prove a working replacement adapter. Current launch paths use permissive native modes; preserve the actual configured boundary rather than claim that approval prompts are universally enabled. [Current/proposed distinction](/research/context/engine/02-architecture/).

## Composition rules

| Combination | Decision | Reason |
|---|---|---|
| Restrained narration plus precise retrieval | Compare after separate qualification | Different boundaries, but added instructions and changed tool choice interact |
| Ponytail implementation policy plus another full persona | Avoid in the default | Changes architecture/testing decisions and destroys attribution |
| RTK command rewriting plus LeanCTX/LemonCrow shell replacement | Do not stack | Competing execution and approval contracts; repeated transformations |
| Headroom/Caveman applied to an already-reduced result | Bypass unless an explicit typed chain is qualified | Summaries and recovery markers are not raw producer formats |
| Several proxies or warmers | Reject in the automatic profile | Credentials, retries, billing and cache ownership become ambiguous |
| Immutable source data shared across worktrees | Only with content/root authorization and generation rules | A shared index does not authorize cross-worktree disclosure |
| Shared mutable exposure ledger | Reject | Context resets, subagents and users do not share a reliable knowledge state |
| Two recovery schemes nested in one result | Reject by default | Ambiguous provenance, expiration and decoding; one external recovery protocol |

A wrapper may use upstream stores internally, but the external handle must have one lifetime and authorization contract. A handle or content hash is not an access credential. Compare ordinary strings and structured fields without executing retrieved instructions.

## Recovery before reduction

Persist the exact authorized observation captured at the boundary before returning a lossy view. Record stdout/stderr and capture completeness; a host-truncated result cannot be relabeled the complete original. Durable acknowledgement, not a unit-returning storage call, is the promotion condition. If optional storage/transformation fails, return the captured original once. Never rerun a side-effecting command to reconstruct output.

Authorization failure, path-integrity failure and required redaction are not optional-transform errors: refuse or surface the error without exposing forbidden raw data. Preserve security findings, exact diffs, executable content and final acceptance evidence according to their stronger fidelity rules. The model may fail to notice an omission even when recovery works; recovery is necessary but not a quality proof.

Fresh probes show why this matters: Headroom's Rust CCR put interface did not propagate a deliberately broken store; LemonCrow Lite could emit unchanged output without a spill reference; Caveman's tested fallible engine path returned the original plus an error. These are specific tested boundaries, not blanket product rankings. [Headroom](/research/context/tools/02-headroom-design/), [LemonCrow](/research/context/tools/10-lemoncrow-design/), [Caveman](/research/context/tools/01-caveman-design/).

Pin originals required by active/resumable sessions. At capacity, stop new lossy transformations before evicting referenced records. Recovery bypasses reducers and returns provenance and complete bytes when permitted. Explicitly test restart, missing/corrupt data, deadlines, storage pressure, interrupted writes and simultaneous consumers.

## Cache stability and context epochs

Transform an eligible observation once and freeze its delivered representation. Keep stable schemas, policy and source prefixes when the host/provider permits it; do not rewrite sent history opportunistically. Current cache rules are provider/model/auth specific, including paid writes and signed thinking. [Caching](/research/context/techniques/07-caching-exploitation/).

Advance or invalidate exposure on compaction, resume, clear, reset, fork and new consumers unless retained content is demonstrated. A process may survive while the model loses its earlier context. The LeanCTX same-agent restart probe returned an AUTO stub without a compaction marker; explicit full retrieval remains a distinct path. Host lifecycle events are inputs to an epoch protocol, not proof that every prior observation survived. [State model](/research/context/engine/07-memory-and-state/).

A compact handoff should carry verified decisions, repository revision, dirty changes, unresolved requirements and recovery references. The child still needs admitted source and its own exposure history. Count child startup, duplicate searches, review, retries and parent interpretation in total task economics.

## Installation and effective off

Generate capsule-local configuration and provision pinned artifacts with applicable notices. Do not run several upstream installers against the operator's home. Disable unselected update checks, telemetry, model downloads, hosted transports and auxiliary provider requests. Caveman record mode alone does not disable its warmer; use the actual component switches. A hidden MCP method must be denied server-side, not merely removed from tools/list.

Off removes new optimizer steering, registrations, workers and routing while preserving the native agent and security configuration. It does not retroactively restore earlier compressed history or delete originals needed for recovery. Rollback keeps the recovery broker available through the declared horizon and reports which configuration owner changed what. Proposed profile names are not current CLI guarantees.

## Smallest decisive composition test

After each component passes host and fidelity tests, run a fixed-model/effort factorial trial with native, component A, component B and A+B arms on representative task clusters. Interleave cold/warm runs and include all attempts. A passive shadow transform only measures the same captured trajectory; it cannot predict the alternative agent's decisions. Observe actual model-bound activation and score acceptance independently. [Evaluation protocol](/research/context/techniques/16-validation-harness/).
