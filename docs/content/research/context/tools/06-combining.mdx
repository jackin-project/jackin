## Summary

Cutoff: **2026-09-23 UTC**. Compose capabilities only when their ownership boundaries are explicit. One transformation owner per observation is the default. A separate narration policy can coexist with retrieval, but the combination is a new treatment. This refresh covers the six named products, not an unverified adjacent-tool popularity list.

## Question and scope

How can Jackin combine useful capabilities without inheriting every product's installers, policies, state stores, and proxy behavior?

## Method

Map where each intervention touches execution, agent-visible output, source selection, instructions, provider requests, and recovery. Assess collisions at those boundaries before measuring combined outcomes.

## Findings

### Candidate composition

```text
Jackin configuration and qualification registry
  |-- versioned, role-aware instructions
  |-- native agent execution and edits
  |-- selected post-execution transforms where the host supports replacement
  |-- one restricted repository-retrieval backend per experiment
  |-- scoped artifact/recovery service and usage evidence
  `-- optional provider proxy in a separately qualified profile
```

The [six-tool matrix](/research/context/tools/05-head-to-head/) establishes each product's reach. The [current Claude hook reference](https://code.claude.com/docs/en/hooks) distinguishes replacement of a result from merely appending context. The [Codex MCP reference](https://developers.openai.com/codex/mcp/) offers a separate server/tool configuration surface; it is not evidence of identical native-result interception.

### Conflict rules

| Combination | Default decision | Reason |
|---|---|---|
| Caveman-style narration plus restricted retrieval | Evaluate after individual arms | Different boundaries, but behavior and prompt overhead can interact |
| Ponytail plus LemonCrow persona | Do not stack by default | Both influence implementation strategy; attribution is lost |
| RTK rewrite plus LeanCTX/LemonCrow shell replacement | Reject unless an explicit experiment owns the chain | Duplicate execution/routing policy and repeated output reduction |
| Headroom transform applied to an already-reduced result | Bypass by default | The second pass may remove recovery hints or misinterpret summaries |
| Multiple provider proxies | Reject in the automatic profile | Overlapping cache/auth/streaming and failure ownership |
| Shared source index plus session-local exposure ledger | Permissible with isolation tests | Immutable data can be shared; what a model has seen cannot |

### Recovery contract

Give each result a producer, workspace identity, content hash, capture-completeness flag, transform/version, and recovery handle. The authoritative preserved object is the exact result captured at that boundary, not an imagined complete command log.

Keep the raw object before reducing it. If storage fails, return the original observed result; do not silently emit an unrecoverable lossy summary. Bound storage, pin artifacts needed by active or resumable sessions, and make eviction explicit. Raw recovery must bypass all reducers and keep source provenance.

Reversibility is operational, not cognitive: a model may confidently misinterpret a summary without asking for its original. Failures, security findings, exact diffs, executable instructions, and final acceptance evidence need stricter raw-preservation rules.

### Cache and deduplication

Transform a new eligible observation once and freeze that representation within the session. Do not silently rewrite previously sent history to improve a local counter. Keep tool schemas and policy prefixes stable when possible.

Deduplication requires a **context epoch**, not just a file hash. Clear or rebuild exposure state after compaction, resume, model reset, or subagent creation unless retained content is proven. Never equate another agent's successful read with this agent knowing the content.

### Multi-agent behavior

Scope mutable state by capsule, worktree, session, and context epoch. Share only explicitly immutable or concurrency-safe data. Do not make tool completion wait behind a machine-wide advisory-counter lock. Unknown completion after a mutation must be resolved through operation identity and state inspection, not automatic retry.

LemonCrow's [current bounded state implementation](https://github.com/lemoncrow-lab/lemoncrow/blob/v0.7.4/src/lemoncrow/gateway/adapters/mcp/smart_state.py) illustrates why lock scope and timeout both matter. A finite timeout is not a latency target for every tool call.

## Implications for jackin❯

Generate capsule-local configuration rather than invoking six installers against the operator's home. Preserve existing hooks and approvals. Disable upstream updaters, telemetry, public listeners, and optional model downloads unless the selected profile explicitly permits them.

Expose operator controls for effective profile, active components, bypass reasons, versions, recovery, and rollback. The command names in future designs are proposals until implemented. No optimizer should be allowed to change the chosen model or reasoning effort to manufacture token savings.

## Limitations and unknowns

A composable API does not establish good combined outcomes. Run factorial ablations only after each individual candidate works. A passive shadow transform can estimate output differences but cannot predict the alternative agent trajectory and must never re-execute a mutating command.
