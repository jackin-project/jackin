**Research state:** Current

## Summary

Source cutoff: **2026-10-24T01:15:00Z**. Reviewed stable release: [LeanCTX v3.11.4](https://github.com/yvgude/lean-ctx/releases/tag/v3.11.4), published October 11, commit `3afe2bbffe0834ec58517ffd493e5a51c5c1ca57`. Release metadata names `main` as its target, so the resolved tag commit, source tree and executable digest are recorded separately. The latest-release recheck remained 3.11.4; later default-branch work is not treated as shipped behavior.

LeanCTX is a credible **restricted retrieval candidate**, not an established winner or an automatic replacement for Jackin's native tools. Current read-scope fixes deserve credit: our executable probes withheld unchanged stubs for the Claude process scope, refreshed after a compaction marker and a branch change, and separated different explicit consumers. The remaining integration obligation is explicit: **a cached source and a model's present context are different states**. The same custom scope can receive a persisted stub after restart even if a new model context never saw the original.

The Rust facade is still **`lean-ctx-embed` 0.1.0, unpublished Preview**. Its first-engine-wins process-global environment configuration and fixed default temporary path are concrete reasons to prefer a scoped subprocess initially. The public source does not justify installing the full runtime, registry, proxy, memory policy or steering assets by default.

## Question and scope

Should Jackin use native precise reads/search, a restricted LeanCTX MCP worker, or its embedded Rust engine? Treat retrieval, automatic selection, delivery deduplication, memory, shell shaping, policy admission, proxy compression and model routing as separate interventions.

## Method and evidence

Reopened release/tag, package registries, licensing matrix, manifests, effective read/stub/cache code, embedding facade, telemetry/setup defaults, withdrawn benchmarks and the original negative-evaluation leads. Verified the Linux x86_64 musl release archive against its GitHub SHA-256 digest and ran its binary over JSONL MCP with a local 300-line Git fixture. No provider/model calls, global installation or production optimizer activation occurred.

The <RepoFile path="docs/content/research/context/techniques/tools/refresh-2026-10-24/rtk-leanctx/README.md">reproduction record</RepoFile> preserves scripts, model-visible MCP response bytes, schema measurements, lifecycle results and build logs. These are protocol/component fixtures, not live Claude Code/Codex sessions or accepted-task trials.

## Actual embedding contract

The facade's engine dependency disables defaults, avoiding the engine's optional jemalloc allocator, **but explicitly enables tree-sitter, embeddings, HTTP-server and secure-update**. Its compile graph is not a minimal no-ML kernel: it still includes native parsing/SQLite and optional-ML infrastructure such as ONNX Runtime integration. A lexical operation need not download a model; that is different from a no-ML feature graph. The locked facade check started compiling dependencies but was interrupted during workspace disk contention before producing a complete result. Neither actual minimum toolchain compatibility nor a successful Jackin link is established.

[EngineBuilder and dispatch](https://github.com/yvgude/lean-ctx/blob/3afe2bbffe0834ec58517ffd493e5a51c5c1ca57/rust/crates/lean-ctx-embed/src/engine.rs) own a multithreaded Tokio runtime, defaulting to two workers; methods are synchronous and require a blocking boundary in an async host. The API admits an explicit read-tool allowlist; write/exec require separate opt-ins. Path checks reject escapes and secret paths, but are not an OS sandbox against hard links, concurrent path changes or explicitly enabled shell execution.

The same file's `configure_process_env` uses a static `Once`: **the first engine sets all four process-wide data/config/state/cache environment paths**. Its default is `temp_dir()/lean-ctx-embed`, not a unique directory per instance. Different later `.data_dir(...)` values do not give independently configured processes. Session/cache objects are instance-owned, but substantial surrounding state remains process-global; the facade has no caller-owned context-epoch/reset contract. These are source-inspected facts, not a reproduced two-engine runtime test.

Ask upstream for injected instance-scoped stores/configuration, caller-owned runtime/cancellation, granular lexical-only features, and an explicit delivery-epoch API before making it a shared in-process Jackin backend. A per-worktree/session subprocess with explicit directories is the current practical isolation boundary. A separate process also avoids assuming compatible `libsqlite3-sys`, native linkage and allocator behavior in Jackin's dependency graph.

## Cached content versus model exposure

[Conversation gating](https://github.com/yvgude/lean-ctx/blob/3afe2bbffe0834ec58517ffd493e5a51c5c1ca57/rust/src/core/conversation.rs) prioritizes explicit `LEAN_CTX_SCOPE`, then supported task identity, then process/transcript signals. The current code recognizes that Claude parent and subagents may share one MCP process: a process-derived identity cannot identify the recipient, so unchanged stubs are withheld. Recent multiplexed conversations also withhold stubs. Unknown warm callers retain a legacy allow path; cold persisted stubs require the same known conversation. An explicit custom scope is safe only when the integration truly owns that consumer's context lifetime.

[The persistent stub index](https://github.com/yvgude/lean-ctx/blob/3afe2bbffe0834ec58517ffd493e5a51c5c1ca57/rust/src/core/read_stub_index.rs) holds delivery metadata, hashes/mtime, path and file references, capped at 1,024 records. It does not hold the file's original content. [Compaction synchronization](https://github.com/yvgude/lean-ctx/blob/3afe2bbffe0834ec58517ffd493e5a51c5c1ca57/rust/src/server/compaction_sync.rs) reads the host's marker or radar events, resets delivery/search state and clears persisted stubs. Its last-seen timestamp is process-global, another reason not to assume independent embedded instances.

### Executed lifecycle matrix

The fixture first delivered a full file and then explicitly requested `auto` to exercise stubs. Explicit `full`/`raw` requests are forced fresh by current code; testing only those modes would not test deduplication.

| Case in the released binary | Observed response | What it establishes |
|---|---|---|
| Unknown caller; warm auto reread | 55-byte unchanged stub after annotation was exhausted | Legacy unknown-caller reuse remains enabled; identity cannot be inferred from the cache alone. |
| Explicit `agent-A`; warm auto reread | Same unchanged stub | Custom scope permits reuse after full delivery. |
| `CLAUDECODE=1`; warm auto reread | Source content, no unchanged stub | Process-scope safeguard worked in this fixture. This was an environment simulation, not a Claude session. |
| Host-style compaction marker written | Next auto read returned current cognitive selection, not a stub | Marker invalidation worked; auto may still select less than the full file. Actual host event delivery remains to verify. |
| Git checkout to changed branch | Read reflected the changed function name | This fixture did not serve stale source after the branch change. |
| Restart after the compaction-marker arm | Content returned for both same and different explicit consumer | This particular persisted state did not resurrect a stub. |
| Separate no-marker arm, same explicit consumer after restart | Persisted unchanged stub returned | Reusing an identity is not proof the restarted model possesses the old observation. |
| Same no-marker data, different explicit consumer | Content returned | Scope separation worked for sequential processes sharing that state. |
| Explicit raw benign text | CRLF, Unicode and missing final newline preserved | Exact bytes for this fixture, not universal bypass of admission/redaction. |

No concurrent multi-worktree process test or real host context-reset/resume session was executed. A silent reset with no delivered event cannot be inferred by the server; Jackin must change the consumer/epoch or force fresh reads. Native edit prerequisites may require the native read tool even when an MCP read was exact.

## Recovery is several stores, with different lifetimes

The [archive](https://github.com/yvgude/lean-ctx/blob/3afe2bbffe0834ec58517ffd493e5a51c5c1ca57/rust/src/core/archive.rs) stores content plus tool/command/session and authority metadata, subject to admission, truncation, disk budget and age. [Defaults](https://github.com/yvgude/lean-ctx/blob/3afe2bbffe0834ec58517ffd493e5a51c5c1ca57/rust/src/core/config/sections.rs) include an 800-byte threshold despite the `threshold_chars` name, 48-hour age and 500 MiB archive budget; the production per-entry cap is 10 MiB. These are not guarantees that every observation is archived completely.

The [in-memory reference store](https://github.com/yvgude/lean-ctx/blob/3afe2bbffe0834ec58517ffd493e5a51c5c1ca57/rust/src/server/reference_store.rs) is process-global, with a five-minute TTL, 200-entry and 64 MiB aggregate limits. It can decline storage on contention and cannot survive process exit. [Recovery verification](https://github.com/yvgude/lean-ctx/blob/3afe2bbffe0834ec58517ffd493e5a51c5c1ca57/rust/src/core/recovery_verify.rs) distinguishes missing, expired, digest-mismatched and policy-refused handles. Recovery stores admitted text, and current policy may refuse return; it is not an unrestricted original-byte vault. Storage failure, expiry, policy changes and a model overlooking a missing detail remain different failure modes. These recovery implementations were inspected; their full fault corpus was not executed.

## Schema, annotation and resource overhead

With rules injection off, minimal-overhead requested, telemetry/proxy disabled and headless startup, `tools/list` still advertised **12 tools occupying 10,608 bytes of compact JSON**, including `ctx_patch`, `ctx_shell` and `shell`. This is a wire-byte measurement, not token or billed-schema accounting. Zero initialization instruction bytes did not mean zero later steering: the first large full read gained a 202-byte nudge and the second response gained 115 bytes of automatic project context. The fixture also returned a 1,177-byte map for 4,886 source bytes, but that selected representation is not an accepted-task saving.

On this one tiny repository, recorded initialization was roughly 13–21 ms, first full reads 0.23–0.28 s and first map reads 0.44–0.46 s; subsequent measured calls were roughly 11–43 ms. These isolated single samples are not a latency distribution or comparison with native tools. Indexing, model loading, larger-repository CPU/RAM/disk, concurrent worktrees and long-running memory growth were not measured. Keep those costs in the proposed evaluation rather than projecting toy-file timings.

## Defaults, network and installation

[Telemetry defaults](https://github.com/yvgude/lean-ctx/blob/3afe2bbffe0834ec58517ffd493e5a51c5c1ca57/rust/src/core/config/sections.rs) are **on** for current v2 aggregates; `DO_NOT_TRACK=1`, `LEAN_CTX_TELEMETRY=off` or explicit stored opt-out disable them. Older “telemetry off” field-report statements do not describe this release. Setup defaults also include MCP updates and hook management. [Server initialization](https://github.com/yvgude/lean-ctx/blob/3afe2bbffe0834ec58517ffd493e5a51c5c1ca57/rust/src/server/server_handler.rs) can maintain installed rules/skills/hooks and check versions; headless mode avoids that maintenance path. [MCP startup](https://github.com/yvgude/lean-ctx/blob/3afe2bbffe0834ec58517ffd493e5a51c5c1ca57/rust/src/cli/dispatch/server.rs) includes housekeeping and optional proxy startup, not only read handling.

The probe set all four LeanCTX directories explicitly, disabled telemetry/proxy/update/rule/skill/hook management and capped worker/index threads. No model was downloaded. That configuration is a scoped research treatment, not the upstream install default. Optional semantic-index construction can require model/runtime downloads; external providers and the proxy introduce their own credentials and egress.

[Uninstall](https://github.com/yvgude/lean-ctx/blob/3afe2bbffe0834ec58517ffd493e5a51c5c1ca57/rust/src/uninstall/mod.rs) reaches processes, autostart, shell configuration, MCP registrations, rules, skills, data and binary, with dry-run/keep options. Its breadth is a reason for Jackin to own a small scoped registration rather than rely on a general installer/uninstaller. Neither installation nor cleanup was exercised against host-global state.

## Jackin decision and decisive next steps

1. **Keep native exact read/edit and execution as the default.** Compare a read-only LeanCTX worker with the native baseline and other retrieval candidates. A profile name or hidden tool list is not authorization: deny execution/write at dispatch and enforce the intended filesystem boundary.
2. **Use explicit process and state scopes.** Separate worktree/session workers initially. Share immutable index material only through a verified versioned contract; never share mutable delivery state merely because repositories share files. Change context epoch on reset, compaction or a new consumer unless preserved context is proven.
3. **Request upstream embedding improvements before a shared in-process dependency.** Complete a clean, locked build with constrained debug/incremental settings, then test two simultaneous roots/data directories, cancellation and epoch invalidation. The existing interrupted build is not a product build failure or a successful feasibility gate.
4. **Measure the actual restricted treatment.** Disable unrequested telemetry, proxy, steering, automatic setup and optional learning; count remaining schemas, nudges, indexing and recovery. Confirm exact native edit prerequisites in each supported host. Full-product memory/proxy/persona arms are separate comparisons.
5. **Promote only after lifecycle and accepted-task gates pass.** The smallest missing correctness experiment is an actual host parent/subagent/reset/resume transcript with stub creation, epoch changes and raw recovery, plus concurrent worktrees. The smallest outcome experiment pairs native precise reads with this scoped retrieval profile on representative discovery/refactor tasks at fixed model/effort, including all retries and failures. Rollback removes the worker registration and retains native access to source and Jackin-owned evidence.
