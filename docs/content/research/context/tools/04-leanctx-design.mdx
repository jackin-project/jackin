## Summary

Cutoff: **2026-09-23 UTC**. Reviewed release: [LeanCTX v3.10.2](https://github.com/yvgude/lean-ctx/releases/tag/v3.10.2). LeanCTX is the closest Rust-based integrated retrieval/runtime candidate in this set. The current experimental embedding crate is **lean-ctx-embed**, not the previous facade path. Its availability does not imply a stable SDK or proven task savings.

## Question and scope

Should Jackin adopt the complete runtime, use restricted MCP retrieval, or call the Rust engine in process?

## Method

Inspect the tagged workspace, embedding manifest and README, and benchmark-status file. Separate the published engine crate, unpublished embedding facade, host integration, and outcome evidence.

## Findings

### Retrieval before compression

LeanCTX combines structural reads, search, symbols, outlines, session reuse, shell shaping, recovery, and optional proxy paths. Its [embedding surface](https://github.com/yvgude/lean-ctx/blob/v3.10.2/rust/crates/lean-ctx-embed/README.md) offers read, search, symbol, outline, and tree operations. These can avoid broad reads; their failure mode is retrieval incompleteness or stale reuse, not only lossy compression.

A short unchanged-read response is correct only when the recipient still has the referenced content. A shared source cache and a model's current conversational memory are different things. Compaction, resume, a new subagent, and another worktree must be represented in the reuse contract.

### Actual Rust boundary

The [workspace](https://github.com/yvgude/lean-ctx/blob/v3.10.2/rust/Cargo.toml) declares an engine library and the `lean-ctx-embed` workspace member. The [facade manifest](https://github.com/yvgude/lean-ctx/blob/v3.10.2/rust/crates/lean-ctx-embed/Cargo.toml) declares version 0.1.0, Apache-2.0, and `publish = false`. Its README explicitly marks the API preview rather than a stable public Rust SDK.

The facade disables engine defaults to avoid imposing the engine's global allocator, but explicitly enables tree-sitter, embeddings, HTTP-server, and secure-update features. It is not a minimal no-ML kernel just because default features are disabled at one dependency edge.

Methods are synchronous and own a multithreaded Tokio runtime. The README directs async callers through a blocking boundary. Jackin must measure contention and cancellation rather than invoking this API indiscriminately on runtime workers.

### Evidence status

The current [BENCHMARKS.md](https://github.com/yvgude/lean-ctx/blob/v3.10.2/BENCHMARKS.md) withdraws historical numbers from technical decisions. No independent accepted-task result for this exact release and restricted profile was established. Installation matrices and generated command counts are not execution or outcome guarantees.

## Implications for jackin❯

**Best part:** a replaceable read-only retrieval backend, especially for repeated exploration of large repositories.

**Integration choice:** begin with a per-worktree stdio MCP process restricted to the required read/search/symbol/outline functions. Enforce read-only behavior at the dispatcher and filesystem boundary; hiding a tool in a prompt is not an authorization check. Preserve the native exact-read/edit workflow until edit prerequisites are verified.

A second arm can embed the commit-pinned facade behind an internal adapter. Ask upstream for granular feature gates and a caller-owned runtime before committing Jackin's stable architecture to it. Do not conflate the Python SDK, HTTP clients, published engine, and unpublished Rust facade.

**Default decision:** do not activate the complete tool registry, memory policies, shell rewriting, or proxy automatically. Promote only a measured profile, including schema and indexing overhead.

## Limitations and unknowns

The embedding build was not run in this review. Public documentation describes different source, installed-runtime, and SDK baselines; [current CLI guidance](https://leanctx.com/docs/cli-reference/) explicitly identifies stale generated help. Pin source and artifact independently. Structural graphs and embeddings are navigation aids, not proof of complete semantic impact.
