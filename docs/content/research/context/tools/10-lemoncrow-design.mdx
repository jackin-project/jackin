**Research state:** Current


## Summary

Snapshot: **2026-10-24 01:15:00 UTC**. Stable [v0.8.0](https://github.com/lemoncrow-lab/lemoncrow/releases/tag/v0.8.0), published **2026-10-19 15:18:45 UTC**, resolves to `d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d`. The canonical repository remains `lemoncrow-lab/lemoncrow`.

**Evaluate the public Runtime Lite as a restricted retrieval sidecar; do not label LemonCrow the winner or install its complete tool replacement by default.** Version 0.8 changes the relevant product: local Runtime Lite is a small standard-library client with deterministic indexing, while advanced hosted/enterprise intelligence is now private. Explicit-root and concurrent-worktree probes passed, but recovery failure and model-exposure state still need Jackin-owned controls.

## Question and scope

Can Jackin package useful indexed retrieval without replacing native execution/editing, inheriting a global installer or confusing the old full engine's benchmarks with the new local kernel?

## Method

Reopened the current release, licensing/source boundary, product packaging, Runtime Lite dispatcher/index, historical full MCP state and worktree code, PR #46 and benchmark provenance. Compared the published Runtime client archive with the release source, ran 45 selected Runtime Lite upstream tests and an independent offline boundary probe using real Git worktrees. No model, hosted-service or subscription session was executed. See the <RepoFile path="docs/content/research/context/techniques/tools/refresh-2026-10-24/headroom-lemoncrow/README.md">commands and evidence</RepoFile>.

## Findings

### Current components and source boundary

| Component | Current identity and behavior | Jackin consequence |
|---|---|---|
| Runtime Lite | Public local lexical/symbol/import index, bounded reads and execution helpers; one stdio process | Can be evaluated without a LemonCrow application server or account. |
| Published Runtime client | `lemoncrow-runtime-client-0.8.0-py3-none-any.whl` inside the GitHub release archive | Actual distributed name differs from source project's `lemoncrow-client`. Python 3.12–3.13; wheel declares no dependencies. |
| Review client/engine | Separate release archives and installers; optional loopback service/frontend | Not required for the retrieval experiment. Review capture and hosted behavior are a different data boundary. |
| Public full source | `lemoncrow==0.8.0`, `lemoncrow-client==0.8.0`; many optional dependencies and legacy/full MCP paths | Source package presence does not mean the public runtime exposes every historical capability. |
| Hosted/Enterprise Runtime | Advanced private code intelligence, semantic engine, managed execution and organization services | Not reproducible from the public repository; separate service terms and permission review. |

The [public source boundary](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/docs/reference/open-source-boundary.md) states that releases through **0.7.4** published the advanced engine under Apache-2.0 and retain that grant. Later public trees keep contracts, neutral rendering and local capability glue in `src/lemoncrow/pro`; the advanced implementation comes from the private distribution. The [mirror allowlist](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/scripts/public-paths.txt) confirms the distinction. Both older blanket claims—“engine source is missing” and “the current entire engine is open”—need version and component qualification.

The [license](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/LICENSE) grants Apache-2.0 for public/local source, requires preserving applicable notices, and excludes the proprietary enterprise tree. It does not grant access to absent advanced code. Historical Apache source remains a possible fork input, but that would be a deliberate old-engine maintenance commitment, not a current upstream dependency.

### Package correspondence and release qualification

The Runtime archive's SHA-256 is `73bb7c7d062f1f622dff50a851d36a71b1c8efa9ebebd7017d1d09cf81529e94`, matching GitHub's release digest. All **87 packaged `lemoncrow_client` files** compared byte-for-byte with the pinned source; there were no changed or source-missing files in that comparison. This establishes selected package/source correspondence, not bit-reproducible construction of every release bundle. The checked PyPI version endpoints for `lemoncrow/0.8.0` and `lemoncrow-client/0.8.0` returned 404; install the reviewed release artifact rather than infer public registry availability from a manifest or README command.

The release explicitly discloses **no complete passing G11 qualification stamp**: its first-party Reader-open p95 exceeded the 950 ms target, and other exhaustive performance evidence was incomplete. That Reader measurement is not Runtime Lite retrieval latency. The release's reported multi-platform checks are upstream claims; this investigation independently executed only the selected Linux/Python checks listed here. [Release disclosure](https://github.com/lemoncrow-lab/lemoncrow/releases/tag/v0.8.0).

### What Runtime Lite sees and changes

The [Lite architecture](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/docs/architecture/runtime-lite.md) and [dispatcher](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/client/src/lemoncrow_client/lite/mcp.py) define local index/search and selected tools. They do not intercept native host reads, shell results, edits or provider requests automatically. Full upstream guidance routes work through LemonCrow's tools; a Jackin read-only integration must be evaluated as its own treatment.

| Intervention | Mechanism | Correctness and cost boundary |
|---|---|---|
| Lexical retrieval | SQLite FTS5, exact/partial symbols, path evidence, bounded import expansion and deterministic ranking | Selects evidence lossily; ranking and small snippets do not guarantee recall. Keep native search/read fallback. |
| File/symbol reads | Bounded source reads and source hydration | A native host may still require its own read before native editing. Preserve byte-sensitive CRLF/no-final-newline paths separately. |
| Shell/edit replacement | Local command policy, execution, compaction, redaction, delta markers and edit validation | Changes native contracts and approvals. Exclude from the restricted retrieval arm. |
| Optional semantic helper | Separate Model2Vec helper with preprovisioned local weights; lexical fallback | Not the private advanced semantic engine. Model download/setup and cold memory are separate opt-ins. |
| Hosted client | Revision-bound remote source/view transport and tools | Uploads/access controls differ from local Lite; exclude from local defaults. |

The visible tool list is **`bash`, `edit`, `read`, `code_search`, `web_fetch`**; our compact-JSON schema measurement was **4,058 UTF-8 bytes**, not provider-billed tokens. Other locally placed tools are callable even when absent from `tools/list`; an unadvertised `grep` call succeeded in the probe. Filtering tool descriptions alone is therefore not a read-only security boundary. The adapter must reject disallowed dispatches server-side. [Executable placement policy](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/client/src/lemoncrow_client/lite/policy.py).

### Worktrees: improved Lite routing, a different legacy/full path

PR [#46](https://github.com/lemoncrow-lab/lemoncrow/pull/46) is **closed, not merged as that public PR**; the maintainer says the fix was mirrored into v0.7.1. Its original change inferred edit roots from the process's most recent shell cwd. The current full-source [MCP wrapper](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/src/lemoncrow/gateway/adapters/mcp_server.py) still contains `_last_session_cwd` and an explicit shared-process debt note. Do not promote that path merely because the old issue was addressed.

Runtime Lite instead calls `WorktreeCatalog.route(arguments, active=None)` on each request: **there is no sticky active-worktree state**. Its [path router](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/client/src/lemoncrow_client/worktrees.py) recognizes Git-registered checkouts, rejects one request spanning several trees, and gives each checkout separate index and session-memory objects. The module's general sticky-routing description is not the Lite call site's effective behavior.

Executed boundary results:

- Two parallel `LiteMcp` objects with explicit roots returned their own different `app.py` content.
- A shared process's `bash(cwd=worktree-A)` did not redirect a subsequent relative read away from the launch root; an explicit worktree-A file path selected A correctly.
- One read naming files in both A and B was refused.
- All 45 tests in `client/tests/test_runtime_lite.py` passed, including no-network, freshness, linked-worktree, WAL and concurrent-dispatch cases present in that file.

These are fixture results, not proof of every host session or race. Launch one process per explicit worktree/session initially. A main-root process cannot infer that an otherwise unqualified relative path means another agent's worktree; Jackin must bind the intended root rather than rely on the user's preceding shell command.

### Index lifecycle, state and recovery

Lite stores the lexical index in `.lemoncrow/workspace/runtime-lite-v3.sqlite3`, uses WAL and generation refresh, and excludes its state from the repository walk. Versioned files avoid rewriting an older live process's index schema; compatible older state can be copied using SQLite backup. Initialization starts a session-owned background index thread; indexed operations wait up to 20 seconds then return an explicit indexing-in-progress result, while direct reads/shell/edit do not wait. Optional semantic generation files are separate. [Index implementation](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/client/src/lemoncrow_client/lite/index.py).

The independent two-file fixture measured approximately **34 ms cold prepare / 0.45 ms warm prepare**. This is a tiny local fixture, not a repository-scale latency claim. Full indexing CPU, RAM, disk growth, cancellation and long-session contention remain unmeasured here. The implementation may return the previous committed generation while a refresh runs; callers must preserve freshness/provenance metadata and avoid treating a selected stale result as a complete current-tree answer.

The historical [smart-state lock](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/src/lemoncrow/gateway/adapters/mcp/smart_state.py) still defaults to five seconds, then proceeds without the cross-process lock. That prevents indefinite advisory-counter blocking but permits lost updates. It is part of the fuller MCP path, not evidence that the Lite index uses the same global state. A timeout can still exceed a useful tool-latency budget.

Shell output history is now per `SessionMemory`; identical successful output over 500 characters can become an `unchanged` marker. Its [RunHistory](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/client/src/lemoncrow_client/kit/output_delta.py) tracks process/session exposure, not a model context epoch. A surviving process is not proof that the current model context still contains the earlier bytes. Disable `LEMONCROW_BASH_UNCHANGED_DELTA` in a Jackin experiment unless epoch/reset handling is qualified.

[Spill storage](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/client/src/lemoncrow_client/localtools/shell.py) defaults to a per-user temporary directory, **512 files per kind** and **24-hour retention**, with explicit overrides. It is ephemeral, not a session-complete transcript. In the independent probe, making the spill location unusable caused a repeated shell result to remain an `unchanged` marker **without an original or recovery path**. `spill_text` returns `None` on failure and presentation continues. This is a concrete promotion blocker for output replacement, not for using an isolated retrieval-only backend.

The hosted thin client's separate [search deduplicator](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/client/src/lemoncrow_client/search_dedup.py) has session/view/revision and compaction-epoch scoping plus `force=true` recovery. That improvement must not be attributed automatically to Lite shell history or every host. Shared immutable indexes and shared model-exposure state need different owners.

### Installation, networking and cleanup

Runtime Lite has no application server, resident daemon or listener on its standard stdio path. Default lexical execution does not need a LemonCrow account or upload source. Explicit `web_fetch` is still network access; hosted/remote MCP and Review are separate optional paths. The semantic helper sets offline mode for query-time use and requires weights provisioned outside the search path. [Architecture](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/docs/architecture/runtime-lite.md).

The general installer selects products and can modify shell setup; product update and first-use lazy installation can fetch release scripts. Runtime host registration is opt-in. Pin the Runtime artifact, supply the interpreter and explicit root/state directory, disable lazy installation and updates, and skip Review/hosted/remote services. The [Runtime uninstaller](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/scripts/uninstall_runtime.sh) removes runtime state and owned host registrations while preserving account/Review and pairing state. Per-repository indexes and temporary spills need an explicit Jackin retention/cleanup owner.

Local Lite traces default on under the configured LemonCrow home, with **14-day / 256-MB retention** and an off switch. They record arguments except bulk bodies, which become size/digest metadata. Local traces are not a provider receipt or a subscription-quota meter. No global installer or telemetry service was activated in this research.

### Evidence does not establish a current winner

The [benchmark document](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/BENCHMARKS.md) preserves vendor-operated June/July and September results. Its 50-task, five-repetition SWE-bench Verified result tested the fuller `lemoncrow:auto` treatment and a historical model/harness; 250 trials represent 50 task clusters. Later single-repetition results use old baselines or changing bind-mounted source and explicitly disclose provenance gaps. None is a controlled comparison of public Runtime Lite 0.8.0 against native Jackin tools.

This refresh's independent benchmark workstream also recomputed the historical Terminal-Bench baseline from pinned [task rows](https://github.com/lemoncrow-lab/benchmarks/blob/8aaee7ffa5b6f5f7e4a4a9a520af89ed527c7ec1/harbor/results/baseline/tbench_opus48_claudecode_2.1.205_tasks.csv) and [turn rows](https://github.com/lemoncrow-lab/benchmarks/blob/8aaee7ffa5b6f5f7e4a4a9a520af89ed527c7ec1/harbor/results/baseline/tbench_opus48_claudecode_2.1.205_turns.csv). The task table's cache column matches cache reads in all 445 rows. Subtracting it alone yields **12,873,472** input tokens that include cache writes; subtracting both reads and writes yields **70,310 ordinary fresh-input tokens**. The advertised 98.6% “fresh-input” reduction is therefore unsupported as labeled. The candidate's narrative 182K figure was not independently reconstructed, so no replacement reduction ratio is asserted. The separate normalized-price calculation uses both cache classes and must be assessed on its own assumptions. [Recalculation and evidence limits](/research/context/tools/07-evidence-and-claims/).

The newer [Runtime credit gate](https://github.com/lemoncrow-lab/lemoncrow/blob/d96bad0e59dbc799d54ac5ca1a6a4fe9b8a8ab8d/docs/operations/runtime-credit-gate.md) appropriately requires paired provider usage and independent acceptance evidence rather than sidecar estimates. A gate specification is not evidence that the stable release passed it; the release explicitly withholds complete G11 qualification. JetBrains' studies of other tools supply no LemonCrow result. No source reviewed here establishes LemonCrow as the overall winner.

## Implications for jackin❯

**Recommended experiment:** package the pinned Runtime client as a per-worktree/session sidecar, expose only `code_search` and bounded reads behind a server-side allowlist, retain native search/read/edit/shell/approval flows, and measure the additional schema and indexing cost. Keep raw observations and provenance in Jackin-owned storage; disable output/history dedup until context-epoch handling is proven. This is an adaptation with its own test arm, not the exact upstream product.

**Alternatives:** native precise reads/search first; compare LeanCTX and other retrieval primitives under the same tasks. A small wrapper around the public Lite API is preferable to reimplementing its ranking without evidence. Ask upstream for a supported read-only dispatch surface, fallible spill/storage protocol, explicit context-epoch reset and stable embedding contract. The current Python implementation is not rejected on language grounds.

**Default:** do not activate shell/edit replacement, hosted transport, owned agent execution, policy/persona replacement, automatic semantic downloads or the general installer. Full-product adoption needs its own native-tool/approval/cancellation/resume and task-quality qualification. A fork of historical 0.7.4 advanced code would need an owner, security/update policy, regression corpus and retirement plan; no present result justifies that burden.

## Limitations and unknowns

The selected tests do not prove artifact bit-reproducibility, cross-platform behavior, every concurrent process topology, crash/disk-full durability, full engine correctness or complete-task savings. The advanced current private engine cannot be inspected from the public mirror. Actual Claude Code/Codex delivery, read-before-edit prerequisites and compaction/resume were not executed with a model. A library result or visible MCP schema is insufficient activation evidence.

The smallest decisive tests are a strict read-only adapter with direct denied-call controls; restart/stale-index/branch-change and parallel-host fixtures; failed-spill passthrough before output replacement; and a randomized native-versus-Lite retrieval task trial at fixed model/effort. These resolve the current choice without purchasing or adopting the entire runtime first.
