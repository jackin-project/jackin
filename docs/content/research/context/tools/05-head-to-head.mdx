## Summary

Cutoff: **2026-10-24T01:15:00Z**; verified October 24. There is no supported current overall winner. Adopt separately selectable capabilities with exact host, content and lifecycle contracts. The [release register](/research/context/tools/08-current-release-register/) fixes product, binary, package and license identities.

## Question and method

Which intervention addresses observed waste without changing the task, selected model, reasoning effort or configured security boundary? Compare effective runtime paths. Distinguish source inspection, built APIs, local fixture outcomes and accepted-task outcomes. Package identity, licensing, activation, recovery and maintenance matter alongside correctness and economics.

## Reuse decisions

| Capability | First comparison | Demonstrated limitation and next action |
|---|---|---|
| Repository discovery | Native exact tools versus LeanCTX full reads and restricted LemonCrow Lite | AUTO exposure can survive restart; Lite schema filtering is not read-only enforcement. Add epochs and denied-call controls. |
| Symbol/section selection | Native tools versus narrow fff-search, sem-core and mq-markdown primitives | Qualify grammar features, native dependencies, root identity and published artifacts. [Market scan](/research/context/techniques/03-prior-art-and-market-scan/). |
| Structured observations | Caveman Go worker versus selected Headroom no-ML Rust transforms | Caveman has fallible recovery and CGO-dependent capabilities; Headroom has duplicate-key and persistence-interface failures. No blanket default. |
| Command output | Apache RTK OSS pipe or explicitly invoked qualified commands | Some pipe paths omit diff metadata or suppress unmatched input. Preserve raw originals and qualify each filter. |
| Generic pipeline | RTK engine as a separately licensed arm | Public traits and passing tests establish feasibility, not distribution permission or task fidelity. |
| Narration | Minimal native clarity-first policy versus Caveman skill | Count delivered overhead and hidden reasoning. Exclude model-selecting bundled agents and extreme styles. |
| Reuse policy | Small Jackin policy versus exact Ponytail product | Preserve complete migrations, tests, review and explicit off state. Adaptations inherit no benchmark percentage. |
| Provider interception | Native features, then one explicit proxy if the host seam is insufficient | Qualify auth, streaming, signed thinking, cache writes, auxiliary calls and usage events. |

The previous unconditional preference for Headroom is withdrawn: its no-ML build makes it a contender, while current fidelity and recovery findings prevent automatic promotion. Caveman's former engine-license rejection is obsolete for the Apache releases. A Go process is acceptable when its complete costs and contracts beat a Rust alternative.

## APIs and dependency feasibility

RTK exports a reusable pipeline with Block, Method and registry/provenance surfaces. Its application library exposes the application entry but keeps command modules private; rtk-engine and rtk-text are unpublished internal packages. A stdin-filter command now exists. The default engine is BUSL-1.1; the OSS command edition is Apache-2.0. [Manifest](https://github.com/rtk-ai/rtk/blob/4ef8730cf3a0dea11c8d64a9b90bc0616fe52100/Cargo.toml), [engine license](https://github.com/rtk-ai/rtk/blob/4ef8730cf3a0dea11c8d64a9b90bc0616fe52100/engine/LICENSE).

Headroom's unpublished headroom-core is a real public Rust surface. Its selected no-ML profile compiled without fastembed, ONNX Runtime or Magika but retained SQLite, Oniguruma and tree-sitter native dependencies. LeanCTX's unpublished lean-ctx-embed preview owns a multithreaded Tokio runtime and process-global configuration; the build attempt here was interrupted rather than completed. Exact resolution, allocator ownership and native SQLite compatibility require concrete graph probes. [Headroom core](https://github.com/headroomlabs-ai/headroom/blob/76133cff59b71284399bf760c5578dc373c97231/crates/headroom-core/Cargo.toml), [LeanCTX facade](https://github.com/yvgude/lean-ctx/blob/3afe2bbffe0834ec58517ffd493e5a51c5c1ca57/rust/crates/lean-ctx-embed/Cargo.toml).

A sidecar initially contains runtime ownership, linkage and state more clearly than importing every engine into Jackin. It still adds startup, IPC, supervision and cancellation work. Direct dependency promotion requires a narrow stable API, a compatible graph and measured benefit. Python Runtime Lite is not rejected on language grounds.

The initial RTK candidate is the pinned OSS `pipe --filter <named-family>` subprocess, starting with one qualified test/diagnostic format. Its resolver includes named Cargo test, pytest, Go test/build, TypeScript and other formats; it does not expose a generic Clippy, Cargo check or lint filter. Broader compiler/lint fixtures are qualification inputs, not already supported coverage. The application's private command modules are not an Apache public Rust filter library. [Named filter resolver](https://github.com/rtk-ai/rtk/blob/4ef8730cf3a0dea11c8d64a9b90bc0616fe52100/src/cmds/system/pipe_cmd.rs).

## Correctness and recovery

| Evidence | Establishes | Does not establish |
|---|---|---|
| Exact recovery fixture | Tested original bytes can be retrieved | Agent notices omission and recovers before a wrong decision |
| Never enlarges a payload | Local size bound | Semantic equivalence, retained diagnostics, lower bill or quota use |
| Merged fix | Named defect changed in a selected path | Parallel-backend, edition or malformed-input correctness |
| Read-only tool list | Advertised capabilities | Server-side denial of hidden exec/edit calls |
| Stable index | Reusable source information | Model knowledge after compaction, reset, fork or another agent's read |
| Component tests | Tested API behavior | Complete-task quality or native host conformance |

Security findings, authorization decisions, exact diffs, executable material and final acceptance evidence need stronger preservation than routine redundant text. Optional-transform failure returns the captured result once; authorization/integrity failure remains an error. Never rerun a mutating producer merely because transformation failed.

## Evidence and economic limits

Historical studies concern different releases, hosts, models and policies. Current RTK evidence exists but is narrow. LemonCrow's old full-runtime benchmark does not qualify Lite retrieval; JetBrains studies of other tools contain no LemonCrow treatment. Full Ponytail, an adapted policy and passive instructions are separate arms. [Evidence eligibility](/research/context/tools/07-evidence-and-claims/).

A smaller payload can increase spending through cache misses, extra turns, reasoning, recovery or local inference. Count every attempt per accepted task, preserve aggregate and task-weighted estimates, and measure cold/warm latency and resource growth. Percentages from different interventions are not additive.

## Implications for jackin❯

Proceed with scoped configuration, qualification and evidence ownership. Package pinned experimental components automatically instead of invoking host-global installers. Reuse upstream APIs; contribute fallible persistence, epoch reset, exact-result contracts and read-only dispatch before forking. A fork needs an owner, upstream synchronization, regression corpus, security response and exit condition. [Reuse matrix](/research/context/engine/09-reuse-decision-matrix/).
