## Summary

Cutoff: **2026-09-23 UTC**. Reviewed release: [Headroom v0.38.0](https://github.com/headroomlabs-ai/headroom/releases/tag/v0.38.0), release commit `94206e265203acfd72a3b939e9a964e29175ad50`. Headroom is the strongest **source-level Rust transform candidate** in this comparison, not an established task-cost winner. Evaluate selected library capabilities before adopting its complete provider proxy.

## Question and scope

Can Jackin reuse the existing Rust implementation while retaining ownership of execution, recovery, configuration, and provider authentication?

## Method

Read the release, workspace manifest, core crate manifest, and exported transform surface at the release tag. Separate callable source APIs from stable SDK promises, successful builds, and outcome evidence.

## Findings

### The Rust surface is real

The [workspace](https://github.com/headroomlabs-ai/headroom/blob/v0.38.0/Cargo.toml) includes `headroom-core`, `headroom-proxy`, Python bindings, simulators, and parity tooling under Apache-2.0. The [core exports](https://github.com/headroomlabs-ai/headroom/blob/v0.38.0/crates/headroom-core/src/transforms/mod.rs) include `LogCompressor`, `SearchCompressor`, `CompressionPipelineBuilder`, `JsonMinifier`, and recovery-aware pipeline types. Describing Headroom as Python-only or requiring a wholesale Rust rewrite is incorrect.

| Choice | Advantage | Additional responsibility |
|---|---|---|
| Selected core transforms | Reuse existing algorithms without global wrapping | Typed payload contract, fidelity, packaging, bounded latency |
| Supervised worker | Fault and dependency isolation from the launcher | Lifecycle, deadlines, IPC, state scoping |
| Full proxy | Access to assembled provider requests | Authentication, streaming, cache continuity, retries, recovery protocol |

### Feature and dependency reality

The [core manifest](https://github.com/headroomlabs-ai/headroom/blob/v0.38.0/crates/headroom-core/Cargo.toml) declares internal crate version **0.1.0**, not product version 0.38.0. ML is enabled by default; `default-features = false` excludes optional ONNX/embedding/classifier dependencies. The remaining core still includes tokenizers, grammars, SQLite, and network-capable dependencies. Feature exclusion is not proof of a small binary, offline operation, or a successful build on every Jackin target.

The source explicitly distinguishes parity with the Python implementation from information preservation. Matching upstream output can reproduce upstream omissions. Jackin therefore needs independent fidelity tests, not just parity fixtures.

### Evidence and operational interpretation

No independent accepted-task result tied to this exact release and a proposed Jackin profile was established. Payload compression counters are not a control trajectory. A proxy benchmark configured to rewrite more historical content cannot qualify a selected-transform integration, and a selected-transform test cannot qualify the whole proxy. See [evidence eligibility](/research/context/tools/07-evidence-and-claims/).

## Implications for jackin❯

**Best part:** typed transformations of large structured observations, with explicit recovery and result metadata. Keep source code, diffs, requirements, and acceptance evidence raw until separately qualified.

**Integration choice:** try a commit-pinned `headroom-core` dependency inside an optional Jackin worker. Start with ML disabled and a small transform allowlist. Measure cold startup, allocations, concurrency, payload limits, and model/artifact access. Do not expose upstream types as Jackin's durable public API.

**Reuse before rewrite:** request upstream feature decomposition or a smaller supported kernel API when necessary. Extract licensed, tested source only when the library cannot satisfy a demonstrated boundary requirement. Do not rewrite the algorithms merely to avoid a Python wrapper that this integration does not need.

**Default decision:** no global provider proxy or automatic model download. Qualified transforms can later be activated invisibly at a supported tool-result seam.

## Limitations and unknowns

This review did not compile the dependency or run proxy traffic. Default-disabled ML does not remove all transitive complexity. Deadlines must cover the entire pipeline, not only one compressor. Recovery must remain available for resumed sessions, and a smaller result is not automatically semantically sufficient.
