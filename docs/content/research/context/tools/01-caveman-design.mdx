## Summary

Cutoff: **2026-09-23 UTC**. Reviewed release: [Caveman v2.7.0](https://github.com/JuliusBrussee/caveman/releases/tag/v2.7.0), with the release's **bin-v1.1.7** runtime. Caveman is two interventions, not one: a response-style skill and an input-processing stack. Jackin should evaluate these separately. A useful narration policy does not justify installing a provider proxy.

## Question and scope

Which Caveman capabilities belong in an automatically configured coding-agent environment, and which require separate compatibility, quality, and distribution decisions?

## Method

Inspect the release and tagged licensing map; distinguish the skill, engine-linked binaries, wrappers, and client SDKs. Mechanism evidence is not a new task benchmark. Study eligibility is recorded in [07 — Evidence](/research/context/tools/07-evidence-and-claims/).

## Findings

### Mechanisms and boundaries

| Surface | What it changes | Appropriate measurement |
|---|---|---|
| Skill / instruction asset | Visible narration and response style | Clarity, output tokens, entire task cost, correction turns |
| Engine / MCP / proxy | Selected input representations and recovery references | Reach, fidelity, recovery, cache tiers, accepted-task outcomes |
| Host wrapper | Installation, hooks, endpoint routing, local state | Configuration ownership, activation, credentials, rollback |

The [release notes](https://github.com/JuliusBrussee/caveman/releases/tag/v2.7.0) describe ownership-tracked native skill installation, config-home handling, endpoint validation before credential routing, per-request accounting, and recovery-store locking fixes. They also state that Codex shell rewriting was removed because it interfered with saved approvals. This is a concrete reason not to equate successful installation with preserved host semantics.

The release distinguishes repository, binary, CLI, SDK, and middleware versions. Some npm publications are marked pending. Pin the artifact actually obtained; do not infer registry availability from a GitHub tag or assign the product version to every component.

### Reuse and licensing

The tagged [licensing map](https://github.com/JuliusBrussee/caveman/blob/v2.7.0/LICENSING.md) assigns MIT to the skill and several adoption/client surfaces, and BSL-1.1 to the compression engine and engine-linked proxy, MCP, browser, and recovery components. Its additional grant distinguishes first-party use from third-party hosted, managed, or embedded services.

An MIT client does not relicense the engine it invokes. A separate process does not by itself settle the distribution boundary. Review the exact Jackin distribution model before shipping engine-linked functionality; this dossier is not a legal clearance.

### Evidence

No independent, release-matched accepted-task evaluation of this combined release was established in this review. The JetBrains skill study is not a test of this input stack or this exact release. Current release test counts are upstream reports, not tests executed by this review. Retirement of unmeasured stats claims improves reporting but is not itself a savings result.

## Implications for jackin❯

**Best part:** optional concise narration with exact-content and task-completeness protections. Ship a reviewed instruction asset only to suitable roles, or adapt a short policy and treat that adaptation as a new experimental treatment. Preserve identifiers, commands, requirements, error details, and requested explanations.

**Integration choice:** no Rust engine crate was established here. Native instruction delivery is preferable to adopting Caveman's global installer. Keep any full-engine/proxy experiment independently selectable, license-reviewed, and separate from the narration arm.

**Default decision:** do not impose a stylized dialect, suppress reasoning effort, or route credentials through the engine automatically. The [integration plan](/research/context/tools/11-jackin-integration/) defines a compatibility-qualified automatic profile instead.

## Limitations and unknowns

Shorter narration can change the agent's next actions; it is not merely cosmetic. A recoverable representation may still hide the fact that recovery is needed. Provider streaming, cache behavior, host approvals, and component-specific package availability require executable conformance tests on the distributed build.
