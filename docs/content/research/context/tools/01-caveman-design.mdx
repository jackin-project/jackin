**Research state:** Current


## Summary

Evidence cutoff: **2026-10-24T01:15:00Z**; sources accessed on **2026-10-24 UTC**, with release identities rechecked at 01:28–01:29 and 02:36–02:37 UTC. The product release is [v4.0.1](https://github.com/JuliusBrussee/caveman/releases/tag/v4.0.1), commit `d262ab3882952a59312ff3537cd86d894523c5ab`; the newest separately released runtime is [bin-v4.0.2](https://github.com/JuliusBrussee/caveman/releases/tag/bin-v4.0.2), commit `b4531dfc05a3ef0ba93b57e8bfa5f48564a4b4d6`. **The published 4.0.1 npm CLI still pins bin-v4.0.1.** Installing that CLI does not by itself select the runtime reviewed here. The releases contain different source trees as well as different build toolchains; do not attribute every bin-v4.0.2 behavior to the product-tag checkout.

Two previous conclusions change. Current repository code is Apache-2.0, including the formerly BSL engine; the older distribution objection is obsolete for these releases. The runtime is a reusable Go implementation with an exact-original store, so a narrow process integration is a credible alternative to a Jackin rewrite. Neither change establishes accepted-task savings. The full plugin also includes model-selecting subagents, and the proxy can make auxiliary cache-warming requests even when ordinary processing uses record mode. Concise instructions, input selection, schema changes, browser extraction, memory, proxying, warming, and cloud routing require separate treatment definitions.

## Question and scope

Which Caveman components can improve complete Jackin tasks, with a reviewed installation, reliable recovery, stable cache prefixes, preserved native permissions, and an effective off path? The analysis separates the useful primitive from the full installer and from unexecuted claims about model behavior.

## Method

Inspect tagged source, live GitHub releases, npm and PyPI distributions, generated runtime pins, licenses, and effective hook output. Run selected upstream tests and a generated JSON/recovery fixture without installing host-global hooks or using a paid model. The two source revisions are reported independently. The <RepoFile path="docs/content/research/context/techniques/tools/refresh-2026-10-24/caveman-ponytail/README.md">pinned reproduction method and provenance</RepoFile> documents exact commands, curated logs, failed build attempts, probes, source registers, package correspondence, and limits. The frozen sources were reexamined and the selected checks rerun; earlier results are not counted as new execution.

### What each component changes

| Component | Execution and interception boundary | Fidelity and reach |
|---|---|---|
| Default skill | Host-delivered instructions affect generated answers and behavior | No tool-result replacement; preserves exact literals, negation, requested language and needed explanations; stronger ultracave/megacave modes are separate treatments |
| Additional plugin skills / agents | Repository-root plugin discovery exposes policy and role files | Investigator/reviewer select Haiku; builder imposes a two-file scope limit; this changes more than narration |
| Go Engine | Local content classification and deterministic type-specific compression | Lossy selection plus exact-original recovery; unknown, malformed, or unhelpful transformations pass through |
| Proxy / wrapper | Intercepts requests routed to its endpoint; wrapper changes host routing and installs temporary tool/instruction surfaces | Does not automatically intercept every native tool or every provider connection; output filtering and recovery depend on the adapter |
| TOON | Explicit supported structured-data encoding and decoding | Restricted logical JSON round trip; not original byte formatting and not universal JSON support |
| Pixel | Opt-in text-to-image representation with model gate and density setting | Exact visual reading is a model capability, not guaranteed by reversible rendering |
| Shrink | Reduces tool-schema annotations and descriptions while retaining structural fields | Names/types/enums surviving does not prove unchanged tool choice or argument semantics |
| Cavemem | SQLite/BM25 memory with remember, recall, supersede, history, forget | Retrieved notes are not a complete session transcript or proof another agent has seen a fact |
| Browse / browser extension | Browser-specific extraction and CDP operations | A different tool surface, not a transparent replacement for arbitrary native reads |
| SDK / middleware | Local or remote API clients and integration helpers | Caller still owns routing, permissions, lifecycle, scope and recovery availability |
| Cache warmer | Background requests through the proxy to eligible direct Anthropic requests | On by default unless disabled; additional request cost and credential handling are separate from result compression |
| Cloud Auto | Optional remote model/effort routing | Changes the selected model or effort and belongs outside the fixed-policy compression comparison |

These boundaries are visible in the pinned [Engine API](https://github.com/JuliusBrussee/caveman/blob/b4531dfc05a3ef0ba93b57e8bfa5f48564a4b4d6/engine/engine.go), [result options](https://github.com/JuliusBrussee/caveman/blob/b4531dfc05a3ef0ba93b57e8bfa5f48564a4b4d6/engine/result.go), [TOON implementation](https://github.com/JuliusBrussee/caveman/blob/b4531dfc05a3ef0ba93b57e8bfa5f48564a4b4d6/engine/toon.go), [pixel gate](https://github.com/JuliusBrussee/caveman/blob/b4531dfc05a3ef0ba93b57e8bfa5f48564a4b4d6/engine/pixel/gate.go), [memory documentation](https://github.com/JuliusBrussee/caveman/blob/b4531dfc05a3ef0ba93b57e8bfa5f48564a4b4d6/mem/README.md), and [Shrink documentation](https://github.com/JuliusBrussee/caveman/blob/b4531dfc05a3ef0ba93b57e8bfa5f48564a4b4d6/shrink/README.md).

### Effective defaults, overhead, and exposure

The [v4.0.1 delivered skill](https://github.com/JuliusBrussee/caveman/blob/d262ab3882952a59312ff3537cd86d894523c5ab/skills/caveman/SKILL.md) now puts clarity ahead of compression. It protects code, paths, errors, numbers, negations, existing comments, requested language, ambiguity/safety explanations, persisted artifacts, and harness-required status messages. Describing it only as broken grammar misses these guards. Its presence still does not prove obedience or unchanged task choices.

The root [marketplace manifest](https://github.com/JuliusBrussee/caveman/blob/d262ab3882952a59312ff3537cd86d894523c5ab/.claude-plugin/marketplace.json) points at the whole plugin. Its [investigator](https://github.com/JuliusBrussee/caveman/blob/d262ab3882952a59312ff3537cd86d894523c5ab/agents/cavecrew-investigator.md) and [reviewer](https://github.com/JuliusBrussee/caveman/blob/d262ab3882952a59312ff3537cd86d894523c5ab/agents/cavecrew-reviewer.md) declare `model: haiku`. The [builder](https://github.com/JuliusBrussee/caveman/blob/d262ab3882952a59312ff3537cd86d894523c5ab/agents/cavecrew-builder.md) refuses work spanning three or more files and has no Bash testing step. These are delivered policies, not evidence that every host selected or executed them. Exclude them from a fixed-model narration experiment and from an adaptation that must finish architectural migrations. The [optional override hook](https://github.com/JuliusBrussee/caveman/blob/d262ab3882952a59312ff3537cd86d894523c5ab/src/hooks/cavecrew-model-overrides.js) can rewrite installed role frontmatter from `CAVECREW_*_MODEL` values; none was set here. Other bundled policies have different scopes; do not generalize one role to every skill.

Hook-generated default activation measured **4,961 bytes / 1,246 o200k_base estimated tokens**; the source skill file alone was **4,678 bytes / 1,158 tokens**. These are different denominators. Count actual host-added text, wrapper schemas, recovery tool descriptions, and repeated injection in each treatment. This probe did not measure a provider-billed request or all host configurations. The earlier 1,248-token activation count came from another generated path/context; the fresh 1,246 estimate is not a universal constant. Isolated hooks preserved explicit off across compact/resume/fork but reset to the configured active default on clear; actual host event delivery still needs conformance testing.

The raw [proxy configuration](https://github.com/JuliusBrussee/caveman/blob/b4531dfc05a3ef0ba93b57e8bfa5f48564a4b4d6/proxy/internal/config/config.go) defaults to loopback and record mode, whereas the [CLI wrapper](https://github.com/JuliusBrussee/caveman/blob/d262ab3882952a59312ff3537cd86d894523c5ab/packages/cli/src/index.ts) selects compression and host-specific recovery/output tooling. Cache planners can alter Anthropic cache breakpoints, OpenAI cache keys, and Bedrock cache points in optimization modes; schema stripping is independently disabled by default. Do not compare a wrapper run against a raw-proxy default as if they were the same treatment.

The [cache-warm switch](https://github.com/JuliusBrussee/caveman/blob/b4531dfc05a3ef0ba93b57e8bfa5f48564a4b4d6/proxy/cmd/caveman-proxy/cache_warm.go) defaults **on**, including when configuration is absent or malformed. The [gateway warmer](https://github.com/JuliusBrussee/caveman/blob/b4531dfc05a3ef0ba93b57e8bfa5f48564a4b4d6/proxy/internal/gateway/cache_warm.go) retains selected request bodies and credential headers in bounded memory and can replay an eligible direct Anthropic request with `max_tokens: 0` and `stream: false`. It applies provider/shape/TTL gates, and accounts warm costs separately. Wiring is independent of ordinary record/compress mode. A controlled raw baseline must explicitly set `CAVEMAN_CACHE_WARM=off`; record mode alone is insufficient evidence of no auxiliary requests. No real provider warm request was sent in this review.

The CLI can write host configuration, download pinned artifacts, and record owned changes for removal. Interactive CLI telemetry is opt-out; `DO_NOT_TRACK=1` or `CAVEMAN_TELEMETRY=0` disables it, while noninteractive telemetry defaults off in the inspected entrypoint. Optional Cloud routing sends prompt-related fields and request facts; the documented Free plan may retain routing data for improvement. Local operation still sends selected context to the chosen model provider. These are separate data flows, described in pinned [security and privacy documentation](https://github.com/JuliusBrussee/caveman/blob/b4531dfc05a3ef0ba93b57e8bfa5f48564a4b4d6/docs/technical/security-and-privacy.md).

### Recovery, storage, concurrency, and failures

The Engine saves the original before returning a lossy result. A missing store prevents lossy compression unless the caller explicitly claims external recovery; that option makes prior persistence the caller's responsibility. Storage failure returns the original with an error; the integration must handle that error without rerunning the underlying command. Record mode is exact pass-through. A successful exact-retrieval check cannot establish that an agent recognizes when a missing detail matters.

The native [CCR implementation](https://github.com/JuliusBrussee/caveman/blob/b4531dfc05a3ef0ba93b57e8bfa5f48564a4b4d6/engine/ccr/store_sqlite.go) defaults to a **512 MiB retained-payload ceiling** and refuses new records rather than evicting old ones. Missing handles are errors. SQLite uses WAL and a five-second busy timeout; initialization can retry idempotent setup for up to 30 seconds. Identity checks invalidate an observed replaced database and require restart; relevant tests cover multiprocess replacement and capacity. This is a specific recovery property, not proof against every filesystem race. WASM/in-memory stores are not durable. Handles are content identifiers, not authorization credentials or encryption. Capsule, repository, worktree, session and context-epoch scope remain integration requirements.

The [middleware store](https://github.com/JuliusBrussee/caveman/blob/b4531dfc05a3ef0ba93b57e8bfa5f48564a4b4d6/proxy/internal/config/middleware.go) has a different lifetime: default one day, maximum seven days, default 576 MiB. Do not extend the native no-eviction promise to middleware records. Memory is another independent database with its own supersession/forget semantics. Its default recall budget is 2,000 estimated tokens; an explicit zero is unlimited, so it is not a global context guard. Native CLI inputs are bounded, but bounds vary by component; Engine accepts up to 64 MiB and Shrink up to 32 MiB. A capsule needs explicit paths and retention policy, not several unnoticed home-directory stores.

### Reuse feasibility and measured local work

The public Go API exposes construction, compression, retrieval, detection, stats, simulation, registry replacement, and an injectable token counter. No supported Rust crate was established. The [token counter](https://github.com/JuliusBrussee/caveman/blob/b4531dfc05a3ef0ba93b57e8bfa5f48564a4b4d6/engine/tokens/tokens.go) embeds o200k_base with an approximation fallback; neither is Anthropic billing ground truth. Builds use SQLite and tree-sitter-related dependencies. This refresh built and tested both CGO settings: no-CGO lost TypeScript, JavaScript and Python listing compression in the selected Engine fixture; the CGO build passed. These are build-profile differences, not evidence that the published native binary failed that fixture. A process boundary avoids importing a Go runtime into Jackin's Rust process, while adding startup, IPC, lifecycle, binary supply and recovery ownership work.

The [MCP server](https://github.com/JuliusBrussee/caveman/blob/b4531dfc05a3ef0ba93b57e8bfa5f48564a4b4d6/mcp/server.go) exposes five tools over stdio. Locally reserializing their definitions produced **3,097 bytes / 694 o200k_base tokens**, before host wrappers or other instructions. Exact recovery is exempt from the normal output cap, so a host must explicitly handle large originals. A complete integration owns authentication, permissions, cancellation, context budgets and recovery discovery; availability of a Go function does not supply those contracts.

The synthetic array fell from **14,002 to 139 estimated tokens**. Repeated rows made it deliberately compressible; this is a component result, not a task-cost claim. Earlier attempts failed before tests because of a network-proxy configuration and then a full shared filesystem. Those setup/build failures, the no-CGO failure and the final passing CGO run are distinct entries in the artifact manifest. All Go tests used the clean pinned runtime checkout; unrelated untracked files were observed in the product checkout and are disclosed rather than treated as release contents.

### What the published studies establish

The [JetBrains July 6 study](https://blog.jetbrains.com/ai/2026/07/speak-to-ai-agents-like-cavemen-tosave-tokens/) tested a historical output skill, Claude Code 2.1.200 and Sonnet 5 at low effort: 82 paired SkillsBench tasks yielded 8.5% less output, a nonsignificant score difference, and 11.6% higher aggregate reported cost dominated by one long-context outlier. JetBrains is an agent-tooling vendor; it did not test this runtime, and nonsignificance does not demonstrate equivalence.

Current [Honest Numbers](https://github.com/JuliusBrussee/caveman/blob/d262ab3882952a59312ff3537cd86d894523c5ab/docs/HONEST-NUMBERS.md) labels its small style comparison as ten prompts, one run per condition, a 3.1.0 skill not rerun after 3.2, and local token estimates. Its default-mode median is 3% shorter than a concise-answer prompt; ultra/mega medians are 35%/9% in that same small sample. These are output-only local estimates. Input overhead and a reviewed fidelity snapshot are not supplied. The previously fixed 65% savings display has been withdrawn; a counter or UI estimate must not be interpreted as observed spend.

The first-party [wrap benchmark](https://github.com/JuliusBrussee/caveman/blob/d262ab3882952a59312ff3537cd86d894523c5ab/docs/WRAP-BENCHMARK.md) reports an August six-fixture/18-pair agent experiment with 33.2% fewer summed input tokens and 18/18 exact answers. That denominator combines fresh input and cache categories without price weighting. The August setup used Claude Code 2.1.223/Sonnet 5, three repetitions of six deterministic 60–95 KB fixtures, with a reported 14.6–48.5% clustered interval for token reduction. Its cloud harness/raw runs are not public; the October 3 per-file `Engine.Simulate` result of 82.4% is a different experiment without agent calls. It cannot establish current bills, diverse task quality, or a six-tool winner.

[CAVEWOMAN](https://arxiv.org/abs/2606.24083) studies input/output telegraphic representations across models and QA tasks, not this Engine. [Notation Matters](https://arxiv.org/abs/2605.29676) reports token/accuracy tradeoffs for tool serialization, including TOON/TRON, on open-weight models. Both motivate fidelity tests; neither supplies a current hosted-agent savings estimate. See [the evidence ledger](/research/context/tools/07-evidence-and-claims/) for study eligibility.

## Implications for jackin❯

**Default candidate:** a short clarity-preserving narration policy delivered by Jackin's native agent configuration, with complete literal/error/status reporting and the operator's model/effort unchanged. Evaluate the exact upstream skill separately from an adapted policy. There is no reason to install a global CLI solely to deliver that text.

**Experimental candidate:** one pinned Go Engine sidecar and one deterministic content family, with Jackin-owned capsule paths, exact originals, explicit retrieval, bounded execution, session provenance, and native passthrough. The Apache licensing change makes reuse preferable to assuming a rewrite. First resolve the CLI/runtime pin mismatch; contribute an independently selectable reviewed-runtime pin and host conformance fixtures upstream where possible. Do not silently replace the reviewed artifact with a floating download.

**Hold separately:** full plugin agents, proxying, cache warming, schema shrinking, memory, browser extraction, TOON, pixels, and cloud routing each need their own reach, safety and economic case. Cloud model/effort routing is a separate intervention regardless of whether the product bundles it. An effective off path must restore native routing and tools and keep required recovery available for references already emitted.

## Limitations and smallest decisive next experiment

No paid agent benchmark, host-global installation, all-platform build, sustained memory measurement, native read-before-edit trial, or subscription-quota experiment was executed. Source tests do not establish actual host interception or cache benefit.

The smallest promotion experiment is a paired accepted-task trial of **native tools versus one current runtime content transformer**, holding agent, model, effort, authentication route and cache policy fixed. Include a repeated JSON/log task with one rare decisive record, a malformed result, a missing recovery record, an interrupted request, and concurrent worktrees. Capture actual model-facing bytes, all recovery calls and failures, fresh/cache-write/cache-read/output usage, correctness, and end-to-end latency. Charge failed attempts and follow-up repair. Only then add a second transformation or the provider proxy.
