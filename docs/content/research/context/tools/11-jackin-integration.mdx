## Summary

Snapshot **2026-10-24 01:15:00 UTC**. Reviewed Jackin base: **`6e266406b49da2ab3c55355f3b7d33d1643ee6cd`**. **Own the small scope, recovery, activation and evidence contracts; preserve native execution/editing/provider policy; reuse reviewed components behind replaceable adapters.** The target is useful automatic optimization, with experimental alternatives and a complete off path. This is a research/implementation decision; no optimizer, dependency or active configuration is added by this PR.

The first substantial automatic-filter candidate is a pinned RTK OSS `pipe --filter <named-family>` subprocess, initially for one qualified test/diagnostic format. Headroom Rust/Python and Caveman's engine are competing transform arms; native retrieval, LeanCTX and LemonCrow Runtime Lite are competing retrieval arms. Concise owned instruction assets are separate. No external treatment currently has the complete Jackin host/task qualification needed for default activation.

## Question and scope

What should Jackin install, configure, activate, embed, adapt or contribute upstream without weakening complete-task correctness, current isolation, credential handling or chosen model/effort? A PTY, library dependency or integration badge does not prove access to model-bound native results.

### Twelve registered agents, six current launch branches

The registry/CLI accept Claude, Codex, Amp, Kimi, OpenCode, Grok, Antigravity, Gemini, Cursor, Muse, omp and Hermes. The reviewed <RepoFile path="docker/runtime/entrypoint.sh">entrypoint</RepoFile> has branches only for the first six. The image builder copies the embedded script unchanged. The isolated case-selection probe returned exit 2 for the remaining six. This establishes a dispatch gap, not end-to-end success for the first six.

The six existing branches deliberately use permissive native modes, including Claude's skip-permissions and Codex's bypass-approvals-and-sandbox flags. Preserve and accurately record the actual configured Jackin isolation/credential boundary; do not claim native prompts are currently enabled. Optimization must not broaden that authority. Fixing missing launch paths or changing native approval policy is separate production work.

OpenCode's inspected default-branch commit is not asserted to be the delivered Jackin host version.

**Claude:** current [hooks documentation](https://code.claude.com/docs/en/hooks) permits `PostToolUse.updatedToolOutput` for native/MCP results; built-in replacements must match the tool's output shape, and invalid shapes leave the original. `additionalContext` appends. Async hooks do not provide synchronous replacement. Original side effects and prior telemetry are not undone. Interactive workspace trust and noninteractive behavior must be respected. Jackin's current async status hook is therefore not this adapter.

**Codex:** current [hooks documentation](https://learn.chatgpt.com/docs/hooks) requires trust for exact nonmanaged hook definitions. PostToolUse block/exit-2 feedback replaces the result and rejects a nested code-mode promise; `continue: false` substitutes feedback without that rejection. `updatedMCPToolOutput` and `suppressOutput` are parsed but unsupported, with failed-hook/original-result behavior. Long-running shell completion can surface later through `write_stdin`. These differences block assuming transparent Claude-compatible output substitution. Automatic spill/truncation is not Jackin's durable recovery guarantee. Test exact installed host behavior without editing trust records to bypass review.

[Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) supports process cwd/environment, tool allow/deny settings and timeouts. Host schema hiding/annotations do not replace server dispatch authorization or filesystem limits. MCP adds another route; it does not automatically remove native reads, execution or editing. Keep native edit receipts and stale-write protection.

### Concrete reuse choices

| Capability | First implementation/comparison | Boundary that must remain Jackin-owned |
|---|---|---|
| Selected noisy diagnostics | Pinned Apache RTK OSS `pipe --filter <named-family>` process; compare Headroom no-ML Rust/Python and Caveman engine independently | Execute once, original capture, typed eligibility, durable recovery and host replacement |
| Repository retrieval | Native baseline versus one restricted LeanCTX or LemonCrow Lite process | Admitted roots, server allowlist, exact-read escape, native edit prerequisites and consumer epoch |
| Output/reuse policy | One restrained owned asset; exact Caveman/Ponytail skill/plugin arms separately | Policy precedence, version/activation, session off state and complete-work requirements |
| Small pure primitives | Native tools or suitable published Rust search/parser/MCP crates | Actual feature/IO/license/native-link graph, target builds and no hidden process state |
| Full proxy/runtime/persona | Explicit experimental treatment only | Provider auth/history/streaming/retry/cache, execution/edit semantics and separate outcome qualification |

The [reuse matrix](/research/context/engine/09-reuse-decision-matrix/) compares all seven implementation modes and specific licenses. Headroom's no-ML build passed but does not supply host delivery or complete recovery. RTK now has a typed engine, but it is BUSL rather than the Apache OSS filter boundary. Caveman's engine is now Apache. LeanCTX's facade is unpublished and process-global. LemonCrow's current public Lite source differs from its private advanced engine and historical full-runtime benchmark. None of those facts alone chooses the default.

## Implications for jackin❯

### Worker, recovery and security contract

The trusted request includes admitted scope, observation/tool identity, content type/exactness, bytes or bounded artifact descriptor, known producer status, capture completeness and deadline. The worker returns unchanged or a candidate with version/configuration, hashes, explicit omissions and authorized recovery reference. Statistics travel out of band.

Authenticate/admit before capture/retrieval. Preserve only the original observation already authorized and subject to mandatory redaction. Acknowledge durable storage before emitting a lossy result; retain active handles through supported resume. Optional transform/storage failure returns the existing authorized observation. Authorization, path integrity, corruption or mandatory redaction failure does not bypass policy. Never rerun a producer command because reduction or recovery failed.

One owner transforms each observation. One selected backend owns each index scope. One host consumer/context epoch owns exposure. Shared immutable indexes may be useful; shared “already seen” state is a different problem. Initial process-per-scope isolation avoids upstream global cwd/environment state, but workers still need OS path/egress/resource confinement. [Observation](/research/context/engine/03-observation-pipeline/), [state](/research/context/engine/07-memory-and-state/).

### Automatic setup, profiles and rollout

Package reviewed commits/artifacts in the capsule image; generate only owned registrations in the real agent home; preserve unrelated configuration and host trust. Disable optimizer telemetry/self-updates/model downloads and unsolicited warmers unless explicitly selected and authorized. Do not silently run upstream global installers or fetch moving latest components at launch.

The proposed `auto` profile preserves native features, delivers duplicate-free restrained guidance and activates approved host/version/content records. `experimental` selects a declared component treatment. `off` stops new optimization while retaining current security and previously referenced originals. None is an existing manifest field. Effective configuration exposes actual source pins, activated boundary, owner, state roots and bypass reasons. A silent no-op is not a successful optimizer.

The first implementation stages are native-policy/usage attribution, owned assets, scoped recovery, one Claude diagnostic adapter, then fixed-model/effort task comparison and automatic canary. Codex and other hosts each need their own conformance gate. The [rollout chapter](/research/context/engine/10-rollout-and-validation/) specifies concrete profiles, absolute cold/warm/resource budgets and rollback; the [evidence protocol](/research/context/tools/07-evidence-and-claims/) owns statistical gates.

Promotion requires zero new critical failures, bounded quality uncertainty, demonstrated all-attempt economic benefit for a new complex optimizer and acceptable task/local latency. Pilot counts are not proof. API and subscription arms use their actual denominators. Low-impact native preservation does not require an artificial large saving. Off/rollback must not delete artifacts still referenced by prior context.

### Upstream work before a fork

Prioritize a pure typed OSS filter interface for RTK; fallible durable CCR/JSON-domain/line-parity contracts for Headroom; caller-owned paths/runtime and explicit epochs for LeanCTX; enforced retrieval-only dispatch and spill-failure semantics for LemonCrow; clear component/runtime/warmer manifests for Caveman; and persistent session opt-out/bounded map IO for Ponytail. These are proposed contribution briefs, not submitted or accepted issues. A narrow fork requires applicable license, named owner, sync cadence, regression corpus and retirement condition. [Detailed briefs](/research/context/engine/09-reuse-decision-matrix/).

## Limitations and unknowns

The dispatch probe is not a container test; documentation/source contracts are not observed model-bound replacement; product tests are not accepted-task results. No paid host/provider experiment, full concurrent capsule security test or combined Jackin dependency build ran. The full-facade offline LeanCTX consumer attempt stopped on missing cached `rmcp`; separate minimal graphs did reproduce SQLite `links` collisions for the extracted 0.39/0.34/0.32 versus Jackin 0.40.2 constraints. Neither is a complete combined product build. Real host trust/discovery, native edit receipts, streaming cancellation, epoch continuity and task benefit remain specific next gates.

This work replaces the old no-build environment assertion with the actual executed product evidence, while preserving the checks that remain unexecuted. It does not treat unknown behavior as ready or use that uncertainty to justify an unconditional rewrite.
