**Research state:** Current

## Summary

Source cutoff: **2026-10-24T01:15:00Z**. Reviewed stable release: [RTK v1.0.1](https://github.com/rtk-ai/rtk/releases/tag/v1.0.1), published October 14, commit `4ef8730cf3a0dea11c8d64a9b90bc0616fe52100`. The release remains current at the final metadata recheck. Later default-branch work and development prereleases are separate treatments.

RTK now has a reusable compression engine, an application library target, a stdin-filter executable interface, and a separate provider proxy. The earlier “no library” conclusion is obsolete. **The default binary includes BUSL-1.1 code; the separately distributed `rtk-oss` edition retains the Apache-2.0 command filters.** These are different reuse and licensing choices.

The strongest immediate option is an experimental **pinned OSS diagnostic filter behind caller-owned capture**, with native execution and approvals retained. Current fixtures support that investigation; they do not establish a task-efficiency winner. Keep machine-consumed output and review diffs exact: the corrected structural diff parser and the Git compacting filter are different implementations, and the latter still omits information on tested inputs.

## Question and scope

Which RTK components can reduce observations without changing command execution, permissions, diagnostic meaning, or access to the original evidence? Evaluate filtering separately from instruction injection, native tool transformation, history compression, routing and representation changes.

## Method and evidence

Reopened tagged source, manifests, licenses, release assets, registry records, parser/recovery implementations and hook lifecycle code. Verified the published Linux x86_64 musl **full and OSS** archives against GitHub asset SHA-256 digests; both report 1.0.1. Built and tested the engine with a locally available Rust 1.99.1 toolchain. Ran real Git and dependency-free Cargo producers, controlled signal fixtures, and malformed stdin probes. No paid agent runs, global installer, proxy activation or model-policy changes were performed.

The <RepoFile path="docs/content/research/context/techniques/tools/refresh-2026-10-24/rtk-leanctx/README.md">reproduction record</RepoFile> contains commands, fixture code, results, source hashes and exact build limitations. Component execution is distinct from host activation and accepted-task evidence.

## Independently selectable interventions

| Intervention | What executes and sees | What changes and remains outside its reach |
|---|---|---|
| Command wrapper/rewrite | Parses a shell request, may rewrite it, then launches the selected command | Deterministic selection/formatting; commands outside the route and native read/search results remain untouched. Execution and approval compatibility need qualification. |
| `rtk pipe --filter FAMILY` | Reads already-produced stdin; does not execute the producer | Process boundary for selected UTF-8 filters. Owns neither producer exit/signal state nor durable raw recovery. |
| `rtk diff -` | Reads a unified diff through the structural region parser | Condensed representation with structural fallback; different from `pipe --filter git-diff`. |
| Engine methods / hook pipelines | Block methods plus optional external process methods | Selected observation transforms or directives where the host supports them. Metadata declaring fidelity/cache stability is an assertion to test. |
| Awareness / terse directives | Instructions delivered through supported hook/configuration paths | Model behavior and instruction overhead; separate arm from filtering. |
| Provider proxy | Separate daemon sees requests routed through its endpoint | Normalization, optional cache alignment, CCR/history, representation and routing; bypass traffic remains invisible. Distinct auth/network/storage intervention. |

Primary implementation: [stdin filters](https://github.com/rtk-ai/rtk/blob/4ef8730cf3a0dea11c8d64a9b90bc0616fe52100/src/cmds/system/pipe_cmd.rs), [method contract](https://github.com/rtk-ai/rtk/blob/4ef8730cf3a0dea11c8d64a9b90bc0616fe52100/engine/src/method.rs), [default pipeline](https://github.com/rtk-ai/rtk/blob/4ef8730cf3a0dea11c8d64a9b90bc0616fe52100/engine/builtin/default.toml), [proxy boundary](https://github.com/rtk-ai/rtk/blob/4ef8730cf3a0dea11c8d64a9b90bc0616fe52100/proxy/README.md). The default pipeline contains shell rewriting and, when a proxy is running, ANSI/progress/dedup normalization; it has no `after_tool` rule. Removing repeated lines or progress information is not universally semantically lossless.

The [posthook implementation](https://github.com/rtk-ai/rtk/blob/4ef8730cf3a0dea11c8d64a9b90bc0616fe52100/src/hooks/posthook.rs) can emit an output-replacement field. That does not establish that a host/version accepts it for every native tool. Verify the model-facing transcript, not just hook stdout or terminal presentation. The [host integration decision](/research/context/tools/11-jackin-integration/) governs that qualification.

## Diff corrections at the correct surface

The [structural parser](https://github.com/rtk-ai/rtk/blob/4ef8730cf3a0dea11c8d64a9b90bc0616fe52100/src/cmds/git/diff_cmd.rs) tracks file regions and hunk budgets, handles header-like content, and rejects malformed/incomplete structures for raw fallback. Source tests cover no-prefix paths, mail patches, combined hunks, truncation and no-newline markers. We did not execute that entire upstream CLI corpus. The old prefix-classifier defect is not a valid blanket rejection of this parser.

However, [Git `compact_diff`](https://github.com/rtk-ai/rtk/blob/4ef8730cf3a0dea11c8d64a9b90bc0616fe52100/src/cmds/git/git_cmd.rs) is a different, budgeted path used by the Git wrapper and `pipe --filter git-diff`. Current executable evidence establishes:

| Same fixture / boundary | `rtk diff -` | `rtk pipe --filter git-diff` |
|---|---|---|
| Real Git patch containing header-like source lines | Retained changed payload and no-final-newline marker | Retained changed payload; omitted no-final-newline marker |
| Patch cut before hunk budget completes | Fell back to input with an added terminating newline | Condensed partial content and counts, without an incomplete-hunk warning |
| Non-diff text without final newline | Returned text with a terminating newline | Empty stdout, exit 0 |
| Invalid UTF-8 ending in newline | Preserved bytes in this fixture | Exit 1, no stdout |

Thus “raw fallback” also needs byte-level qualification: `diff -` deliberately adds a newline when absent. Generic `pipe --passthrough` preserved the tested non-UTF-8/NUL/CRLF bytes. Neither compacting diff surface should supply an applyable patch, exact review evidence or machine protocol without a separately proven representation contract.

## Recovery and provenance

[SQLite recall](https://github.com/rtk-ai/rtk/blob/4ef8730cf3a0dea11c8d64a9b90bc0616fe52100/src/core/retriever.rs) defaults to 10 MiB per entry, 200 entries, 30-day retention and gzip. Its identifier is the first 12 hexadecimal SHA-256 characters of command plus a separator plus captured content. Rows retain command, cwd, exit status, creation time, shown-line position, size, truncation state and payload. The hash itself is not a session/worktree identity. Over-cap storage may preserve a bounded hidden tail rather than a complete original; expiry and oldest-entry eviction occur on writes.

[Tee/retriever dispatch](https://github.com/rtk-ai/rtk/blob/4ef8730cf3a0dea11c8d64a9b90bc0616fe52100/src/core/tee.rs) is conditional. Ordinary failure hints require a nonzero exit and at least 500 captured bytes; forced truncation paths can store successful output. Legacy tee defaults are 20 files and 1 MiB per file, with success capture optional. This is neither raw-rerun-only nor a universal durable original store.

The real failing Cargo-test fixture returned exit 101, retained assertion detail and supplied a working recall reference. A successful Cargo-check warning retained its message/location but produced no recall hint. Missing recall returned an error. Recovery cannot restore bytes never captured or retained, and a model may never request an omitted detail.

The stdin filter does not archive input. It rejects input above 10 MiB or invalid UTF-8 before filtering; panic fallback and estimated-size `never_worse` do not make malformed family inputs safe. Jackin must capture once, preserve stdout/stderr and producer status, and treat optional filter failure as passthrough of that captured observation. Never rerun a side-effecting producer to recover from a transformation error.

## Defaults, costs and lifecycle

`rtk init` can write agent instructions, hook/plugin files and settings at project or global scope. The [agent-specific lifecycle](https://github.com/rtk-ai/rtk/blob/4ef8730cf3a0dea11c8d64a9b90bc0616fe52100/docs/guide/getting-started/supported-agents.md) has different cleanup and ownership rules; removing the binary alone does not remove integrations. No installer/uninstaller was executed. Jackin should own capsule-local files and remove only that profile's registrations, state and executable on rollback.

The [rewrite protocol](https://github.com/rtk-ai/rtk/blob/4ef8730cf3a0dea11c8d64a9b90bc0616fe52100/src/hooks/rewrite_cmd.rs) distinguishes allow/rewrite, defer, deny-to-host and rewrite/ask through exits 0, 1, 2 and 3. These are not producer exit statuses. A denied rewrite must still pass through native authorization; it is not permission to execute.

[Telemetry](https://github.com/rtk-ai/rtk/blob/4ef8730cf3a0dea11c8d64a9b90bc0616fe52100/src/core/telemetry.rs) requires explicit consent, an enabled setting and a compiled endpoint; `RTK_TELEMETRY_DISABLED=1` disables it. Local tracking/recall still write data. The inspected deterministic filters need no model download. Optional external methods and proxy have separate dependencies, credentials and egress boundaries; they were not activated.

The [text estimator](https://github.com/rtk-ai/rtk/blob/4ef8730cf3a0dea11c8d64a9b90bc0616fe52100/text/src/lib.rs) uses UTF-8 byte length divided by four, rounded up. A smaller estimate is not measured provider-token, bill or quota reduction. Filtering a new observation can preserve prior history, but instructions, schemas, recovery calls and serialization still affect cache behavior. Proxy normalization/alignment require separate provider-specific measurements.

| Verification | Result and scope |
|---|---|
| Locked `rtk-engine` tests | **286 unit tests and 1 guide integration test passed**, zero doc tests, Rust 1.99.1/Linux x86_64. Initial run lacked `rustdoc` on PATH; corrected run exited 0. |
| Full and OSS binary fixtures | Each completed the same 25 records. All 15 shell cases preserved exits: quoting, `&&`/`||`, environment, spaced cwd, nested Bash, redirects and selected pipes. Some cases correctly deferred rewriting. |
| Serialization | Standalone porcelain status lost its trailing newline; selected piped/redirected machine consumers stayed raw. This is not complete shell equivalence. |
| Real producers | Dependency-free Cargo success warning/failure diagnostics retained; failure recall worked. CRLF/no-final-newline/non-UTF-8 file comparisons reported differences rather than false equality. |
| Interruption | Controlled long-running Cargo shim retained a pre-SIGTERM diagnostic; wrapper exited by signal. Whole-process-tree, PTY, Windows and arbitrary streaming behavior remain untested. |
| Diff/invalid input | Surface differences reproduced above; over-cap pipe rejected; missing recall failed visibly. |
| Full source CLI tests | Not completed. Checkout residue caused a build-script refusal before selected tests ran: experiment setup failure, not a stable-release defect. |
| Task economics / host delivery | Not run locally. See [evidence review](/research/context/tools/07-evidence-and-claims/) for historical studies and the newly located release-matched external RTK study. |

Individual timings remain in artifacts; they are not randomized cold/warm benchmarks. OS caches and producer compilation differ between calls. RSS, CPU attribution, fleet contention, durable recovery under disk-full/crash and accepted-task cost remain unmeasured.

## Jackin decision and decisive next steps

1. **Qualify pinned OSS for selected noisy diagnostics.** Invoke a chosen stdin filter on captured bytes, with one transformation owner and Jackin-owned recovery. Preserve native execution, approval, auth and model/effort. Optional-transform failures return captured bytes; integrity/authorization failures remain failures.
2. **Keep exact reads, machine formats and review diffs raw.** Current Git compaction behavior independently justifies exclusion. Promote a family only after its malformed/truncation/Unicode/signal corpus and model-facing activation check pass.
3. **Evaluate engine reuse as a licensed arm.** Public traits and passing tests justify a spike, not a supported-SDK assumption. Seek version guarantees, caller-owned recovery and an appropriate distribution grant. Apache CLI private modules do not supply that typed API.
4. **Prefer a narrow upstream API contribution to a full fork.** Proposed contract: typed observation in; bytes, omitted ranges, provenance and recoverability out; no command launch, global settings mutation or implicit storage. An extraction needs verified applicable terms, a maintenance owner, synchronization policy and regression corpus.
5. **Compare complete tasks before default activation.** Hold agent/model/effort and native permissions fixed; count instructions, schemas, recovery, retries, failures and cache classes. Full-product/proxy/representation arms remain separate. Rollback removes the selected reducer while keeping native observations and resumable originals usable.
