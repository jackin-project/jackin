## Question and scope

What exactly should ship, in what order, with which evidence and rollback behavior? This chapter proposes separate implementation work. This research PR adds no production optimizer, dependency, installer or active manifest setting.

## Findings

### Concrete profile decision

| Profile | Packaged/configured behavior | Activation and current readiness |
|---|---|---|
| `auto` | Preserve native execution/editing/provider/model policy; deliver one restrained owned asset; select a pinned diagnostic reducer only for qualified host/version/family; provide recovery | Native behavior exists. Owned asset consolidation, selector and recovery are proposed. First substantial candidate: RTK OSS `pipe --filter <named-family>` subprocess, initially one qualified test/diagnostic format, after all gates. |
| `experimental` | Explicitly choose one upstream transform, restricted retrieval backend or exact policy; keep versions and component effects visible | Headroom Rust/Python, Caveman engine/skill, LeanCTX and LemonCrow Lite are separately selectable candidates; component evidence exists, full Jackin qualification does not. |
| `off` / raw | Disable new reductions, retrieval steering and owned optimization policy; use native authorized observations and current security | Required control/migration work. Keep recovery for earlier transformed observations; disable does not erase the conversation's past. |

The automatic profile is a target implementation, not a claim that named `[optimization]` settings are already accepted. A capability without a passing qualification record remains inactive and reports why. Do not add a full proxy, remote telemetry, model download, paid warmer or silent model/effort change to make the default seem more effective.

The operator can choose an alternate qualified backend or disable one component. Selecting an experimental backend is explicit; it does not grant broader filesystem/credential/network authority. Full-product arms are distinct from restricted filters/retrieval and may require separate host/policy qualification.

### Qualification layers

**Artifact/build:** pin release commit, exact package/binary, feature set, toolchain and notices. Verify package correspondence where possible. Build supported targets and inspect native dependencies, runtime/allocator ownership, startup effects and egress. Source availability, a crates.io name and a passing library test are different evidence.

**Host:** prove discovery, hook trust, synchronous replacement semantics, native read/edit receipts, denied operations, streamed/late results, cancellation, subagents and resume. The existing Claude/Codex status hooks are not replacement adapters. Codex's feedback substitution and unsupported output fields cannot be treated as Claude's typed update contract. [Integration matrix](/research/context/tools/11-jackin-integration/).

**Fidelity/recovery:** use real compiler/test/lint/Git producers and adversarial malformed, Unicode, CRLF/no-final-newline, duplicate-key, binary/rename, truncation and success-diagnostic fixtures. Inject worker timeout/crash, storage failure, missing/corrupt records and context resets. Transform failure uses the already-captured authorized observation; security/integrity failure never bypasses policy or triggers producer rerun.

**Task outcomes:** apply the shared proposed gates: zero new critical correctness/security/permission/isolation/recovery regressions; acceptance lower one-sided 95% bound above −1 percentage point; for a new complex optimizer, upper one-sided 95% all-attempt cost-per-accepted-task ratio at most 0.80; p95 task latency no more than 10% worse unless a separately declared tradeoff profile is evaluated. The quality margin is uncertainty tolerance, not an allowance for known damage. Subscription arms use actual accepted work/window. Insufficient precision keeps a complex treatment provisional/experimental; the cost gate is not waived for convenience.

Twelve to thirty diverse pilot tasks estimate defects and variability; confirmation is planned from paired/task-cluster precision. Existing native optimizations and low-impact owned-delivery fixes do not need an artificial 20% benefit to be preserved. Do not mix these proposed criteria with observed qualification. [Canonical protocol](/research/context/tools/07-evidence-and-claims/).

### Initial absolute local budgets

These are deliberately bounded starting targets for the first treatment, chosen to keep optional work small relative to interactive tool use. Revise a target only as an explicitly declared new profile before evaluating it; do not silently widen it after a failure.

| Resource | First diagnostic-filter qualification target | Restricted retrieval pilot target |
|---|---|---|
| Eligible observation/source corpus | At most 1 MiB per observation; larger/exact/excluded content stays native | Fixed corpus up to 10,000 files / 250 MiB admitted source; larger corpora measured separately |
| Cold readiness | Worker initialization at most 500 ms; native path remains available | Background indexing at most 60 s on the declared corpus; native tools remain available immediately |
| Warm added latency | p95 at most 50 ms; hard transform deadline 100 ms | p95 query latency at most 200 ms; explicit 500 ms query deadline for the initial arm |
| Peak worker RSS | At most 128 MiB | At most 512 MiB |
| Local storage | 256 MiB recovery budget per consumer; refuse new loss before evicting referenced originals | At most 1 GiB index in addition to declared recovery budget |

Record CPU, RSS, disk and hardware/OS/cache state, including startup and concurrent consumers. These targets are not a substitute for p95 complete-task latency. A backend that misses them may still be useful in a separately declared large-repository or latency-tolerant profile; it is not silently promoted to this default.

### Configuration surface and ownership

A future schema can express the following intent; it is **not valid current Jackin configuration**:

```toml
# Proposed schema, requiring a separate implementation and migration.
[optimization]
profile = "auto" # auto | experimental | off

[optimization.components]
diagnostics = "qualified"
retrieval = "native"
policy = "restrained"
```

Effective policy combines operator choice, role, actual host/version, provider/auth route, content family and qualification record. Unknown fields currently fail in `RoleManifest`; documentation must not instruct users to paste this sketch into a current role. Reuse current model/effort selection unchanged.

Package artifacts in reviewed images with checksums/notices and own only generated registrations. No moving-latest startup fetch, upstream global installer, automatic public service or inherited update daemon. Validate existing config and preserve unrelated entries; expose a conflict instead of overwriting them. Current host-specific homes and worker roots must be honored.

## Implications for jackin❯

The first meaningful delivery is a small functioning automatic capability with proven activation and complete-task value, not a multi-product installer or dashboard. That is reached through low-impact owned policy, scope/recovery and one filter family. If the first filter fails the task gate, keep native behavior and evaluate the next bounded candidate; do not lower correctness criteria to preserve a previous recommendation.

Rollback disables the responsible adapter, restores its owned config and stops new lossy observations. It leaves actual security controls, native execution and selected model policy intact. Preserve active recovery handles and audit records through the declared horizon; the broker may need to outlive the transform worker. A later authorized cleanup can remove unreferenced artifacts. Off cannot retroactively undo already-delivered compressed history.

## Limitations and unknowns

No production rollout, real host conformance or paid task experiment occurred in this PR. Current local builds/fixtures establish several narrow feasibility and defect facts; they do not satisfy these promotion stages. Full cross-platform packaging, signed artifact verification for every component, concurrent resource capacity and long-session retention remain explicit implementation gates.

The old overlapping phase thresholds, aggressive automatic routing, shims-as-universal-boundary and numeric compression promises are retired. The proposed staged path remains concrete even while unverified transforms stay inactive.
