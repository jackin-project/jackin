**Research state:** Current

## Summary

Snapshot **2026-10-24 01:15:00 UTC**. Prefer exact, bounded source selection over reading irrelevant material, while measuring the extra schemas, indexing and search turns it creates. Keep native tools as the baseline and exact-read escape. Compare restricted LeanCTX and LemonCrow Runtime Lite independently; neither is a current default winner. A shared source index never implies shared model memory.

## Question and scope

Which retrieval boundary improves repository discovery and complete edits while preserving file authority, dirty state, recall and native read-before-edit requirements? Retrieval-only and full runtime/persona replacement are distinct experiments.

## Method

Reassess the old modality/verb/ranking plan against current product code and worktree/epoch probes, current adjacent primitives and Jackin's existing process/MCP setup. No retrieval server is installed in production by this PR. [Product comparison](/research/context/tools/05-head-to-head/), [adjacent tools](/research/context/techniques/03-prior-art-and-market-scan/).

## Findings

### Modalities and current alternatives

| Need | Native baseline / reusable option | Qualification boundary |
|---|---|---|
| Locate paths and literal text | Existing host tools, ripgrep; fff search primitives | Ignore/private-file policy, Unicode, path roots, match completeness and cold scan cost |
| Navigate symbols and sections | Native exact reads plus tree-sitter; LeanCTX/LemonCrow Lite; narrowly selected language services | Parser/version coverage, source ranges and stale overlays; syntax does not establish semantic call/type completeness |
| Follow references and affected code | Native language tooling, sem/codedb or language-server integration | Macro/generated-code/dynamic dispatch gaps; never treat a partial graph as proof all callers were found |
| Read structured documentation/data | Exact section/range reads, mq or an allowed parser | Query/IO authority, exact text requirements and current parser features |
| Recover an omitted observation | Jackin artifact broker | Historical captured bytes and scope; not a fresh source read or native edit receipt |

The refreshed adjacent register pins fff 0.11.0, sem 0.28.1 and mq 0.9.3 rather than retaining old versions. They are potential primitives, not interchangeable adaptive context runtimes. Full Serena 2.1.0 is GPL-3.0-or-later, while its separable SolidLSP source retains MIT; jCodeMunch 1.108.396 uses current Dual Use terms. Do not assume the old permissive extraction decisions still apply. [Current adjacent source/license assessment](/research/context/techniques/03-prior-art-and-market-scan/).

### Restricted backend treatments

**LeanCTX 3.11.4:** compare the released MCP process with a server-enforced read-only surface, fixed root and a distinct context consumer. The preview unpublished `lean-ctx-embed` facade is another arm: it owns a Tokio runtime and configures process-wide state directories through a one-time initializer. Two facade objects are not demonstrated independent tenants. Its read-tool allowlist is real; the broader MCP server's steering-off option alone does not disable every execution/edit dispatch. [LeanCTX dossier](/research/context/tools/04-leanctx-design/).

The executed lifecycle probe returned a 55-byte unchanged stub after a prior full read for an unknown/custom consumer, including after restart without a compaction marker. A different consumer returned content, and the Claude-specific path had mitigation. These are conditional results, not a universal stale-read claim. Until a host epoch can be bound reliably, use explicit full/raw behavior and disable omission-based stubs.

**LemonCrow 0.8.0 Runtime Lite:** compare its public lexical/symbol/import retrieval with explicit worktree roots and native execution/editing retained. Parallel-root tests, launch-relative reads and mixed-root refusal passed in the selected library path. The current public Lite engine differs from historical fuller runtime benchmarks and legacy `mcp_server.py` state. Model2Vec is optional, not needed for the stdlib lexical baseline. [LemonCrow dossier](/research/context/tools/10-lemoncrow-design/).

LemonCrow advertises shell/edit/read/search/web-fetch tools and still accepts an unadvertised `grep` call. Hiding schemas is not access control. A restricted adapter must reject every undeclared operation at dispatch and use filesystem confinement. Exclude shell/edit/web fetching from the retrieval-only arm and turn off output-delta behavior unless recovery and epochs are independently qualified.

### Proposed query surface

Use a small stable logical interface: locate paths, search literal text, inspect a symbol/section, read an exact range and recover an observation. A backend may combine operations or defer schemas if the host supports it; do not force five always-present tools merely because the design table has five needs.

Every response identifies canonical root, source generation/content hash, path/range, representation (`exact`, `outline`, `selected`) and truncation/omissions. Explicit exact-read requests cannot silently return an outline or unchanged stub. A query with no matches reports the searched scope and limit, not universal absence. Relative paths resolve to the admitted request/worktree root, never a shared “last cwd.”

Measure schema, annotations and server instructions after actual host serialization. LemonCrow's five advertised schemas measured 4,058 UTF-8 JSON bytes and LeanCTX's twelve 10,608 in their probes; these are byte counts, not universal prompt-token costs. Deferred discovery can reduce steady exposure but adds discovery/tool-call costs. [Schema and instruction techniques](/research/context/techniques/).

### Ranking and task policy

Start with explicit path/symbol/range requests and lexical matches. Structural or semantic ranking is a candidate improvement when measured recall supports it. Cap result size, report omitted matches, diversify paths where helpful and offer a straightforward widening operation. Ranking priors such as recently edited files, tests, import distance or “top N” do not authorize omission of required security/configuration/caller changes.

Deliver brief task guidance: search narrowly, inspect definitions and affected callers, then read exact ranges before editing; broaden when evidence is incomplete. Do not enforce fixed “two searches then outline,” size thresholds, restart counts or turn cutoffs without workload evidence. A convergence warning can flag repeated identical searches, but it must not stop required investigation or silently downgrade model effort.

### Index and exposure lifecycle

| Event | Source/index action | Exposure action |
|---|---|---|
| File edit, dirty overlay or rename | Invalidate affected content/ranges; reconcile filesystem before responding | New content hash cannot inherit old exposure |
| Branch/worktree change | Bind new root/tree generation; invalidate graph assumptions | New source scope, even if filenames coincide |
| Compaction or context reset | Index may remain valid | Start a new epoch unless retained exposure is explicitly proven |
| Resume, fork or different agent | Revalidate source generation and persisted index | Require consumer identity/epoch; do not inherit process-global seen flags |
| Backend crash/restart | Verify on-disk format/configuration and incomplete transactions | Unknown delivery stays unknown; never infer exposure from a warm index |
| Permission/ignore-policy change | Rebuild or filter to new admitted security scope | Revoke access to artifacts no longer authorized under the policy |

Immutable index reuse may amortize work across compatible consumers. Mutable exposure, query history and task memory need their own scoped ownership. Watchers can reduce staleness but do not prove freshness under missed events, untracked files, symlink changes or concurrent writers. Retrieval must check generation/hash at the point of use and preserve native stale-edit protection. [State design](/research/context/engine/07-memory-and-state/).

## Implications for jackin❯

Implement a restricted process adapter before embedding a large runtime. Register only the selected capability in the correct agent home; enforce allowlists in the server and allowed roots at the OS boundary. Keep source paths, errors, native execution and edit receipts intact. One per-worktree/consumer worker is the conservative first configuration for process-global upstream state; share immutable index storage only after explicit concurrency tests.

The smallest decisive comparison is native search/exact-read versus each restricted backend on the same pinned repositories and fixed host/model/effort. Include small fixes, multi-crate refactors, documentation, TypeScript/Java discovery, generated/macro-heavy code, dirty files and simultaneous worktrees. Measure recall of required files, accepted patches, exact-read/recovery calls, schema overhead, cold index time, warm latency, CPU/RSS/disk and all attempted work. A warmed tiny fixture is not the cold behavior of a large repository.

## Limitations and unknowns

No task-level benefit, native edit-receipt compatibility, adversarial symlink-race safety or cross-platform lifecycle has been established for the proposed adapter. LeanCTX's facade build was interrupted during shared disk pressure; it is neither a passing integration build nor an upstream build defect. LemonCrow Lite package correspondence does not make its advanced hosted engine reproducible. The old retrieval percentage/latency multipliers and fixed small-file thresholds are retired as default design guarantees.
