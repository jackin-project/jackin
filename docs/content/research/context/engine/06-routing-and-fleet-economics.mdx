## Summary

Snapshot **2026-10-24 01:15:00 UTC**. Keep the selected model and reasoning effort fixed in the principal compression comparison. Routing, effort control, cache warming, batch scheduling and self-hosted inference are separate interventions with their own authority and outcome evidence. A lower unit price or shorter request does not establish more accepted tasks.

## Question and scope

How should Jackin account for provider billing, subscription windows, fleet reuse and latency without disguising policy changes as compression? What can a scheduler safely preserve or recommend before any automatic model-routing implementation exists?

## Method

Read Jackin's current session model/effort and account handling, then use the refreshed provider/economic chapters for live pricing and native feature contracts. Retire old fixed multipliers whose workload, model generation or authentication route no longer matches. No paid cache warmer, model-routing experiment or subscription session ran in this research.

## Findings

### Existing policy ownership and fixed comparison

The current <RepoFile path="crates/apps/jackin-capsule/src/session/agent_cmd.rs">session command builder</RepoFile> receives model, effort, auth mode and instance home from the launch specification; it sets model arguments for supported hosts and Claude/Codex lane environment. It clears ambient account/capability and host-folder variables before applying admitted state. This is existing policy transport, not an optimization router.

Compression arms must record the effective model and effort, not merely requested values. Some hosts have different model flags or incomplete launch paths; a registry entry is not proof that the intended policy reached the host. Pin agent version, role instructions, native tools, permissions, timeouts and auth route alongside model settings. [Current architecture](/research/context/engine/02-architecture/).

### Effort and model-routing research

A separately authorized routing study may compare task-specific models or reasoning levels, but it must label those changes and grade the same complete requirements. Include escalation, retries, failed attempts and repair work in cost and latency. Routing based on model self-confidence, a lexical “difficulty” score or historical success alone is not established correctness.

Do not silently select cheaper subagents, shorten required verification or use a lower-effort result as a compression gain. An advisor/subagent can also add startup prefix cost, duplicated investigation, handoff loss and review work. Compare one-agent and delegated workflows only with declared treatment boundaries. [Routing/delegation techniques](/research/context/techniques/10-model-routing-and-delegation/).

### Billing classes and economic comparisons

For API billing, compute each run from its actual provider/model/route-specific classes: fresh input, cache reads, cache writes by applicable lifetime, visible/reasoning output where exposed, tool/service charges and other fees. Avoid double-counting cached input when a provider reports it as a subset of total input. Separate observed bills from reconstructed estimates and preserve missing fields as unknown.

Use all-attempt cost per accepted task, with acceptance criteria fixed before running. A failed treatment consumes resources even if its final patch is discarded. Report both aggregate and task-weighted results; one enormous task should not hide regressions across many ordinary tasks. [Economics and measurement](/research/context/techniques/01-economics-and-measurement/).

Cache prices and lifetimes now vary substantially across current provider/model families and routes. A universal 0.1× cache-read multiplier or fixed 5× output/input ratio is no longer a design constant. Likewise, reducing a historically cheap cached prefix can cost more than leaving it stable if the rewrite invalidates reuse. The current [provider features](/research/context/techniques/12-provider-features/) and [caching](/research/context/techniques/07-caching-exploitation/) chapters own the dated price tables and contracts.

### Fleet prefixes and spawn choreography

Reuse a stable shared instruction/tool prefix only within a compatible provider cache and authorization scope. Put task-specific content after stable material when the host/provider contract permits it. Do not assume cache sharing across accounts, API projects, tenants, models, auth routes, regions or native hosts. A shared capsule or byte-identical prefix does not prove provider reuse.

First establish observed cache hits and full-task outcomes. Deliberate warm-up calls incur cost and may require retaining request data or credentials. They are not passive telemetry. Caveman's current warmer is enabled by default even in its record mode, so a native/raw comparison must explicitly disable it. [Caveman component defaults](/research/context/tools/01-caveman-design/).

Do not schedule unsolicited keep-alive requests or claim a “cold-spawn tax” from one old experiment. Native provider retention, eviction and project isolation must be verified. In a declared warming arm, charge the warm-up, idle expiry, failures and refreshes to all attempted tasks. A low `max_tokens` request is not inherently free.

### Lanes, batching and subagents

A proposed scheduler can preserve chosen role/model/effort, avoid duplicate identical owned setup and limit concurrent work to available local/provider capacity. It must not infer permission to move work between accounts or alter a user's subscription policy. Separate interactive latency-sensitive tasks from eligible asynchronous batch work; a batch discount is not a blanket interactive-agent optimization.

Measure subagent startup, shared prefix hits, useful work, duplicate reads, parent synthesis and independent verification separately. Repetitions and parallel agents are not free task diversity. Deterministic task decomposition may help, but the old fixed depth/team-size/cheap-worker multipliers are not current performance evidence. [Fleet/multitenant cache](/research/context/techniques/22-fleet-and-multitenant-cache/), [multi-agent protocols](/research/context/techniques/11-multi-agent-protocols/).

### Subscription and quota governance

Subscription quota is not necessarily a public token-price function. Preserve actual provider/account plan, observed usage-window counters, accepted tasks per window, resets, throttling and user-visible limits. Keep missing quota conversion unknown rather than fitting arbitrary token weights and presenting them as provider policy.

Budgets can stop or defer optional work and explain the reason. They cannot silently downgrade the model, bypass approvals, drop required tests or claim successful completion when a window expires. Account/provider errors should remain distinguishable from optimizer failures. Current usage snapshots are inputs to governance, not authoritative proof of task-level causality. [Subscription economics](/research/context/techniques/19-subscription-and-quota-economics/).

### Additional routing constraints

Semantic answer caches require an exact-enough task/source/configuration/authorization key and a fresh verification plan; similarity alone cannot establish that an old patch or answer remains correct. Do not reuse private context across tenants. Self-hosted KV-cache sharing and inference scheduling have different memory/throughput economics and do not imply hosted-provider bill reductions.

Online routing policies or bandits require outcome delay, task mix, exploration cost, holdout protection and stable acceptance definitions. Arbitrary Beta priors, decay constants or automatic reward-only promotion are not an implementation plan. Keep the proposed optimization selector deterministic over approved qualification records until a separate adaptive-policy study justifies more.

## Implications for jackin❯

The initial automatic context profile makes **no model or effort change**, no paid warm-up call and no provider proxy. Preserve native cache/compaction behavior and collect provenance. Separate routing/warming/batch arms can be added only with explicit authorization for their execution, effective-policy receipts and the same complete-task acceptance accounting.

Where a future complex optimizer passes the canonical task-cost and latency gates, promote only the host/model/auth/content configuration actually tested. Subscription benefits require observed task/window evidence. Do not add independent-study percentages or instruction/filter/cache savings as if they were disjoint. [Canonical gates](/research/context/tools/07-evidence-and-claims/).

## Limitations and unknowns

No current dataset in this work establishes the old fleet dollar forecasts, universal worker-price advantage, thinking-reduction percentage or quota weights. The source audit verifies policy transport, not current model availability in every account. Concrete current pricing and provider changes are separately dated in the linked chapters; all routing proposals here remain unimplemented.
