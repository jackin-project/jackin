**Research state:** Current

## Summary

At **2026-10-24 01:15:00 UTC**, Jackin source `6e266406b49da2ab3c55355f3b7d33d1643ee6cd` already owns configuration, images, private agent homes, process isolation, credential execution and usage collection. It does **not** implement the context engine described here. Add narrow contracts to those owners and run complex upstream components in supervised workers first. Do not place a complete optimizer inside the capsule control loop merely because it has a Rust library.

## Question and scope

Where can optimization execute without duplicating configuration, bypassing authority, corrupting shared state or claiming visibility over native traffic it cannot intercept?

## Method

Read current workspace, manifest, protocol, capsule setup, launch, hook installers, isolation, control authorization, MCP/exec and usage sources. The <RepoFile path="docs/content/research/context/techniques/tools/refresh-2026-10-24/jackin-architecture/source-audit.json">source register</RepoFile> pins hashes and paths. An isolated entrypoint-case probe executes only launch selection; no full capsule or native host was launched. Product workers were evaluated in their separate workstreams.

Post-cutoff integration review also inspected main `c98f5f5fdd831e6075e38fde93b9713575406140`: all 26 original audit files remain byte-identical. New installation and account-marker controls are recorded separately in the <RepoFile path="docs/content/research/context/techniques/tools/refresh-2026-10-24/jackin-architecture/main-overlay-review.md">integration-base review</RepoFile>. This does not move the external release cutoff or claim a rerun of native hosts.

### Launch, hooks and authority are different layers

`Agent::ALL` has twelve variants; the embedded entrypoint dispatches six. The source audit executes those six selection branches successfully and returns unknown-agent exit 2 for Antigravity, Gemini, Cursor, Muse, omp and Hermes. It does not prove the six installed binaries launch successfully. The image builder copies that script unchanged and the session command selects it. Fixing the missing launch paths is separate production work, required before optimizer portability can be claimed for those hosts.

Claude's installed `PostToolUse` status hook is asynchronous. Codex installs seven event commands, but its verifier only checks for the script path in the JSON file. Neither mechanism proves host trust, event acceptance or result replacement. Current official [Claude](https://code.claude.com/docs/en/hooks) and [Codex](https://learn.chatgpt.com/docs/hooks) contracts differ; the [integration chapter](/research/context/tools/11-jackin-integration/) owns their detailed qualification matrix.

The current entrypoint selects native approval-bypass modes for its six hosts, while Jackin separately constrains process and credential access. Preserve the configured policy and document it honestly. A worker must not create its own credential forwarding, broaden allowed paths, change native permission flags or infer authority from model-supplied scope fields.

### Proposed process and interface shape

Use a small Rust policy/broker layer associated with the existing session supervisor, plus a worker for the selected transform or retrieval backend. Start with one process per admitted consumer/worktree scope when upstream state is process-global. An IPC boundary gives crash, dependency and runtime separation; it does not itself confine filesystem or network access. Apply explicit roots, private state, resource limits and egress policy when launching the worker.

| Decision in order | Owner | Next result |
|---|---|---|
| Observation is not authorized | Native authority and adapter | Preserve denial; do not enter the transform path |
| Observation is authorized | Adapter/broker | Capture the original once with its status and completeness |
| Capability or content family is unqualified | Qualification selector | Deliver that authorized original |
| Required archive does not acknowledge storage | Recovery broker | Deliver the original; emit no lossy marker |
| Archive succeeds | Selected worker | Produce a bounded candidate without rerunning the producer |
| Candidate is invalid, late or over budget | Adapter/verifier | Deliver the already-captured original |
| Candidate passes all checks | Synchronous host adapter | Deliver the typed replacement with scoped recovery |


The protocol has an authenticated caller, scope, observation ID, producer/tool identity, bytes or bounded artifact descriptor, stdout/stderr roles, exit/signal/interruption data when available, capture completeness, exactness requirements and deadline. A response is unchanged or a candidate replacement with transform/version/config digest, omissions, output shape and recovery reference. Unavailable metadata stays unknown; a text hook must not fabricate a signal or complete stream.

An upstream adapter never owns Jackin's permanent public types. It translates a narrow contract, declares its effect class and cannot issue a fresh producer command on transform failure. Cancellation stops optional work and preserves the original operation's recorded status.

### Scope and storage

`SessionIdentity` is only `{ uid, gid }`. Session launch separately creates `/jackin/run/sessions/<id>` state/tmp/runtime/cache directories and injects a control capability. Those existing facilities are useful, but they do not define model exposure or resumed-session continuity. <RepoFile path="crates/core/jackin-protocol/src/lib.rs">Protocol identity</RepoFile>, <RepoFile path="crates/apps/jackin-capsule/src/session/agent_cmd.rs">session directories</RepoFile>.

The proposed scope contains capsule generation, instance, repository identity, canonical worktree root, source generation, host session/subagent and context epoch. The broker derives/admit-checks this scope from trusted launch metadata; it does not accept an arbitrary path or UID supplied by a hook payload. A content hash verifies bytes; it is neither authorization nor a logical observation ID.

Separate logical owners for raw observations, immutable source indexes, mutable exposure, durable notes and measurement receipts. They may use different physical databases and retention classes. A shared read-only index requires a matching source snapshot, parser/configuration and security domain. Exposure and recovery authority remain consumer-scoped. [State contract](/research/context/engine/07-memory-and-state/).

### Invariants replacing the old unconditional rules

| Contract | Required behavior |
|---|---|
| One owner | One transform per observation; one selected index; one instruction asset owner; no nested compression markers |
| Execute once | Archive the authorized captured result, never rerun the producer to recover omitted output |
| Store before loss | Acknowledged durable write and bounded recovery route before emitting a lossy replacement |
| Security first | Authorization, path integrity and mandatory redaction failures stop; they never fall back to unredacted/raw access |
| Optional failure | Transform timeout, crash, incompatibility or unsuccessful archive creation selects the already-authorized original observation |
| Honest completeness | Native truncation, missing stderr, unknown signal or partial stream are recorded, not converted into “complete” evidence |
| Exposure integrity | No “already seen” omission without a compatible context epoch and delivery evidence |
| Provider stability | Do not mutate established history or preserved reasoning without a separately qualified provider contract |
| Bounded resources | Predeclared cold/warm latency, memory, disk and queue limits; pressure disables new lossy observations before evicting required recovery |
| Measured benefit | Local token non-expansion is only an eligibility guard; it does not prove lower bill, fewer turns or better tasks |

The former universal cache-hit target, one-database rule, blanket fail-open and asserted capsule-wide interception are withdrawn. Provider caching is model/route-specific, and failures at different trust layers require different actions.

## Implications for jackin❯

Implement owned scope, recovery and qualification contracts first; integrate one adapter at a time. Pinned processes are the initial boundary for RTK filters, LeanCTX and LemonCrow retrieval, and broad Headroom/Caveman engines. A small pure Rust library can later move in-process when its dependency graph, state/runtime ownership, target support and cancellation are demonstrated. “Rust” is not sufficient proof of safe embedding. [Reuse matrix](/research/context/engine/09-reuse-decision-matrix/).

Proposed `auto`, `experimental` and `off` policy belongs in a reviewed configuration migration. It is not currently accepted by `RoleManifest`. Off stops new optimization and restores owned configuration while preserving referenced recovery artifacts and configured security. Effective configuration must list source pins, actual host activation, state roots, selected owner and bypass reason.

## Limitations and unknowns

No worker protocol, optimization manifest, artifact broker or selector is implemented in this research PR. Source inspection of Linux isolation is not an executed adversarial security test. Real host replacement, cancellation, edit receipts, restarts and permission interactions remain explicit gates. The existing `jackin-exec` MCP server exposes secure command execution; it is not a general context engine or universal native-tool interception path. Its current dispatcher ignores `notifications/cancelled`, so a new worker cannot inherit a cancellation guarantee merely by using this server.
