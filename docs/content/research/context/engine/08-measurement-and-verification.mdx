## Summary

Snapshot **2026-10-24 01:15:00 UTC**. Reuse Jackin's existing usage infrastructure, but add task/treatment provenance before using it to judge optimizers. Current aggregates are not a complete provider bill, context-exposure ledger or acceptance dataset. Measure actual usage separately from byte/token estimates and counterfactual savings; include every attempted run.

## Question and scope

What evidence proves that a current pinned treatment was activated, preserved complete task quality and improved the relevant economic outcome? What can be measured without launching an extra paid session?

### Proposed receipt model

Record a versioned run manifest containing repository/tree/dirty state, task/grader, host/version, model/effort, provider/auth route, role/instructions, tool schemas, permissions, timeouts, cache condition, treatment/configuration and component artifact hashes. Freeze it before each comparison.

For each observation, record producer/tool/call identity, admitted worktree/session/epoch, known status/completeness, original and delivered byte hashes, transform owner/configuration, eligibility/bypass reason, archive acknowledgement, delivery evidence, recovery requests and local latency/resources. Do not store credentials or gratuitous source text in general telemetry.

For each provider request, preserve actual fields with their original semantics: fresh input, total input if supplied, cache-read subset/additive relation, cache writes by lifetime, output/reasoning where exposed, tool charges and billed cost. Fields not supplied remain null/unknown. Separate repeated/cumulative event reconciliation from raw receipts so the aggregation is auditable.

For each attempted task, retain outcome, independent grader evidence, patch, failures, retries, verification/recovery work, elapsed and active time, compactions, tool/turn counts, CPU/RSS and disk growth. An aborted attempt remains in the denominator of cost; acceptance rules must not be relaxed after seeing the treatment's result.

### Estimates, counterfactuals and calibration

| Quantity | Meaning | Required label |
|---|---|---|
| UTF-8 bytes | Actual serialized size of the measured object | Bytes, encoding and serialization boundary |
| Local tokenizer count | Estimate for a named tokenizer/version and exact string | Estimated tokens; not provider accounting |
| Provider usage receipt | Provider/host-reported classes for a particular request/run | Observed usage, with class semantics and missing fields |
| Reconstructed bill | Usage multiplied by dated applicable prices | Estimated cost; distinguish reported charges and extra fees |
| “Tokens avoided” replay | Difference on a fixed recorded trajectory | Counterfactual payload effect; not causal accepted-task saving |
| Subscription outcome | Accepted work and observed counters within a real usage window | Actual plan/window evidence; no invented token-price conversion |

Calibrate representative code, JSON, schema, multilingual text, images and tool envelopes against current provider-supported counting only where permitted and available. Do not infer hidden reasoning as the difference between total output and visible text unless the provider's accounting definition supports it. A byte/4 heuristic can be useful for conservative routing but is not a universal tokenizer.

Provider counting APIs have their own supported fields, limits and cost contracts. The old claim that one provider's counter is universally free/complete or that tokenizer error is always within a fixed percentage is retired. See [economics](/research/context/techniques/01-economics-and-measurement/) and [measurement tools](/research/context/techniques/tools/).

### Reproducible task program

Use native baseline, separate output-policy/filter/retrieval/SDK arms, full-product arms where meaningful, and combined arms only after individual qualification. Restricted retrieval is not the same treatment as replacing native shell/editing and persona. Hold the principal model/effort fixed; routing is separate.

Cover small fixes, repository discovery, build/test diagnosis, multi-crate refactors, TUI work, TypeScript/Java investigation, documentation, long sessions and concurrent worktrees. Randomize and interleave paired runs, pin initial dirty state, and separate cold/warm indexing and provider-cache conditions. Treat repeated runs as clustered by task. Independent verification uses raw source/artifacts and cannot depend solely on the implementer's compressed evidence.

The proposed promotion criteria are centralized in the [evidence protocol](/research/context/tools/07-evidence-and-claims/): no new critical correctness/security/permission/isolation/recovery failures; one-sided 95% acceptance bound above −1 percentage point; for a new complex optimizer, upper one-sided 95% all-attempt cost-per-accepted-task ratio at most 0.80; p95 task latency no more than 10% worse unless a distinct tradeoff profile is declared; and explicit absolute local resource budgets. The acceptance margin is uncertainty tolerance, not permission for a known loss. Insufficient cost precision keeps the complex treatment provisional/experimental; it is not a default-promotion waiver.

Twelve to thirty varied tasks are a pilot, not automatic statistical confirmation. Plan sample size from paired discordance, clustering and desired precision. A nonsignificant difference does not prove non-inferiority. Preserve aggregate and task-weighted outcomes, exclusions, seeds and grader failures. Subscription arms use actual accepted tasks/window instead of invented weights.

### Online quality, canaries and rollback

After offline qualification, a staged canary records activation, bypass, recovery, errors and resource limits. Compare like tasks with stable evaluation rules and retain a holdout. A critical regression disables the responsible capability immediately and preserves raw evidence; a noisy estimated token change does not trigger an automatic model or permission change.

Passive receipts do not authorize a second paid counterfactual agent. Shadow runs, warmers and subscription experiments require explicit authorization and their own accounting. Publish sanitized artifacts; private source, prompts and credentials are not routine telemetry. Hashes can still reveal equality and should be scoped/access-controlled accordingly.

### CI and operator surfaces

A proposed CI asset-budget check can flag unexpected instruction/schema growth using a named tokenizer and versioned baseline. It must distinguish bytes, estimates and exact provider counts, and verify policy content rather than enforcing an arbitrary universal token ceiling. It is a regression signal, not a quality grader or complete economic gate.

The operator sees effective profile, component/source pins, host activation, selected owner, bypass reason, state scope, observed versus estimated usage and disable controls. That UI supports a real qualified capability; it is not the final product in place of optimization. No `jackin bench` or optimizer dashboard command is claimed to exist by this research.

## Implications for jackin❯

First extend receipt provenance and validate session/instance attribution against native transcripts. Then implement one capture/recovery adapter and its activation probe. Existing usage stores can carry appropriate summaries, but raw artifacts, exposure and task results need explicit ownership and retention. Keep unobserved fields unknown and preserve replayable aggregation inputs.

Do not broaden paid testing merely to produce a ranking. The smallest next experiment resolves one concrete remaining boundary: exact host replacement, epoch continuity, recovery failure or complete-task benefit. Product fixture timings are retained but do not become randomized task-latency claims.

## Limitations and unknowns

No complete current six-way task benchmark, real subscription window study, host request-attribution test or production canary ran here. The source audit and current artifact suite are reproducible local evidence. Final repository checks/CI are recorded by the integration workstream against the actual PR head, not inferred from a historical green job.
