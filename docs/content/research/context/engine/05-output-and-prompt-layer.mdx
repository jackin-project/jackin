**Research state:** Current

## Summary

Snapshot **2026-10-24 01:15:00 UTC**. Deliver concise, role-appropriate guidance without weakening requirements, tests, architecture or the selected model/effort. Start with duplicate-free delivery of Jackin-owned instructions. Treat exact Caveman/Ponytail assets, full plugins and a restrained Jackin adaptation as different experiments; do not transfer one treatment's result to another.

## Question and scope

How can output and instruction design avoid unnecessary narration and repeated context while preserving completeness, precise strings, useful explanations and durable artifacts? This layer changes policy/input assets; it does not intercept arbitrary hidden reasoning or guarantee a shorter task.

## Method

Inspect the effective current Caveman and Ponytail assets and their activation paths, distinguish skill-only from full-plugin behavior, and reconcile historical tokenizer/register measurements with current task evidence. Product pins, source hashes, selected local tests and independent-study limits are in [Caveman](/research/context/tools/01-caveman-design/) and [Ponytail](/research/context/tools/09-ponytail-design/).

## Findings

### Current assets and independently selectable treatments

| Treatment | Current inspected boundary | Proposed use |
|---|---|---|
| Caveman 4.0.1 output skill | Clarity/exact-content guidance; ordinary persisted artifacts retain normal prose | Compare the exact skill independently; do not import the entire plugin to obtain a short-output rule |
| Caveman full plugin | Additional agents, engine/proxy/browser/memory and activation behavior; some agent policies select a model or constrain task scope | Separate full-product arm with declared policy changes; excluded from a fixed-model/effort skill comparison |
| Caveman engine runtime | Separate `bin-v4.0.2` release; product CLI 4.0.1 still points to the earlier runtime | Transform candidate owned by the observation layer, not an assumed part of the output skill |
| Ponytail 5.3.2 exact policy | Reuse-first work with complete affected callers/tests/config/security; current policy is not the old “one line only” caricature | Compare exact skill/plugin with activation evidence |
| Jackin adaptation | Short owned guidance retaining project/user standards and current model/effort | New policy treatment with its own version, tests and task evidence |

Caveman's current public engine/repository is Apache-2.0; the earlier blanket BSL exclusion is obsolete. Ponytail is MIT. Preserve applicable notices when distributing assets; separate private cloud/service terms and third-party assets remain outside that blanket. [Current release/license register](/research/context/tools/08-current-release-register/).

### Proposed instruction content

A small owned policy should ask the agent to complete the requested work, prefer existing abstractions where appropriate, inspect affected code, make precise edits, run the repository's necessary verification and explain consequential decisions concisely. Preserve uncertainty, negations, exceptions, error messages, path names, identifiers and required citations. Avoid repeated restatement of the task and unnecessary narration of routine steps.

Brevity must adapt to the deliverable. A detailed design, incident report, research answer or user-requested explanation may require substantial prose. File contents, public documentation, tests and commit/PR explanations retain their intended style and completeness. An operator's explicit requested depth takes precedence over a terse register.

Do not impose “no new abstraction,” “smallest line count,” fixed file limits, blanket test avoidance or automatic model downgrades. Those can make a short response less correct or maintainable. Current Ponytail has changed materially since earlier criticism; evaluate its actual policy rather than preserving fixed defects as present blockers.

### Exact-content and edit guards

Exact spans are ineligible for language compression when their bytes matter: commands, patches, file paths, API names, quoted evidence, schemas, numbers/units and code. Use native edit-over-rewrite where suitable, but do not force a patch strategy that obscures a required larger refactor. A shorter patch is not proof of complete engineering.

Source retrieval, output policy and coding policy are separate interventions. A terse answer can reduce visible narration while increasing clarification or repair turns. Record those downstream effects. Hidden reasoning, provider-generated summaries and tool invocations must be accounted for only when the provider exposes them; visible answer length is not total output billing.

### Activation, precedence and lifecycle

Jackin should deliver one versioned asset through the host's existing role/configuration mechanism and record its content hash. Avoid simultaneous copies in a system prompt, root instructions, skill and hook reminder. Deduplicate only material that Jackin owns and knows to be identical; do not remove user/project instructions because a similarity heuristic considers them redundant.

Precedence is explicit: operator/user policy and repository requirements remain authoritative; an optimization asset adds compatible defaults. A session-level disable survives compaction, resume and worker restart. The Ponytail plugin's observed mode lifecycle and per-project state demonstrate why installer success alone is insufficient. Two concurrent sessions may choose different modes even if they share a worktree.

Update and uninstall affect only owned asset entries, using content/version identity and a reviewable migration. Preserve unrelated hooks/configuration and surface conflicts rather than erasing them. No upstream host-global installer is needed to package an instruction asset in a capsule.

### Subagent handoffs and report formats

For bounded delegation, request findings, exact source/artifact references, decisions, changed files, unresolved risks and executed verification. Keep distinct ownership and ask reviewers to challenge work they did not author. A concise report can reduce duplicated investigation, but arbitrary hard report-token ceilings can omit the very evidence a reviewer needs.

A handoff is a new input artifact with provenance, not a transcript replay or guaranteed replacement for context. The receiving agent may need exact source and raw evidence. Include that recovery route and account for follow-up reads. Do not claim an “80× fleet multiplier” from a short handoff example or change the selected worker model to manufacture a saving. [Multi-agent protocols](/research/context/techniques/11-multi-agent-protocols/).

### Codebooks, structured outputs and tokenization

Session aliases or codebooks are experimental. Include legend cost, first exposure, context resets, exact-string escapes and repair turns in the comparison. Never rename source identifiers or paths invisibly. An alias that saves characters can expand under another tokenizer; measure the exact model/request serialization.

Structured output is appropriate where a consumer requires a schema. JSON/TOON/TRON, shorthand registers and multilingual phrasing have different delimiters, escaping, comprehension and provider compatibility. Do not turn every user-facing answer into a compact machine format. Keep any provider constrained-output sidecar separate from prose policy and verify current support before using it. [Representation/tokenization techniques](/research/context/techniques/05-tokenizer-arbitrage/).

### Calibration and quality instrumentation

Caveman's inspected skill measured 4,961 UTF-8 bytes and 1,246 o200k tokens in the product probe. That is an asset estimate under one tokenizer, not its billed cost in every host or proof of break-even. Full plugin schemas and instructions add separately. Measure actual activation bytes/tokens once, repeated delivery, output changes, recovery and clarification costs.

Historical fixed-text register percentages and “negative-cost always-on” claims do not establish current task benefit. Preserve historical experiments in the evidence ledger with their denominators. Grade completeness, correctness, maintainability, tests, exact strings and useful explanation using independent checks; a model's 1–10 style score is supplementary, not an acceptance oracle. [Evidence protocol](/research/context/tools/07-evidence-and-claims/).

## Implications for jackin❯

The initial proposed automatic asset contains restrained role guidance and duplicate-free owned delivery. It does not bundle a full proxy, memory system, codemap or agent fleet. Current source does not yet implement this selector or asset manifest. Qualification first checks policy precedence, activation, off/resume behavior and unchanged task requirements, then compares exact upstream and adapted policies separately.

For a product plugin that changes agent model, scope or test behavior, either isolate those components or declare the full treatment separately. Main compression comparisons keep model and reasoning effort fixed. There is no accepted-task evidence in this refresh that authorizes unconditional terse language across all roles.

## Limitations and unknowns

Local asset tests and token counts cannot establish broad accepted-task benefit. No paid style-policy task comparison ran. The old fixed dollar ceilings, output multipliers, alias break-even counts and small instruction budgets are withdrawn as universal rules. Provider prices and task mixes belong in the current economic model, not hard-coded policy defaults.
