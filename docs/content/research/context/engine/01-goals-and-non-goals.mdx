**Research state:** Current

## Summary

Snapshot **2026-10-24 01:15:00 UTC**. Optimize **resources per accepted complete task**, with no known new critical correctness, security, permission, isolation or recovery regression. The desired product installs and configures reviewed components automatically and activates qualified capabilities. It must also provide component overrides and a complete off path. This is a proposed design, not shipped optimizer behavior.

## Question and scope

Which interventions reduce unnecessary context or work while preserving the user's requirements, repository quality standards and chosen model/effort? Include input selection, output policy, observations, retrieval, compaction, memory, tool schemas, local resources and operator maintenance. Evaluate model routing and effort control separately.

## Method

Reconcile the old engine goals against current product evidence, current provider/native behavior and Jackin source `6e266406b49da2ab3c55355f3b7d33d1643ee6cd`. Separate inspected implementation, executed fixtures, independent historical outcomes and proposed policy. The [evidence protocol](/research/context/tools/07-evidence-and-claims/) is the authoritative statistical specification; this chapter defines the product objective.

### Evidence bars

| Question | Required evidence | What does not answer it |
|---|---|---|
| Does the component exist and fit? | Immutable source/package pin, license boundary, feature graph and target-specific build or explicit missing result | README badge, internal crate version or install success alone |
| Does the intervention reach the model? | Host/version activation receipt and observation of the resulting model-bound tool content | Terminal display, asynchronous status event or appended guidance |
| Is it faithful and recoverable? | Producer-generated/adversarial fixtures, raw acknowledgement, scoped recovery and lifecycle failures | Determinism, a hash marker or an inaccessible stored original |
| Does it improve tasks? | Paired fixed-model/effort tasks, independent graders, all-attempt costs and uncertainty | Payload percentage, successful-runs-only totals or a nonsignificant quality difference |
| Can it be automatic? | Stable configuration, predictable local costs, clean disable, compatible trust and security, regression ownership | A manual demo or a dashboard without an effective capability |

A 12–30-task pilot can discover defects and estimate variability. It is not a confirmation sample by definition. Plan confirmation from task diversity, paired discordance and clustering; repeated runs of one task do not add independent task diversity. The former five-percentage-point quality allowance and fixed pilot counts are superseded by the shared protocol.

## Findings

### Goals

**Preserve the native baseline before adding machinery.** Existing caching, compaction, tool discovery, bounded reads and edit operations may already solve part of the problem. Record which are active for each host/version/auth route, then compare each new treatment against that baseline. A “raw” arm is the native authorized observation, not an invented unbounded agent. [Native-feature assessment](/research/context/techniques/23-cross-agent-portability/).

**Make useful optimization automatic after qualification.** The target `auto` profile packages a small owned policy and a qualified transform/retrieval selection. The first proposed low-impact work is duplicate-free delivery of Jackin-owned instructions and concise narration that retains all requirements and tests. A pinned RTK OSS `pipe --filter <named-family>` subprocess, initially for one qualified test/diagnostic format, is the first substantial automatic-filter candidate; other backends remain comparators. No whole external product is presently qualified for default activation. [Rollout](/research/context/engine/10-rollout-and-validation/).

**Reduce avoidable work before relying on lossy text.** Exact path/symbol/section retrieval, complete affected-caller discovery and edit-over-rewrite can prevent irrelevant reads. These are not guaranteed savings: bad ranking, extra schemas, indexing and missed dependencies can increase turns or damage quality. Preserve an exact-read escape and the host's native edit prerequisites. [Retrieval](/research/context/engine/04-retrieval-layer/).

**Make every lossy observation accountable.** Capture the already-authorized observation once, retain bytes and completeness, acknowledge durable recovery, select one transform, then record what was delivered. Missing recovery, transform timeouts and malformed replacement must not rerun the original command. An authorization, redaction or integrity failure is a stop condition, never a raw-output bypass. [Observation pipeline](/research/context/engine/03-observation-pipeline/).

**Protect prefixes and consumer memory separately.** Avoid rewriting an established provider history without a provider-specific contract. A compact observation before first exposure is different from rewriting earlier conversation content. A source index being fresh does not prove a resumed or compacted model has seen its contents. Exposure needs session/context-epoch identity; unknown continuity disables omission-based stubs. [State](/research/context/engine/07-memory-and-state/).

**Keep the configured model, effort and authority.** Compression comparisons retain model, reasoning effort, instructions, permissions, timeouts and authentication. A cheaper model, lower reasoning level or changed approval regime is a separate treatment. Current Jackin launch flags are permissive within its configured isolation; the optimizer does not reinterpret that as permission to weaken credential or filesystem controls. [Current entrypoint](https://github.com/jackin-project/jackin/blob/6e266406b49da2ab3c55355f3b7d33d1643ee6cd/docker/runtime/entrypoint.sh).

**Account for complete economics.** Measure fresh/cache-read/cache-write/output/reasoning classes where available, accepted tasks, all failed attempts, retries, recovery, latency and local resources. API bills, subscription windows, context pressure and developer time are separate outcomes. Unknown quota weights remain unknown. Do not add overlapping savings or transfer self-hosted KV-cache throughput to hosted billed-token claims. [Measurement](/research/context/engine/08-measurement-and-verification/).

**Prefer reuse with a bounded owner.** Compare native behavior, public library, pinned process, instruction asset, upstream API contribution, narrow fork and Jackin implementation for each capability. Rust is preferred for Jackin-owned control code; language alone cannot reject a better Python or Go backend. Licenses apply to the selected component/distribution, not an old product label. [Reuse matrix](/research/context/engine/09-reuse-decision-matrix/).

## Implications for jackin❯

The proposed promotion gate for a new complex optimizer is zero observed new critical failures, a one-sided 95% acceptance bound above a loss of one percentage point, and an upper 95% all-attempt cost-per-accepted-task ratio at or below 0.80 where that economic arm applies. The acceptance margin limits statistical uncertainty; it does not authorize a known correctness loss. The proposed p95 task-latency allowance is at most 10%, with explicit absolute cold/warm and resource budgets. Subscription arms instead use actual accepted tasks per observed usage window. These are design thresholds, not measured qualification results. [Canonical protocol](/research/context/tools/07-evidence-and-claims/).

Preserving native optimizations or making a low-impact duplicate-delivery correction does not require manufacturing a 20% benefit. Such changes still need direct functional evidence and no lost policy content. A qualified automatic capability is selected narrowly by host/version/content; an experimental feature is visibly identified and can be disabled independently.

## Limitations and unknowns

No current evidence establishes a universal task multiplier or rules one out for every workload. The old workload decompositions, fixed output-cost ceilings, “20–35% default” forecasts, universal cached-input discounts and claimed portability percentages are retired unless their original data and current treatment can be reconstructed. The [techniques dossier](/research/context/techniques/) owns fresh scenario-specific economics.

### Non-goals and separately gated interventions

| Intervention | Current design decision |
|---|---|
| Full provider-history proxy | Experimental, separately qualified for authentication, streaming, retries, preserved reasoning and cache behavior |
| Semantic rewriting, learned compression or embeddings | Not forbidden by language/model category; require fidelity, local model/resource/network and task evidence; disabled in the first automatic filter arm |
| Image/PDF or text-to-image conversion | Separate exact-text/layout/model comparison; no universal image-token discount or automatic vision-model switch |
| Keep-alive/cache warming | No unsolicited paid requests, credential retention or subscription consumption; measured opt-in arm only |
| Semantic answer cache | Never substitute an old answer solely on similarity where repository state, authorization or task intent differs |
| Cross-tenant cache sharing | No assumed shared authority, credentials or provider cache; prove tenant policy and provider isolation first |
| Self-hosted KV optimization | Relevant to owned inference infrastructure, not a claim about hosted API billing |
| Global identifier rewriting or pervasive codebooks | Experimental representation with exact-string escape and measured legend/recovery costs |
| One physical database for all state | Replaced by one accountable owner per state class and explicit scope/retention contracts |
| Automatic model/effort downgrade | Separate authorized routing research; excluded from the principal compression arm |

These exclusions are current scope choices, not claims that all such mechanisms are technically impossible or permanently inferior.
