Research snapshot: **2026-10-24 01:15:00 UTC**. Jackin source: **`6e266406b49da2ab3c55355f3b7d33d1643ee6cd`**. This dossier specifies proposed work; it does not implement or activate an optimizer. Current means the research was refreshed, not that the design is deployed or task-qualified.

## Research question

What should Jackin package, configure and automatically activate to improve complete accepted tasks while preserving the configured execution, editing, authentication, isolation and model policy?

## Headline findings

### Decision and confidence

**Build a small Rust control and recovery boundary, preserve native agent behavior, and reuse qualified components behind replaceable adapters.** The target is useful automatic optimization: Jackin delivers the reviewed components and enables a capability for a verified host/version/content combination without requiring unrelated installers. No external transform currently has the complete Jackin qualification record needed for automatic activation.

The first implementation should eliminate duplicate delivery of Jackin-owned instruction assets, provide concise role guidance that preserves requirements and tests, and retain native caching, discovery and compaction. The first substantial automatic-transform candidate is a pinned **RTK OSS `pipe --filter <named-family>` subprocess for one qualified test/diagnostic format**, after capture, recovery, fidelity and task gates. It must not rewrite or rerun the producer command. Headroom Rust/Python and Caveman's Go engine remain competing transform treatments; native retrieval, LeanCTX and LemonCrow Runtime Lite remain competing retrieval treatments. There is no defensible universal backend winner. [Reuse decision](/research/context/engine/09-reuse-decision-matrix/).

Confidence is high in the inspected boundaries and reproduced component defects, moderate in the proposed ownership architecture, and limited in whole-task benefit: this investigation did not run paid agent comparisons. Compression percentages, component tests and source availability cannot supply that missing outcome evidence. [Evidence protocol](/research/context/tools/07-evidence-and-claims/).

### Three profiles, with readiness stated separately

| Proposed profile | Concrete behavior | Readiness at this snapshot |
|---|---|---|
| `auto` | Preserve native optimizations; install one versioned owned policy; activate only qualified host/content adapters; automatically bypass incompatible optional transforms | Native behavior exists. Asset consolidation and the qualification selector are proposed. No external transform is qualified for automatic activation yet. |
| `experimental` | Select one pinned filter, retrieval backend or exact upstream policy per treatment; retain raw recovery and fixed model/effort; expose effective versions and limits | Several component builds/tests exist; actual Jackin host and complete-task qualification remains open. |
| `off` / raw | Disable new transforms, retrieval steering and owned optimization policy; keep configured security and native behavior; continue serving already-referenced recovery artifacts | Required implementation contract, not an existing manifest field. Raw means the authorized observation, including native bounds and mandatory redaction. |

The operator can disable everything or one component, select alternatives and inspect the effective configuration. A nonworking hook must report its bypass reason; it cannot count as an optimization. [Rollout and exact gates](/research/context/engine/10-rollout-and-validation/).

### Current architecture changes the integration plan

Jackin registers **twelve** agent types. Its reviewed entrypoint has launch cases for **six**: Claude, Codex, Amp, Kimi, OpenCode and Grok. An isolated execution of that case statement returned exit 2 for the other six names. This is a launch-dispatch finding, not a full container test. Existing status hooks cover Claude, Codex and OpenCode; Codex already installs seven lifecycle events. Those hooks report state, not transformed results. [Source audit and executable probe](https://github.com/jackin-project/jackin/blob/6e266406b49da2ab3c55355f3b7d33d1643ee6cd/docker/runtime/entrypoint.sh) and <RepoFile path="docs/content/research/context/techniques/tools/refresh-2026-10-24/jackin-architecture/source-audit.json">captured evidence</RepoFile>.

The six launch cases deliberately select permissive native-agent modes. Preserving security therefore means preserving the **actual configured Jackin isolation, credential and authorization boundary**, not claiming native approval prompts are enabled. A new optimizer must never broaden that authority or turn a denied operation into passthrough. The optimization research does not change launch permissions.

### Ownership that makes reuse safe

| State or action | Proposed single owner | Consequence |
|---|---|---|
| Native command, edit and provider connection | Existing host and Jackin security path | MCP registration or PTY ownership does not replace every native tool |
| Each transformed observation | One selected host adapter and transform worker | No stacked filters, nested recovery markers or repeated producer execution |
| Original authorized observation | Jackin recovery broker | Durable acknowledgement before lossy replacement; scoped retrieval and retained completeness metadata |
| Repository index | One selected backend per declared source/security scope | Immutable index data may be shared; mutable exposure state may not |
| Model exposure | Consumer session and context epoch | Compaction, resume, fork and agent changes cannot inherit an unproven “already seen” claim |
| Instruction delivery | Versioned Jackin asset manifest | Avoid duplicate schemas and preserve project/user policy precedence |

The existing `SessionIdentity` contains only OS UID/GID. It is not a repository, logical session or context epoch. The proposed observation scope must add those identities without repurposing credential capabilities. [Architecture](/research/context/engine/02-architecture/), [memory and state](/research/context/engine/07-memory-and-state/).

## Method and evidence

The refreshed investigation reopens the existing detailed chapters, current Jackin code, primary host documentation, release source and executable evidence from all six product workstreams. Headroom's no-ML Rust build and selected Python tests passed; LemonCrow Lite's package/source correspondence and worktree tests passed; LeanCTX lifecycle probes demonstrate that a source cache is not model memory. These are useful feasibility results with narrow scopes. The product pages preserve failed/incomplete attempts separately from passing checks.

Material reversals include RTK's new typed engine API and split license, Caveman's current Apache engine, Headroom's Python-only line-boundary fix, and LemonCrow's current public Lite/private advanced-engine split. The old blanket Apache RTK extraction, BSL Caveman exclusion, full-public LemonCrow assumption and preferred Headroom integration are retired. [Release register](/research/context/tools/08-current-release-register/), [six-tool comparison](/research/context/tools/05-head-to-head/).

## Limitations and open questions

No real Claude/Codex model-bound replacement, native edit-receipt, full capsule launch, paid task outcome or production rollout was executed by this workstream. Native hook documentation is a contract to test, not proof of installed behavior. The smallest decisive work is one host's captured-result round trip, durable recovery under failure, an epoch/reset/concurrent-root test, then the paired task protocol. Keep the selected model and reasoning effort fixed throughout compression comparisons.
