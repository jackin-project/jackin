**Research state:** Current

## Summary

Snapshot **2026-10-24 01:15:00 UTC**. A useful optimizer reduces a result at a verified model-input boundary while keeping the original operation and its evidence recoverable. The proposed pipeline captures once, checks eligibility, acknowledges durable recovery before loss, transforms once and validates the host-specific replacement. It never reruns a command to repair failed compression.

## Question and scope

Which shell outputs, structured results, source views and media can be reduced without changing their meaning, concealing errors, bypassing authority or falsely implying completeness? This chapter defines the proposed adapter contract; no production pipeline is implemented.

## Method

Combine current host documentation with the executed Headroom, RTK, LeanCTX and LemonCrow component probes, and inspect Jackin's secure execution/MCP paths at `6e266406b49da2ab3c55355f3b7d33d1643ee6cd`. ## Findings

### Ordered pipeline and failure behavior

| Step | Required action | Failure disposition |
|---|---|---|
| 1. Admit | Authenticate the caller and bind trusted session/worktree scope; preserve the host's authorization result | Denied or invalid scope stops. Do not expose an alternative raw path. |
| 2. Capture | Observe the executed result once, after mandatory redaction; retain byte boundaries and known status/completeness | Preserve the native failure/partial-capture contract. Never claim unavailable bytes exist. |
| 3. Select | Check host/version/tool/content qualification, exactness requirements and one-owner rule | Unknown or excluded class returns the original observed result. |
| 4. Persist | Commit the original and metadata; obtain durable acknowledgement and authorized recovery reference | Return the original already-captured observation if storage is unavailable; emit no lossy marker. |
| 5. Transform | Run one pinned adapter within deadline/resource bounds; no producer access or provider calls by default | Optional worker failure returns the stored/captured original. |
| 6. Validate | Check result schema, status, omissions, fidelity guards and configured output budget | Invalid candidate is discarded, not recursively compressed. |
| 7. Deliver | Use the tested host replacement contract; record actual delivery if observable | If acceptance cannot be proven, mark exposure unknown and disable omission-based reuse. |

Storage is required for an eligible lossy replacement, not for every observation in the off/native baseline. “Original” means the authorized observation the host supplied. It may already be truncated, redacted or missing stream detail. The proposed archive must preserve those limitations. Jackin's current <RepoFile path="crates/apps/jackin-capsule/src/exec.rs">secure capture</RepoFile> and <RepoFile path="crates/apps/jackin-capsule/src/mcp_server.rs">MCP result rendering</RepoFile> already distinguish denial/redaction from successful output; an optimizer must not recover pre-redaction secrets.

A missing artifact discovered during recovery is an integrity failure: report that the original is unavailable and preserve its provenance. Do not fabricate a replacement, retrieve another session's equal hash, or reexecute a side-effecting producer. A user may separately authorize a new command, but that is a new operation with a new observation ID.

### Shell boundary: preserve execution, filter explicit observations

The first candidate is a pinned `rtk-oss pipe --filter FAMILY` process consuming an already-captured result. Its stdin filter does not execute the producer or create an archive. Jackin must supply recovery and validate the named family. Start with one qualified test/diagnostic format: available names include `cargo-test`/`cargo`, `pytest`, `go-test`/`go-build`, `ctest`, `tsc`, `vitest`, `mypy` and `ruff`. This is not a generic clippy/cargo-check/lint interface or a public Apache Rust library kernel. This permits a diagnostic-filter experiment without changing quoting, shell expansion, pipelines, redirects, environment, cwd or command exit behavior. [RTK current source and reproductions](/research/context/tools/03-rtk-design/).

Do not default to a PATH shim or generic command rewriter. Native hosts may use absolute binaries, internal tools, code-mode calls, shells with different parsing, or result bounds before any shim. A wrapper can also accidentally change pipeline status, signal propagation, redirection, TTY behavior or streaming. Rewriting is a separate treatment with shell-generated fixtures, not a consequence of choosing RTK as a formatter.

Preserve stdout/stderr association, exit code and signal/interruption when the host actually supplies them. Do not universally convert signals to `128 + n` or infer success from exit zero alone: compilers and linters can emit important diagnostics on success. Initial automatic eligibility should exclude unknown/free-form shell text, machine-readable output consumed downstream, source patches and exact Git evidence.

### Native tools, MCP and editing

A synchronous replacement seam can change selected model-bound content after native execution. An asynchronous status event or `additionalContext` merely adds information and cannot prove original input was removed. Adding MCP retrieval tools also does not intercept native `Read`, shell or edit calls. The host/version adapter must prove the actual path and capture completeness.

Native edits may require a prior native read receipt, exact old text or a current file version. An MCP outline or cache hit cannot be assumed to satisfy those requirements. Keep exact native reads available and require them before editing when the host contract demands it. Never replace native edit authorization or stale-write checks with an optimizer's “file already seen” ledger.

### Content-specific candidates and exclusions

| Content class | Candidate treatment | Required preservation / current decision |
|---|---|---|
| Build/test/lint qualification corpus | Named RTK OSS filters only where applicable, or independently qualified Rust/Python/Go alternatives | Keep failures, warnings, paths, line/column, exit status, counts and raw recovery; producer-generated corpus first |
| JSON | Whitespace-only lexer or typed unique-key domain | Headroom's Rust and Python agent-mode probes collapse duplicate keys; parsed equality is not exact evidence. Reject ambiguous input or pass through. |
| Logs and tables | Bounded selection with explicit omitted ranges | Keep row/field associations, multiline events, negations, units and time ordering. Do not create a sentence by joining unrelated lines. |
| Search results | Exact path/range selection plus bounded match context | Record omitted counts and search scope; an empty ranked result does not prove absence |
| Source and code outlines | Syntax outline for navigation followed by exact reads | Preserve names/signatures/spans; syntax is not complete type, macro, call-graph or dependency analysis |
| Git diff/patch | Native exact output by default | Preserve no-final-newline markers, binary/rename/mode changes and truncation. RTK stdin git-diff and structural diff parser are distinct paths. |
| Prose | Native or explicitly scoped format changes first | Learned summarization and semantic rewriting need separate task tests; determinism alone is not fidelity |
| Images/PDFs/screenshots | Native media or separately qualified preprocessing | Preserve exact-text/layout needs and model policy; no automatic cheaper-model routing or assumed universal token ratio |

The Headroom Python shell-line reconstruction fix passed focused tests, while the Rust Kompress code still uses whitespace splitting/joining. A product-level “fixed” label cannot authorize another backend. LemonCrow Lite's repeated-shell probe emitted an unchanged result even when spill creation failed. Those observations motivate backend-specific guards and durable acknowledgement; they do not imply all transforms in either product are defective. [Headroom](/research/context/tools/02-headroom-design/), [LemonCrow](/research/context/tools/10-lemoncrow-design/).

### Guard contracts

The host adapter declares whether it received exact bytes, decoded text, structured fields or an already-bounded rendering. Validate encoding before text transforms; preserve original UTF-8 bytes, Unicode normalization form, CRLF and no-final-newline information when exactness matters. Do not decode invalid bytes with silent replacement and then call the archive lossless.

A transform manifest identifies algorithm/configuration version, input/output hashes, content class, expected omissions, token-estimate method and recovery handle. Keep statistics outside model-visible text unless needed for a meaningful decision. A short explicit omission notice is useful; a verbose per-result telemetry block can erase the saving.

Use size, repetition or compressibility heuristics only as routing signals. They are not proofs that a field is irrelevant. Require retained evidence checks on a diverse fixture corpus and pass through unknown structures. A local “output tokens no larger than input” guard does not guarantee task savings: schema, recovery calls and extra turns still count.

## Implications for jackin❯

Start with one synchronous host adapter, one diagnostic family and a raw verifier lane. Keep errors and exact evidence native until individually qualified. Compare RTK OSS, Headroom no-ML Rust, Python `densify` and Caveman's engine as separate arms against the same original result. A smaller pure adapter is preferable to a full proxy only when it actually reaches the needed boundary.

The minimal conformance corpus includes real Rust build/test/lint output; success with stderr diagnostics; Git CRLF/no-EOL/binary/rename/mode/truncated diffs; duplicate-key and malformed JSON; multiline tables/logs; Unicode/source reads; native truncation; cancellation; a stalled/crashed worker; missing/replaced artifact; and unavailable storage. The source/package tests already executed are not a substitute for these end-to-end host checks. [Validation protocol](/research/context/techniques/16-validation-harness/).

## Limitations and unknowns

The research did not execute real host result replacement, streaming cancellation or native read-before-edit across agents. It did not simulate a full disk for the proposed broker. Headroom's injected storage fault removed its SQLite table; LemonCrow's spill probe used an unusable spill directory. Preserve those exact fault models rather than relabeling them as exhaustive durability proof.

Provider-history rewriting, chained shell rewriting, arbitrary source compression, default embeddings, full runtime replacement and media/model routing remain separate experimental treatments. Recovery availability also does not prove a model will notice an omission; accepted-task tests must measure missed facts and recovery behavior.
