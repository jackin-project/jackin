This document describes jackin❯ security implementation from a contributor perspective. It covers the threat model, the specific functions that enforce security invariants, the external tools bundled in the construct image, and the six high-autonomy launch branches (`claude`, `codex`, `amp`, `kimi`, `opencode`, and `grok`) in the 12-agent catalog.

## Threat model

| Threat | Defended? | Where in code | Residual risk |
|---|---|---|---|
| Agent reads/writes files on host | Yes | Mount scoping in <RepoFile path="crates/core/jackin-config/src/mounts.rs">crates/core/jackin-config/src/mounts.rs</RepoFile> | Explicitly mounted rw paths |
| Credential theft via symlink | Yes | Directory-relative admission in <RepoFile path="crates/services/jackin-instance-credentials/src/auth_directory/files.rs" /> | Explicitly shared credential state remains sensitive |
| Container escape | Out of scope | Docker hardening tracked in [Docker runtime hardening contract](/roadmap/docker-runtime-hardening-contract/) and [smolvm backend research](/research/platform/isolation/smolvm-backend/) | Shared kernel; future microVM work addresses this |
| Agent exfiltration over network | Needs policy | Tracked in [Network egress policy](/roadmap/network-egress-policy/) | Open egress by default today |
| Supply chain (capsule binary) | SHA256 + signed manifest | <RepoFile path="crates/adapters/jackin-image/src/capsule_binary.rs">crates/adapters/jackin-image/src/capsule_binary.rs</RepoFile> | See [signed releases](/roadmap/security-threat-model-and-signed-releases/) |

## Security functions

Credential filesystem helpers are re-exported by <RepoFile path="crates/services/jackin-instance-credentials/src/lib.rs" />. Provider provisioning and GitHub source resolution live in <RepoFile path="crates/services/jackin-instance-agents/src/lib.rs" />.

### `reject_symlink`

<RepoFile path="crates/services/jackin-instance-credentials/src/paths.rs" /> checks the final path with `symlink_metadata` and rejects symlinks. `reject_auth_path` also checks ancestors. A path check alone is not atomic admission; Unix file operations use the directory-relative helpers below.

### `repair_permissions`

<RepoFile path="crates/services/jackin-instance-credentials/src/permissions.rs" /> delegates Unix permission repair to <RepoFile path="crates/services/jackin-instance-credentials/src/auth_directory/files.rs" />. The implementation locks the target, checks ownership and regular-file identity, opens without following symlinks, compares the opened identity, and applies `0o600` through the file descriptor. Failures are returned to the caller; missing files are harmless.

### `write_private_bytes` / `write_private_file`

On Unix, <RepoFile path="crates/services/jackin-instance-credentials/src/auth_directory/files.rs" /> admits the parent directory and existing target, checks ownership and identity, writes a private temporary file relative to that directory, and publishes it with `renameat`. Unchanged contents retain their file while permissions are tightened. The implementation synchronizes writes and cleans up failed temporary files.

### `create_private_file_if_absent`

The same Unix owner uses `openat` with `O_CREAT|O_EXCL|O_NOFOLLOW` and `0o600` to seed a missing credential file. An existing entry is accepted only after regular-file and identity validation; existing content is retained.

### `host_home_is_real`

<RepoFile path="crates/services/jackin-instance-agents/src/github.rs" /> gates host GitHub credential fallback on whether `host_home` matches `directories::BaseDirs::new().home_dir()`. Temporary test homes cannot silently consume the operator's host credentials.

### `parse_gh_hosts_yml`

The GitHub owner uses `serde_saphyr` to parse `~/.config/gh/hosts.yml`. Malformed input, a missing `github.com` token, and empty or whitespace-only tokens return `None`. An optional nonempty user name accompanies the accepted token.

## External security tools

Both tools are installed in the construct image and active in every container session by default.

### shellfirm

Intercepts dangerous shell commands at the shell level before execution, blocking `rm -rf /`, `chmod 777`, `curl | bash`, and similar patterns. CI prepares the pinned binary before Docker Buildx runs, stages it in the construct context as `prebuilt/shellfirm`, and <RepoFile path="docker/construct/Dockerfile">docker/construct/Dockerfile</RepoFile> copies that binary into the image in the shellfirm `COPY` step. Shell hook wired in <RepoFile path="docker/construct/zshrc">docker/construct/zshrc</RepoFile> and <RepoFile path="docker/construct/fish-config.fish">docker/construct/fish-config.fish</RepoFile>.

Protects against both accidental operator mistakes and agent-generated destructive commands. Disable per-session by setting `JACKIN_DISABLE_SHELLFIRM=1` in the container environment.

### tirith

Security scanner that validates container runtime state against a policy. Guards against configuration drift and unexpected privilege escalation during a session. Downloaded in the tirith install block in <RepoFile path="docker/construct/Dockerfile">docker/construct/Dockerfile</RepoFile> via a SHA256-verified curl + `tar` extraction. Shell hook wired in the same shell config files as shellfirm.

Disable per-session by setting `JACKIN_DISABLE_TIRITH=1` in the container environment.

## High-autonomy launch flags

jackin❯ launches each agent with flags that remove tool-approval prompts. These are defined in <RepoFile path="docker/runtime/entrypoint.sh">docker/runtime/entrypoint.sh</RepoFile> and applied at container start before the agent binary runs.

| Agent | Configuration | Where |
|---|---|---|
| Claude | `--dangerously-skip-permissions` CLI flag + `skipDangerousModePermissionPrompt: true` in settings JSON | line 41 |
| Codex | `--dangerously-bypass-approvals-and-sandbox` CLI flag | line 47 |
| Amp | `--dangerously-allow-all` CLI flag | line 53 |
| Kimi | `--yolo` CLI flag (auto-approves all tool actions) | line 58 |
| Grok | `--always-approve` CLI flag (auto-approves edits and tools) | line 127 |
| OpenCode | `OPENCODE_CONFIG_CONTENT='{"permission":"allow"}'` env var + `~/.config/opencode/opencode.json` written with `"permission": "allow"` by capsule runtime setup | line 64 + <RepoFile path="crates/apps/jackin-capsule/src/runtime_setup.rs">crates/apps/jackin-capsule/src/runtime_setup.rs</RepoFile> |

When any of these configurations are active: jackin❯ still enforces mount scoping, network isolation, and the host Docker socket exclusion. The flags remove tool-approval prompts but do not remove auth prompts, user questions, plan confirmation, model/account issues, runtime updates, or terminal-level failures. Operators who need the approval prompts restored can rebuild the derived image without the high-autonomy flags by customising the entrypoint hook.

## Container boundary contract

The operator is responsible for what they mount. Explicitly mounted read-write paths are accessible to the agent — this is intentional and documented in the [Mounts guide](/guides/mounts/). The security model defends against the agent escaping the defined mount scope, not against the agent using what the operator chose to expose.

The YOLO flags above reduce friction at the cost of prompt-level damage prevention. The remaining guarantees (mount scoping, network isolation, no host Docker socket) hold regardless of flag state.
