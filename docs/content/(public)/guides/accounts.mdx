Jackin keeps two kinds of accounts on the host. A **usage account** connects directly to a provider and supplies usage data to the console and usage commands. An **execution account** supplies credentials for a sandbox launch. Usage accounts never provide launch credentials. For the terms, see [Core concepts](/getting-started/concepts/).

## Connect an account for usage

Open the console and press `c` to open Accounts. In the account tree, press `n` to add a usage account, or focus the action buttons and choose **Add usage account…**. Select a provider and follow its sign-in prompts. To inspect a saved usage account, select its name under **Usage accounts** or open **Usage accounts…**. Usage accounts are separate from execution accounts, which supply credentials to sandbox launches. You can also connect an account from the CLI:

```sh
jackin account usage connect claude
jackin account usage connect codex
jackin account usage connect kimi --region global
```

The provider determines the sign-in method. Some providers open a browser, some display a device code, and API-key providers ask for a key in a masked prompt. Jackin stores credentials in the host operating system's credential store. Unlock the Secret Service collection on Linux or the login Keychain on macOS before connecting.

For regional providers, select the region that matches your account. MiMo Token Plan accounts also require the subscription region. Gemini usage requires an eligible Cloud Code Assist project and a registered Google Desktop OAuth client. Set `JACKIN_GOOGLE_OAUTH_CLIENT_FILE` to the downloaded Desktop app JSON for browser consent and managed project discovery. If it is unset, provide the client and project details when prompted. This connects Cloud Code Assist project usage, not consumer Gemini usage.

List and manage saved connections with the CLI:

```sh
jackin account usage ls
jackin account usage rename <account-id> "Work account"
jackin account usage reconnect <account-id>
jackin account usage replace-key <account-id>
jackin account usage rm <account-id>
```

Reconnect or replace a key to keep the account ID and its dashboard settings. Removing a connection deletes the local account and its saved credentials. A connected hub has separate lifecycle commands under `jackin account usage hub`.

## Check usage

Run `jackin` and press `u` to open the Usage dashboard. It refreshes connected accounts while the console runs. Use **Refresh all** to request a refresh, or open an account to inspect its status and metrics. The dashboard can show limits, balances, credits, spend, and reset times when a provider reports them. A failed refresh keeps the last successful values and shows a failure notice.

The CLI can show the dashboard summary, read a saved snapshot, or refresh connected accounts:

```sh
jackin usage
jackin usage --json
jackin usage details
jackin usage details --provider claude
jackin usage details --account <account-id>
jackin usage snapshot --account <account-id>
jackin usage refresh --account <account-id>
jackin usage share
```

`jackin usage details` lists saved accounts with their usage details. Use `--provider` or `--account` to filter the results. Details and snapshot commands read saved data without contacting providers. Refresh contacts the provider. `jackin usage share` prints a redacted report for sharing.

## Read usage from execution accounts

`jackin usage host` is a separate, read-only command for credentials configured as execution accounts. It reads credential sources on the host and checks the account providers. It does not use or modify the connected usage accounts above.

```sh
jackin usage host
jackin usage host --json
```

This host read supports the credential sources configured for execution accounts. A `file:` source can contain a token or a JSON login. The command does not refresh tokens. Use native usage connections for the dashboard and the provider sign-in flows described above.

Add a credential source to an execution account with `--credential`:

```sh
jackin account add claude --name personal --credential env:CLAUDE_TOKEN
jackin account add openrouter --name routing --credential 'op://Private/OpenRouter/credential'
jackin account add cursor --name editor --credential file:/Users/me/cursor-token
```

| Source | Meaning |
|---|---|
| `env:NAME` | The environment variable `NAME` on the host. |
| `op://...` | A 1Password reference that `jackin usage host` resolves on the host. This account is usage-only, and a launch refuses it. |
| `file:PATH` | A host file that contains a token or a JSON login. |
| `omp-host` | A credential saved by OMP for the selected provider. |

Jackin resolves each source on the host. An account can launch only when its credential type matches a supported provider and agent. A Codex account that uses a ChatGPT login must use `--chatgpt-from`.

## Add a Codex account for launches

Codex can run in a sandbox only with a ChatGPT login. Import the login from a Codex home directory:

```sh
jackin account add codex --name work --chatgpt-from ~/.codex
```

Jackin reads `auth.json` from the directory. It puts the login into an OpenShell provider named `jackin-work-codex` on the selected gateway. The gateway holds the access token and the refresh token. The sandbox gets only a placeholder, and the gateway swaps in the real token on the allowed hosts.

The gateway rotates the refresh token. The login in your Codex home can stop working afterwards. If that happens, run `codex login` on the host again.

## Choose the default account

Each execution provider has at most one default account:

```sh
jackin account default work
jackin account default --clear codex
```

The default account counts as a reference. `jackin account rm` refuses to remove an account while a default, a workspace binding, or a role binding still points at it. Clear the default or binding first, then remove the account.

## Bind an execution account

A workspace binding holds one account for each provider in that workspace. A role binding holds the default account of the role for the agent:

```sh
jackin account bind work --workspace my-app
jackin account bind work --role my-role
```

Pass exactly one of `--workspace` and `--role`.

For each launch, jackin picks the account of the agent in this order:

1. The `--account` flag of `jackin load`.
2. The workspace binding for the provider of the agent.
3. The role binding for the agent.
4. The default account of the provider.
5. The only account of the provider, when exactly one exists.

If no rule selects an account, the launch stops with an error that names the missing binding.

## List and remove execution accounts

```sh
jackin account ls
jackin account rm work
```

`jackin account rm` first removes the OpenShell provider of the account from every configured gateway. If it cannot reach one of them, it stops and names the gateway. To remove a gateway entry without contacting it, run `jackin gateway rm <name> --offline`. Its OpenShell providers then stay on that gateway until you reset it.
