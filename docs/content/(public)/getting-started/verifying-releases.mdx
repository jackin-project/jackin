---
title: "Verifying Releases"
---

Release channels have different artifact contracts. Stable tagged releases currently cover the macOS desktop ZIP; the rolling preview release publishes six CLI/capsule payload archives with provenance sidecars. This page explains what is available and how to use it.

## What you need to do

Nothing. When jackin❯ downloads `jackin-capsule` for the first time (or after clearing the cache), it automatically verifies a signed manifest before accepting and caching the binary. Subsequent launches reuse the already-verified cached binary. The verification is silent and transparent — you only notice it if something is wrong (in which case the launch aborts with an error message).

The verification tools described below are for operators who want to audit a download themselves, integrate jackin❯ into a supply chain policy, or confirm the integrity of any release asset manually.

## Stable tagged desktop release

The tag-triggered <RepoFile path=".github/workflows/release.yml">.github/workflows/release.yml</RepoFile> lane is limited to the arm64 macOS desktop ZIP. It Developer ID signs, notarizes, staples, and GitHub-attests that ZIP. It does not publish CLI or capsule tarballs, archive cosign bundles, SBOM sidecars, or `capsule-manifest.json`.

| Asset | Verification |
|---|---|
| `jackin-desktop-<version>-aarch64-apple-darwin.zip` | Developer ID signature, notarization, stapled ticket, and GitHub build attestation |

## Rolling preview package

The generated <RepoFile path=".github/workflows/preview.yml">.github/workflows/preview.yml</RepoFile> lane publishes exactly six payload archives:

- four CLI tarballs: macOS arm64, macOS x86_64, Linux arm64, and Linux x86_64
- two Linux capsule tarballs: arm64 and x86_64

Each preview payload has three sidecars: `<payload>.sha256`, `<payload>.bundle`, and `<payload>.sbom.json`. The package also includes `SHA256SUMS`, `capsule-manifest.json` plus `capsule-manifest.json.bundle`, `release-manifest.json`, and `identity.json`. GitHub build provenance covers the six payloads and the declared supporting assets.

## Verify with SLSA provenance (GitHub Attestations)

Requires `gh` CLI (already installed if you used Homebrew to install jackin❯).

```sh
gh attestation verify <file> --repo jackin-project/jackin
```

Use this for the stable desktop ZIP, any preview payload, or any declared preview supporting asset. It checks that the file was produced by the corresponding jackin❯ GitHub Actions run and is linked to the source commit. No extra tools required.

## Verify everything with one local gate

From a checkout of this repository, download a rolling-preview payload and its three sidecars, then run:

```sh
cargo xtask release-verify <file>.tar.gz
```

The gate checks a preview payload against its sibling `.sha256` sidecar, verifies the `.bundle` with the same cosign identity and issuer policy shown below, verifies the GitHub artifact attestation for `jackin-project/jackin`, and parses the `.sbom.json` sidecar. Any preview payload archive path with those three siblings works; the stable desktop ZIP follows the Apple signing/notarization and direct attestation contract above.

For example:

```sh
gh release download jackin-dev-v0.1.13 \
  --repo jackin-project/jackin \
  --pattern 'jackin-dev-0.1.13-aarch64-unknown-linux-gnu.tar.gz*' \
  --dir /tmp/jackin-release-check

cargo xtask release-verify \
  /tmp/jackin-release-check/jackin-dev-0.1.13-aarch64-unknown-linux-gnu.tar.gz
```

The command fails closed. If the archive content changes after the `.sha256` file is published, the digest mismatch aborts verification before signature or provenance checks run.

## Verify with cosign bundle

Requires `cosign` installed locally (`brew install cosign` or `mise install cosign`).

```sh
cosign verify-blob \
  --bundle <file>.bundle \
  --certificate-identity-regexp 'https://github.com/jackin-project/jackin/' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  <file>
```

Preview payloads and `capsule-manifest.json` use this keyless OIDC signature path. It confirms the certificate was issued to a jackin❯ GitHub Actions workflow and checks the Sigstore transparency log entry; the stable desktop ZIP uses Apple signing/notarization plus GitHub attestation instead.

To verify the capsule manifest specifically:

```sh
cosign verify-blob \
  --bundle capsule-manifest.json.bundle \
  --certificate-identity-regexp 'https://github.com/jackin-project/jackin/' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  capsule-manifest.json
```

## Inspect the SBOM

Preview payload `.sbom.json` files are CycloneDX JSON documents listing the binary's file-level and ELF-level dependencies.

```sh
# Inspect raw content
jq . <file>.sbom.json

# Validate with cyclonedx-cli (.NET tool, install separately)
cyclonedx validate --input-file <file>.sbom.json
```

## Download release assets

Stable desktop releases use versioned `v<version>` tags. Preview builds publish the six-payload package to the `preview` rolling tag. Both are available at `https://github.com/jackin-project/jackin/releases`, but their verification contracts differ as described above.
