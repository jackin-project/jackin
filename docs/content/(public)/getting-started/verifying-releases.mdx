---
title: "Verifying Releases"
---

Historical Jackin releases included signed artifacts. The current generated
workflow does not yet publish Jackin preview releases or Homebrew updates, so
there is no current preview release to install or audit. This page describes
the available GitHub verification command and the verification contract used
by the capsule downloader when immutable previews are published.

## What you need to do

For an eligible immutable preview version, Jackin's capsule downloader verifies
the signed release receipt, the selected capsule payload, and the capsule
manifest before caching the binary. It also verifies Sigstore transparency
evidence and GitHub provenance against the fixed Jackin preview workflow
identity. This describes the consumer verification code; it is not proof that
the release publisher is enabled or that a live capsule download has passed.

The verification tools described below are for operators who want to audit a download themselves, integrate jackin❯ into a supply chain policy, or confirm the integrity of any release asset manually.

## Historical release assets

Historical release assets used per-archive sidecars. The current Velnor receipt
contract instead binds an exact payload inventory, CycloneDX SBOMs, companions,
and their signatures; future published previews must follow that contract.

| Asset | Purpose |
|---|---|
| `<name>.tar.gz` or `<name>.zip` | The binary / app archive |
| `<name>.…sha256` | SHA256 digest of the archive (suffix `.tar.gz.sha256` or `.zip.sha256`) |
| `<name>.…bundle` | Cosign keyless signature bundle |
| `<name>.…sbom.json` | CycloneDX SBOM (software bill of materials) |

Historical capsule releases additionally used a signed manifest:

| Asset | Purpose |
|---|---|
| `capsule-manifest.json` | Version + per-architecture SHA256 digests |
| `capsule-manifest.json.bundle` | Cosign keyless signature bundle for the manifest |

## Verify GitHub provenance

Requires `gh` CLI (already installed if you used Homebrew to install jackin❯).

```sh
gh attestation verify <file> --repo jackin-project/jackin
```

This verifies the attestation for the selected file against the named repository.
It does not by itself validate the Jackin release receipt, asset inventory, or
the exact workflow policy required by the capsule downloader.

There is no current `cargo xtask release-verify` command. The historical
`jackin-dev-v0.1.13` check performed on 2026-07-04 remains historical evidence;
it does not validate the new receipt format or establish current publication.

## Inspect the SBOM

The `.sbom.json` files are CycloneDX JSON documents listing the binary's file-level and ELF-level dependencies.

```sh
# Inspect raw content
jq . <file>.sbom.json

# Validate with cyclonedx-cli (.NET tool, install separately)
cyclonedx validate --input-file <file>.sbom.json
```

## Download release assets

When native preview publication is enabled, it uses immutable `v<version>` tags.
The former rolling `preview` tag is not the installation source. Until the
publisher is enabled and a live release is verified, use only releases and
assets actually listed on the GitHub Releases page.
