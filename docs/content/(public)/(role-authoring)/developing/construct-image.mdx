---
title: The construct image
description: The base image that every role Dockerfile starts from, and what jackin adds on top of your role.
---

The construct image is the base of every role. Jackin builds it from a `Dockerfile` that is part of jackin, and caches it by digest. It needs no registry. Your role `Dockerfile` refers to it as `construct`.

## What the construct image has

- It starts from the OpenShell default sandbox image, `nvcr.io/nvidia/base/ubuntu:24.04`, pinned by digest.
- It has the user `sandbox`, uid and gid 1000, with the home directory `/sandbox`. The `ubuntu` user is removed. The gateway driver takes the runtime user from `/etc/passwd`, not from the image `USER` line.
- It has `git`, `curl`, `ca-certificates`, `jq`, `bash`, and the other shell tools that roles commonly need. Export needs `git` in the sandbox.
- It has no setuid or setgid bit. The build fails if `sudo`, a firewall tool, or a container tool is on `PATH`.

Jackin puts its own files under `/usr/local`, because the default Landlock policy denies `/opt`. Put yours there too.

## What jackin adds to your role

After the role image builds, jackin builds a final image on top of it. As root, the final layer:

- Installs `codex` and `codex-code-mode-host` at the pinned Codex version, over any file your role put at those paths.
- Writes `/etc/codex/config.toml` with `check_for_update_on_startup = false`.
- Installs `jackin-start` at `/usr/local/bin/jackin-start`. It is the main process of the sandbox. It starts Codex, and it keeps the sandbox alive when Codex exits so that you can still export your work.
- Installs the role hooks at `/usr/local/lib/jackin/hooks/setup` and `/usr/local/lib/jackin/hooks/preflight`.
- Sets the user to `sandbox`.
- Scans the result. The build fails on a setuid or setgid file, a file capability, a forbidden tool, a changed `codex`, or a jackin path that is not a real root-owned path.

When the Docker capability is on, the final layer also adds the Docker client at `/usr/local/bin/docker` with its `buildx` and `compose` plugins, and the scan allows them. It never adds an engine.

## How images are named and cached

Every image name starts with `jackin.invalid/`. That host never resolves, so a build that refers to a missing local image fails instead of pulling an image with the same name from a public registry.

The image tag is the cache key. It covers the role revision, the `Dockerfile` digest, the construct image, the Codex version, the platform, the Docker capability, and the digests of the jackin files in the image. When an image with that tag exists, jackin does not build it again. `--rebuild` ignores the cache.
