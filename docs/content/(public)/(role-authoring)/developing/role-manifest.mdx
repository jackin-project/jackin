---
title: Role manifest
description: Reference for jackin.role.toml, the manifest at the root of every role repository.
---

Every role repository has a `jackin.role.toml` at its root. The parser rejects unknown fields. A change to the format is a breaking change, so there is no migration.

## Example

```toml
schema = 1

[role]
name = "sentinel"
dockerfile = "Dockerfile"
policy = "policy.yaml"

[codex]
model = "example-model"

[docker]
enabled = false

[hooks]
setup = "hooks/setup.sh"
preflight = "hooks/preflight.sh"

[env.EXAMPLE_NAME]
default = "value"
prompt = "Text for the operator"
```

## Fields

| Key | Required | Meaning |
|---|---|---|
| `schema` | Yes | The format version. The only value is `1`. |
| `role.name` | Yes | The role name. Use ASCII letters, digits, `.`, `_`, and `-`, up to 63 characters. It must start and end with a letter or digit. It must equal the name you give to `jackin role add`. |
| `role.dockerfile` | Yes | The path of the `Dockerfile`. |
| `role.policy` | Yes | The path of the [policy](/developing/role-policy/). |
| `codex.model` | No | The Codex model name. Jackin writes it to the Codex `config.toml` in the sandbox. |
| `docker.enabled` | No | `true` turns on the [Docker capability](/guides/docker-capability/) for every launch of the role. The default is `false`. |
| `hooks.setup` | No | The path of the setup hook. |
| `hooks.preflight` | No | The path of the preflight hook. |
| `env.<NAME>.default` | No | The value to use when the operator gives none. |
| `env.<NAME>.prompt` | No | The text that jackin shows when it asks for the value. |

A path is relative to the role repository. The parser rejects a path that is absolute or contains `..`. A hook path must name a regular file in the repository.

## Hooks

Jackin copies the hooks into the image as root-owned files, so the agent cannot change them. It runs them with `exec` as user `sandbox`, with no terminal, the working directory `/sandbox/project`, the `[env]` values, and stdin closed.

| Hook | When it runs |
|---|---|
| `setup` | Once for each launch. Jackin writes a marker after it finishes. Write it to be safe to run again. |
| `preflight` | Before each start of Codex, including `jackin attach --restart`. |

A non-zero exit stops the launch. Jackin shows the hook name, the exit code, and the output with terminal control sequences removed. The sandbox stays ready for a later retry. Cancelling the launch stops the hook.

## Environment values

Each `[env.NAME]` table declares a value for the role. At each launch, jackin resolves the values and writes them into the sandbox. Hooks, the Codex supervisor, and shells all read the same file.

Jackin picks a value in this order:

1. The launch answer: the `--env NAME=VALUE` flag of `jackin load`, or the answer to the prompt when a terminal is attached.
2. The value in the workspace-and-role scope of the jackin configuration.
3. The value in the workspace scope.
4. The value in the global scope.
5. The `default` of the manifest.

Without a terminal, an entry uses its `default`. An entry with no default stops the launch unless `--env` gives the value.

Put only values that are not secrets in `[env]`. Jackin reserves these names, and the parser refuses them:

- Names that start with `JACKIN_`, `OPENAI_`, `CODEX_`, `LD_`, `OPENSHELL_`, `DOCKER_`, or `BUILDX_`.
- `PATH`, `HOME`, `BASH_ENV`, `ENV`, `SSL_CERT_FILE`, and `SSL_CERT_DIR`.
