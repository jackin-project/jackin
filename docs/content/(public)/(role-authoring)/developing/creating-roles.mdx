<EarlyDevelopmentNotice />

A role is a repository that tells jackin how to build the image for one kind of work and which network access the sandbox gets. This page shows how to write one, check it, and build it.

## Create the repository

A role repository holds three required files:

```text
my-role/
  Dockerfile
  jackin.role.toml
  policy.yaml
  hooks/
    setup.sh
    preflight.sh
```

The `hooks/` directory is optional. All paths in the manifest are relative to the repository root.

## Write the manifest

`jackin.role.toml` names the role and points to its files:

```toml
schema = 1

[role]
name = "my-role"
dockerfile = "Dockerfile"
policy = "policy.yaml"

[docker]
enabled = false

[hooks]
setup = "hooks/setup.sh"
preflight = "hooks/preflight.sh"
```

The role name must match the name you give to `jackin role add`. The parser rejects unknown fields. See the [role manifest reference](/developing/role-manifest/).

## Write the Dockerfile

Start the final stage `FROM construct`. `construct` is the base image that jackin builds. See [The construct image](/developing/construct-image/).

```dockerfile
FROM construct

USER 0
RUN --mount=type=bind,source=tools,target=/mnt/tools \
    install -D -m 0755 -o root -g root /mnt/tools/my-tool /usr/local/bin/my-tool
USER 1000
```

Jackin checks these rules before it builds:

- The final stage starts `FROM construct`.
- No stage is named `construct`.
- A `syntax` parser directive names only the `docker/dockerfile` frontend.
- The final stage sets no `ENV` variable that starts with `DOCKER_` or `BUILDX_`, and no `ENV` name that expands a variable.

Follow these rules too:

- Install files under `/usr/local`. The default Landlock policy denies `/opt`.
- Install as root, then switch back to user `sandbox` (uid 1000).
- Do not install `sudo`, a firewall tool, or a container tool. Do not leave setuid or setgid bits. After the build, a scan fails the image on any of them.
- Do not install Codex. Jackin installs `codex` at its pinned version and replaces any file at that path.
- Use only regular files in the repository. A symlink is refused. One file can hold up to 16 MiB, and the repository up to 64 MiB.

Jackin builds the image with `docker buildx`, using your registry login. The repository files are the build context.

## Write the policy

`policy.yaml` is a native OpenShell policy. Start from the filesystem and process sections in the [policy reference](/developing/role-policy/), and add network rules for the hosts the role needs.

## Add hooks

Hooks are shell scripts that jackin runs inside the sandbox as user `sandbox`, with no terminal and the working directory `/sandbox/project`.

- `setup` runs once for each launch. It must be safe to run again, because a crash before it finishes runs it again.
- `preflight` runs before each start of Codex.

A hook that exits with a non-zero code stops the launch. The agent cannot change a hook, because jackin copies the hooks into the image as root-owned files.

## Check the role

Run the check from the role repository, or pass its path:

```sh
jackin role check .
```

A valid role prints nothing and exits with status 0. An invalid role prints `error:` and the cause, and exits with status 1:

```text
error: invalid role manifest at /path/jackin.role.toml: reserved environment name PATH
```

The check covers the manifest, the `Dockerfile`, and the policy.

## Use the role

Add the role to jackin. The source is a directory or the URL of a git repository:

```sh
jackin role add my-role ~/roles/my-role
jackin role add my-role https://example.com/me/my-role.git --rev v1
```

`--rev` takes a branch, a tag, or a commit, and applies to a git source only. A git role is cloned into the jackin cache. Each launch fetches it again. The role revision is the commit and a digest of the role files.

Build the image without launching a sandbox:

```sh
cd ~/Projects/my-app
jackin build my-role
```

`jackin build` uses the saved workspace of the current directory, including its Docker setting, so it builds the image that `jackin load` uses. It prints the image ID. Jackin caches the image under a key that covers the role revision, the construct image, the Codex version, the platform, and the Docker capability. Pass `--rebuild` to ignore the cache.

## Enable the Docker capability

Set `[docker] enabled = true` in the manifest to give every launch of the role access to a Docker engine. Read [Docker capability](/guides/docker-capability/) first. It is off by default.
