## Migration discipline (every slice below)

Each step maps readers/writers/ownership before moving anything;
defines forward plus rollback; sequences expand, migrate, verify, then
contract; keeps steps idempotent with partial failure observable;
verifies old and new paths at each transition; and never performs
destructive contraction implicitly: stop after the requested stage
passes.

## Sequenced plan

### 1. Manifest centralization

- `version.workspace = true` x28 (decision first: `jackin-dev`
  `0.1.52` vs workspace `0.6.4`: align versions or keep the outlier
  with a documented exemption).
- `rustix.workspace = true` x1 (process-directory).
- `[lints] workspace = true` x3 (capsule, process-directory, usage-ffi).
- Centralize-or-exempt the 10 remaining non-workspace deps from the
  Phase 1 audit (capsule libc; config shell-words; console open;
  diagnostics sysinfo + rustc_version; docker bollard; image sigstore;
  usage-ffi boltffi; lints dylint): move into `[workspace.dependencies]`
  or record the exemption with owner and expiry.
- Forward: edit member manifests only. Rollback: revert the commit.
  Verify: `cargo metadata --no-deps` package set unchanged,
  `cargo check --workspace` green, `GAP-INHERIT-*` at zero.
  Clears: `GAP-INHERIT-001/002/003`.

### 2. Toolchain alignment

- Bump `rust-toolchain.toml` channel `1.97.1` -> `1.98.1`; add an
  explicit `[tools] rust = "1.98.1"` pin to `mise.toml` (parity rule
  keeps the two in sync; the current idiomatic-only resolution is
  invisible to it). Decide `rust-version` in root `Cargo.toml`
  (`1.97` today): align MSRV with the channel or document the split.
- Forward: pin files only. Rollback: revert. Verify: full `cargo
  check` + nextest suite on the new channel (this is the one step
  whose blast radius is the whole tree; gate on green CI).
  Clears: `toolchain-channel-pinned`, `toolchain-mise-parity`.

### 3. Grouped S4 moves (`crates/*` -> `crates/<group>/<package>`)

- Per group, map readers/writers/ownership first: workspace `members`
  list, CI path filters, docs links, docker contexts, xtask path
  assumptions, `renovate.json` `ignorePaths` (jackin-lints entry),
  CODEOWNERS-style path rules. One group per commit; forward is `git
  mv` + member-list update; rollback is revert of that commit.
- Expand: register the new path in `members` alongside the old.
  Migrate: move the directory. Verify: `cargo metadata --no-deps`
  package set identical, `cargo check --workspace`, layout rules for
  the moved group green, targeted nextest for the group. Contract:
  drop the old path (explicit step, never implicit).
- Move all 33 manifests incl. excluded `jackin-lints`.
- After the last group, re-run the FULL check: native
  `cargo-workspace-inherit-*` and `tests-*` rules go blind-to-live at
  depth 2 and will surface new findings; `tests-dir-present` x60 noise
  collapses to one finding per real crate lacking `tests/`.
- Clears: `layout-no-flat-crate-manifest` (re-baselines `tests-*`,
  `cargo-workspace-inherit-*`).

### 4. Fuzz-crate placement (decision + move)

- The 4 `fuzz/` manifests sit at depth 2 today (12 inherit findings)
  and cannot move to `crates/<group>/<pkg>/fuzz/` (depth 3 trips
  `layout-no-deep-crate-manifest`). Recommended: top-level `fuzz/<pkg>/`
  (cargo-fuzz default shape, outside all `crates/`-scoped rules).
- Map readers first (CI fuzz jobs, docs, cargo-fuzz invocations);
  same expand/migrate/verify/contract rhythm as step 3.
- Clears: `cargo-workspace-inherit-*` x12.

### 5. Patch and vendor removal (waits on upstream)

- `[patch.crates-io] arrayref` + `vendor/arrayref` (1 patch finding, 2
  size findings) exist for a security reason. Forward only after a
  trustworthy upstream resolution lands: swap `vendor/arrayref` for
  the upstream version, verify lockfile + `cargo deny` + full tests,
  then contract by deleting `vendor/` in an explicit commit.
  Security signoff required. Clears: `cargo-no-patch`, vendor size
  findings.

### 6. Test normalization

- `GAP-TEST-001` x147: move each to `tests/` or the sibling `tests.rs`
  in canonical form (`#[cfg(test)] mod tests;`, private, external,
  single attribute). Sequence by crate, biggest files first; each file
  independently verifiable via nextest for its crate.
- `GAP-TEST-002` x5: drop `#[path]`, inline `tests.rs` child modules.
- `GAP-TEST-003` x33: declare the module or delete the file (deletion
  is a contract step: confirm no reader first).
- Post-move `tests-dir-present` remainder: add a `tests/` dir per
  crate (no `.gitkeep` strays: `tests-only-rust`).
- Clears: `GAP-TEST-001/002/003`, `tests-dir-present`.

### 7. Size budgets (long tail, per crate)

- 368 files over 400 lines, 14 `lib.rs`/`main.rs` over 150, 15 crates
  over 6000 code lines, 7 crates over 60 files. Order: console,
  runtime, capsule, usage, jackin, xtask, config, then the rest.
  Per-file splits are idempotent and independently verifiable
  (`alint check` on the crate + its nextest target). Crate splits
  follow the step-3 move discipline with ownership mapping.
- Clears: `size-file-400`, `size-lib-main-150`,
  `GAP-SIZE-001/002`.

### 8. Docs consolidation

- Move the 15 root markdown files to `docs/` (AGENTS.md, CLAUDE.md,
  README.md, CHANGELOG.md stay). Map readers first: root README links,
  docs-site references, scripts that read these paths. Forward: move +
  fix links; verify: docs build + lychee; no contraction beyond the
  move itself. Clears: `docs-root-only-allowed`.

### 9. CI conformance + gate

- Add a `build` job on `ubuntu-latest` to every workflow (1 today).
  Decide the toolchain pin spelling: keep mise-action (currently
  tolerated by `toolchain-ci-parity` via allow-missing) or add an
  explicit pin the parity regex sees (dtolnay `toolchain:` or `rustup
  toolchain install`) for defense in depth.
- Wire the gate: materialize the pinned policy release into
  `.cache/rust-policy` (checksum-verified), install the helper, run
  `alint check` as a required job.
- Clears: `ci-build-runs-on`.

### 10. Registries + dependency direction

- Author `policy/owned-packages.json` (workspace package names),
  `policy/package-groups.json` (tool/library/support/ffi/lints per
  package), `policy/ci-recipes.json` (expected CI job IDs). Verify
  each against `cargo metadata` / workflow job sets; expect
  `GAP-CI-002/003`, `GAP-DEPS-001/002/003`, `GAP-INV-002/003` to surface
  on first landing and sequence a direction-remediation slice for
  `GAP-DEPS-001` before declaring green.
- Clears: `GAP-INV-001`, `GAP-DEPS-004`, `GAP-CI-001` (then the
  newly surfaced set).
