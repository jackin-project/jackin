## Provider contracts at the pinned base

Both browser flows request a code using S256 PKCE and a fresh state. They bind IPv4 loopback, open the browser after the listener starts, and race the callback against pasted input. A pasted absolute callback URL and a `code#state` pair can supply state. A bare code fails state validation. Stop the listener on every exit. The device flow displays a copyable code and HTTPS verification address first. Prefer the complete verification URI and resolve relative URLs against the start endpoint. The user chooses Open Browser. Poll at the supplied interval (default five seconds, minimum one), add five seconds on slowdown, stop at expiry or denial, retry transient network failures within the deadline, and cancel on Back. All in-flight completions must check cancellation before saving. ## Implementation sequence at the pinned base

1. Establish owned usage identities and a vault boundary. Exercise lifecycle operations independently from launch accounts before provider sign-ins share it.
2. Add each sign-in and provider reader behind a common async service. Validate profile/key and workspace scope through the exact provider protocol. Keep auth-only test evidence separate from quota and history evidence.
3. Persist typed observations, notices, last-good history and reset inventory by account. Implement provider-specific reads and scheduling, then explicit reset actions and hub reconciliation.
4. Drive those services from the existing account list, dashboard and CLI. Prove cached export runs with no credential or network access.
5. Port the linked regression cases to deterministic boundary fixtures, run repository gates, exercise interactive paths in a PTY, and record separately any actual live-account verification. Preserve the [upstream MIT notice][license] for ports.
