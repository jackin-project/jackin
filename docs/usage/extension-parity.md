# Kimi, MiniMax, MiMo and Google usage accounts

Jackin connects these usage accounts in the CLI and TUI. This audit compares the implementation with each provider's contract as of 22 November 2026. These are additions to the pinned OpenUsage provider set. The tests use local fixtures and a test vault. The Antigravity check also used a live Google AI Ultra subscription. [OpenUsage baseline](https://github.com/robinebers/openusage/tree/53f70b396698656cb5e1e3f59c40d1b86d6b5296) · [Initial jackin implementation](https://github.com/jackin-project/jackin/tree/1b8a6f85c5f0ba0d7e25b406e0850f7abc8533a8)

## Verification

The provider tests exercise successful reads, wrong products, zero versus absent counters and upstream refusal. The account tests drive region and method selection, grant cancellation or denial, Kimi subject mismatch, retained account identity, MiniMax state and PKCE, renewal and recovery after the vault entry disappears. Gemini tests exercise the local browser callback, registered-client renewal, managed project enrollment, operation host restrictions and project refusal. MiMo tests cover exact amounts above JavaScript's integer precision, UTC dates, currency separation, empty ranges, partial failure and independent retry cadence. [Regional device accounts](../../crates/usage/jackin-usage/tests/connected_accounts/regional_device.rs) · [Extension integration tests](../../crates/usage/jackin-usage/tests/extension_connections.rs) · [Gemini enrollment tests](../../crates/usage/jackin-usage-provider-gemini/tests/account.rs) · [MiMo credits and balance](../../crates/usage/jackin-usage-provider-mimo/tests/token_plan.rs)

Live authenticated verification requires matching subscriptions, eligible projects and an OAuth client registration accepted by the issuer for device or browser sign-in. No jackin release registration is bundled. The Kimi and MiniMax upstream sources publish registrations for their own clients. Public third-party registration procedures for those providers have not been verified. Their console-key methods operate independently of OAuth registration. The HTTP fixtures use test credentials.


## Which Google usage does each product report?

The reference OpenUsage Mac app registers its Google entry as Antigravity. It opens Google's browser consent page with a preconfigured installed-app client, uses PKCE and a loopback callback, and reads Antigravity's project and quota summary. The separate OpenUsage CLI detects an existing Gemini CLI login and requests Code Assist quota. These paths report different products. [Mac browser flow](https://github.com/robinebers/openusage/blob/53f70b396698656cb5e1e3f59c40d1b86d6b5296/Sources/OpenUsage/Services/BrowserProviderLogins.swift#L119) · [Antigravity quota reader](https://github.com/robinebers/openusage/blob/53f70b396698656cb5e1e3f59c40d1b86d6b5296/Sources/OpenUsage/Providers/Antigravity/AntigravityUsageClient.swift) · [OpenUsage CLI Gemini reader](https://openusage.sh/docs/providers/gemini-cli/)

Google retired consumer Gemini CLI and Code Assist access for individual, Google AI Pro and Ultra accounts on June 18, 2026. The Jackin Gemini connector applies to eligible Cloud Code Assist projects. A registered desktop client identifies the application to Google. Browser consent then authorizes the individual user. [Google deprecation](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals) · [Google app registration policy](https://developers.google.com/identity/protocols/oauth2/policies)

Google One shows the subscription tier. Jackin’s Antigravity connection reads the plan and model quotas from the official CLI status line. For usage in the Gemini app itself, open **Settings → Usage Limits** in that app. The published OAuth scopes and Gemini Apps user guide do not document an endpoint for reading personal Gemini Apps usage windows. [Gemini Apps limits](https://support.google.com/gemini/answer/16275805?hl=en) · [Google OAuth scopes](https://developers.google.com/identity/protocols/oauth2/scopes)

### Can Jackin sign in to a personal Ultra subscription on its own?

The Antigravity account verified in Jackin uses Google's own sign-in. The signed-in CLI publishes the account, plan and quota windows to Jackin through its status line. Starting that CLI again updates the saved reading. While it is closed, Jackin can display the last observation and its timestamp. [Antigravity status-line contract](https://antigravity.google/docs/cli/statusline)

Standalone onboarding remains a gap relative to the OpenUsage Mac flow. Google says it offers no consumer-plan OAuth partner program for third-party apps. Its guidance permits personal sign-in through specific first-party runtimes and restricts reuse of their OAuth credentials. We found no documented third-party, read-only quota grant for these four windows. A Google Cloud desktop client registration covers the separate Code Assist connection. [Google’s answer on third-party subscription access](https://discuss.ai.google.dev/t/supported-gemini-subscription-access-for-a-third-party-vs-code-extension/189889/2) · [Google’s clarification on first-party runtimes](https://discuss.ai.google.dev/t/conflicting-guidance-on-using-t3-code-with-personal-google-ai-subscriptions/197131)

### Antigravity implementation requirements from the source audit

| Area | OpenUsage behavior at the pinned revision | Jackin integration |
|---|---|---|
| Account lifecycle | Google sign-in establishes identity before the first quota read. Duplicate checks use a known identity. Reconnection validates the candidate before replacing the old grant and preserves account settings. | The status-line connector enrolls a specified email on its first matching quota report. The callback supplies an email and quota observations. Google manages its credentials. |
| Plan | Prefer a recognized paid-tier ID, then the paid-tier name, then the current-tier name. The plan label does not determine the size of an allowance. | Read the reported plan tier when available. Preserve the previously observed tier if a later callback for the same account omits it. |
| Quota | Keep independent five-hour and weekly fractions for Gemini and third-party models. Each number describes the percentage of its own pool remaining. An optional separate Gemini 4 Argon weekly pool belongs between the Gemini and Claude rows. | Clamp each finite fraction to the interval from zero to one. Skip an unusable bucket independently and keep valid siblings. Preserve precision and raw reset times in JSON. Hide the countdown and pace mark on an unused five-hour window with a future reset. An expired reset timestamp alone cannot establish a refill. |
| Partial responses | The first usable observation for each bucket wins. A complete primary response needs all four standard pools. A successful partial summary replaces the previous set. A failed refresh retains the last successful observation. | One callback supplies one observation. A usable report replaces the saved quota set. Startup callbacks without usable readings leave the previous observation and timestamp intact. |
| Refresh and failure | Poll quota every five minutes. Cache plan metadata for an hour, mark quota stale after ten minutes, and honor rate limits during manual refresh. Distinguish rejected credentials from subscription access refusal and temporary outages. | The official CLI publishes updates while it runs. Jackin records observation time and exposes freshness. The callback contains no OAuth or HTTP failure details from which to classify an upstream refusal. |
| Verification | Exercise account replacement and removal races, secondary-source fallback, malformed and missing buckets, precise fractions, reset times, and successful empty versus failed responses. | Use controlled callback fixtures for malformed and partial data. Compare the CLI and TUI against a real enrolled account separately. Direct Google sign-in, grant renewal, and background fetch while Antigravity is closed remain unverified in Jackin. |

The supplied Jackin research describes the older implementation at `1b8a6f85`. The current connected-account registry already stores account IDs, last observations and timestamps, and the Antigravity connector already reaches both the CLI and TUI. Use the existing registry for this feature. An execution-account import would change the credential source and would not establish a direct monitoring grant. [Account lifecycle](../../crates/usage/jackin-usage/src/accounts/antigravity.rs) · [Enrollment](../../crates/usage/jackin-usage/src/onboarding/antigravity.rs) · [Quota parser](../../crates/usage/jackin-usage-provider-gemini/src/statusline.rs)

The reference discovers Argon from a named group and an unambiguous weekly bucket. Jackin receives keyed windows through the status line. That payload has no group membership with which to identify an arbitrary new ID as Argon. The reference also exports its own metric IDs, while Jackin retains its existing resource IDs for CLI consumers. [Reference mapper](https://github.com/robinebers/openusage/blob/53f70b396698656cb5e1e3f59c40d1b86d6b5296/Sources/OpenUsage/Providers/Antigravity/AntigravityUsageMapper.swift) · [Reference refresh runtime](https://github.com/robinebers/openusage/blob/53f70b396698656cb5e1e3f59c40d1b86d6b5296/Sources/OpenUsage/Providers/AccountProviderRuntime.swift)

For a future direct integration, account consent and permission to read subscription quota are separate prerequisites. Use an OAuth client authorized for Jackin. The browser flow needs S256 PKCE, single-use state, a loopback callback, cancellation, and state validation on pasted responses. Keep stable account identity separate from rotating access tokens. Serialize renewal and replacement per account, retain a usable token during a failed early renewal, and reject late writes after reconnect or removal. Google sign-in alone proves identity. A quota read must establish access to the subscription. [Reference lifecycle and renewal](https://github.com/robinebers/openusage/blob/53f70b396698656cb5e1e3f59c40d1b86d6b5296/Sources/OpenUsage/Providers/AccountProviderRuntime.swift)

For independently fetched summaries, process valid observations in source priority order and fill only missing buckets from the fallback. Keep a successful response even when the other source fails. Distinguish malformed responses from a successful empty set. Treat a subscription-access refusal separately from an expired grant; renew at most once after a token refusal. OpenUsage caps a positive Retry-After at one hour in the HTTP response parser and accepts both seconds and an HTTP date. Its refresh scheduler preserves that hold during a forced refresh. These behaviors require an authorized direct data source to verify end to end.
