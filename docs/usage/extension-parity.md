# Kimi, MiniMax, MiMo and Gemini usage accounts

Jackin connects these four providers in the CLI and TUI. This audit compares the implementation with each provider's contract as of 22 November 2026. These are additions to the pinned OpenUsage provider set. The acceptance evidence below comes from local HTTP fixtures and a test vault. [OpenUsage baseline](https://github.com/robinebers/openusage/tree/53f70b396698656cb5e1e3f59c40d1b86d6b5296) · [Initial jackin implementation](https://github.com/jackin-project/jackin/tree/1b8a6f85c5f0ba0d7e25b406e0850f7abc8533a8)

| Provider | Connect and reconnect | Usage |
|---|---|---|
| Kimi | Select `global` or `cn`. The default method accepts a Kimi Code console key. Device sign-in prompts for a registered OAuth client ID, displays the verification URI and user code, and polls the regional token endpoint. The OAuth account identity combines the region and authenticated user ID. Sign In Again reuses the client registration. Jackin renews expiring grants and saves rotated tokens in the vault. [Regions](https://github.com/MoonshotAI/kimi-code/blob/83e4dde93453dd22e89da03d2c96d84999e7d0c2/packages/oauth/src/region.ts) · [Device and refresh grants](https://github.com/MoonshotAI/kimi-code/blob/83e4dde93453dd22e89da03d2c96d84999e7d0c2/packages/oauth/src/oauth.ts) · [Identity](https://github.com/MoonshotAI/kimi-code/blob/83e4dde93453dd22e89da03d2c96d84999e7d0c2/packages/oauth/src/managed-userinfo.ts) | Five-hour, weekly, monthly total and monthly code windows carry separate usage ratios and optional resets. The optional booster wallet preserves sub-cent balances, monthly spend, the cap and its enabled state. [Usage contract](https://github.com/MoonshotAI/kimi-code/blob/83e4dde93453dd22e89da03d2c96d84999e7d0c2/packages/oauth/src/managed-usage.ts) |
| MiniMax | Select `global` or `cn`. A Token Plan key validates through plan quota. A metered `sk-api-` key validates through balance. Device sign-in prompts for a registered OAuth client ID, verifies the state response, polls with an S256 PKCE verifier and renews on the saved regional issuer. An OAuth access token can begin with `sk-api-` and still use plan quota. The documented device token response supplies no stable account subject. Jackin retains the local account ID and keys API-key connections by fingerprint. | Xiaomi MiMo | For Token Plan, select `cn`, `sgp` or `ams` to match the subscription and enter the `tp-` key. A regular `sk-` key uses the separate balance and daily history product. [Cluster selection](https://mimo.mi.com/docs/en-US/tokenplan/Token%20Plan/subscription) · [Credits](https://mimo.mi.com/docs/en-US/api/asset/credits-get) · [Balance](https://mimo.mi.com/docs/en-US/api/asset/balance-get) | Plan credits are integer total, used and remaining counts with UTC period bounds. Regular accounts expose balances per currency, model and plugin consumption, request and token counts, six-decimal usage costs and two-decimal bills. Jackin fetches the last 30 inclusive UTC days starting no earlier than 1 September 2026. Bills and consumption retain independent timestamps. Automatic reads cache successful history for one hour. Manual and failed reads have a five-minute retry interval. History details retain each currency separately and identify stale reads. | Gemini | Register a Desktop app OAuth client in Google Cloud, enable the APIs required for the project and configure the consent screen. Set `JACKIN_GOOGLE_OAUTH_CLIENT_FILE` to the downloaded Desktop app JSON to open consent directly and discover the managed project. With the variable unset, enter the client ID, optional masked secret and optional Cloud project interactively. Jackin requests offline access with PKCE and an ephemeral loopback callback, then reads the authenticated subject and Code Assist project. The account identity includes both. Reconnect reuses the vault registration or prompts for it again when the slot is missing. Google lists the client ID as required and the client secret as optional for the desktop token exchange. ## Verification

The provider tests exercise successful reads, wrong products, zero versus absent counters and upstream refusal. The account tests drive region and method selection, grant cancellation or denial, Kimi subject mismatch, retained account identity, MiniMax state and PKCE, renewal and recovery after the vault entry disappears. Gemini tests exercise the local browser callback, registered-client renewal, managed project enrollment, operation host restrictions and project refusal. MiMo tests cover exact amounts above JavaScript's integer precision, UTC dates, currency separation, empty ranges, partial failure and independent retry cadence. [Regional device accounts](../../crates/usage/jackin-usage/tests/connected_accounts/regional_device.rs) · [Extension integration tests](../../crates/usage/jackin-usage/tests/extension_connections.rs) · [Gemini enrollment tests](../../crates/usage/jackin-usage-provider-gemini/tests/account.rs) · [MiMo credits and balance](../../crates/usage/jackin-usage-provider-mimo/tests/token_plan.rs)

Live authenticated verification requires matching subscriptions, eligible projects and an OAuth client registration accepted by the issuer for device or browser sign-in. No jackin release registration is bundled. The Kimi and MiniMax upstream sources publish registrations for their own clients. Public third-party registration procedures for those providers have not been verified. Their console-key methods operate independently of OAuth registration. No customer credential was used in these checks.


## Which Google account does browser sign-in connect?

The reference OpenUsage Mac app registers its Google entry as Antigravity. It opens Google's browser consent page with a preconfigured installed-app client, uses PKCE and a loopback callback, and reads Antigravity's project and quota summary. The separate OpenUsage CLI detects an existing Gemini CLI login and requests Code Assist quota. These paths report different products. [Mac browser flow](https://github.com/robinebers/openusage/blob/53f70b396698656cb5e1e3f59c40d1b86d6b5296/Sources/OpenUsage/Services/BrowserProviderLogins.swift#L119) · [Antigravity quota reader](https://github.com/robinebers/openusage/blob/53f70b396698656cb5e1e3f59c40d1b86d6b5296/Sources/OpenUsage/Providers/Antigravity/AntigravityUsageClient.swift) · [OpenUsage CLI Gemini reader](https://openusage.sh/docs/providers/gemini-cli/)

Google retired consumer Gemini CLI and Code Assist access for individual, Google AI Pro and Ultra accounts on June 18, 2026. The Jackin Gemini connector applies to eligible Cloud Code Assist projects. A registered desktop client identifies the application to Google. Browser consent then authorizes the individual user. [Google deprecation](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals) · [Google app registration policy](https://developers.google.com/identity/protocols/oauth2/policies)

Gemini Apps exposes consumer subscription limits in **Settings → Usage Limits**. Antigravity reports its own model quotas, and Google One shows the subscription tier. The published Google OAuth scope list and Gemini Apps user guide do not identify a third-party endpoint for reading the personal Gemini Apps usage windows. Signing in with Google establishes identity. Jackin still needs a verified way to read those windows with its own authorization before it can display them as a native connection. [Gemini Apps limits](https://support.google.com/gemini/answer/16275805?hl=en) · [Google OAuth scopes](https://developers.google.com/identity/protocols/oauth2/scopes)
